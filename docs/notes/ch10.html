벡터: 문자열

문자열을 작동하게 하는 요소를 배우고 마음대로 사용할 수 있는 강력한 문자열 조작 도구를 숙달할 때입니다. 문자열과 문자형 벡터(character vectors)를 만드는 세부적인 내용부터 시작하겠습니다. 그런 다음 데이터에서 문자열을 만드는 방법과, 반대로 데이터에서 문자열을 추출(extracting)하는 방법으로 깊이 들어갈 것입니다. 이후 개별 글자(letters)를 다루는 도구에 대해 논의하겠습니다.

library(tidyverse)
library(babynames)

모든 stringr 함수는 str_로 시작하기 때문에 여러분이 stringr 함수를 언제 사용하고 있는지 빠르게 알 수 있습니다. RStudio를 사용하는 경우 이것이 특히 유용한데, str_을 입력하면 자동 완성(autocomplete)이 실행(trigger)되어 사용 가능한 기능을 기억해 내는(jog your memory) 데 도움이 되기 때문입니다.

1 문자열 만들기

우리는 이 책의 앞부분에서 스쳐 지나가며 문자열을 만들었지만 세부 사항에 대해서는 논의하지 않았습니다. 우선 단일 따옴표(')나 이중 따옴표(")를 사용하여 문자열을 만들 수 있습니다. 둘 사이에 동작의 차이는 없으므로 일관성을 위해 문자열에 여러 개의 "가 포함되지 않는 한 "를 사용하는 것을 tidyverse 스타일 가이드는 권장합니다.

string1 <- "This is a string"
string2 <- 'If I want to include a "quote" inside a string, I use single quotes'

따옴표를 닫는 것을 잊어버리면 + 프롬프트가 나타납니다.

> "This is a string without a closing quote
+ 
+ 
+ HELP I'M STUCK IN A STRING

이런 일이 발생했는데 어떤 따옴표를 닫아야 할지 모르겠다면(can’t figure out) Escape 키를 눌러 취소하고 다시 시도하세요.

1.1 이스케이프

문자열에 리터럴 단일 또는 이중 따옴표(literal single or double quote)를 포함하려면 \를 사용하여 “이스케이프(escape)”할 수 있습니다.

double_quote <- "\"" # or '"'
single_quote <- '\'' # or "'"

따라서 문자열에 리터럴 백슬래시(literal backslash)를 포함하려면 "\\"로 이스케이프해야 합니다.

backslash <- "\\"

문자열의 출력된 표현(printed representation)은 인쇄된 표현에 이스케이프가 표시되기 때문에 문자열 자체와 동일하지 않다는 점에 주의하세요(다시 말해 문자열을 인쇄할 때 출력을 복사하고 붙여넣어 그 문자열을 다시 만들 수 있습니다). 문자열의 원래 내용(raw contents)을 보려면 str_view()1를 사용하세요.

x <- c(single_quote, double_quote, backslash)
x
#> [1] "'"  "\"" "\\"
str_view(x)
#> [1] │ '
#> [2] │ "
#> [3] │ \

1.2 원시 문자열

여러 개의 따옴표나 백슬래시를 사용하여 문자열을 만들면 금방 혼란스러워집니다. 문제를 설명(illustrate)하기 위해, double_quote와 single_quote 변수를 정의하는 코드 블록의 내용을 포함하는 문자열을 만들어 보겠습니다.

tricky <- "double_quote <- \"\\\"\" # or '\"'
single_quote <- '\\'' # or \"'\""
str_view(tricky)
#> [1] │ double_quote <- "\"" # or '"'
#>     │ single_quote <- '\'' # or "'"

백슬래시가 참 많습니다! 이것을 때때로 기울어진 이쑤시개 증후군이라고 합니다. 이스케이프를 없애려면(eliminate) 대신 원시 문자열(raw string)2을 사용할 수 있습니다.

tricky <- r"(double_quote <- "\"" # or '"'
single_quote <- '\'' # or "'")"
str_view(tricky)
#> [1] │ double_quote <- "\"" # or '"'
#>     │ single_quote <- '\'' # or "'"

원시 문자열은 보통 r"(로 시작하고 )"로 끝납니다. 하지만 문자열에 )"가 포함되어 있다면 r"[]"나 r"{}"를 대신 사용할 수 있고, 그래도 충분하지 않다면 여러 개의 대시(dashes)를 삽입하여 열고 닫는 쌍을 고유하게 만들 수 있습니다.

1.3 기타 특수 문자

", ', \ 외에도 유용하게 사용할 수 있는 몇 가지 특수 문자가 있습니다. 흔한 것은 줄 바꿈(new line)인 \n과 탭(tab)인 \t입니다. 문자열에 \u 또는 \U로 시작하는 유니코드 이스케이프가 포함된 것도 가끔 볼 수 있습니다. 이것은 모든 시스템에서 작동하는 영어가 아닌 문자를 작성하는 방법입니다. ?Quotes에서 다른 특수 문자의 전체 목록을 볼 수 있습니다.

x <- c("one\ntwo", "one\ttwo", "\u00b5", "\U0001f604")
x
#> [1] "one\ntwo" "one\ttwo" "µ"        "😄"
str_view(x)
#> [1] │ one
#>     │ two
#> [2] │ one{\t}two
#> [3] │ µ
#> [4] │ 😄

str_view()는 탭을 쉽게 눈에 띄게 만들기 위해(easier to spot)3 중괄호(curly braces)를 사용한다는 점에 유의하세요. 텍스트 작업의 과제 중 하나는 텍스트에 공백(white space)이 포함될 수 있는 다양한 방법이 있다는 것이므로, 이 배경(background)은 무언가 이상한 일이 일어나고 있음을 인식(recognize)하는 데 도움이 됩니다.

2 데이터에서 여러 문자열 만들기

“수동(by hand)”으로 한두 개의 문자열을 만드는 기본 사항을 배웠으므로, 다른 문자열로부터 문자열을 만드는 세부 사항으로 넘어가겠습니다. 이는 여러분이 작성한 텍스트를 데이터 프레임의 문자열과 결합하려는(combine) 일반적인 문제를 해결하는 데 도움이 될 것입니다. 예를 들어 “Hello”를 name 변수와 결합하여 인사말(greeting)을 만들 수 있습니다.

2.1 str_c()

str_c()는 여러 개의 벡터를 인수로 받고 문자형 벡터를 반환합니다.

str_c("x", "y")
#> [1] "xy"
str_c("x", "y", "z")
#> [1] "xyz"
str_c("Hello ", c("John", "Susan"))
#> [1] "Hello John"  "Hello Susan"

str_c()는 기본 paste0()과 매우 유사하지만 결측값을 재활용(recycling)하고 전파(propagating)하는 일반적인 tidyverse 규칙을 따름으로써 mutate()와 함께 사용하도록 설계되었습니다.

df <- tibble(name = c("Flora", "David", "Terra", NA))
df |> mutate(greeting = str_c("Hi ", name, "!"))
#> # A tibble: 4 × 2
#>   name  greeting 
#>   <chr> <chr>    
#> 1 Flora Hi Flora!
#> 2 David Hi David!
#> 3 Terra Hi Terra!
#> 4 <NA>  <NA>

결측값이 다른 방식으로 표시되게 하려면 coalesce()를 사용하여 대체하세요. 원하는 방식에 따라 str_c() 내부 또는 외부에서 사용할 수 있습니다.

df |>
    mutate(
        greeting1 = str_c("Hi ", coalesce(name, "you"), "!"),
        greeting2 = coalesce(str_c("Hi ", name, "!"), "Hi!")
    )
#> # A tibble: 4 × 3
#>   name  greeting1 greeting2
#>   <chr> <chr>     <chr>    
#> 1 Flora Hi Flora! Hi Flora!
#> 2 David Hi David! Hi David!
#> 3 Terra Hi Terra! Hi Terra!
#> 4 <NA>  Hi you!   Hi!

2.2 str_glue()

str_c()로 많은 고정 문자열과 변수 문자열을 섞다(mixing) 보면 "를 많이 입력하게 되어 코드의 전체적인 목표를 파악하기 어렵다는 것을 알게 될 것입니다. 이에 대한 대안적 접근 방식은 str_glue()4를 통한 glue 패키지(https://glue.tidyverse.org)에 의해 제공됩니다. 이 함수에는 특별한 기능이 있는 단일 문자열을 제공합니다. {} 안의 모든 내용은 따옴표 밖에 있는 것처럼 평가(evaluated)됩니다.

df |> mutate(greeting = str_glue("Hi {name}!"))
#> # A tibble: 4 × 2
#>   name  greeting 
#>   <chr> <glue>   
#> 1 Flora Hi Flora!
#> 2 David Hi David!
#> 3 Terra Hi Terra!
#> 4 <NA>  Hi NA!

보시다시피 str_glue()는 현재 결측값을 "NA" 문자열로 변환하므로, 안타깝게도 str_c()와 일관성이 없습니다.

문자열 안에 일반적인 {나 }를 포함해야 하는 경우 어떻게 되는지 궁금할 수도 있습니다. 어떻게든 이스케이프해야 할 것이라고 짐작했다면 올바른 방향(on the right track)입니다. 요령(trick)은 glue가 약간 다른 이스케이프 기술을 사용한다는 것입니다. \와 같은 특수 문자로 접두사(prefixing)를 붙이는 대신 특수 문자를 두 번 씁니다(double up).

df |> mutate(greeting = str_glue("{{Hi {name}!}}"))
#> # A tibble: 4 × 2
#>   name  greeting   
#>   <chr> <glue>     
#> 1 Flora {Hi Flora!}
#> 2 David {Hi David!}
#> 3 Terra {Hi Terra!}
#> 4 <NA>  {Hi NA!}

2.3 str_flatten()

str_c()와 str_glue()는 출력이 입력과 길이가 동일하기 때문에 mutate()와 잘 작동합니다. summarize()와 잘 작동하는 함수, 즉 항상 단일 문자열을 반환하는 함수를 원한다면 어떻게 할까요? 그것이 바로 str_flatten()5의 임무(job)입니다. 문자형 벡터를 취하고 벡터의 각 요소를 단일 문자열로 결합합니다.

str_flatten(c("x", "y", "z"))
#> [1] "xyz"
str_flatten(c("x", "y", "z"), ", ")
#> [1] "x, y, z"
str_flatten(c("x", "y", "z"), ", ", last = ", and ")
#> [1] "x, y, and z"

이렇게 하면 summarize()와 잘 작동합니다.

df <- tribble(
    ~name     , ~fruit       ,
    "Carmen"  , "banana"     ,
    "Carmen"  , "apple"      ,
    "Marvin"  , "nectarine"  ,
    "Terence" , "cantaloupe" ,
    "Terence" , "papaya"     ,
    "Terence" , "mandarin"
)
df |>
    group_by(name) |>
    summarize(fruits = str_flatten(fruit, ", "))
#> # A tibble: 3 × 2
#>   name    fruits                      
#>   <chr>   <chr>                       
#> 1 Carmen  banana, apple               
#> 2 Marvin  nectarine                   
#> 3 Terence cantaloupe, papaya, mandarin

3 데이터에서 문자열 추출하기

여러 변수가 단일 문자열에 함께 쑤셔 넣어지는(crammed together) 경우는 매우 흔합니다.

  • df |> separate_longer_delim(col, delim)
  • df |> separate_longer_position(col, width)
  • df |> separate_wider_delim(col, delim, names)
  • df |> separate_wider_position(col, widths)

자세히 보면 여기에 공통된 패턴이 있다는 것을 알 수 있습니다. separate_, 그다음 longer 또는 wider, 그다음 _, 그리고 delim 또는 position. 이 네 가지 함수가 두 가지 더 단순한 원시 요소(primitives)로 구성(composed)되어 있기 때문입니다.

-pivot_longer() 및 pivot_wider()와 마찬가지로 _longer 함수는 새 행을 만들어 입력 데이터 프레임을 더 길게(longer) 만들고, _wider 함수는 새 열을 생성하여 입력 데이터 프레임을 더 넓게(wider) 만듭니다. - delim은 ", " 또는 " "와 같은 구분 기호(delimiter)로 문자열을 분할합니다; position은 c(3, 5, 2)와 같이 지정된 너비로 분할합니다.

이것은 wider 함수 중 유연하지만 이것을 사용하려면 정규 표현식에 대해 알아야 합니다.

3.1 행으로 분리하기

문자열을 행으로 분리하는 것은 구성 요소(components)의 수가 행마다 다를 때(varies) 유용합니다. 일반적인 경우는 구분 기호를 기준으로 분할하기 위해 separate_longer_delim()이 필요한 경우입니다.

df1 <- tibble(x = c("a,b,c", "d,e", "f"))
df1 |>
    separate_longer_delim(x, delim = ",")
#> # A tibble: 6 × 1
#>   x    
#>   <chr>
#> 1 a    
#> 2 b    
#> 3 c    
#> 4 d    
#> 5 e    
#> 6 f

실전에서(in the wild) separate_longer_position()을 보는 것은 더 드물지만(rarer), 일부 오래된 데이터셋은 각 문자가 하나의 값을 기록하는 데 사용되는 매우 조밀한 형식(compact format)을 사용합니다.

df2 <- tibble(x = c("1211", "131", "21"))
df2 |>
    separate_longer_position(x, width = 1)
#> # A tibble: 9 × 1
#>   x    
#>   <chr>
#> 1 1    
#> 2 2    
#> 3 1    
#> 4 1    
#> 5 1    
#> 6 3    
#> # ℹ 3 more rows

3.2 열로 분리하기

문자열을 열로 분리하는 것은 각 문자열에 고정된 수의 구성 요소가 있고 그것들을 열로 펼치고자(spread) 할 때 유용합니다. 열의 이름을 지정해야 하기 때문에 상응하는 longer에 비해 약간 더 복잡합니다.

예를 들어 다음 데이터셋에서 x는 코드, 에디션 번호 및 연도로 구성되어 있으며 "."으로 구분되어 있습니다. separate_wider_delim()을 사용하기 위해 우리는 구분 기호와 이름(names)을 두 개의 인수로 제공합니다.

df3 <- tibble(x = c("a10.1.2022", "b10.2.2011", "e15.1.2015"))
df3 |>
    separate_wider_delim(
        x,
        delim = ".",
        names = c("code", "edition", "year")
    )
#> # A tibble: 3 × 3
#>   code  edition year 
#>   <chr> <chr>   <chr>
#> 1 a10   1       2022 
#> 2 b10   2       2011 
#> 3 e15   1       2015

특정 조각(piece)이 유용하지 않은 경우 NA 이름을 사용하여 결과에서 생략할 수 있습니다.

df3 |>
    separate_wider_delim(
        x,
        delim = ".",
        names = c("code", NA, "year")
    )
#> # A tibble: 3 × 2
#>   code  year 
#>   <chr> <chr>
#> 1 a10   2022 
#> 2 b10   2011 
#> 3 e15   2015

separate_wider_position()은 일반적으로 각 열의 너비를 지정해야 하기 때문에 조금 다르게 작동합니다. 따라서 이름(name)이 새 열의 이름을 제공하고 값(value)이 그것이 차지하는(occupies) 문자 수를 나타내는 이름이 있는(named) 정수형 벡터를 제공합니다.

이름을 지정하지 않으면 출력에서 값을 생략할 수 있습니다.

df4 <- tibble(x = c("202215TX", "202122LA", "202325CA"))
df4 |>
    separate_wider_position(
        x,
        widths = c(year = 4, age = 2, state = 2)
    )
#> # A tibble: 3 × 3
#>   year  age   state
#>   <chr> <chr> <chr>
#> 1 2022  15    TX   
#> 2 2021  22    LA   
#> 3 2023  25    CA

3.3 widening 문제 진단하기

separate_wider_delim()6에는 고정되어 있고 알려진(known) 열 집합이 필요합니다. 일부 행에 예상되는 개수의 조각이 없다면 어떻게 될까요?

너무 적거나(too few) 너무 많은(too many) 조각이라는 두 가지 가능한 문제가 있으므로 separate_wider_delim()은 도움이 되는 두 가지 인수인 too_few와 too_many를 제공합니다. 먼저 다음 샘플 데이터셋으로 too_few 경우를 살펴보겠습니다.

df <- tibble(a = c("1-1-1", "1-1-2", "1-3", "1-3-2", "1"))

df |>
    separate_wider_delim(
        a,
        delim = "-",
        names = c("x", "y", "z")
    )
#> Error in `separate_wider_delim()`:
#> ! Expected 3 pieces in each element of `a`.
#> ! 2 values were too short.
#> ℹ Use `too_few = "debug"` to diagnose the problem.
#> ℹ Use `too_few = "align_start"/"align_end"` to silence this message.

오류가 발생한다는 것을 알 수 있지만, 이 오류는 어떻게 진행(proceed)할 수 있는지에 대한 몇 가지 제안(suggestions)을 제공합니다. 문제를 디버깅(debugging)하는 것부터 시작하겠습니다.

debug <- df |>
    separate_wider_delim(
        a,
        delim = "-",
        names = c("x", "y", "z"),
        too_few = "debug"
    )
#> Warning: Debug mode activated: adding variables `a_ok`, `a_pieces`, and
#> `a_remainder`.
debug
#> # A tibble: 5 × 7
#>   x     y     z     a     a_ok  a_pieces a_remainder
#>   <chr> <chr> <chr> <chr> <lgl>    <int> <chr>      
#> 1 1     1     1     1-1-1 TRUE         3 ""         
#> 2 1     1     2     1-1-2 TRUE         3 ""         
#> 3 1     3     <NA>  1-3   FALSE        2 ""         
#> 4 1     3     2     1-3-2 TRUE         3 ""         
#> 5 1     <NA>  <NA>  1     FALSE        1 ""

디버그 모드를 사용하면 출력에 세 개의 추가 열이 더해집니다. a_ok, a_pieces, a_remainder (변수를 다른 이름으로 분리하면 접두사가 다르게 됩니다). 여기서 a_ok를 사용하면 실패한 입력을 빠르게 찾을 수 있습니다.

debug |> filter(!a_ok)
#> # A tibble: 2 × 7
#>   x     y     z     a     a_ok  a_pieces a_remainder
#>   <chr> <chr> <chr> <chr> <lgl>    <int> <chr>      
#> 1 1     3     <NA>  1-3   FALSE        2 ""         
#> 2 1     <NA>  <NA>  1     FALSE        1 ""

a_pieces는 예상되는 3(names의 길이)과 비교하여 몇 개의 조각이 발견되었는지 알려줍니다. a_remainder는 조각이 너무 적을 때는 유용하지 않지만 곧 다시 보게 될 것입니다.

때로는 이 디버깅 정보를 보면 구분 기호 전략에 문제가 있음이 드러나거나(reveal) 분리하기 전에 전처리(preprocessing)를 더 해야 한다는 것을 시사할 수 있습니다. 이런 경우, 상류(upstream)에서 문제를 수정하고 too_few = "debug"를 제거하여 새로운 문제가 오류가 되도록 하세요.

다른 경우에는 누락된 부분을 NA로 채우고 계속 진행(move on)하고 싶을 수 있습니다. 이것이 too_few = "align_start" 및 too_few = "align_end"의 임무(job)이며, 이를 통해 NA가 위치해야 할 곳을 제어할 수 있습니다.

df |>
    separate_wider_delim(
        a,
        delim = "-",
        names = c("x", "y", "z"),
        too_few = "align_start"
    )
#> # A tibble: 5 × 3
#>   x     y     z    
#>   <chr> <chr> <chr>
#> 1 1     1     1    
#> 2 1     1     2    
#> 3 1     3     <NA> 
#> 4 1     3     2    
#> 5 1     <NA>  <NA>

너무 많은 조각이 있는 경우에도 동일한 원리가 적용됩니다.

df <- tibble(a = c("1-1-1", "1-1-2", "1-3-5-6", "1-3-2", "1-3-5-7-9"))

4 글자

이 섹션에서는 문자열 내의 개별 글자로 작업할 수 있게 해주는 함수들을 소개합니다. 문자열의 길이를 구하는 방법, 부분 문자열(substrings)을 추출하는 방법, 그래프과 표에서 긴 문자열을 다루는(handle) 방법을 배우게 됩니다.

4.1 길이

str_length()는 문자열에 있는 글자의 개수를 알려줍니다.

str_length(c("a", "R for data science", NA))
#> [1]  1 18 NA

이것을 count()와 함께 사용하여 미국 아기 이름 길이의 분포를 찾은 다음, filter()를 사용하여 긴 이름을 볼 수 있습니다(우연히(happen to) 15글자인 이름들입니다)7.

babynames |>
    count(length = str_length(name), wt = n)

babynames |>

    count(name, wt = n, sort = TRUE)

4.2 부분집합

str_sub(string, start, end)를 사용하여 문자열의 일부를 추출할 수 있으며, 여기서 start와 end는 부분 문자열이 시작되고 끝나야 하는 위치입니다. start와 end 인수는 포함(inclusive)되므로, 반환되는 문자열의 길이는 end - start + 1이 됩니다.

x <- c("Apple", "Banana", "Pear")
str_sub(x, 1, 3)
#> [1] "App" "Ban" "Pea"

음수 값을 사용하여 문자열의 끝에서부터 거꾸로(back) 셀 수 있습니다. -1은 마지막 문자, -2는 끝에서 두 번째 문자 등입니다.

str_sub(x, -3, -1)
#> [1] "ple" "ana" "ear"

문자열이 너무 짧아도 str_sub()는 실패하지 않는다는 점에 유의하세요. 단지 가능한 만큼 반환할 것입니다.

str_sub("a", 1, 5)
#> [1] "a"

우리는 mutate()와 함께 str_sub()를 사용하여 각 이름의 첫 글자와 마지막 글자를 찾을 수 있습니다.

babynames |>
    mutate(
        first = str_sub(name, 1, 1),
        last = str_sub(name, -1, -1)
    )
#> # A tibble: 1,924,665 × 7
#>    year sex   name          n   prop first last 
#>   <dbl> <chr> <chr>     <int>  <dbl> <chr> <chr>
#> 1  1880 F     Mary       7065 0.0724 M     y    
#> 2  1880 F     Anna       2604 0.0267 A     a    
#> 3  1880 F     Emma       2003 0.0205 E     a    
#> 4  1880 F     Elizabeth  1939 0.0199 E     h    
#> 5  1880 F     Minnie     1746 0.0179 M     e    
#> 6  1880 F     Margaret   1578 0.0162 M     t    
#> # ℹ 1,924,659 more rows

  2. str_length()와 str_sub()를 사용하여 각 아기 이름에서 중간 글자를 추출하세요. 문자열에 짝수 개의 문자가 있으면 어떻게 할 것입니까?

  3. 시간이 지남에 따라 아기 이름의 길이에 주요 추세(major trends)가 있습니까? 첫 글자와 마지막 글자의 인기는 어떻습니까?

5 영어가 아닌 텍스트

지금까지 우리는 영어 텍스트에 초점을 맞췄는데, 이는 두 가지 이유로 다루기 특히 쉽습니다. 첫째, 영어 알파벳은 비교적 간단합니다. 단 26개의 글자만 있습니다. 둘째 (아마 더 중요하게도), 오늘날 우리가 사용하는 컴퓨팅 인프라는 주로(predominantly) 영어 사용자에 의해 설계되었습니다. 안타깝게도 영어가 아닌 언어를 온전히(full treatment) 다룰 공간이 없습니다. 그럼에도 불구하고(Still) 우리는 인코딩(encoding), 글자 변형(letter variations), 그리고 로케일 종속 함수(locale-dependent functions)와 같이 여러분이 마주칠(encounter) 수 있는 큰 과제 중 일부에 여러분의 주의를 환기(draw your attention)하고 싶었습니다.

5.1 인코딩

영어가 아닌 텍스트로 작업할 때 첫 번째 과제는 종종 인코딩(encoding)입니다. 무슨 일이 일어나고 있는지 이해하려면 컴퓨터가 문자열을 표현하는 방식을 파헤쳐봐야(dive into) 합니다. R에서는 charToRaw()를 사용하여 문자열의 기본 표현(underlying representation)을 알 수 있습니다.

charToRaw("Hadley")
#> [1] 48 61 64 6c 65 79

이 여섯 개의 16진수(hexadecimal numbers) 각각은 하나의 글자를 나타냅니다. 48은 H, 61은 a 등등. 16진수에서 문자로의 매핑(mapping)을 인코딩이라고 하며, 이 경우 인코딩을 ASCII라고 합니다. ASCII는 정보 교환을 위한 미국 표준 코드(American Standard Code for Information Interchange)이기 때문에 영어 문자를 훌륭하게 표현합니다.

영어 이외의 언어에 대해서는 상황이 그렇게 쉽지 않습니다. 컴퓨팅 초창기에는 영어 이외의 문자를 인코딩하기 위한 여러 경쟁 표준(competing standards)이 있었습니다. 예를 들어 유럽에는 두 가지 다른 인코딩이 있었습니다. 서유럽 언어에는 Latin1(일명 ISO-8859-1)이 사용되었고, 중부 유럽 언어에는 Latin2(일명 ISO-8859-2)가 사용되었습니다. Latin1에서 바이트 b1은 “±”이지만, Latin2에서는 “ą”입니다! 다행히 오늘날에는 거의 모든 곳에서 지원되는 하나의 표준인 UTF-8이 있습니다. UTF-8은 오늘날 인간이 사용하는 거의 모든 문자와 이모티콘 같은 많은 추가 기호를 인코딩할 수 있습니다.

readr은 모든 곳에서 UTF-8을 사용합니다. 이것은 좋은 기본값이지만 UTF-8을 사용하지 않는 구형(older) 시스템에서 생성된 데이터에 대해서는 실패할 것입니다. 이런 일이 발생하면 문자열을 인쇄할 때 문자열이 이상해 보일 것입니다. 때로는 한두 문자만 엉망이 될(messed up) 수도 있고, 다른 때는 완전히 뜻 모를 글(gibberish)을 얻게 될 것입니다. 예를 들어 여기에 비정상적인 인코딩을 가진 두 개의 인라인 CSV가 있습니다8:

x1 <- "text\nEl Ni\xf1o was particularly bad this year"
read_csv(x1)$text
#> [1] "El Ni\xf1o was particularly bad this year"

x2 <- "text\n\x82\xb1\x82\xf1\x82\xc9\x82\xbf\x82\xcd"
read_csv(x2)$text
#> [1] "\x82\xb1\x82\xf1\x82ɂ\xbf\x82\xcd"

이들을 올바르게 읽으려면 locale 인수를 통해 인코딩을 지정합니다.

read_csv(x1, locale = locale(encoding = "Latin1"))$text
#> [1] "El Niño was particularly bad this year"

read_csv(x2, locale = locale(encoding = "Shift-JIS"))$text
#> [1] "こんにちは"

올바른 인코딩을 어떻게 찾을 수 있을까요? 운이 좋다면 데이터 설명서 어딘가에 포함되어 있을 것입니다. 안타깝게도 그런 경우는 드물기(rarely the case) 때문에 readr은 사용자가 알아내는 데 도움이 되도록 guess_encoding()을 제공합니다. 이것은 완벽하지 않으며(not foolproof) 텍스트가 많을 때(여기서와 달리) 더 잘 작동하지만 시작하기에는 합리적인 곳입니다. 올바른 인코딩을 찾기 전에 몇 가지 다른 인코딩을 시도해 볼 것을 예상하세요.

인코딩은 풍부하고(rich) 복잡한 주제입니다; 여기서는 표면만 살짝 다루었을(scratched the surface) 뿐입니다. 더 자세히 알아보고 싶다면 http://kunststube.net/encoding/의 자세한 설명을 읽어보는 것을 추천합니다.

5.2 글자 변형 (Letter variations)

강세(accents)가 있는 언어로 작업할 때, 악센트가 있는 문자가 단일 개별 문자(ü)로 인코딩되거나 강세가 없는 문자(u)와 발음 구별 기호(diacritic mark)(¨)를 결합하여 두 문자로 인코딩될 수 있기 때문에 문자의 위치를 결정할 때(str_length() 및 str_sub() 사용 시) 중대한(significant) 과제가 제기(poses)됩니다. 예를 들어, 이 코드는 똑같이(identical) 보이는 ü를 나타내는 두 가지 방법을 보여줍니다.

u <- c("\u00fc", "u\u0308")
str_view(u)
#> [1] │ ü
#> [2] │ ü

하지만 두 문자열은 길이가 다르고 첫 번째 문자도 다릅니다.

str_length(u)
#> [1] 1 2
str_sub(u, 1, 1)
#> [1] "ü" "u"

마지막으로, ==를 사용하여 이러한 문자열을 비교하면 이러한 문자열이 다르다고 해석하는 반면, stringr의 편리한 str_equal() 함수는 둘의 외형(appearance)이 동일함을 인식한다는 점에 유의하세요.

u[[1]] == u[[2]]
#> [1] FALSE

str_equal(u[[1]], u[[2]])
#> [1] TRUE

5.3 로케일 종속 함수

마지막으로 동작이 로케일(locale)에 의존하는 몇 가지 stringr 함수가 있습니다. 로케일은 언어와 유사하지만 언어 내의 지역적 차이를 처리하기 위한 선택적(optional) 지역 지정자(region specifier)를 포함합니다. 로케일은 소문자 언어 약어(abbreviation)로 지정되며 선택적으로 _와 대문자 지역 식별자(region identifier)가 뒤따릅니다. 예를 들어 “en”은 영어, “en_GB”는 영국 영어, “en_US”는 미국 영어입니다.

해당 언어의 코드를 아직 모른다면 위키백과(https://en.wikipedia.org/wiki/List_of_ISO_639-1_codes)에 좋은 목록이 있으며, stringi::stri_locale_list()를 통해 stringr에서 지원되는 언어를 확인할 수 있습니다.

기본 R 문자열 함수는 자동으로 운영 체제에 설정된 로케일을 사용합니다. 이것은 기본 R 문자열 함수가 여러분의 언어에 대해 예상하는 대로 작동하지만 다른 국가에 사는 사람과 코드를 공유하면 코드가 다르게 작동할 수 있음을 의미합니다. 이 문제를 피하기 위해 stringr은 “en” 로케일을 사용하여 기본적으로 영어 규칙을 적용하고 locale 인수를 지정하여 이를 무시(override)하도록 요구합니다. 다행히 로케일이 정말로 중요한 함수 집합은 대소문자 변경(changing case)과 정렬(sorting) 두 가지뿐입니다.

대소문자 변경 규칙은 언어마다 다릅니다. 예를 들어 터키어에는 점이 있는 i와 점이 없는 i, 두 개의 i가 있습니다. 이들은 서로 다른 두 글자이므로 대문자로 표기하는 방법이 다릅니다.

str_to_upper(c("i", "ı"))
#> [1] "I" "I"
str_to_upper(c("i", "ı"), locale = "tr")
#> [1] "İ" "I"

문자열 정렬은 알파벳 순서에 따라 달라지며, 알파벳 순서가 모든 언어에서 동일하지는 않습니다9. 예를 들면 다음과 같습니다. 체코어에서 “ch”는 알파벳 h 다음에 나오는 복합 문자(compound letter)입니다.

str_sort(c("a", "c", "ch", "h", "z"))
#> [1] "a"  "c"  "ch" "h"  "z"
str_sort(c("a", "c", "ch", "h", "z"), locale = "cs")
#> [1] "a"  "c"  "h"  "ch" "z"

이것은 dplyr::arrange()로 문자열을 정렬할 때도 발생하며, 이것이 바로 locale 인수도 가지고 있는 이유입니다.
