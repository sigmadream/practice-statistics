데이터 불러오기

대규모 데이터셋은 수작업으로 계산하는 것이 불가능하지는 않더라도 지루하기 때문에, 수작업으로 데이터를 분석할 수 있는 경우는 거의 없습니다. 따라서 프로그램의 함수와 컴퓨팅 능력을 활용하기 위해 데이터를 다룰 수 있어야 합니다.

데이터를 수집하고 나면, 통계 프로세스의 다음 단계는 탐색적 데이터 분석(exploratory data analyses)을 통해 데이터를 분석하기 시작하는 것입니다. 분석을 더 쉽게 만드는 데 도움이 되는 특정 함수와 데이터를 담고 있는 R의 라이브러리(library), 그리고 파일에서 R로 데이터를 불러오는 방법에 초점을 맞추겠습니다.

라이브러리에 저장된 데이터셋 불러오기

라이브러리에는 분석을 위한 다양한 함수와 데이터셋이 들어 있습니다. 데이터셋의 이름만 알면 이러한 데이터셋을 R 작업 공간(workspace)으로 불러오는 것은 간단합니다. R의 data 함수는 다음 코드를 사용하여 데이터셋을 작업 공간으로 호출합니다.

data(dataset_name, package = "package_name")

그런 다음 Enter 키를 누릅니다. 예로 MASS 라이브러리의 nlschools 데이터셋을 살펴보겠습니다. 이 데이터셋은 네덜란드의 중학교 2학년 학생 2,000명 이상의 시험 점수입니다. 이를 불러오기 위해 다음 코드를 사용합니다.

data(nlschools, package = "MASS")

그런 다음 Enter 키를 누릅니다. 이제 작업 공간에는 분석에 사용할 수 있는 nlschools라는 이름의 데이터 프레임이 존재합니다.

csv 파일을 R로 불러오기

라이브러리에 저장된 데이터셋 외에도 csv 파일에 저장된 데이터셋을 R로 불러올 수도 있습니다. 기본 R의 read.csv()도 사용할 수 있지만, 여기서는 열 유형을 더 명확히 확인할 수 있는 readr::read_csv()를 기본 예시로 사용하겠습니다.

readr를 사용하기 위해서는 tidyverse 라이브러리를 설치해야 합니다. tidyverse는 아래와 같이 설치하세요.

install.packages("tidyverse")

이제 readr 패키지의 read_csv 함수를 사용할 수 있습니다. 이 함수는 csv 파일을 읽어와 데이터 프레임으로 변환합니다. 다음과 같이 사용합니다.

readr::read_csv("data/file_name.csv", show_col_types = FALSE)

파일 위치(file location)는 때때로 찾기 어려울 수 있으며, 위치를 알고 있더라도 함수에 파일 경로(file pathway)를 입력할 때 실수할 가능성이 있습니다. 초기 학습 단계에서는 file.choose()로 파일을 직접 고를 수도 있지만, 재현 가능한 수업 노트에서는 프로젝트 내부의 상대 경로를 명시하는 편이 좋습니다. 코드는 다음과 같을 수 있습니다.

my_data <- readr::read_csv("data/penguins.csv", show_col_types = FALSE)

이 방식은 어떤 파일을 읽었는지가 코드에 남습니다. 불러온 데이터 프레임 my_data는 penguins처럼 의미 있는 이름의 객체로 저장해 주십시오. 그렇지 않으면 파일 내용이 화면에 출력되더라도 이후 분석 단계에서 재사용하기 어렵습니다.

패키지와 데이터 불러오기의 현대적 기준

데이터 분석 과정에서 패키지 설치는 가능하면 코드로 남기는 편이 좋습니다. 메뉴를 눌러 설치하는 방식은 처음 학습할 때 직관적이지만, 나중에 같은 분석 환경을 다시 만들기 어렵습니다. 따라서 분석 과정에는 다음처럼 필요한 패키지를 명시해 두는 습관을 권합니다.

install.packages(c("tidyverse", "MASS"))
library(tidyverse)
library(MASS)

CSV 파일을 불러올 때도 기본 R의 read.csv()는 여전히 사용할 수 있지만, tidyverse 환경에서는 readr::read_csv()를 기본 선택지로 삼을 수 있습니다. read_csv()는 열 유형을 더 일관되게 추정하고, 결과를 tibble로 반환하며, 큰 파일을 다룰 때도 편리합니다.

students <- readr::read_csv(
  file = "data/students.csv",
  show_col_types = FALSE
)

students |>
  glimpse()

file.choose()는 파일을 고를 때 유용하지만, 재현 가능한 분석에는 적합하지 않습니다. 다른 사람이 같은 코드를 실행할 때 어떤 파일을 골랐는지 알 수 없기 때문입니다. 따라서 분석 과정에서는 프로젝트 폴더 안에 data/ 같은 하위 폴더를 만들고, 상대 경로를 사용해 파일을 불러오는 방식을 우선합니다.

nlschools_tbl <- MASS::nlschools |>
  as_tibble()

nlschools_tbl |>
  select(lang, IQ, class) |>
  slice_head(n = 5)

이 방식은 패키지 데이터셋과 외부 파일을 같은 원칙으로 다루게 해 줍니다. 데이터가 어디서 왔는지, 어떤 객체 이름으로 저장되었는지, 처음 확인한 구조가 무엇인지가 코드에 남기 때문에 이후의 탐색적 분석과 추론이 더 안전해집니다.
