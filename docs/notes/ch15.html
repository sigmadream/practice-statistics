Joins

데이터 분석에 단 하나의 데이터 프레임만 포함되는 경우는 드뭅니다(rare). 일반적으로 많은 데이터 프레임이 있으며 관심 있는 질문에 답하려면 데이터 프레임들을 함께 조인(join)해야 합니다. 이 장에서는 두 가지 중요한 조인 유형을 소개합니다.

  • 다른 데이터 프레임에서 일치하는 관측값을 가져와(from matching observations) 한 데이터 프레임에 새 변수를 추가하는 변형 조인(Mutating joins).
  • 다른 데이터 프레임의 관측값과 일치하는지 여부를 기준으로 한 데이터 프레임의 관측값을 필터링하는 필터링 조인(Filtering joins).
library(tidyverse)
library(nycflights13)

1 키 (Keys)

조인을 이해하려면 먼저 각 테이블 내에서 한 쌍의 키를 통해 두 테이블이 어떻게 연결(connected)될 수 있는지 이해해야 합니다. 이 섹션에서는 두 가지 유형의 키에 대해 배우고 nycflights13 패키지의 데이터셋에서 둘 다의 예를 볼 수 있습니다. 또한 키가 유효한지(valid) 확인하는 방법과 테이블에 키가 부족한(lacks) 경우 수행할 작업도 알아봅니다.

1.1 기본 키와 외래 키

모든 조인에는 기본 키(primary key)와 외래 키(foreign key)라는 한 쌍의 키가 포함됩니다. 기본 키(primary key)는 각 관측값을 고유하게 식별하는 변수 또는 변수의 집합입니다. 두 개 이상의 변수가 필요한 경우 해당 키를 복합 키(compound key)라고 합니다.

  • airlines는 각 항공사에 대한 두 가지 데이터, 즉 항공사 코드(carrier code)와 전체 이름을 기록합니다. 두 글자로 된 항공사 코드로 항공사를 식별할 수 있으므로 carrier가 기본 키가 됩니다.

외래 키(foreign key)는 다른 테이블의 기본 키에 해당하는(corresponds to) 변수(또는 변수의 집합)입니다.

  1. flights$tailnum은 기본 키 planes$tailnum에 해당하는 외래 키입니다.
  2. flights$carrier는 기본 키 airlines$carrier에 해당하는 외래 키입니다.
  3. flights$origin은 기본 키 airports$faa에 해당하는 외래 키입니다.
  4. flights$dest는 기본 키 airports$faa에 해당하는 외래 키입니다.
  5. flights$origin-flights$time_hour는 복합 기본 키 weather$origin-weather$time_hour에 해당하는 복합 외래 키입니다.

이러한 키 설계에는 좋은 특징(nice feature)이 있다는 것을 눈치채실 것입니다. 기본 키와 외래 키는 거의 항상 같은 이름을 가지고 있으며, 이는 곧 보게 되겠지만 조인 작업을 훨씬 쉽게 만들어 줄 것입니다. 반대 관계(opposite relationship)도 주목할(noting) 가치가 있습니다. 여러 테이블에서 사용된 거의 모든 변수 이름은 각 위치에서 동일한 의미를 갖습니다. 예외는 단 하나뿐입니다. year는 flights에서는 출발 연도를, planes에서는 제조 연도를 의미합니다. 이것은 우리가 테이블을 실제로 함께 조인하기 시작할 때 중요해질 것입니다.

1.2 기본 키 확인

이제 각 테이블에서 기본 키를 식별했으므로 해당 키가 실제로 각 관측값을 고유하게 식별하는지 확인하는(verify) 것이 좋은 습관입니다. 이를 수행하는 한 가지 방법은 기본 키를 count()하고 n이 1보다 큰 항목(entries)을 찾는 것입니다. 이를 통해 planes와 weather가 모두 좋아 보인다는 것을 알 수 있습니다.

planes |> 
  count(tailnum) |> 
  filter(n > 1)
#> # A tibble: 0 × 2
#> # ℹ 2 variables: tailnum <chr>, n <int>

weather |> 
  count(time_hour, origin) |> 
  filter(n > 1)
#> # A tibble: 0 × 3
#> # ℹ 3 variables: time_hour <dttm>, origin <chr>, n <int>

기본 키에 결측값이 있는지도 확인해야 합니다. 결측값이 있으면 관측값을 식별할 수 없습니다!

planes |> 
  filter(is.na(tailnum))
#> # A tibble: 0 × 9
#> # ℹ 9 variables: tailnum <chr>, year <int>, type <chr>, manufacturer <chr>,
#> #   model <chr>, engines <int>, seats <int>, speed <int>, engine <chr>

weather |> 
  filter(is.na(time_hour) | is.na(origin))
#> # A tibble: 0 × 15
#> # ℹ 15 variables: origin <chr>, year <int>, month <int>, day <int>,
#> #   hour <int>, temp <dbl>, dewp <dbl>, humid <dbl>, wind_dir <dbl>, …

1.3 대리 키

지금까지 flights에 대한 기본 키에 대해서는 이야기하지 않았습니다. 이 데이터 프레임을 외래 키로 사용하는 데이터 프레임이 없기 때문에 여기서는 그렇게 중요하지는 않지만, 관측값을 다른 사람에게 설명할 방법이 있으면 작업하기가 더 쉽기 때문에 여전히(still) 고려하는 것이 유용합니다.

약간의 생각과 실험 끝에 우리는 각 항공편을 고유하게 식별하는 세 개의 변수가 있다고 결정(determined)했습니다.

flights |> 
  count(time_hour, carrier, flight) |> 
  filter(n > 1)
#> # A tibble: 0 × 4
#> # ℹ 4 variables: time_hour <dttm>, carrier <chr>, flight <int>, n <int>

중복(duplicates)이 없다고 해서 자동으로 time_hour-carrier-flight가 기본 키가 됩니까? 물론 좋은 시작(good start)이긴 하지만 보장(guarantee)하지는 않습니다. 예를 들어 고도(altitude)와 위도(latitude)가 airports에 대한 좋은 기본 키입니까?

airports |>
  count(alt, lat) |> 
  filter(n > 1)
#> # A tibble: 1 × 3
#>     alt   lat     n
#>   <dbl> <dbl> <int>
#> 1    13  40.6     2

고도와 위도로 공항을 식별하는 것은 분명히 나쁜 생각이며(bad idea), 일반적으로 데이터만으로 변수의 조합이 좋은 기본 키가 되는지 여부를 아는 것은 불가능합니다. 하지만 항공편의 경우, time_hour, carrier, flight의 조합은 합리적(reasonable)으로 보입니다. 왜냐하면 공중에 같은 편명(flight number)을 가진 여러 항공편이 동시에 떠 있다면 항공사와 승객들에게 정말 혼란스러울 것이기 때문입니다.

그렇다 하더라도(That said) 행 번호를 사용하여 단순한 숫자형 대리 키(surrogate key)를 도입하는 것이 더 나을 수도 있습니다.

flights2 <- flights |> 
  mutate(id = row_number(), .before = 1)
flights2

대리 키는 다른 사람과 의사소통할 때 특히 유용할 수 있습니다. 누군가에게 2013-01-03 오전 9시에 출발한 UA430을 보라고 말하는 것보다 2001번 항공편을 보라고 말하는 것이 훨씬 쉽습니다.

1.4 연습 문제

  1. weather에는 NYC에 있는 세 개의 출발지 공항에 대한 정보만 포함되어 있습니다. 미국 내 모든 공항의 날씨 기록이 포함되어 있다면 flights와 어떤 추가 연결(additional connection)을 갖게 될까요?

  2. year, month, day, hour 및 origin 변수는 거의 weather의 복합 키를 형성(form)하지만 중복된 관측값이 있는 1시간이 있습니다. 그 시간의 어떤 점이 특별한지 알아낼 수 있습니까?

  3. 우리는 일 년 중 어떤 날은 특별해서 평소보다 비행기를 타는 사람이 적다는 것을 알고 있습니다(크리스마스이브와 크리스마스). 해당 데이터를 데이터 프레임으로 어떻게 나타낼 수 있습니까? 기본 키는 무엇입니까? 기존 데이터 프레임과 어떻게 연결(connect)됩니까?

  4. Lahman 패키지에 있는 Batting, People, Salaries 데이터 프레임 간의 연결을 보여주는 다이어그램을 그리세요. People, Managers, AwardsManagers 간의 관계를 보여주는 또 다른 다이어그램을 그리세요. Batting, Pitching, Fielding 데이터 프레임 간의 관계를 어떻게 특징지을(characterize) 수 있습니까?

2 기본 조인

이제 데이터 프레임이 키를 통해 어떻게 연결되는지 이해했으므로 조인을 사용하여 flights 데이터셋을 더 잘 이해할 수 있습니다. dplyr은 여섯 가지 조인 함수를 제공합니다. left_join(), inner_join(), right_join(), full_join(), semi_join(), anti_join(). 모두 동일한 인터페이스를 가지고 있습니다. 한 쌍의 데이터 프레임(x와 y)을 취하고 데이터 프레임을 반환합니다. 출력의 행과 열 순서는 주로 x에 의해 결정됩니다.

2.1 변형 조인

변형 조인(mutating join)을 사용하면 두 데이터 프레임의 변수를 결합(combine)할 수 있습니다. 먼저 키를 기준으로 관측값을 일치시킨 다음(matches) 한 데이터 프레임에서 다른 데이터 프레임으로 변수를 복사합니다. mutate()와 마찬가지로 조인 함수는 변수를 오른쪽에 추가하므로 데이터셋에 변수가 많으면 새 변수가 표시되지 않습니다. 이러한 예제에서는 단 6개의 변수만 있는 더 좁은(narrower) 데이터셋을 만들어 진행 상황을 더 쉽게 확인할 수 있도록 하겠습니다.

flights2 <- flights |> 
  select(year, time_hour, origin, dest, tailnum, carrier)

year 변수는 변수가 x에서 왔는지 y 인수에서 왔는지를 알려주는 접미사(suffix) (year.x 및 year.y)가 출력에 포함되어 명확해집니다(disambiguated). suffix 인수를 사용하여 기본 접미사를 재정의(override)할 수 있습니다.

join_by(tailnum)은 join_by(tailnum == tailnum)의 줄임말입니다. 두 가지 이유에서 이 더 완전한(fuller) 형태에 대해 아는 것이 중요합니다. 첫째, 두 테이블 간의 관계(relationship)를 설명합니다. 키는 같아야 합니다(equal). 그래서 이러한 유형의 조인을 흔히 동등 조인(equi join)이라고 합니다.

둘째, 이것이 각 테이블에서 서로 다른 조인 키를 지정하는 방법입니다. 예를 들어 flight2와 airports 테이블을 조인하는 두 가지 방법이 있습니다. dest 또는 origin 기준입니다.

이전 코드에서는 문자형 벡터를 사용하여 조인 키를 지정하는 다른 방법을 볼 수도 있습니다.

  1. by = "x"는 join_by(x)에 해당합니다.
  2. by = c("a" = "x")는 join_by(a == x)에 해당합니다.

이제 이 함수가 존재하므로(exists) 더 명확하고 유연한 사양(specification)을 제공하는 join_by()를 선호합니다(prefer).

inner_join(), right_join(), full_join()은 left_join()과 동일한 인터페이스를 갖습니다. 차이점은 그들이 어떤 행을 유지하는지입니다. 왼쪽 조인은 x의 모든 행을 유지하고, 오른쪽 조인은 y의 모든 행을 유지하고, 전체 조인은 x 또는 y의 모든 행을 유지하며, 내부 조인은 x와 y 모두에 나타나는(occur) 행만 유지합니다.

3 조인은 어떻게 작동합니까?

이제 조인을 몇 번 사용해 보았으므로 x의 각 행이 y의 행과 어떻게 일치하는지에 초점을 맞춰 조인이 어떻게 작동하는지 자세히 알아볼 차례입니다. 이 예제에서는 key라는 단일 키와 단일 값 열(val_x 및 val_y)을 사용하지만 이 아이디어는 모두 여러 키와 여러 값으로 일반화됩니다.

x <- tribble(
  ~key, ~val_x,
     1, "x1",
     2, "x2",
     3, "x3"
)
y <- tribble(
  ~key, ~val_y,
     1, "y1",
     2, "y2",
     4, "y3"
)

  1. 출력의 행과 열은 주로 x에 의해 결정되므로 x 테이블은 수평(horizontal)이며 출력과 나란히 정렬(lines up)됩니다.

  2. 왼쪽 조인(left join)은 x의 모든 관측값을 유지합니다. x의 모든 행은 y의 NA 행과 일치하는 폴백(fall back)을 가질 수 있기 때문에 출력에 보존(preserved)됩니다.

  3. 오른쪽 조인(right join)은 y의 모든 관측값을 유지합니다. y의 모든 행은 x의 NA 행과 일치하는 폴백을 가질 수 있기 때문에 출력에 보존됩니다. 출력은 여전히 가능한 한 많이 x와 일치합니다; y의 추가(extra) 행은 끝에 추가됩니다.

  4. 전체 조인(full join)은 x 또는 y에 나타나는 모든 관측값을 유지합니다. x와 y 모두 NA 폴백 행을 가지기 때문에 x와 y의 모든 행이 출력에 포함됩니다. 다시 말해, 출력은 x의 모든 행으로 시작하고, 그 뒤를 나머지(remaining) 일치하지 않는 y 행이 따릅니다.

  5. 동등 조인(equi joins)으로, 키가 동일한 경우 행이 일치합니다. 동등 조인은 조인의 일반적인 유형이므로 일반적으로 동등 접두사를 생략하고 “동등 내부 조인”이 아니라 그냥 “내부 조인”이라고 합니다.

3.1 행 일치

지금까지 x의 행이 y의 0개 또는 1개의 행과 일치하는 경우 무슨 일이 일어나는지 탐구했습니다. 둘 이상의 행과 일치하면 어떻게 됩니까? x의 행에 대한 세 가지 가능한 결과(outcomes)가 있습니다.

  1. 아무것과도 일치하지 않으면 삭제됩니다.
  2. y의 1개 행과 일치하면 보존됩니다.
  3. y의 1개 이상의 행과 일치하면 각 일치에 대해 한 번씩 복제(duplicated)됩니다.

원칙적으로(In principle) 이는 출력의 행과 x의 행 간에 보장된 대응(guaranteed correspondence)이 없음을 의미하지만 실제로는 이로 인해 문제가 발생하는 경우는 드뭅니다. 하지만 조합적 폭발(combinatorial explosion)을 일으킬 수 있는 특히 위험한(dangerous) 사례가 하나 있습니다. 다음 두 테이블을 조인한다고 상상해 보세요.

df1 <- tibble(key = c(1, 2, 2), val_x = c("x1", "x2", "x3"))
df2 <- tibble(key = c(1, 2, 2), val_y = c("y1", "y2", "y3"))

df1의 첫 번째 행은 df2의 한 행과만 일치하지만, 두 번째와 세 번째 행은 모두 두 행과 일치합니다. 이것을 때로는 다대다(many-to-many) 조인이라고 부르며, dplyr이 경고를 발생시킵니다.

df1 |> 
  inner_join(df2, join_by(key))
#> Warning in inner_join(df1, df2, join_by(key)): Detected an unexpected many-to-many relationship between `x` and `y`.
#> ℹ Row 2 of `x` matches multiple rows in `y`.
#> ℹ Row 2 of `y` matches multiple rows in `x`.
#> ℹ If a many-to-many relationship is expected, set `relationship =
#>   "many-to-many"` to silence this warning.
#> # A tibble: 5 × 3
#>     key val_x val_y
#>   <dbl> <chr> <chr>
#> 1     1 x1    y1   
#> 2     2 x2    y2   
#> 3     2 x2    y3   
#> 4     2 x3    y2   
#> 5     2 x3    y3

의도적으로(deliberately) 이 작업을 수행하는 경우 경고에서 제안하는 대로 relationship = "many-to-many"를 설정할 수 있습니다.

3.2 필터링 조인

일치하는 항목 수도 필터링 조인의 동작을 결정합니다.

  1. 세미 조인은 y에 하나 이상의 일치 항목이 있는 x의 행을 유지합니다.
  2. 안티 조인은 y에 일치하는 행이 0개인 x의 행을 유지합니다.

두 경우 모두 일치 항목이 존재한다는 것만이 중요합니다. 일치하는 횟수는 중요하지 않습니다. 즉, 필터링 조인은 변형 조인과 같이 행을 복제하지 않습니다.

4 비동등 조인

지금까지는 동등 조인, 즉 x 키가 y 키와 같을 때 행이 일치하는 조인만 보았습니다. 이제 그 제한(restriction)을 완화하고(relax) 한 쌍의 행이 일치하는지 여부를 결정하는 다른 방법에 대해 논의하겠습니다.

하지만 그 전에 위에서 만든 단순화(simplification)를 다시 살펴봐야(revisit) 합니다. 동등 조인에서는 x 키와 y가 항상 같기 때문에 출력에 하나만 표시하면 됩니다. keep = TRUE를 사용하여 dplyr이 두 키를 모두 유지하도록 요청할 수 있습니다.

x |> inner_join(y, join_by(key == key), keep = TRUE)
#> # A tibble: 2 × 4
#>   key.x val_x key.y val_y
#>   <dbl> <chr> <dbl> <chr>
#> 1     1 x1        1 y1   
#> 2     2 x2        2 y2

동등 조인에서 벗어날 때(move away from) 키 값은 종종 달라지기 때문에 항상 키를 표시할 것입니다. 예를 들어 x$key와 y$key가 같을 때만 일치시키는 대신 x$key가 y$key보다 크거나 같을 때마다 일치시킵니다. dplyr의 조인 함수는 동등 조인과 비동등 조인의 이러한 구분을 이해하므로 비동등 조인을 수행할 때 항상 두 키를 모두 표시합니다.

비동등 조인은 조인이 무엇인지가 아니라 무엇이 아닌지만 알려주기 때문에 특히 유용한 용어는 아닙니다. dplyr은 특히 유용한 네 가지 유형의 비동등 조인을 식별하여 도움을 줍니다.

  1. 크로스 조인(Cross joins)은 모든 행 쌍을 일치시킵니다.
  2. 부등 조인(Inequality joins)은 == 대신 <, <=, >, >=를 사용합니다.
  3. 롤링 조인(Rolling joins)은 부등 조인과 유사하지만 가까운 일치 항목만 찾습니다.
  4. 오버랩 조인(Overlap joins)은 범위(ranges)와 함께 작동하도록 설계된 특별한 유형의 부등 조인입니다.

이들 각각은 다음 섹션에서 자세히 설명합니다.

4.1 크로스 조인

크로스 조인은 모든 것을 일치시켜 행의 데카르트 곱(Cartesian product)을 생성합니다. 이는 출력에 nrow(x) * nrow(y) 행이 있음을 의미합니다.

df1 <- tibble(key = c(1, 2, 2), val_x = c("x1", "x2", "x3"))
df2 <- tibble(key = c(1, 2, 2), val_y = c("y1", "y2", "y3"))

df1의 첫 번째 행은 df2의 한 행과만 일치하지만, 두 번째와 세 번째 행은 모두 두 행과 일치합니다. 이것을 때로는 다대다(many-to-many) 조인이라고 부르며, dplyr이 경고를 발생시킵니다.

df1 |> 
  inner_join(df2, join_by(key))
#> Warning in inner_join(df1, df2, join_by(key)): Detected an unexpected many-to-many relationship between `x` and `y`.
#> ℹ Row 2 of `x` matches multiple rows in `y`.
#> ℹ Row 2 of `y` matches multiple rows in `x`.
#> ℹ If a many-to-many relationship is expected, set `relationship =
#>   "many-to-many"` to silence this warning.
#> # A tibble: 5 × 3
#>     key val_x val_y
#>   <dbl> <chr> <chr>
#> 1     1 x1    y1   
#> 2     2 x2    y2   
#> 3     2 x2    y3   
#> 4     2 x3    y2   
#> 5     2 x3    y3

의도적으로(deliberately) 이 작업을 수행하는 경우 경고에서 제안하는 대로 relationship = "many-to-many"를 설정할 수 있습니다.

4.2 부등 조인

부등 조인은 <, <=, >=, 또는 >를 사용하여 가능한 일치 항목 세트를 제한합니다. 부등 조인은 매우 일반적(general)이어서 의미 있는(meaningful) 특정 사용 사례(use cases)를 떠올리기(come up with)가 어렵습니다. 작지만 유용한 한 가지 기술(technique)은 크로스 조인을 제한하여 모든 순열을 생성하는 대신 모든 조합(combinations)을 생성하도록 하는 것입니다.

df <- tibble(id = 1:4, name = c("John", "Simon", "Tracy", "Max"))

df |> inner_join(df, join_by(id < id))
#> # A tibble: 6 × 4
#>    id.x name.x  id.y name.y
#>   <int> <chr>  <int> <chr> 
#> 1     1 John       2 Simon 
#> 2     1 John       3 Tracy 
#> 3     1 John       4 Max   
#> 4     2 Simon      3 Tracy 
#> 5     2 Simon      4 Max   
#> 6     3 Tracy      4 Max

4.3 롤링 조인

롤링 조인은 부등식을 만족하는(satisfies) 모든 행을 가져오는 대신 가까운 행만 가져오는 특수한 유형의 부등 조인입니다. closest()를 추가하여 모든 부등 조인을 롤링 조인으로 전환할 수 있습니다. 예를 들어 join_by(closest(x <= y))는 x보다 크거나 같은 작은 y와 일치하고, join_by(closest(x > y))는 x보다 작은 큰 y와 일치합니다.

롤링 조인은 완벽하게 일치하지 않는 두 개의 날짜 테이블이 있고 테이블 2의 특정 날짜 전(또는 후)에 나오는 테이블 1의 가까운 날짜를 찾고 싶을 때 특히 유용합니다. 예를 들어 여러분이 회사의 파티 기획 위원회(party planning commission)를 맡고(in charge of) 있다고 상상해 보세요. 여러분의 회사는 꽤 짠돌이(cheap)라서 개인 파티를 하는 대신 분기별로 한 번씩만 파티를 엽니다. 파티 개최 시기를 결정하는 규칙은 약간 복잡합니다. 파티는 항상 월요일에 열리고, 휴가를 가는 사람이 많아서 1월 첫째 주는 건너뛰고(skip), 2022년 3분기의 첫 번째 월요일은 7월 4일이므로 일주일 뒤로 미뤄야(pushed back) 합니다. 이렇게 하면 다음과 같은 파티 날짜가 됩니다.

parties <- tibble(
  q = 1:4,
  party = ymd(c("2022-01-10", "2022-04-04", "2022-07-11", "2022-10-03"))
)

이제 직원 생일 테이블이 있다고 상상해 보세요.

set.seed(123)
employees <- tibble(
  name = sample(babynames::babynames$name, 100),
  birthday = ymd("2022-01-01") + (sample(365, 100, replace = TRUE) - 1)
)
employees
#> # A tibble: 100 × 2
#>   name     birthday  
#>   <chr>    <date>    
#> 1 Kemba    2022-01-22
#> 2 Orean    2022-06-26
#> 3 Kirstyn  2022-02-11
#> 4 Amparo   2022-11-11
#> 5 Belen    2022-03-25
#> 6 Rayshaun 2022-01-11
#> # ℹ 94 more rows

그리고 각 직원에 대해 생일 이전(또는 생일 당일)에 있었던 마지막 파티 날짜를 찾고 싶습니다. 롤링 조인으로 이를 표현할 수 있습니다.

employees |> 
  left_join(parties, join_by(closest(birthday >= party)))
#> # A tibble: 100 × 4
#>   name     birthday       q party     
#>   <chr>    <date>     <int> <date>    
#> 1 Kemba    2022-01-22     1 2022-01-10
#> 2 Orean    2022-06-26     2 2022-04-04

#> 5 Belen    2022-03-25     1 2022-01-10
#> 6 Rayshaun 2022-01-11     1 2022-01-10

하지만 이 접근 방식(approach)에는 한 가지 문제가 있습니다. 1월 10일 이전에 생일이 있는 사람(folks)들은 파티를 열지 못합니다.

employees |> 
  anti_join(parties, join_by(closest(birthday >= party)))
#> # A tibble: 2 × 2
#>   name   birthday  
#>   <chr>  <date>    
#> 1 Maks   2022-01-07
#> 2 Nalani 2022-01-04

이 문제를 해결하려면 오버랩 조인(overlap joins)이라는 다른 방법으로 문제를 해결(tackle)해야 합니다.

4.4 오버랩 조인

오버랩 조인은 구간(intervals)으로 작업하기 쉽도록 부등 조인을 사용하는 세 가지 도우미(helpers)를 제공합니다.

  • between(x, y_lower, y_upper)는 x >= y_lower, x <= y_upper의 줄임말입니다.
  • within(x_lower, x_upper, y_lower, y_upper)는 x_lower >= y_lower, x_upper <= y_upper의 줄임말입니다.
  • overlaps(x_lower, x_upper, y_lower, y_upper)는 x_lower <= y_upper, x_upper >= y_lower의 줄임말입니다.

생일 예제를 계속하여 어떻게 사용할 수 있는지 알아보겠습니다. 위에서 사용한 전략(strategy)에는 한 가지 문제가 있습니다. 1월 1일부터 9일 사이의 생일을 위한 파티가 없습니다. 따라서 각 파티가 포괄하는(spans) 날짜 범위에 대해 명시적(explicit)으로 정하고 이러한 초기 생일(early birthdays)에 대해 특별한 경우를 만드는 것이 더 나을 수 있습니다.

parties <- tibble(
  q = 1:4,
  party = ymd(c("2022-01-10", "2022-04-04", "2022-07-11", "2022-10-03")),
  start = ymd(c("2022-01-01", "2022-04-04", "2022-07-11", "2022-10-03")),
  end = ymd(c("2022-04-03", "2022-07-11", "2022-10-02", "2022-12-31"))
)
parties
#> # A tibble: 4 × 4
#>       q party      start      end       
#>   <int> <date>     <date>     <date>    
#> 1     1 2022-01-10 2022-01-01 2022-04-03
#> 2     2 2022-04-04 2022-04-04 2022-07-11
#> 3     3 2022-07-11 2022-07-11 2022-10-02
#> 4     4 2022-10-03 2022-10-03 2022-12-31

해들리(Hadley)는 데이터 입력을 절망적(hopelessly)으로 못하기 때문에 파티 기간이 겹치지(overlap) 않는지 확인하고 싶어 했습니다. 이를 수행하는 한 가지 방법은 셀프 조인을 사용하여 시작-종료(start-end) 구간이 다른 구간과 겹치는지 확인하는 것입니다.

parties |> 
  inner_join(parties, join_by(overlaps(start, end, start, end), q < q)) |> 
  select(start.x, end.x, start.y, end.y)
#> # A tibble: 1 × 4
#>   start.x    end.x      start.y    end.y     
#>   <date>     <date>     <date>     <date>    
#> 1 2022-04-04 2022-07-11 2022-07-11 2022-10-02

이런(Ooops), 겹치는 부분이 있으니 그 문제를 고치고 계속 진행합시다.

parties <- tibble(
  q = 1:4,
  party = ymd(c("2022-01-10", "2022-04-04", "2022-07-11", "2022-10-03")),
  start = ymd(c("2022-01-01", "2022-04-04", "2022-07-11", "2022-10-03")),
  end = ymd(c("2022-04-03", "2022-07-10", "2022-10-02", "2022-12-31"))
)

이제 각 직원을 자신의 파티와 일치시킬 수 있습니다. 파티가 할당되지 않은 직원이 있는지 빨리 확인하고 싶기 때문에(we want to quickly find out) 이럴 때는 unmatched = "error"를 사용하는 것이 좋습니다.

employees |> 
  inner_join(parties, join_by(between(birthday, start, end)), unmatched = "error")
#> # A tibble: 100 × 6
#>   name     birthday       q party      start      end       
#>   <chr>    <date>     <int> <date>     <date>     <date>    
#> 1 Kemba    2022-01-22     1 2022-01-10 2022-01-01 2022-04-03
#> 2 Orean    2022-06-26     2 2022-04-04 2022-04-04 2022-07-10
#> 3 Kirstyn  2022-02-11     1 2022-01-10 2022-01-01 2022-04-03
#> 4 Amparo   2022-11-11     4 2022-10-03 2022-10-03 2022-12-31
#> 5 Belen    2022-03-25     1 2022-01-10 2022-01-01 2022-04-03
#> 6 Rayshaun 2022-01-11     1 2022-01-10 2022-01-01 2022-04-03
