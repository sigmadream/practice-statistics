데이터 불러오기

대규모 데이터셋을 수작업으로 계산하는 것은 거의 불가능에 가까우며, 극심한 시간 소모와 오류를 유발합니다. 따라서 현대의 통계 분석에서는 프로그래밍 언어의 내장 함수와 강력한 컴퓨팅 능력을 활용하여 데이터를 체계적으로 다룰 수 있어야 합니다.

데이터 수집 단계를 마치고 나면, 통계 프로세스의 다음 단계는 탐색적 데이터 분석(Exploratory Data Analysis)을 통해 데이터 이면의 의미 파악을 시작하는 것입니다. 본 장에서는 분석을 원활하게 수행하도록 돕는 R의 라이브러리(Library) 생태계를 이해하고, 외부 파일로부터 R 환경으로 데이터를 안전하게 불러오는 방법에 초점을 맞추어 설명하겠습니다. 데이터를 불러오는 과정 역시 UI 클릭 같은 수동 조작 없이 코드로 투명하게 기록되어야 재현성(Reproducibility)을 확보할 수 있습니다.

1 라이브러리에 저장된 데이터셋 불러오기

R의 각종 패키지(라이브러리)에는 분석 기법을 실습하기 위한 다양한 내장 함수와 데이터셋이 포함되어 있습니다. 데이터셋의 정확한 명칭과 소속 패키지 이름만 알고 있다면, 이를 R의 작업 공간(Workspace)으로 불러오는 것은 매우 간단합니다. R의 내장 data() 함수를 사용하여 다음 코드를 실행하시면 됩니다.

data(dataset_name, package = "package_name")

가령 MASS 라이브러리에 포함된 nlschools 데이터셋을 살펴보겠습니다. 이 데이터셋은 네덜란드의 8학년(초등학교 최종 학년, 만 11세가량) 학생 2,287명의 시험 점수와 배경 변수를 담고 있습니다. 이를 작업 공간으로 불러오기 위해서는 다음과 같이 코드를 작성하십시오.

data(nlschools, package = "MASS")

코드를 실행하고 나면, 현재 작업 공간 메모리에 분석에 즉시 활용할 수 있는 nlschools라는 이름의 데이터 프레임이 생성됩니다.

2 CSV 파일을 R로 불러오기

패키지에 내장된 데이터셋뿐만 아니라, 로컬 컴퓨터나 서버의 CSV(쉼표로 구분된 텍스트) 파일에 저장된 외부 데이터셋을 R로 불러오는 작업은 실무에서 가장 빈번하게 발생합니다. 기본 R 시스템의 read.csv() 함수를 사용할 수도 있지만, 본 교재에서는 각 열의 데이터 유형(Data type)을 더 명확하고 안전하게 처리하는 readr::read_csv() 함수를 표준 예시로 사용하겠습니다.

readr 패키지의 기능을 온전히 사용하려면 먼저 tidyverse 메타 패키지를 설치해야 합니다. 아직 설치하지 않으셨다면 콘솔에 다음 코드를 입력하십시오.

install.packages("tidyverse")

설치가 완료되면 library() 함수를 통해 패키지를 불러오십시오.

이제 readr 패키지 소속의 read_csv() 함수를 사용할 준비가 끝났습니다. 이 함수는 경로에 지정된 CSV 파일을 읽어 들여 빠르고 안정적인 데이터 프레임 구조(티블, tibble)로 변환합니다. 기본적인 문법은 다음과 같습니다.

readr::read_csv("data/file_name.csv", show_col_types = FALSE)

초학자들의 경우 파일의 정확한 경로(File pathway)를 찾는 데 어려움을 겪어, 대화형 파일 탐색기를 띄우는 file.choose() 함수에 의존하기도 합니다. 그러나 이는 치명적인 약점을 가집니다. 분석 코드를 다른 컴퓨터로 옮기거나 배치 작업으로 자동 실행할 때, 팝업 창을 클릭할 수단이 없어 전체 과정이 중단되기 때문입니다. 따라서 재현 가능성을 담보해야 하는 실무와 수업 노트에서는 항상 프로젝트 폴더를 기준으로 한 ’상대 경로’를 코드에 명시하는 방식을 권장합니다. 올바른 코드는 다음과 같이 작성됩니다.

my_data <- readr::read_csv("data/penguins.csv", show_col_types = FALSE)

이 방식을 사용하면 어떤 위치의 어떤 파일을 불러왔는지가 코드에 명확한 기록으로 남습니다. 아울러 불러온 데이터 프레임은 my_data나 penguins처럼 직관적이고 의미 있는 이름의 객체로 할당해 주십시오. 객체에 할당하지 않으면 데이터의 내용이 콘솔 화면에 잠시 출력되고 휘발되어, 이후의 분석 단계에서 재사용할 수 없습니다.

4 패키지와 데이터 불러오기의 현대적 기준

현대적인 데이터 분석 워크플로우에서 패키지 설치는 가급적 코드로 명시해 두는 편이 훨씬 유리합니다. RStudio의 GUI 메뉴를 클릭하여 패키지를 설치하는 방식은 처음 학습할 때 직관적일지 모르나, 나중에 동일한 분석 환경을 완전히 새로 구축해야 할 때 재현성을 크게 떨어뜨립니다. 따라서 R 스크립트의 상단에는 다음과 같이 프로젝트에 필요한 패키지들을 명시하는 습관을 들이시기를 권합니다.

install.packages(c("tidyverse", "MASS"))
library(MASS)
library(tidyverse)

여기서 로드 순서에 주의해야 합니다. MASS에는 능형회귀용 select() 함수가 들어 있어 dplyr::select()와 이름이 충돌합니다. R은 나중에 로드한 패키지의 함수를 우선하므로, MASS를 뒤에 로드하면 MASS::select()가 dplyr::select()를 가려 버려 이후의 열 선택 코드가 unused arguments 오류를 냅니다. 위와 같이 MASS를 먼저 로드하면 tidyverse 로드 시점에 앞서 본 충돌 메시지가 출력되면서 dplyr::select()가 우선권을 갖게 됩니다. 순서를 신경 쓰고 싶지 않다면 dplyr::select()처럼 패키지명을 명시하는 것이 가장 안전합니다.

외부 CSV 파일을 불러올 때도 마찬가지입니다. 베이스 R의 read.csv()가 여전히 널리 쓰이고는 있으나, 최신 tidyverse 생태계에서는 readr::read_csv()를 기본 선택지로 삼는 것이 표준으로 굳어졌습니다. read_csv()는 빅데이터 시대에 걸맞게 대용량 파일을 읽어 들이는 속도가 훨씬 빠르며, 각 열의 데이터 유형을 지능적이고 일관되게 추정하여 오류를 줄입니다. 또한 콘솔에 너무 많은 내용이 출력되지 않도록 정제된 형태의 데이터 구조인 티블(Tibble)로 결과를 반환하여 편의성을 높입니다.

students <- readr::read_csv(
  file = "data/students.csv",
  show_col_types = FALSE
)

students |>
  glimpse()

앞서 강조했듯 file.choose()는 단발적인 파일 확인 용도로는 유용할 수 있으나, 재현 가능한 분석 스크립트에는 결코 포함되어서는 안 됩니다. 동료 연구자나 AI 시스템이 동일한 코드를 실행할 때 어떤 파일을 선택해야 하는지 추적할 방법이 없기 때문입니다. 언제나 프로젝트 루트 폴더 하위에 data/와 같은 독립적인 데이터 폴더를 생성하고, 상대 경로 체계를 사용하여 파일을 불러오는 원칙을 준수해 주십시오.

nlschools_tbl <- MASS::nlschools |>
  as_tibble()

nlschools_tbl |>
  dplyr::select(lang, IQ, class) |>
  slice_head(n = 5)

이러한 규범을 따르면 패키지에 내장된 데이터셋과 외부 로컬 파일을 동일한 일관성으로 다룰 수 있습니다. 데이터의 출처(Provenance)가 어디인지, R 환경에서 어떤 명칭의 객체로 저장되었는지, 초기 데이터의 구조적 특징은 어떠한지가 분석 코드에 투명하게 새겨집니다. 이 탄탄한 토대 위에서 이어지는 탐색적 데이터 분석과 통계적 추론은 한층 더 안전하고 강력해질 것입니다.
