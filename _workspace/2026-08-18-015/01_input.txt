데이터 분석에 단 하나의 데이터 프레임만 포함되는 경우는 드뭅니다(rare). 일반적으로 많은 데이터 프레임이 있으며 관심 있는 질문에 답하려면 데이터 프레임들을 함께 조인(join)해야 합니다.
이 장에서는 두 가지 중요한 조인 유형을 소개합니다.

- 다른 데이터 프레임에서 일치하는 관측값을 가져와(from matching observations) 한 데이터 프레임에 새 변수를 추가하는 변형 조인(Mutating joins).
- 다른 데이터 프레임의 관측값과 일치하는지 여부를 기준으로 한 데이터 프레임의 관측값을 필터링하는 필터링 조인(Filtering joins).

```{r}
#| label: setup
#| message: false
library(tidyverse)
library(nycflights13)
```

## 키 (Keys)

조인을 이해하려면 먼저 각 테이블 내에서 한 쌍의 키를 통해 두 테이블이 어떻게 연결(connected)될 수 있는지 이해해야 합니다. 이 섹션에서는 두 가지 유형의 키에 대해 배우고 nycflights13 패키지의 데이터셋에서 둘 다의 예를 볼 수 있습니다. 또한 키가 유효한지(valid) 확인하는 방법과 테이블에 키가 부족한(lacks) 경우 수행할 작업도 알아봅니다.

### 기본 키와 외래 키

모든 조인에는 기본 키(primary key)와 외래 키(foreign key)라는 한 쌍의 키가 포함됩니다. 기본 키(primary key)는 각 관측값을 고유하게 식별하는 변수 또는 변수의 집합입니다. 두 개 이상의 변수가 필요한 경우 해당 키를 복합 키(compound key)라고 합니다. 

- `airlines`는 각 항공사에 대한 두 가지 데이터, 즉 항공사 코드(carrier code)와 전체 이름을 기록합니다. 두 글자로 된 항공사 코드로 항공사를 식별할 수 있으므로 `carrier`가 기본 키가 됩니다.

```{r}
airlines
```

- `airports`는 각 공항에 대한 데이터를 기록합니다. 세 글자로 된 공항 코드로 각 공항을 식별할 수 있으므로 `faa`가 기본 키가 됩니다.

```{r}
#| R.options:
#|   width: 67
airports
```

- `planes`는 각 비행기에 대한 데이터를 기록합니다. 꼬리 번호(tail number)로 비행기를 식별할 수 있으므로 `tailnum`이 기본 키가 됩니다.

```{r}
#| R.options:
#|   width: 67
planes
```

- `weather`는 출발지 공항의 날씨에 대한 데이터를 기록합니다. 위치(location)와 시간의 조합으로 각 관측값을 식별할 수 있으므로 `origin`과 `time_hour`가 복합 기본 키가 됩니다.

```{r}
#| R.options:
#|   width: 67
weather
```

외래 키(foreign key)는 다른 테이블의 기본 키에 해당하는(corresponds to) 변수(또는 변수의 집합)입니다.

1. `flights$tailnum`은 기본 키 `planes$tailnum`에 해당하는 외래 키입니다.
2. `flights$carrier`는 기본 키 `airlines$carrier`에 해당하는 외래 키입니다.
3. `flights$origin`은 기본 키 `airports$faa`에 해당하는 외래 키입니다.
4. `flights$dest`는 기본 키 `airports$faa`에 해당하는 외래 키입니다.
5. `flights$origin`-`flights$time_hour`는 복합 기본 키 `weather$origin`-`weather$time_hour`에 해당하는 복합 외래 키입니다.

이러한 키 설계에는 좋은 특징(nice feature)이 있다는 것을 눈치채실 것입니다. 기본 키와 외래 키는 거의 항상 같은 이름을 가지고 있으며, 이는 곧 보게 되겠지만 조인 작업을 훨씬 쉽게 만들어 줄 것입니다. 반대 관계(opposite relationship)도 주목할(noting) 가치가 있습니다. 여러 테이블에서 사용된 거의 모든 변수 이름은 각 위치에서 동일한 의미를 갖습니다. 예외는 단 하나뿐입니다. `year`는 `flights`에서는 출발 연도를, `planes`에서는 제조 연도를 의미합니다. 이것은 우리가 테이블을 실제로 함께 조인하기 시작할 때 중요해질 것입니다.

### 기본 키 확인

이제 각 테이블에서 기본 키를 식별했으므로 해당 키가 실제로 각 관측값을 고유하게 식별하는지 확인하는(verify) 것이 좋은 습관입니다. 이를 수행하는 한 가지 방법은 기본 키를 `count()`하고 `n`이 1보다 큰 항목(entries)을 찾는 것입니다. 이를 통해 `planes`와 `weather`가 모두 좋아 보인다는 것을 알 수 있습니다.

```{r}
planes |> 
  count(tailnum) |> 
  filter(n > 1)

weather |> 
  count(time_hour, origin) |> 
  filter(n > 1)
```

기본 키에 결측값이 있는지도 확인해야 합니다. 결측값이 있으면 관측값을 식별할 수 없습니다!

```{r}
planes |> 
  filter(is.na(tailnum))

weather |> 
  filter(is.na(time_hour) | is.na(origin))
```

### 대리 키

지금까지 `flights`에 대한 기본 키에 대해서는 이야기하지 않았습니다. 이 데이터 프레임을 외래 키로 사용하는 데이터 프레임이 없기 때문에 여기서는 그렇게 중요하지는 않지만, 관측값을 다른 사람에게 설명할 방법이 있으면 작업하기가 더 쉽기 때문에 여전히(still) 고려하는 것이 유용합니다.

약간의 생각과 실험 끝에 우리는 각 항공편을 고유하게 식별하는 세 개의 변수가 있다고 결정(determined)했습니다.

```{r}
flights |> 
  count(time_hour, carrier, flight) |> 
  filter(n > 1)
```

중복(duplicates)이 없다고 해서 자동으로 `time_hour`-`carrier`-`flight`가 기본 키가 됩니까? 물론 좋은 시작(good start)이긴 하지만 보장(guarantee)하지는 않습니다. 예를 들어 고도(altitude)와 위도(latitude)가 `airports`에 대한 좋은 기본 키입니까?

```{r}
airports |>
  count(alt, lat) |> 
  filter(n > 1)
```

고도와 위도로 공항을 식별하는 것은 분명히 나쁜 생각이며(bad idea), 일반적으로 데이터만으로 변수의 조합이 좋은 기본 키가 되는지 여부를 아는 것은 불가능합니다. 하지만 항공편의 경우, `time_hour`, `carrier`, `flight`의 조합은 합리적(reasonable)으로 보입니다. 왜냐하면 공중에 같은 편명(flight number)을 가진 여러 항공편이 동시에 떠 있다면 항공사와 승객들에게 정말 혼란스러울 것이기 때문입니다.

그렇다 하더라도(That said) 행 번호를 사용하여 단순한 숫자형 대리 키(surrogate key)를 도입하는 것이 더 나을 수도 있습니다.

```{r}
flights2 <- flights |> 
  mutate(id = row_number(), .before = 1)
flights2
```

대리 키는 다른 사람과 의사소통할 때 특히 유용할 수 있습니다. 누군가에게 2013-01-03 오전 9시에 출발한 UA430을 보라고 말하는 것보다 2001번 항공편을 보라고 말하는 것이 훨씬 쉽습니다.

2. `year`, `month`, `day`, `hour` 및 `origin` 변수는 거의 `weather`의 복합 키를 형성(form)하지만 중복된 관측값이 있는 1시간이 있습니다. 그 시간의 어떤 점이 특별한지 알아낼 수 있습니까?

## 기본 조인

이제 데이터 프레임이 키를 통해 어떻게 연결되는지 이해했으므로 조인을 사용하여 `flights` 데이터셋을 더 잘 이해할 수 있습니다. dplyr은 여섯 가지 조인 함수를 제공합니다. `left_join()`, `inner_join()`, `right_join()`, `full_join()`, `semi_join()`, `anti_join()`. 모두 동일한 인터페이스를 가지고 있습니다. 한 쌍의 데이터 프레임(`x`와 `y`)을 취하고 데이터 프레임을 반환합니다. 출력의 행과 열 순서는 주로 `x`에 의해 결정됩니다.

### 변형 조인

변형 조인(mutating join)을 사용하면 두 데이터 프레임의 변수를 결합(combine)할 수 있습니다. 먼저 키를 기준으로 관측값을 일치시킨 다음(matches) 한 데이터 프레임에서 다른 데이터 프레임으로 변수를 복사합니다. `mutate()`와 마찬가지로 조인 함수는 변수를 오른쪽에 추가하므로 데이터셋에 변수가 많으면 새 변수가 표시되지 않습니다. 이러한 예제에서는 단 6개의 변수만 있는 더 좁은(narrower) 데이터셋을 만들어 진행 상황을 더 쉽게 확인할 수 있도록 하겠습니다.

```{r}
flights2 <- flights |> 
  select(year, time_hour, origin, dest, tailnum, carrier)
flights2
```

네 가지 유형의 변형 조인이 있지만 여러분이 거의 항상 사용하게 될 조인이 하나 있습니다. 바로 `left_join()`입니다. 이것이 특별한 이유는 출력이 조인 대상(joining to) 데이터 프레임인 `x`와 항상 동일한 행을 갖기 때문입니다. `left_join()`의 주요 용도는 추가 메타데이터를 추가하는 것입니다. 예를 들어 `left_join()`을 사용하여 `flights2` 데이터에 전체 항공사 이름을 추가할 수 있습니다.

```{r}
flights2 |>
  left_join(airlines)
```

또는 각 비행기가 출발할 때의 온도와 풍속을 알아낼 수 있습니다.

```{r}
flights2 |> 
  left_join(weather |> select(origin, time_hour, temp, wind_speed))
```

또는 어떤 크기의 비행기가 비행 중인지 알아낼 수 있습니다.

```{r}
flights2 |> 
  left_join(planes |> select(tailnum, type, engines, seats))
```

`left_join()`이 `x`의 행에 대한 일치 항목을 찾지 못하면(fails to find a match) 새 변수를 결측값으로 채웁니다. 예를 들어 꼬리 번호가 `N3ALAA`인 비행기에 대한 정보가 없으므로 `type`, `engines`, `seats`가 누락(missing)됩니다.

```{r}
flights2 |> 
  filter(tailnum == "N3ALAA") |> 
  left_join(planes |> select(tailnum, type, engines, seats))
```

이 장의 나머지 부분에서 이 문제로 몇 번 돌아오겠습니다.

### 조인 키 지정하기

기본적으로 `left_join()`은 두 데이터 프레임에 모두 나타나는 모든 변수를 조인 키로 사용하며 이를 자연(natural) 조인이라고 부릅니다. 이것은 유용한 휴리스틱(heuristic)이지만 항상 작동하는 것은 아닙니다. 예를 들어 `flights2`를 완전한 `planes` 데이터셋과 조인하려고 하면 어떻게 됩니까?

```{r}
flights2 |> 
  left_join(planes)
```

우리의 조인이 `tailnum`과 `year`를 복합 키로 사용하려고 하기 때문에 많은 결측 일치 항목이 생깁니다. `flights`와 `planes` 모두 `year` 열이 있지만 의미가 다릅니다. `flights$year`는 비행이 발생한 연도이고 `planes$year`는 비행기가 제작된 연도입니다. 우리는 `tailnum`에 대해서만 조인하기를 원하므로 `join_by()`를 사용하여 명시적으로(explicit specification) 제공해야 합니다.

```{r}
flights2 |> 
  left_join(planes, join_by(tailnum))
```

`year` 변수는 변수가 `x`에서 왔는지 `y` 인수에서 왔는지를 알려주는 접미사(suffix) (`year.x` 및 `year.y`)가 출력에 포함되어 명확해집니다(disambiguated). `suffix` 인수를 사용하여 기본 접미사를 재정의(override)할 수 있습니다.

`join_by(tailnum)`은 `join_by(tailnum == tailnum)`의 줄임말입니다. 두 가지 이유에서 이 더 완전한(fuller) 형태에 대해 아는 것이 중요합니다. 첫째, 두 테이블 간의 관계(relationship)를 설명합니다. 키는 같아야 합니다(equal). 그래서 이러한 유형의 조인을 흔히 동등 조인(equi join)이라고 합니다. 

둘째, 이것이 각 테이블에서 서로 다른 조인 키를 지정하는 방법입니다. 예를 들어 `flight2`와 `airports` 테이블을 조인하는 두 가지 방법이 있습니다. `dest` 또는 `origin` 기준입니다.

```{r}
flights2 |> 
  left_join(airports, join_by(dest == faa))

flights2 |> 
  left_join(airports, join_by(origin == faa))
```

이전 코드에서는 문자형 벡터를 사용하여 조인 키를 지정하는 다른 방법을 볼 수도 있습니다.

1. `by = "x"`는 `join_by(x)`에 해당합니다.
2. `by = c("a" = "x")`는 `join_by(a == x)`에 해당합니다.

이제 이 함수가 존재하므로(exists) 더 명확하고 유연한 사양(specification)을 제공하는 `join_by()`를 선호합니다(prefer).

`inner_join()`, `right_join()`, `full_join()`은 `left_join()`과 동일한 인터페이스를 갖습니다. 차이점은 그들이 어떤 행을 유지하는지입니다. 왼쪽 조인은 `x`의 모든 행을 유지하고, 오른쪽 조인은 `y`의 모든 행을 유지하고, 전체 조인은 `x` 또는 `y`의 모든 행을 유지하며, 내부 조인은 `x`와 `y` 모두에 나타나는(occur) 행만 유지합니다. 

### 필터링 조인

짐작하시겠지만 필터링 조인의 주요 동작은 행을 필터링하는 것입니다. 세미 조인(semi-joins)과 안티 조인(anti-joins) 두 가지 유형이 있습니다. 세미 조인은 `y`에 일치 항목이 있는 `x`의 모든 행을 유지합니다. 예를 들어 세미 조인을 사용하여 출발지 공항만 표시하도록 `airports` 데이터셋을 필터링할 수 있습니다.

```{r}
airports |> 
  semi_join(flights2, join_by(faa == origin))
```

또는 도착지만 표시할 수도 있습니다.

```{r}
airports |> 
  semi_join(flights2, join_by(faa == dest))
```

안티 조인은 반대입니다. `y`에 일치 항목이 없는 `x`의 모든 행을 반환합니다. 데이터에 암묵적(implicit)인 결측값을 찾는 데 유용하며, 암묵적인 결측값은 `NA`로 나타나지 않고 대신 부재(absence)로만 존재합니다. 예를 들어 일치하는 도착지 공항이 없는 항공편을 찾아 `airports`에서 누락된 행을 찾을 수 있습니다.

```{r}
flights2 |> 
  anti_join(airports, join_by(dest == faa)) |> 
  distinct(dest)
```

또는 `planes`에서 어떤 `tailnum`이 누락되었는지 확인할 수 있습니다.

```{r}
flights2 |>
  anti_join(planes, join_by(tailnum)) |> 
  distinct(tailnum)
```

## 조인은 어떻게 작동합니까?

이제 조인을 몇 번 사용해 보았으므로 `x`의 각 행이 `y`의 행과 어떻게 일치하는지에 초점을 맞춰 조인이 어떻게 작동하는지 자세히 알아볼 차례입니다. 이 예제에서는 `key`라는 단일 키와 단일 값 열(`val_x` 및 `val_y`)을 사용하지만 이 아이디어는 모두 여러 키와 여러 값으로 일반화됩니다.

```{r}
x <- tribble(
  ~key, ~val_x,
     1, "x1",
     2, "x2",
     3, "x3"
)
y <- tribble(
  ~key, ~val_y,
     1, "y1",
     2, "y2",
     4, "y3"
)
```

1. 출력의 행과 열은 주로 `x`에 의해 결정되므로 `x` 테이블은 수평(horizontal)이며 출력과 나란히 정렬(lines up)됩니다.

2. 왼쪽 조인(left join)은 `x`의 모든 관측값을 유지합니다. `x`의 모든 행은 `y`의 `NA` 행과 일치하는 폴백(fall back)을 가질 수 있기 때문에 출력에 보존(preserved)됩니다.

3. 오른쪽 조인(right join)은 `y`의 모든 관측값을 유지합니다. `y`의 모든 행은 `x`의 `NA` 행과 일치하는 폴백을 가질 수 있기 때문에 출력에 보존됩니다. 출력은 여전히 가능한 한 많이 `x`와 일치합니다; `y`의 추가(extra) 행은 끝에 추가됩니다.

4. 전체 조인(full join)은 `x` 또는 `y`에 나타나는 모든 관측값을 유지합니다. `x`와 `y` 모두 `NA` 폴백 행을 가지기 때문에 `x`와 `y`의 모든 행이 출력에 포함됩니다. 다시 말해, 출력은 `x`의 모든 행으로 시작하고, 그 뒤를 나머지(remaining) 일치하지 않는 `y` 행이 따릅니다.

5. 동등 조인(equi joins)으로, 키가 동일한 경우 행이 일치합니다. 동등 조인은 조인의 일반적인 유형이므로 일반적으로 동등 접두사를 생략하고 "동등 내부 조인"이 아니라 그냥 "내부 조인"이라고 합니다.

### 행 일치

지금까지 `x`의 행이 `y`의 0개 또는 1개의 행과 일치하는 경우 무슨 일이 일어나는지 탐구했습니다. 둘 이상의 행과 일치하면 어떻게 됩니까? `x`의 행에 대한 세 가지 가능한 결과(outcomes)가 있습니다.

1. 아무것과도 일치하지 않으면 삭제됩니다.
2. `y`의 1개 행과 일치하면 보존됩니다.
3. `y`의 1개 이상의 행과 일치하면 각 일치에 대해 한 번씩 복제(duplicated)됩니다.

원칙적으로(In principle) 이는 출력의 행과 `x`의 행 간에 보장된 대응(guaranteed correspondence)이 없음을 의미하지만 실제로는 이로 인해 문제가 발생하는 경우는 드뭅니다. 하지만 조합적 폭발(combinatorial explosion)을 일으킬 수 있는 특히 위험한(dangerous) 사례가 하나 있습니다. 다음 두 테이블을 조인한다고 상상해 보세요.

```{r}
df1 <- tibble(key = c(1, 2, 2), val_x = c("x1", "x2", "x3"))
df2 <- tibble(key = c(1, 2, 2), val_y = c("y1", "y2", "y3"))
```

`df1`의 첫 번째 행은 `df2`의 한 행과만 일치하지만, 두 번째와 세 번째 행은 모두 두 행과 일치합니다.
이것을 때로는 `다대다(many-to-many)` 조인이라고 부르며, dplyr이 경고를 발생시킵니다.

```{r}
df1 |> 
  inner_join(df2, join_by(key))
```

의도적으로(deliberately) 이 작업을 수행하는 경우 경고에서 제안하는 대로 `relationship = "many-to-many"`를 설정할 수 있습니다.

### 필터링 조인

일치하는 항목 수도 필터링 조인의 동작을 결정합니다. 

1. 세미 조인은 `y`에 하나 이상의 일치 항목이 있는 `x`의 행을 유지합니다.
2. 안티 조인은 `y`에 일치하는 행이 0개인 `x`의 행을 유지합니다.

두 경우 모두 일치 항목이 존재한다는 것만이 중요합니다. 일치하는 횟수는 중요하지 않습니다. 즉, 필터링 조인은 변형 조인과 같이 행을 복제하지 않습니다.

## 비동등 조인

지금까지는 동등 조인, 즉 `x` 키가 `y` 키와 같을 때 행이 일치하는 조인만 보았습니다. 이제 그 제한(restriction)을 완화하고(relax) 한 쌍의 행이 일치하는지 여부를 결정하는 다른 방법에 대해 논의하겠습니다.

하지만 그 전에 위에서 만든 단순화(simplification)를 다시 살펴봐야(revisit) 합니다. 동등 조인에서는 `x` 키와 `y`가 항상 같기 때문에 출력에 하나만 표시하면 됩니다.
`keep = TRUE`를 사용하여 dplyr이 두 키를 모두 유지하도록 요청할 수 있습니다.

```{r}
x |> inner_join(y, join_by(key == key), keep = TRUE)
```

동등 조인에서 벗어날 때(move away from) 키 값은 종종 달라지기 때문에 항상 키를 표시할 것입니다. 예를 들어 `x$key`와 `y$key`가 같을 때만 일치시키는 대신 `x$key`가 `y$key`보다 크거나 같을 때마다 일치시킵니다. dplyr의 조인 함수는 동등 조인과 비동등 조인의 이러한 구분을 이해하므로 비동등 조인을 수행할 때 항상 두 키를 모두 표시합니다.

비동등 조인은 조인이 무엇인지가 아니라 무엇이 아닌지만 알려주기 때문에 특히 유용한 용어는 아닙니다. dplyr은 특히 유용한 네 가지 유형의 비동등 조인을 식별하여 도움을 줍니다.

1. 크로스 조인(Cross joins)은 모든 행 쌍을 일치시킵니다.
2. 부등 조인(Inequality joins)은 `==` 대신 `<`, `<=`, `>`, `>=`를 사용합니다.
3. 롤링 조인(Rolling joins)은 부등 조인과 유사하지만 가까운 일치 항목만 찾습니다.
4. 오버랩 조인(Overlap joins)은 범위(ranges)와 함께 작동하도록 설계된 특별한 유형의 부등 조인입니다.

이들 각각은 다음 섹션에서 자세히 설명합니다.

### 크로스 조인

크로스 조인은 모든 것을 일치시켜 행의 데카르트 곱(Cartesian product)을 생성합니다. 이는 출력에 `nrow(x) * nrow(y)` 행이 있음을 의미합니다.

```{r}
df1 <- tibble(key = c(1, 2, 2), val_x = c("x1", "x2", "x3"))
df2 <- tibble(key = c(1, 2, 2), val_y = c("y1", "y2", "y3"))
```

`df1`의 첫 번째 행은 `df2`의 한 행과만 일치하지만, 두 번째와 세 번째 행은 모두 두 행과 일치합니다. 이것을 때로는 `다대다(many-to-many)` 조인이라고 부르며, dplyr이 경고를 발생시킵니다.

```{r}
df1 |> 
  inner_join(df2, join_by(key))
```

의도적으로(deliberately) 이 작업을 수행하는 경우 경고에서 제안하는 대로 `relationship = "many-to-many"`를 설정할 수 있습니다.

### 부등 조인

부등 조인은 `<`, `<=`, `>=`, 또는 `>`를 사용하여 가능한 일치 항목 세트를 제한합니다. 부등 조인은 매우 일반적(general)이어서 의미 있는(meaningful) 특정 사용 사례(use cases)를 떠올리기(come up with)가 어렵습니다. 작지만 유용한 한 가지 기술(technique)은 크로스 조인을 제한하여 모든 순열을 생성하는 대신 모든 조합(combinations)을 생성하도록 하는 것입니다.

```{r}
df <- tibble(id = 1:4, name = c("John", "Simon", "Tracy", "Max"))

df |> inner_join(df, join_by(id < id))
```

### 롤링 조인

롤링 조인은 부등식을 만족하는(satisfies) 모든 행을 가져오는 대신 가까운 행만 가져오는 특수한 유형의 부등 조인입니다. `closest()`를 추가하여 모든 부등 조인을 롤링 조인으로 전환할 수 있습니다. 예를 들어 `join_by(closest(x <= y))`는 x보다 크거나 같은 작은 `y`와 일치하고, `join_by(closest(x > y))`는 `x`보다 작은 큰 `y`와 일치합니다.

롤링 조인은 완벽하게 일치하지 않는 두 개의 날짜 테이블이 있고 테이블 2의 특정 날짜 전(또는 후)에 나오는 테이블 1의 가까운 날짜를 찾고 싶을 때 특히 유용합니다. 예를 들어 여러분이 회사의 파티 기획 위원회(party planning commission)를 맡고(in charge of) 있다고 상상해 보세요. 여러분의 회사는 꽤 짠돌이(cheap)라서 개인 파티를 하는 대신 분기별로 한 번씩만 파티를 엽니다. 파티 개최 시기를 결정하는 규칙은 약간 복잡합니다. 파티는 항상 월요일에 열리고, 휴가를 가는 사람이 많아서 1월 첫째 주는 건너뛰고(skip), 2022년 3분기의 첫 번째 월요일은 7월 4일이므로 일주일 뒤로 미뤄야(pushed back) 합니다.
이렇게 하면 다음과 같은 파티 날짜가 됩니다.

```{r}
parties <- tibble(
  q = 1:4,
  party = ymd(c("2022-01-10", "2022-04-04", "2022-07-11", "2022-10-03"))
)
```

이제 직원 생일 테이블이 있다고 상상해 보세요.

```{r}
set.seed(123)
employees <- tibble(
  name = sample(babynames::babynames$name, 100),
  birthday = ymd("2022-01-01") + (sample(365, 100, replace = TRUE) - 1)
)
employees
```

그리고 각 직원에 대해 생일 이전(또는 생일 당일)에 있었던 마지막 파티 날짜를 찾고 싶습니다. 롤링 조인으로 이를 표현할 수 있습니다.

```{r}
employees |> 
  left_join(parties, join_by(closest(birthday >= party)))
```

하지만 이 접근 방식(approach)에는 한 가지 문제가 있습니다. 1월 10일 이전에 생일이 있는 사람(folks)들은 파티를 열지 못합니다.

```{r}
employees |> 
  anti_join(parties, join_by(closest(birthday >= party)))
```

이 문제를 해결하려면 오버랩 조인(overlap joins)이라는 다른 방법으로 문제를 해결(tackle)해야 합니다.

### 오버랩 조인

오버랩 조인은 구간(intervals)으로 작업하기 쉽도록 부등 조인을 사용하는 세 가지 도우미(helpers)를 제공합니다.

-   `between(x, y_lower, y_upper)`는 `x >= y_lower, x <= y_upper`의 줄임말입니다.
-   `within(x_lower, x_upper, y_lower, y_upper)`는 `x_lower >= y_lower, x_upper <= y_upper`의 줄임말입니다.
-   `overlaps(x_lower, x_upper, y_lower, y_upper)`는 `x_lower <= y_upper, x_upper >= y_lower`의 줄임말입니다.

생일 예제를 계속하여 어떻게 사용할 수 있는지 알아보겠습니다.
위에서 사용한 전략(strategy)에는 한 가지 문제가 있습니다. 1월 1일부터 9일 사이의 생일을 위한 파티가 없습니다.
따라서 각 파티가 포괄하는(spans) 날짜 범위에 대해 명시적(explicit)으로 정하고 이러한 초기 생일(early birthdays)에 대해 특별한 경우를 만드는 것이 더 나을 수 있습니다.

```{r}
parties <- tibble(
  q = 1:4,
  party = ymd(c("2022-01-10", "2022-04-04", "2022-07-11", "2022-10-03")),
  start = ymd(c("2022-01-01", "2022-04-04", "2022-07-11", "2022-10-03")),
  end = ymd(c("2022-04-03", "2022-07-11", "2022-10-02", "2022-12-31"))
)
parties
```

해들리(Hadley)는 데이터 입력을 절망적(hopelessly)으로 못하기 때문에 파티 기간이 겹치지(overlap) 않는지 확인하고 싶어 했습니다.
이를 수행하는 한 가지 방법은 셀프 조인을 사용하여 시작-종료(start-end) 구간이 다른 구간과 겹치는지 확인하는 것입니다.

```{r}
parties |> 
  inner_join(parties, join_by(overlaps(start, end, start, end), q < q)) |> 
  select(start.x, end.x, start.y, end.y)
```

이런(Ooops), 겹치는 부분이 있으니 그 문제를 고치고 계속 진행합시다.

```{r}
parties <- tibble(
  q = 1:4,
  party = ymd(c("2022-01-10", "2022-04-04", "2022-07-11", "2022-10-03")),
  start = ymd(c("2022-01-01", "2022-04-04", "2022-07-11", "2022-10-03")),
  end = ymd(c("2022-04-03", "2022-07-10", "2022-10-02", "2022-12-31"))
)
```

이제 각 직원을 자신의 파티와 일치시킬 수 있습니다.
파티가 할당되지 않은 직원이 있는지 빨리 확인하고 싶기 때문에(we want to quickly find out) 이럴 때는 `unmatched = "error"`를 사용하는 것이 좋습니다.

```{r}
employees |> 
  inner_join(parties, join_by(between(birthday, start, end)), unmatched = "error")
```
