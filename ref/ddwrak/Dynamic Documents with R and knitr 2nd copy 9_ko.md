### 9

###### 교차 참조

knitr에서는 코드 청크와 하위 문서를 교차 참조할 수 있습니다. 이를 통해 원본 문서를 더 효과적으로 구성할 수 있습니다. 아래에 실용적인 예제가 있습니다. 사용자 지정 ggplot2 테마가 있고 이를 문서 내의 몇 가지 그래프에 적용하고자 합니다.

<<my-theme, eval=FALSE>>= theme(legend.text = element_text(size = 12, angle = 45)) +

theme(legend.position = "bottom") @

만약 이 코드를 한 번만 사용한다면 코드 청크에 바로 복사하여 붙여넣으면 됩니다. 하지만 여러 청크에 붙여넣는 것은 유지 관리에 있어 좋은 방법이 아닙니다. 대신 청크 레이블을 사용하여 간단히 참조할 수 있습니다. 예를 들어,

qplot(carat, price, data = diamonds, color = cut) +

<<my-theme>>

그러면 knitr는 이 청크를 평가하기 전에 < <my-theme> > 부분을 실제 소스 코드로 확장합니다. 이 참조를 여러 곳에서 사용할 수 있지만 원본 코드는 단일 복사본으로 유지할 수 있습니다.

###### 9.1 청크 참조

청크 참조를 사용하면 동일한 코드를 다시 입력할 필요 없이 코드 청크를 쉽게 재사용할 수 있습니다. 정의된 청크를 다른 청크 안에 삽입하거나 전체 청크를 새로운 청크로 재사용할 수 있습니다.

###### 9.1.1 코드 청크 삽입하기

하나의 청크를 다른 청크의 일부로 사용할 수 있습니다. 구문은 < <label> >입니다 (앞에 공백이 허용되며, label은 청크 레이블을 의미합니다).

91

청크 헤더와 달리 > > 뒤에 = 기호가 없습니다. 예를 들어, 청크 A를 B에 삽입합니다.

- <<A>>= x <- rnorm(1) @
- <<B>>= x <<A>> x @

이 경우 청크 B는 본질적으로 다음과 같습니다 (< <A> >는 청크 A의 코드로 대체되지만 eval을 포함한 청크 A의 모든 청크 옵션은 무시됩니다):

x x <- rnorm(1) x

청크는 유한한 재귀에 한해 서로 재귀적으로 중첩될 수 있습니다. 예를 들어, A를 B에 삽입하고, B를 C에 삽입할 수 있습니다. 하지만 C를 다시 A에 삽입해서는 안 됩니다. 무한 재귀가 발생하기 때문입니다.

###### 9.1.2 전체 청크 재사용하기

전체 청크를 재사용하는 두 가지 방법이 있습니다. 첫 번째 방법은 동일한 레이블을 사용하되 청크를 비워두는 것입니다. 이 방법의 문제점 중 하나는 청크 옵션이 다를 경우 두 청크 모두 캐시할 수 없다는 것입니다. MD5 해시가 달라지기 때문이며, knitr는 레이블당 한 세트의 캐시 파일만 허용합니다. 한 가지 예가 여기에 있습니다.

<<chunkA, eval=FALSE>>= x <- 1 + 1 @ <<chunkA, eval=TRUE>>= @

두 번째 방법은 ref.label 옵션을 사용하는 것입니다. 이 옵션은 원본 청크의 청크 레이블 벡터를 인수로 받습니다. 대상 청크에는 새로운 레이블을 사용할 수 있습니다. 다음 예제에서 청크 C는 A와 B의 코드를 모두 사용합니다.

- <<A>>=

- x <- rnorm(1) @

<<B>>=

- y <- x + 2 @

- <<C, ref.label=c( A , B )>>= @

청크 C를 위한 코드는 본질적으로 다음과 같습니다.

- x <- rnorm(1)
- y <- x + 2

###### 9.2 코드 외부화

R 코드 청크를 원본 문서에 섞어 작성하는 것보다 별도의 R 스크립트로 작성하는 것이 더 편리할 수 있습니다. 예를 들어, 순수한 R 스크립트에서 다른 텍스트를 건너뛰지 않고 청크에서 청크로 R 코드를 연속적으로 실행할 수 있습니다.

또 다른 이유는 LYX와 같은 일부 편집기가 R 코드를 대화형으로 실행하는 기능을 지원하지 않기 때문입니다. 단일 청크의 결과를 알고 싶을 때에도 매번 전체 문서를 다시 컴파일해야 합니다.

따라서 knitr는 코드 외부화 기능을 도입했습니다. read_chunk()를 통해 외부 R 스크립트에서 코드 청크를 읽어올 수 있습니다. R 스크립트는 두 가지 형태로 작성할 수 있습니다. 스크립트 내에서 레이블을 사용하여 코드 청크를 구분하거나, 줄 번호를 기반으로 청크를 지정할 수 있습니다.

###### 9.2.1 레이블된 청크

설정 방법은 다음과 같습니다. R 스크립트에서도 청크 레이블(## ---- chunk-label 형식)을 사용합니다. 원본 문서의 코드 청크가 비어 있다면, knitr는 원본 문서의 레이블과 R 스크립트의 레이블을 일치시켜 외부 R 코드를 입력합니다.

예를 들어, 원본 문서와 동일한 디렉토리에 있는 shared.R이라는 R 스크립트에 Q1로 레이블이 지정된 코드 청크가 있다고 가정해 보겠습니다.

## ---- Q1 ---gcd <- function(m, n) {

while ((r <- m%%n) != 0) {

- m <- n
- n <- r

} n

}

원본 문서에서는 먼저 read_chunk() 함수를 사용하여 스크립트를 읽을 수 있습니다.

read_chunk("shared.R")

이는 문서의 첫 번째 청크와 같은 초기 청크에서 일반적으로 수행됩니다. 그 후 원본 문서 내에서 Q1 청크를 사용할 수 있습니다.

<<Q1>>= @

###### 9.2.2 줄 기반 청크

기본적으로 read_chunk()는 R 스크립트가 레이블되어 있다고 가정합니다(## ---이 구분 기호입니다). 또는 세 개의 인수 labels, from, to를 통해 코드 청크를 지정하는 대안적인 방법이 있습니다. 이들은 길이가 동일한 벡터입니다. 코드 청크의 시작과 끝 줄 번호는 각각 from과 to를 통해 설정할 수 있으며, labels는 청크 레이블의 벡터입니다.

예를 들어, R 스크립트 foo.R의 1-5줄, 7-9줄, 15-21줄이 레이블 A, B, C를 가진 세 개의 청크를 형성하도록 하려면 read_chunk() 함수를 다음과 같이 호출할 수 있습니다.

read_chunk("foo.R", labels = c("A", "B", "C"), from = c(1,

7, 15), to = c(5, 9, 21))

그런 다음 원본 문서에 레이블 A, B, C를 사용하여 세 개의 빈 청크를 작성할 수 있습니다. 또한 시작 줄과 끝 줄을 지정할 때 from과 to에 정규 표현식을 사용할 수도 있습니다.

서로 다른 문서에서 동일한 R 스크립트를 읽을 수 있으므로 R 코드는 여러 입력 문서에 걸쳐 재사용될 수 있습니다.

###### 9.3 하위 문서

주 문서가 클 때 하위 문서라는 개념은 LATEX 사용자에게 익숙할 것입니다. 문서를 작은 부분으로 나누고 \input{foo.tex}를 사용하여 주 문서에 포함할 수 있습니다. 예를 들어 책은 여러 장으로 나눌 수 있으며 각 장은 하나의 파일에 포함됩니다.

###### 9.3.1 하위 문서 포함하기

이와 비슷하게 knitr 원본 문서를 하위 문서의 모음으로 관리할 수 있습니다. 청크 옵션 child는 하위 문서에 대한 참조를 제공합니다. 동일한 디렉토리 아래에 book.Rnw라는 주 문서와 chap1.Rnw라는 하위 문서가 있다고 가정해 보겠습니다. 주 문서에는 다음과 같은 내용이 있습니다.

주 문서의 청크 중 하나입니다.

- <<A, eval=TRUE>>=

- x <- rnorm(12) @ 변수 x를 사용하는 하위 문서를 포함합니다.

<<B, child= chapt1.Rnw >>= @

자유도가 12인 카이제곱 확률 변수의 한 구현 값은 \Sexpr{y}입니다.

주 문서의 청크 B에서 하위 문서를 참조했습니다. 주 문서를 컴파일할 때 knitr는 하위 문서를 찾아 적절하게 컴파일합니다. 주 문서 환경의 현재 시점까지의 모든 내용이 하위 문서에서 사용 가능합니다. 변수 x가 그 예입니다. 하위 문서는 다음과 같습니다.

이것은 하위 문서입니다. <<B1>>=

- y <- sum(x^2) @

하위 문서에서 새로운 객체 y를 생성했습니다. 하위 문서가 컴파일된 후 주 문서의 이후 청크에서도 사용할 수 있게 됩니다.

이것이 \Sexpr{y}가 동작하는 이유입니다. 참고로, n개의 독립적이고 동일하게 분포된 표준 정규 확률 변수의 합은 카이제곱 분포(n 자유도)를 따르므로, y는 자유도가 12인 카이제곱 분포에서 생성된 난수 하나입니다.

청크 참조와 마찬가지로 하위 문서는 중첩 수준에 제한이 없습니다. 하나의 하위 문서가 더 많은 하위 문서를 가질 수 있으며 하나의 청크가 여러 하위 문서를 포함할 수 있습니다.

###### 9.3.2 하위 문서를 템플릿으로 사용하기

다른 데이터 입력을 가지고 템플릿을 사용하여 동일한 분석을 수행하는 것은 흔한 일이며 하위 문서는 이러한 작업에도 도움이 될 수 있습니다. 간단한 예제로, 주 문서에서 카이제곱 분포로부터 또 다른 난수를 계속 생성해 보겠습니다.

% second part of book.Rnw 위의 예제를 계속 진행합니다. 이제 자유도를 8로 변경합니다.

- <<C, eval=TRUE>>= x <- rnorm(8) @ 그리고 하위 문서를 다시 포함합니다.
- <<D, child= chapt1.Rnw >>= @

자유도가 8인 카이제곱 확률 변수의 한 구현 값은 \Sexpr{y}입니다.

여기서 하위 문서가 수행하는 작업은 x에 대한 제곱합을 계산하고 그 결과를 y에 할당하는 것뿐입니다. 우리가 흔히 보는 순수한 소스 코드는 아니지만 서브루틴과 매우 유사합니다.

청크 참조와 하위 문서를 사용하면 프로그래밍과 같은 방식으로 분석을 모듈화할 수 있습니다.

###### 9.3.3 독립 실행형 모드

이 섹션은 LATEX에 한정된 내용입니다. Rnw 하위 문서는 \documentclass에서 \begin{document}까지의 LATEX 서문이 없다는 점에서 종종 불완전합니다. 따라서 이들을 직접 컴파일하면 LATEX 오류가 발생하게 됩니다.

하위 문서는 부모 문서와 관련이 있어야 하지만, 일부 경우에는 반드시 그렇지 않습니다. 때로는 하위 문서가 단지 방대한 문서를 구성하기 위한 목적으로만 존재하며 하위 문서 내의 연산이 부모와 전혀 관련이 없을 수 있습니다. 이 경우 부모 문서의 서문을 빌려 결과물을 컴파일할 때 하위 문서에 추가하기만 하면 됩니다.

set_parent() 함수는 하위 문서의 부모 문서가 무엇인지 knitr에 알립니다. 이 함수가 호출되면 knitr는 Rnw 문서를 TEX로 컴파일할 때 부모 문서의 서문을 읽어 하위 문서에 씁니다. 예를 들어 chapt1.Rnw에서 다음과 같이 작성할 수 있습니다.

<<parent, include=FALSE>>= set_parent("book.Rnw") @

그러면 chapt1.Rnw의 내용이 book.Rnw 안에 있는 것처럼 book.Rnw의 서문에 정의된 모든 LATEX 스타일이 chapt1.tex에서 사용 가능하게 됩니다.
