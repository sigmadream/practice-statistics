# Python 및 R 구하기 (Obtaining Python and R)

Python이나 R을 실행하는 두 가지 옵션이 존재합니다. 프로그램을 컴퓨터에 로컬로 설치하거나 클라우드 호스팅 버전을 사용할 수 있습니다. 1980년대 후반 *개인용 컴퓨터*가 등장한 이후부터 2010년대까지 거의 모든 컴퓨팅은 로컬에서 이루어졌습니다. 고용주가 클라우드 액세스나 로컬 서버를 호스팅하고(비용을 지불하고) 제공하지 않는 한 사람들은 소프트웨어를 다운로드하여 로컬 컴퓨터에 설치했습니다. 대부분의 사람들은 여전히 이 접근 방식을 사용하여 클라우드가 아닌 로컬 컴퓨팅을 사용합니다. 최근 들어 소비자 규모(consumer-scale)의 클라우드 도구를 쉽게 사용할 수 있게 되었습니다. 두 가지 접근 방식 모두 트레이드오프(trade-off)가 존재합니다.

- 개인용 컴퓨터 사용의 이점:

  - 사전에 알려진 하드웨어 초기 일회성 비용이 있습니다.

  - 모든 하드웨어 및 소프트웨어(저장 장치 포함)를 제어합니다.

  - 원하는 것을 모두 설치할 수 있습니다.

  - 인터넷 중단 시, 외딴 지역 또는 비행 중과 같이 인터넷 연결 없이도 프로그램이 실행됩니다.

- 소비자 규모의 클라우드 기반 컴퓨팅 사용의 이점:

  - 필요한 컴퓨팅 리소스에 대해서만 비용을 지불합니다.

  - 많은 무료 소비자 서비스가 존재합니다.

  - 고가의 하드웨어가 필요하지 않습니다. 예를 들어 크롬북이나 iPad와 같은 태블릿도 사용할 수 있습니다.

  - 클라우드 기반 컴퓨팅은 리소스가 더 필요할 때 확장(upscale)하는 데 비용이 덜 듭니다.

  - 플랫폼 및 지원 수준에 따라 프로그램 설치를 책임지지 않아도 됩니다.

# 스크립트 (Scripts)

*스크립트 파일* (간단히 *스크립트*)을 사용하면 향후 코드를 응용하기 위해 작업 내용을 저장할 수 있습니다. 예제에서는 터미널에 직접 입력하는 것을 보여주지만, 터미널에 입력하는 것은 효과적이거나 쉽지 않습니다. 이러한 파일은 일반적으로 언어에 따른 특정 확장자로 끝납니다. Python 파일은 *.py*로 끝나고 R 파일은 *.R*로 끝납니다.

이 책을 진행하는 동안 여러분은 Python과 R을 대화형으로(interactively) 사용하게 됩니다. 그러나 일부 사람들은 이 언어들을 배치 파일(batch files)로 실행하기도 합니다. *배치 파일*은 단순히 컴퓨터에 전체 파일을 실행하도록 지시한 다음 해당 파일에서 출력을 뱉어냅니다. 배치 파일의 예로는 PFF와 같은 회사가 NFL 시즌 동안 매주 실행하여 요약 통계를 계산한 다음 고객 보고서에 배치하는 작업이 있을 수 있습니다.

배치 파일 외에도 어떤 사람들은 코드나 코드 출력을 설명하는 데 필요한 대량의 텍스트를 가지고 있습니다. 이러한 응용 프로그램의 경우 종종 스크립트 파일보다 다른 형식이 더 잘 작동합니다. 예를 들어 Jupyter Notebook을 사용하면 읽기 쉬운 문서와 함께 실행 가능한 코드를 생성, 포함 및 사용할 수 있습니다. "Jupyter Notebook"이라는 이름의 *Notebooks*는 텍스트와 관찰 내용이 섞이는 과학자의 실험실이나 현장 노트(field notebook)와의 유사성을 시사합니다.

마찬가지로 마크다운(Markdown) 기반 파일(예: Quarto 또는 구형 R Markdown 파일)을 사용하면 정적 코드와 코드 출력을 문서에 삽입할 수 있습니다. 우리는 두 가지를 모두 작업에 사용합니다. 다른 사람들이 우리의 코드를 대화형으로 쉽게 실행할 수 있기를 원할 때는 Jupyter Notebook을 사용합니다. NFL 팀용 프로젝트 파일이나 과학 논문 같은 정적 보고서를 작성하고자 할 때는 R Markdown 기반 워크플로를 사용합니다.

이 책의 초기 초안은 출판사인 O'Reilly가 Quarto 기반 워크플로를 지원한다는 사실을 인지하지 못했기 때문에 Jupyter Notebook으로 작성되었습니다. 후기 초안은 우리(저자)가 이 언어를 더 잘 알기 때문에 Quarto로 작성되었습니다. 게다가 Quarto는 동일한 문서 내에서 Python 및 R과 모두 더 잘 작동했습니다. 따라서 저자인 우리는 출판사의 시스템에 맞춰 도구 선택을 조정했으며, 이는 도구 상자 유연성의 중요성을 잘 보여줍니다.

###### 경고 (Warning)

Microsoft Word와 같은 많은 프로그램은 "스마트 따옴표(smart quotes)" 및 다른 텍스트 서식을 사용합니다. 이로 인해 PDF, Word 문서 또는 웹페이지와 같이 일반 텍스트(plain-text) 파일이 아닌 파일에서 복사한 코드의 경우 각별히 주의하시기 바랍니다.

# Python 및 R의 패키지 (Packages in Python and R)

Python과 R 모두 패키지를 통해 확장할 수 있기 때문에 언어로서 성공하고 번창하고 있습니다. Python에는 다중 패키지 관리 시스템(multiple package-management systems)이 있으며, 이는 초보자와 고급 사용자 모두에게 혼란을 줄 수 있습니다. 초보 사용자는 종종 어떤 시스템을 사용해야 할지 모르고, 고급 사용자는 시스템 간에 패키지 버전이 충돌하는 문제에 직면합니다.

Python 패키지를 설치하는 가장 간단한 방법은 아마도 `pip` 명령을 사용하여 Python 외부의 터미널에서 설치하는 것일 겁니다. 예를 들어 `pip install seaborn`을 사용하여 `seaborn`을 설치할 수 있습니다. R에는 현재 이 책의 독자가 관심을 가질 만한 주요 저장소가 하나 있는데 바로 CRAN(Comprehensive R Archive Network)입니다. 두 번째 저장소인 Bioconductor는 주로 생물정보학(bioinformatics) 프로젝트를 지원합니다. R 패키지는 `install.packages()` 함수를 사용하여 R 내부에서 설치할 수 있습니다. 예를 들어 `install.packages("ggplot2")`를 사용하여 `ggplot2`를 설치할 수 있습니다.

패키지가 CRAN에 없거나 코드를 사용하지 못하게 만드는 버그를 수정하기 위해 개발 버전(development version)이 필요하기 때문에, 여러분도 언젠가는 GitHub와 같은 사이트에서 패키지를 설치해야 하는 상황에 놓일 수 있습니다. 이러한 설치 방법은 이 책의 범위를 벗어나지만 검색 엔진을 사용하여 쉽게 찾을 수 있습니다. 게다가 패키지 버전을 잠글(lock down) 수 있는 환경 관리 소프트웨어도 존재합니다. 이에 대해서는 <a href="ch09.html#sec-advanced-tool" data-type="xref">9장</a>에서 논의했습니다.

# nflfastR 및 nfl_data_py 팁 (nflfastR and nfl_data_py Tips)

이 섹션에서는 `nflfastR` 및 `nfl_data_py` 패키지에 대한 우리의 구체적인 관찰 내용을 제공합니다. 먼저, 우리(저자)는 이 패키지들을 사랑합니다. 이들은 데이터를 위한 훌륭한 무료 리소스입니다.

###### 팁 (Tip)

새로운 경기를 통해 더 많은 데이터가 추가되므로, 시즌 내내 `nflfastR` 및 `nfl_data_py` 패키지를 정기적으로 업데이트하십시오. 그러면 최신 데이터에 액세스할 수 있습니다.

여러분은 데이터에 대해 상당한 양의 랭글링(wrangling)을 수행해야 한다는 것을 눈치채셨을 것입니다. 그것은 이 패키지들의 단점이 아닙니다. 오히려 데이터 소스의 유연성과 깊이를 보여주는 것입니다. 깨끗한 데이터셋을 제공하는 대신 데이터셋을 정리하도록 하는 이유는 여러분이 데이터를 정리하는 방법을 배우기를 원하기 때문입니다. 또한 이 데이터셋은 풋볼 시즌 동안 매일 밤 업데이트되므로, 이 패키지들을 사용하는 방법을 보여줌으로써 여러분에게 자체 데이터를 얻는 도구를 제공하는 것입니다.

두 패키지에 대해 더 자세히 알아보려면 해당 세부 사항을 파헤쳐 보는 것을 권장합니다. 패키지의 기본 함수와 구조를 살펴본 후에는 코드를 보고 "후드 아래를 엿보는(peek under the hood)" 것도 좋을 것입니다. [`nflfastR`](https://oreil.ly/B6qiV) 및 [`nfl_data_py`](https://oreil.ly/ss6d_)는 모두 GitHub에 있습니다. 이 사이트를 통해 이슈(issues) 및 버그를 보고하고 변경 사항을 제안할 수 있으며, 이상적으로는 여러분이 직접 코드를 제공할 수도 있습니다!

마지막으로 이러한 도구를 제공하는 오픈 소스 커뮤니티에 기여하시기를 권장합니다. 모든 사람이 코드를 기여할 수는 없지만 문서화(documentation)와 같은 다른 작업을 돕는 것은 더 쉽게 접근할 수 있습니다.

# 통합 개발 환경 (Integrated Development Environments)

*통합 개발 환경(* *IDE* *)*이라는 강력한 코드 편집 도구를 사용할 수 있습니다. 풋볼 팬들이 역대 최고 쿼터백이 누구인지에 대해 싸우는 것처럼, 프로그래머들도 종종 어떤 IDE가 최고인지 논쟁을 벌입니다. IDE는 강력하지만(예를 들어, IDE는 종종 맞춤법 검사기와 유사한 구문 검사기 및 자동 완성 도구를 포함합니다), 단점도 있을 수 있습니다.

일부 IDE는 복잡하여 전문가 사용자에게는 유용할 수 있지만 초보자 및 일반 사용자에게는 압도적일 수 있습니다. 예를 들어, Emacs 텍스트 편집기는 '좋은 텍스트 편집기가 한두 개 내장된 운영 체제'라고 농담처럼 묘사되기도 합니다. 그 밖에도 웹 코믹 [“xkcd” 역시 emacs와 같은 IDE를 조롱합니다](https://xkcd.com/378). 마찬가지로 일부 전문 프로그래머들은 IDE에 내장된 단축키가 프로그래머에게 그들이 작업하는 언어에 대한 깊은 이해를 요구하지 않기 때문에 언어에 대한 이해를 제한하거나 제약한다고 느낍니다.

그러나 대부분의 사용자, 특히 일반 사용자의 경우 IDE의 이점이 단점보다 훨씬 큽니다. 만약 직장이나 다른 곳에서 다른 언어를 위해 이미 다른 IDE를 사용하고 있다면, 해당 IDE가 Python 그리고 어쩌면 R과도 함께 잘 작동할 가능성이 높습니다.

이 책을 집필할 때 우리는 시간과 파일 형식에 따라 각기 다른 편집기를 사용했습니다. 우리가 사용한 편집기에는 RStudio Desktop, JupyterLab, Visual Studio Code, 그리고 Emacs가 있습니다. 우리가 나열하지 않은 많은 것을 포함하여 훌륭한 IDE가 많이 존재합니다. 일부 옵션은 다음과 같습니다.

- [Posit RStudio Desktop](https://posit.co)

- [JetBrain PyCharm](https://www.jetbrains.com/pycharm)

- [Project Jupyter JupyterLab](https://jupyter.org)

- [GNU Project Emacs](https://www.gnu.org/software/emacs)

# 기본 Python 데이터 형식 (Basic Python Data Types)

Python에 대한 속성 코스(crash course)로서 언어 내에는 다양한 유형의 객체가 존재합니다. 적어도 이 책에서 사용되는 가장 기본적인 형식에는 *정수(integers)*, *부동 소수점 숫자(floating-point numbers)*, *논리값(logical)*, *문자열(strings)*, *리스트(lists)*, *딕셔너리(dictionaries)* 가 포함됩니다. 일반적으로 Python은 이러한 데이터 형식에 대한 고민을 알아서 처리하며 일반적으로 숫자의 형식을 대신 변경해 줍니다.

*정수(Integers)* (줄여서 *ints*)는 1, 2, 3과 같은 자연수(whole numbers)입니다. 때로는 객체를 인덱싱하기 위해 정수가 필요합니다(예를 들어 벡터 `x`에 대해 `x[1]`을 사용하여 두 번째 요소를 가져오는 경우. Python은 `0`부터 계산하기 시작함을 기억하십시오). 예를 들어 Python에서 정수 `x`를 만들 수 있습니다.

```
## Python
x = 1
x.__class__
```

```

y = x/2

```

결과는 다음과 같습니다.

\<class 'float'\>

컴퓨터는 숫자의 모든 자리수를 기억할 수 없으며(예를 들어 `float16`은 16자리만 추적함), 컴퓨터의 숫자는 수학적 숫자가 아닙니다. 대학원 시절 리차드의 수학 공동 지도교수가 그에게 가르쳐준 응접실 묘기(parlor trick)를 살펴봅시다.

```
## Python
1 + 1 + 1 == 3
```

결과는 다음과 같습니다.

True

그러나 이것이 항상 작동하는 것은 아닙니다.

```
## Python
0.1 + 0.1 + 0.1 == 0.3
```

결과는 다음과 같습니다.

False

왜 이 코드가 작동하지 않을까요? 컴퓨터 칩에서 숫자를 계산할 때 반올림 오차(rounding error)가 발생하기 때문입니다. 따라서 컴퓨터는 수학적 덧셈에 "실패"합니다.

Python에는 *부울 객체(Boolean objects)* 또는 *bool*이라고 하는 `True` 및 `False` 논리 연산자도 있습니다. 앞의 예제에서는 논리 연산자에서 bool이 어떻게 결과로 나오는지 보여주었습니다.

문자는 *문자열(strings)* (줄여서 *str*)로 저장됩니다. 문자열로 저장된 숫자는 숫자처럼 작동하지 않습니다. 예를 들어, 다음을 살펴보세요.

```
## Python
a = "my two"
c = 2
a * c
```

결과는 다음과 같습니다.

'my twomy two'

Python에는 값 그룹(groups of values)이 있습니다. 리스트는 `list()` 또는 `[]`를 사용하여 생성할 수 있습니다.

```
## Python
my_list = [1, 2, 3]
my_list_2 = list(("a", "b", "c"))
```

딕셔너리(Dictionaries)는 또한 *키(key)* 와 함께 값을 저장할 수 있으며 `dict()` 또는 `{}`를 사용하여 생성됩니다. 우리는 거의 전적으로 `{}`를 사용하지만 완전성을 위해 다른 방법도 보여줍니다. 예를 들면 다음과 같습니다.

```
## Python
my_dict = dict([('fred', 2), ('sally', 5), ('joe', 3)])
my_dict_2 = {"a": 0, "b": 1}
```

또한 `numpy` 패키지를 사용하면 데이터를 배열(arrays)에 저장할 수 있고, `pandas` 패키지를 사용하면 데이터를 데이터프레임(dataframes)에 저장할 수 있습니다. 배열은 동일한 데이터 형식이어야 하지만 데이터프레임은 혼합된 열(예: 한 열은 숫자이고 두 번째 열은 이름)을 가질 수 있습니다.

# 기본 R 데이터 형식 (Basic R Data Types)

R에 대한 속성 코스로서, Python에서와 마찬가지로 언어 내에 여러 유형의 객체가 존재합니다. 적어도 이 책에서 사용되는 가장 기본적인 형식에는 *정수(integers)*, *숫자 부동 소수점 수(numeric floating-point numbers)*, *논리값(logical)*, *문자(characters)*, *리스트(lists)* 가 포함됩니다. 일반적으로 R은 사용자를 대신하여 이러한 구조에 대한 고민을 알아서 처리하며 일반적으로 사용자를 위해 형식을 변경해 줍니다. R은 Python과 약간 다른 이름을 사용합니다. 따라서 이 섹션은 <a href="#sec-py-datatypes" data-type="xref">“기본 Python 데이터 형식(Basic Python Data Types)”</a>과 유사하지만 약간 다릅니다.

*정수(Integers)* 는 1, 2, 3과 같은 자연수(whole numbers)입니다. 때때로 객체를 인덱싱하기 위해 정수가 필요합니다. 예를 들어 벡터 `x`에 대해 `x[2]`를 사용하여 두 번째 요소를 가져오는 경우입니다. R은 `1`부터 계산하기 시작함을 기억하십시오. 예를 들어, `L`을 사용하여 R에서 정수 `x`를 만들 수 있습니다.

```
## R
x <- 1L
class(x)
```

결과는 다음과 같습니다.

\[1\] "integer"

*숫자 부동 소수점 수(Numerical floating-point numbers)* (간단히 *숫자형(numeric)*)는 컴퓨터가 유한한 수의 자리까지 추적하는 십진수입니다. R은 필요할 때 다음처럼 정수를 숫자형으로 변환합니다.

```
## R
y <- x / 2
class(y)
```

결과는 다음과 같습니다.

\[1\] "numeric"

컴퓨터는 숫자의 모든 자릿수를 기억할 수 없으며(예를 들어 `float16`은 16자리만 추적함), 컴퓨터의 숫자는 수학적 숫자가 아닙니다. 대학원 시절 리차드의 수학 공동 지도교수가 그에게 가르쳐준 응접실 묘기를 살펴봅시다.

```
## R
1 + 1 + 1 == 3
```

결과는 다음과 같습니다.

\[1\] TRUE

그러나 이것이 항상 작동하는 것은 아닙니다.

```
## R
0.1 + 0.1 + 0.1 == 0.3
```

결과는 다음과 같습니다.

\[1\] FALSE

이것은 답을 계산하는 컴퓨터 칩에서 발생하는 반올림 오차 때문입니다.

R에는 논리 연산자인 `TRUE`와 `FALSE`도 있으며 간단히 *논리값(logical)* 이라고 합니다. 앞의 예제에서는 논리 연산자에서 논리적 출력이 어떻게 결과로 나오는지 보여주었습니다.

문자는 R에서 *문자(characters)* 로 저장됩니다. 이들은 숫자 연산자(numeric operators)와 함께 작동하지 않습니다. 예를 들어 다음을 살펴보십시오.

```
## R
a <- "my two"
c <- 2
a * c
```

R에는 *리스트(lists)* 또는 *벡터(vectors)* 라고 하는 값 그룹이 있습니다. 리스트는 *결합(combine)* 또는 *연결(concatenate)* 함수를 사용하여 만들 수 있습니다. 예를 들면 다음과 같습니다.

```
## R
my_list <- c(1, 2, 3)
```

또한 기본 R에는 숫자를 저장하는 행렬(matrices)과 혼합 열(예: 한 열은 숫자이고 두 번째 열은 이름)을 저장하는 데이터프레임이 포함되어 있습니다. 우리는 이 책에서 데이터프레임의 업그레이드 버전으로 `tidyverse`의 티블(tibbles)을 사용합니다.
