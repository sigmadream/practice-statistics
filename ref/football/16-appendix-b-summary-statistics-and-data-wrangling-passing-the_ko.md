# 부록 B. 요약 통계 및 데이터 랭글링: 패스 (Appendix B. Summary Statistics and Data Wrangling: Passing the Ball)

이 부록에는 몇 가지 기본 통계를 이해하는 데 도움이 되는 자료가 포함되어 있습니다. 이 주제가 처음이라면 <a href="ch01.html#sec-introduction" data-type="xref">1장</a> 또는 <a href="ch02.html#sec-EDA-stable" data-type="xref">2장</a>을 읽은 후 이 책에 너무 깊이 들어가기 전에 이 자료를 읽는 것을 권장합니다.

<a href="ch02.html#sec-EDA-stable" data-type="xref">2장</a>에서는 플레이의 어떤 측면이 성과에 근본적인 영향을 미치고 어떤 측면이 노이즈가 많아 향후 성과를 예측하는 데 잘못된 길로 이끌 수 있는지 이해하기 위해 다양한 패스 깊이에서 쿼터백의 성과를 살펴보았습니다. 운 좋게도 여러분은 이 분석을 수행할 수 있도록 데이터가 어느 정도 준비된(ready-made) 형태로 주어졌습니다. 분석을 위해 자신만의 변수를 만들어야 했지만, 그러한 *데이터 랭글링(data wrangling)* 은 기껏해야 최소한의 수준이었습니다.

스포츠 분석 전반, 특히 풋볼 분석은 아직 발전 초기 단계에 있습니다. 따라서 데이터셋이 항상 가장 깔끔하거나 타이디(tidy)하지는 않을 수 있습니다. *타이디(tidy)* 데이터셋은 컴퓨터가 쉽게 읽을 수 있고 사람이 쉽게 이해할 수 있는 테이블 형태인 경우가 많습니다. 게다가 어떤 분야에서든 데이터 분석(풋볼 분석도 다르지 않음)에는 종종 다른 목적으로 생성된 데이터셋이 필요합니다. 데이터 랭글링은 바로 이런 상황에서 유용할 수 있습니다. 많은 사람들이 지저분한 데이터를 정리해야 했기 때문에 이 분야에는 여러 용어가 존재합니다. *데이터 랭글링(data wrangling)* 의 동의어로는 *데이터 정리(data cleaning)*, *데이터 조작(data manipulating)*, *데이터 변형(data mutating)*, *셰이핑(shaping)*, *타이디(tidying)*, *먼징(munging)* 등이 있습니다. 보다 구체적으로 이러한 용어들은 Python이나 R과 같은 프로그래밍 언어를 사용하여 사용자의 요구 사항에 맞게 데이터셋을 업데이트하는 프로세스를 설명합니다.

###### 참고 (Note)

*타이디(tidy)* 데이터에는 두 가지 정의가 있습니다. 넓은 의미로 깔끔한(clean) 데이터를 나타냅니다. 좀 더 공식적으로, 해들리 위컴(Hadley Wickham)은 ["Tidy Data."](https://oreil.ly/tidy)라는 제목의 논문에서 이 용어를 정의합니다. 위컴은 *타이디 데이터*가 "(1) 각 변수가 열을 형성하고, (2) 각 관찰 단위가 행을 형성하며, (3) 각 관찰 단위 유형이 테이블을 형성하는" 특정 구조를 가진 것으로 정의합니다.

우리 경력을 통틀어 프로젝트에서 데이터 랭글링이 가장 많은 시간을 차지한다는 것을 알게 되었습니다. 예를 들어, 한 번은 우리 상사 중 한 명이 새로운 모델을 피팅하는 데 문제가 생겨서 Google 채팅으로 우리에게 메시지를 보낸 적이 있습니다. 확인해 보니 문제는 모델이 아니라 데이터 형식이었습니다. 모델과 작동하도록 데이터를 형식화하는 방법을 알아내는 데 약 30분이 걸렸습니다. 그러나 그가 겪고 있던 데이터 구조 문제를 파악한 후 R에서 새 모델을 실행하는 데는 약 30초밖에 걸리지 않았습니다.

###### 팁 (Tip)

컴퓨터 도구는 끊임없이 변화하며, 데이터 랭글링도 예외는 아닙니다. 리차드는 자신의 경력 동안 데이터 랭글링을 위한 4가지 도구를 배워야 했습니다. 기본 R(2007년경), R의 `data.table`(2012년경), R의 `tidyverse`(2015년경), 그리고 Python의 `pandas`(2020년경)입니다. 따라서 여러분도 이 책에서 가르치는 도구에 대한 기술 세트를 업데이트해야 할 것입니다. 그러나 기본을 이해하는 한 기초(fundamentals)는 절대 변하지 않습니다.

Python이나 R과 같은 프로그래밍 언어는 데이터를 사용 가능하게 만드는 데 가장 효과적인 도구입니다. 이 언어들은 스크립팅(scripting)을 허용하여 데이터에 오류가 유입되었는지 여부를 포함하여 변경 사항을 추적하고 수행한 작업을 확인할 수 있게 해줍니다.

많은 사람이 데이터 조작을 위해 Microsoft Excel이나 Google Sheets와 같은 스프레드시트 프로그램을 사용하는 것을 좋아합니다. 불행히도 이러한 프로그램은 변경 사항을 쉽게 추적하지 못합니다. 마찬가지로 손으로 데이터를 편집하는 것은 확장되지(scale) 않으므로 문제의 크기가 너무 커지면(예: 플레이당 초당 10~25회 횟수로 모든 선수에 대해 하나의 기록이 있는 선수 *추적 데이터(tracking data)* 로 작업하는 경우) 스프레드시트 환경에서 작동하는 워크플로를 빠르고 효율적으로 구축할 수 없습니다. 따라서 Excel을 사용하여 한두 개의 파일을 손으로 편집하는 것은 쉽지만 천 개나 이천 개의 파일을 손으로 편집하는 것은 쉽지 않습니다.

반대로 Python이나 R과 같은 프로그래밍 언어는 쉽게 확장(scale)할 수 있습니다. 예를 들어 매주 경기가 끝난 후 데이터 형식을 지정해야 하는 경우, Python이나 R은 데이터 파이프라인(data pipeline)의 일부로 쉽게 사용할 수 있지만 스프레드시트 기반 데이터 랭글링은 데이터 파이프라인으로 자동화하기 어려울 것입니다.

###### 참고 (Note)

*데이터 파이프라인(data pipeline)* 은 데이터가 한 위치에서 다른 위치로 이동하면서 서식 지정(formatting)과 같은 변경을 겪을 때 데이터의 흐름(flow of data)을 의미합니다. 예를 들어 에릭이 PFF에서 일할 때의 데이터 파이프라인은 주간 수치를 가져와 숫자의 형식을 지정하고 모델을 실행한 다음 보고서를 생성할 수 있었습니다. 컴퓨터 과학에서 *파이프(pipe)* 연산자는 한 함수의 출력을 다른 함수로 직접 전달하는 것을 의미합니다.

그렇긴 하지만 우리는 많은 사람이 익숙한 도구를 사용하는 것을 좋아한다는 점을 이해합니다. Excel과 같은 프로그램을 사용하다가 Python 또는 R로 전환하는 경우 한 번에 한 단계씩 전환하는 것을 권장합니다. 비유하자면, 요리사가 요리의 맛을 보기 위해 반죽 숟가락을 핥는 것을 생각해 보십시오. 집에서 가족을 위해 요리할 때 많은 사람이 이렇게 합니다. 하지만 레스토랑의 셰프가 숟가락을 핥고 재사용했다가는 해고당할 것입니다. 마찬가지로 취미로 하는 데이터 분석(recreational data analysis)의 경우 데이터를 편집하기 위해 Excel과 같은 프로그램을 합리적으로 사용할 수 있습니다. 그러나 전문적인 데이터 분석(professional data analysis)에서는 데이터를 랭글링(wrangle)하기 위해 코드를 사용해야 합니다.

###### 팁 (Tip)

이미 Excel과 같은 프로그램을 사용하고 있다면 Python이나 R에서 한 번에 한 단계씩 작업을 수행해 보는 것을 권장합니다. 예를 들어, 현재 Excel에서 풋볼 데이터의 형식을 지정하고, Excel에서 데이터를 시각화하고, Excel에서 선형 회귀 모델을 피팅한다고 가정해 보겠습니다. 다음에 데이터로 작업할 때는 Python이나 R에서 데이터를 시각화하는 것부터 시작하십시오. 요령을 터득한 후에는 Python이나 R에서 모델 피팅을 시작하십시오. 마지막으로 Python이나 R에서 데이터 형식을 지정하는 단계로 전환하십시오. 이러한 전환에 도움이 필요한 경우 조지 마운트(George Mount)가 쓴 <a href="https://learning.oreilly.com/library/view/advancing-into-analytics/9781492094333" class="orm:hideurl"><em>Advancing into Analytics: From Excel to Python and R</em></a> (O’Reilly, 2021)에서 자료를 제공합니다.

이 부록에서는 데이터 랭글링 외에도 몇 가지 기본 통계에 대해서도 알아봅니다. *통계(Statistics)* 는 사람에 따라 다른 의미를 갖습니다.

우리는 일상 업무(day jobs) 중에 이 단어가 네 가지 용도로 사용되는 것을 봅니다. 일반적으로 사람들은 이 단어를 가공되지 않은 데이터(raw data)나 객관적인 데이터를 가리킬 때 사용합니다. 예를 들어 패스 타깃이 된(targeted) 위치의 (*x*, *y*) 좌표를 해당 플레이의 *통계(stats)* 라고 부를 수 있습니다. 때로는 예상 추가 점수(expected points added, EPA)나 쿼터백이나 오펜스의 예상 완패 비율(completion percentage above expected)처럼 추정되는 것을 *통계(statistic)* 라고 할 수도 있습니다. 좀 더 공식적으로, *통계학(statistics)* 은 체계적인 데이터의 수집 및 분석을 의미할 수 있습니다. 예를 들어, 누군가 과학 실험의 일부로, 또는 데이터 과학을 활용하는 비즈니스 분석가로서 통계 분석(statistical analysis)을 실행할 수 있습니다. 마지막으로 데이터 수집 및 분석과 관련된 학문 분야를 *통계학(statistics)* 이라고 합니다. 예를 들어, 여러분은 고등학교에서 통계학 수업을 들었을 수도 있고 전문 통계학자로 일하는 사람을 알 수도 있습니다.

이 부록에서는 추정할 수 있는 요소(특히 요약 통계)로서의 *통계(statistic)* 사용에 중점을 두고, 통계를 사용하여 데이터를 요약하는 방법을 보여줍니다. 예를 들어 게임의 플레이 바이 플레이(play-by-play) 보고서를 모두 읽는 대신 게임의 요약 통계(summary statistics)를 보고 어떤 일이 있었는지 이해할 수 있을까요? 에릭은 업무상 모든 경기를 여러 번은 고사하고 한 번씩 시청할 시간조차 없으며, 각 경기의 플레이 바이 플레이 데이터를 수동으로 꼼꼼히 살펴볼 기회도 없습니다. 따라서 그는 일반적으로 효율적인 방법으로 추세(trends)가 나타나는 것을 파악하는 데 도움이 될 수 있는 *핵심 성과 지표(key performance indicators, KPIs)* 를 제공할 수 있는 시스템을 구축합니다. 요약 통계는 모델의 *특징(features)* 역할도 할 수 있습니다. 예를 들어, 누군가 특정 경기에서 쿼터백이 던질 터치다운 횟수에 베팅하고 싶다면 그가 한 경기에서 던진 평균 터치다운 패스 횟수가 매우 유용할 것입니다.

# 기본 통계 (Basic Statistics)

그리 매력적이지는 않지만, 기본 요약 통계는 데이터 분석과 많은 시각화 도표(plots)의 토대(foundation) 역할을 하기 때문에 종종 더 중요합니다.

## 평균 (Averages)

아마도 가장 간단한 통계는 숫자 집합의 *평균(average)* 이나 *산술 평균(mean)*, 또는 수학에 관심이 있는 사람들에게는 *기댓값(expectation)* 일 것입니다. 일반적으로 데이터셋의 *평균(average)* 에 대해 이야기할 때 데이터의 중심 경향(central tendency), 즉 데이터의 "균형을 맞추는(balances)" 값에 대해 이야기합니다. 다음 섹션에서 이 값들을 손으로 계산하는 방법을 보여 드리겠습니다.

네브래스카-링컨 대학교에서 에릭을 가르쳤던 데이브 로건(Dave Logan) 교수가 "대부분의 계산 세부 사항은 모든 사람의 일생에서 한 번은 수행되어야 하지만, 두 번은 수행해서는 안 된다"라고 말했던 것처럼, 우리는 이 섹션에 코드를 의도적으로 포함하지 않았습니다. 나중에 이 부록에서 Python 및 R을 사용하여 이를 계산하는 방법을 보여 드리겠습니다.

이 연습을 진행하기 위해 <a href="ch01.html#sec-introduction" data-type="xref">1장</a>에 표시된 것처럼 패스 플레이를 다시 탐색해 보겠습니다. 이번에는 쿼터백과 그의 팀이 패스 게임에 접근하는 방식을 이해하기 위해 쿼터백의 `air_yards`를 살펴보고 그 속성을 연구할 것입니다. 2020년 리차드가 가장 좋아하는 팀인 그린베이 패커스와 디비전 라이벌 중 하나인 디트로이트 라이언스 간의 경기 데이터를 사용하며, 디트로이트가 필드 중앙으로 향한 `air_yards` 수치를 가지는 플레이만 살펴볼 것입니다. <a href="#sec-apdx-filter-select" data-type="xref">"열 필터링 및 선택(Filtering and Selecting Columns)"</a>에서 이 데이터를 얻고 필터링하는 방법을 설명합니다. 작은 데이터셋을 살펴보면 손으로 쉽게 계산을 수행할 수 있습니다.

먼저 손으로 *산술 평균(mean)* 을 계산합니다. 에어 야드(air yards)는 5, -1, 5, 8, 5, 6, 1, 0, 16, 17입니다. 평균을 계산하려면 먼저 숫자를 모두 더합니다(*합(sum)*).

5 + -1 + 5 + 8 + 6 + 5 + 6 + 1 + 0 + 16 + 17 = 68

다음으로, 에어 야드가 있는 전체 플레이 수로 나눕니다.

``` math
\frac{68}{11} = 6\!.\! 2
```

이를 통해 2020년 디트로이트가 그린베이와의 첫 경기에서 필드 중앙으로 향한 평균 에어 야드가 6.2야드인 것으로 추정할 수 있습니다. 또한 결과를 6.2로 반올림했습니다. 평균 결과의 소수점이 끝나지 않고 데이터가 정수(integers)로 되어 있기 때문에 소수점 이하 첫 번째 자리까지만 알면 되므로 반올림해야 합니다. 좀 더 공식적으로, 이를 *유효 숫자(significant digits)* 또는 수치(figures)라고 합니다.

###### 팁 (Tip)

결과를 보고할 때 유효 숫자(Significant digits)는 중요합니다. 공식적인 규칙이 존재하지만, 대부분의 경우 잘 작동하는 경험 법칙(rule of thumb)은 유용한 자릿수만 보고하는 것입니다.

데이터 집합의 "중심(center)"을 추정하는 또 다른 방법은 중앙값을 조사하는 것입니다. *중앙값(median)* 은 단순히 가운데 숫자, 즉 평균값(average value)이 아닌 평균적인 개인(average individual)의 값을 의미합니다. 중앙값을 계산하려면 숫자를 가장 작은 것부터 가장 큰 것까지 순서대로 적은 다음 가운데 숫자를 찾거나 값이 짝수 개인 경우 가운데 두 숫자의 평균을 구합니다.

평균 숫자를 추정하는 마지막 일반적인 방법은 최빈값(mode)을 조사하는 것입니다. *최빈값(mode)* 은 데이터셋에서 가장 많이 나타나는 값입니다. 최빈값을 계산하려면 <a href="#tbl-mode" data-type="xref">표 B-1</a>과 같이 개수(counts)와 에어 야드(air yards)가 있는 표를 만들어야 합니다.

이 예시에서는 세 번의 관찰에서 5의 에어 야드 수치가 나왔기 때문에 5가 최빈값입니다. 데이터는 다봉형(multimodal, 최빈값이 여러 개)일 수 있습니다. 예를 들어, 두 결과가 동일한 빈도로 발생하면 이봉형(bimodal) 결과가 발생한 것입니다.

각 중심 경향 측정에는 장단점이 있습니다. 일련의 숫자들의 산술 평균(mean)은 이상치(outliers)에 크게 의존합니다. (*이상치(outliers)* 에 대한 공식적인 정의는 <a href="ch02.html#sec-boxplot" data-type="xref">"상자 수염 그림(Boxplots)"</a>을 참조하십시오). 이 글을 쓸 당시 연간 약 4,500만 달러를 버는 2022 NFL MVP 패트릭 마홈스(Patrick Mahomes)가 (2022년 기준 각각 207,000달러를 버는) 9명의 연습생 선수단 무리에 섞여 들어간다면, 그룹의 1인당 평균 연봉은 약 450만 달러가 되는데, 이는 이 그룹에 대해 어떤 것도 정확하게 나타내지 못합니다. 이 데이터셋의 중앙값과 최빈값은 마홈스가 포함되더라도 전혀 변하지 않습니다(207,000달러). 왜냐하면 중간 선수는 단지 반 자리만 밀려나고, 수치가 가장 높은 그룹은 연습생 연봉이기 때문입니다. 그렇긴 하지만, 그동안 구축된 이론적 수학의 상당 부분은 산술 평균에서 훨씬 더 잘 작동하며, 데이터 포인트가 데이터 집합의 중간 범위에서 벗어났다는 이유로 그 점들을 버리는 것도 좋은 관행은 아닙니다. 따라서 다른 모든 것과 마찬가지로 어떤 것을 사용해야 하는가에 대한 대답은 "상황에 따라 다르다(it depends)"입니다.

마지막으로, 다른 종류의 평균(means)도 존재하지만 이 책에서는 다루지 않습니다. 예를 들어 스포츠 베팅(또는 일반적인 금융 투자)에서는 앞서 계산한 산술 평균(arithmetic mean)보다 데이터셋의 기하 평균(geometric mean)을 더 중요하게 생각하는 경우가 많습니다. *기하 평균(geometric mean)* 은 단순히 데이터셋의 모든 숫자를 함께 곱한 다음 데이터셋의 요소 수에 해당하는 루트(root)를 취하여 계산합니다. 베팅이나 금융 시장에서 이것이 선호되는 이유는 분명합니다. 이 경우 숫자는 덧셈(additively)이 아니라 기하급수적으로(exponentially) 증가하거나 감소하기 때문입니다.

먼저 *mean* (온라인에서는 파란색)으로 표시된 선이 중앙값 (온라인에서는 빨간색) 오른쪽에 있다는 것을 알 수 있습니다. 이는 데이터가 왜곡(skewed)되었거나 오른쪽에 이상치가 있음을 의미합니다. 둘째, 이 예시에서는 중앙값이 최빈값(mode)과 같으므로 두 선이 겹칩니다. 우리를 포함한 대부분의 사람들은 일반적으로 mean을 *평균(average)* 이라고 부릅니다.

그렇다면 이것은 이 경기에서 디트로이트의 패스에 대해 무엇을 알려줄까요? 첫째, 산술 평균과 중앙값의 차이는 몇 개의 긴 패스를 제외하고는 많은 패스 플레이가 짧았음을 보여줍니다. 이 히스토그램은 데이터의 "모양"과 그것이 말해주는 경기 관련 스토리를 보여주며, 이는 아마 단순한 요약 통계보다 더 나을 것입니다. 이것이 데이터 크기에 따라 반드시 선형적으로 확장(scale up)되는 것은 아니지만, 작업을 시작할 때 데이터를 시각화하는 것이 항상 좋은 이유와 <a href="ch02.html#sec-EDA-stable" data-type="xref">2장</a>에서 탐색적 데이터 분석(EDA)의 일부로 시각화(plotting)를 다룬 이유를 잘 보여줍니다.

## 변동성 및 분포 (Variability and Distribution)

이전 섹션에서는 중심 경향을 다루었습니다. 그러나 많은 상황에서 데이터의 *변동성(variability)* 을 알아야 합니다. 데이터의 변동성을 조사하는 가장 쉬운 방법은 *범위(range)* 인데, 이는 데이터에서 가장 작은 숫자(최솟값 또는 min)와 가장 큰 숫자(최댓값 또는 max) 사이의 거리입니다. <a href="#tbl-mode" data-type="xref">표 B-1</a>에 표시된 데이터의 경우 최솟값은 –1이고 최댓값은 17이므로 범위는 17 - -1 = 17 + 1 = 18입니다.

데이터셋의 범위와 분포를 조사하는 또 다른 방법은 *분위수(quantiles)* 를 살펴보는 것입니다. 이는 분포의 특정 부분에 초점을 맞추며, 이를 사용하면 극단적인 이상치(severe outliers)의 영향을 피할 수 있습니다. $n$번째 분위수는 데이터의 *n%* 가 해당 데이터 포인트 아래에 있는 데이터 포인트입니다. 50번째 분위수는 중앙값과 같으므로 이전에 이미 이 중 하나를 살펴본 적이 있습니다. <a href="ch02.html#sec-boxplot" data-type="xref">"상자 수염 그림(Boxplots)"</a>에서는 분위수를 (구체적으로 상자 수염 그림의 맥락에서) 다루었습니다. 25번째, 50번째 및 75번째 분위수를 보통 *사분위수(quartiles)* 라고 하며 1사분위수와 3사분위수 사이의 차이를 *사분위수 범위(interquartile range, IQR)* 라고 합니다.

상자 수염 그림은 데이터의 중간 50%가 어디에 있는지 보여줍니다. 때로는 다른 유형의 분위수도 사용할 수 있습니다. 분위수의 이점은 이들이 중심 경향 이외의 추정된 끝점(end points)이라는 것입니다. 예를 들어 평균이나 중앙값을 사용하면 평균적인 선수의 성과를 조사할 수 있지만, 분위수를 사용하면 최고 수준의 선수가 얼마나 뛰어난지 조사할 수 있습니다(예를 들어, 다른 선수의 95%보다 더 뛰어나려면 어떤 성적이 필요한가?).

데이터셋의 변동성을 조사하는 가장 일반적인 방법은 분산(variance)과 그 제곱근인 *표준 편차(standard deviation)* 를 살펴보는 것입니다. 대략적으로 *분산*은 데이터 포인트와 평균 사이의 평균 제곱 편차(average squared deviation)입니다. 각 데이터 포인트와 평균 사이의 거리가 양수로 계산되도록 제곱을 사용합니다. 그래야 평균보다 낮고 높은 변동성이 "상쇄(cancel out)"되지 않기 때문입니다. 디트로이트 라이언스 에어 야드 예시를 사용하여 <a href="#tbl-var" data-type="xref">표 B-2</a>에 제공된 숫자로 이 계산을 수동으로 수행할 수 있습니다. ## 추정치의 불확실성 (Uncertainty Around Estimates)

사람들이 여러분에게 예측이나 요약을 제공할 때, 예측이나 요약에 얼마나 확신을 가질 수 있는지(how much certainty exists) 묻는 것은 합리적인 질문입니다. 종종 *SEM*, 또는 간단히 *SE(standard error)* 로 약칭되는 *평균의 표준 오차(standard error of the mean)* 를 사용하여 평균 주변의 불확실성을 보여줄 수 있습니다. 더 유익한 방법으로는 *신뢰 구간(confidence intervals, CIs)* 을 추정할 수 있습니다. 가장 일반적으로 사용되는 CI는 통계학의 역사적 관례에 따라 95%입니다. 관찰 프로세스를 아주 여러 번 반복하면 CI는 95%의 확률로 진짜 또는 올바른 추정치를 포함하게 됩니다. 세계관을 이러한 확률적 관점으로 받아들인다면, 여러분의 신뢰구간(CI)이 95%의 경우 평균을 포함할 것이라는 점은 알게 되지만, 그 95%가 정확히 언제일지는 모를 뿐입니다.

표준 오차는 표준 편차와 동일하지 않지만 관련이 있습니다. 전자는 모집단 평균의 추정치(estimate of the population’s mean)에 대한 변동성을 찾으려는 반면 후자는 모집단 자체의 변동성을 찾으려는 것입니다. 표준 편차에서 표준 오차를 계산하려면 표준 편차를 표본 크기의 제곱근으로 나누면 됩니다. 따라서 표본 크기 *n*이 커질수록 모집단 평균에 대한 추정치가 더 촘촘해지고(tighter) 표준 오차는 감소하는 반면 모집단의 변동성은 그동안 줄곧 일정하게(fixed) 유지됩니다.

신뢰 구간의 상한과 하한을 계산하려면 가이드로 *경험적 법칙(empirical rule)* 을 사용합니다. 경험적 법칙에 따르면 대략 68%의 데이터가 데이터의 표준 편차 1 이내에 있고, 95%가 표준 편차 2 이내에 있고, 99.7%가 3 이내에 위치합니다. 이러한 값은 분포에 따라 변경되고 정규 분포(종형 곡선이라고도 함)에서 가장 잘 작동하지만 상황에 관계없이 꽤 안정적입니다. 95% CI의 실제 값은 1.96입니다.

이전 예시를 계속 이어가서, 표준 오차를 계산해 봅시다. $7.41\,/\,\sqrt{77} = 0.84$. 따라서 평균을 8.03 ± 0.84(SE)로 쓰거나 95% CI를 사용하여 8.03 (95% CI 6.38 - 9.68)로 쓸 수 있습니다. 이는 8.03 ± 0.84 × 1.96 = 1.64로 계산됩니다.

###### 경고 (Warning)

기술적인 배경을 가진 청중에게 프레젠테이션할 때는 항상 평균과 같은 추정치 주변에 CI와 같은 불확실성을 포함하십시오. 아무런 조건이 없는(naked) 평균값을 제시하는 것은 독자가 추정치 주변에 얼마나 불확실성이 존재하는지 볼 수 없게 하므로 좋지 않은 형식으로 간주됩니다.

통계적 관례에 따라 95% CI를 비교하여 추정치가 다른지 검토할 수 있습니다. 예를 들어 95% CI가 0을 포함하지 않기 때문에 추정치 8.03(6.38 - 9.68 95% CI)은 0과 다릅니다. 따라서 통계적 불확실성을 고려할 때 2020년 2주차에 디트로이트 라이언스의 에어 야드가 0과 다르다고 말할 수 있습니다. 추정된 두 평균을 비교하는 경우 두 95% CI를 모두 비교할 수 있습니다. CI가 겹치지 않으면 산술 평균(means)이 통계적으로 다르다고 말할 수 있습니다.

###### 참고 (Note)

사람들은 관례상 5% / 95%를 사용합니다. 로널드 L. 바서스타인(Ronald L. Wasserstein) 등은 2019년 [*The American Statistician*](https://oreil.ly/k_83m) 사설에서 이에 대해 논의합니다. 이들의 사설은 통계적 추론(statistical inference)을 위한 대안적인 방법에 대해 많은 관점을 제시합니다.

###### 참고 (Note)

논리 연산자(Logic operators)는 단순히 명령문을 비교하고 이진 응답을 제공하는 컴퓨터 코드를 의미합니다. Python에서 논리 결과는 `True` 또는 `False`입니다. R에서 논리 결과는 `TRUE` 또는 `FALSE`입니다.

Python과 R은 데이터를 필터링하는 방식이 서로 다릅니다. 우리는 우리가 사용하는 도구에 초점을 맞췄지만 다른 유용한 접근 방식도 존재합니다. 예를 들어 `pandas` 데이터프레임에는 `.loc[]`보다 간결하기 때문에 우리가 즐겨 사용하는 `.query()` 함수가 있습니다. 그러나 `.query()`가 모든 상황에서 작동하는 것은 아니므로 일부 필터링에는 `.loc[]`가 필요합니다. 마찬가지로 R의 `tidyverse`에는 `filter()` 함수가 있습니다. 논리 연산자와 함께 이러한 함수를 사용할 수 있습니다.

R에서는 `filter()` 함수를 사용하여 이 작업을 수행할 수 있습니다. 두 개의 참(true)인 명령문은 *and* (`&`) 기호와 결합될 수 있습니다. 예를 들어 `home_team`으로 그린베이(`GB`)를 선택하고 어웨이 팀으로 디트로이트(`DET`)를 선택한 다음 `filter()` 함수와 함께 `home_team == 'GB' & away_team == 'DET'`를 사용합니다. 마찬가지로 `select()` 함수를 사용하면 필요한 열(columns)만 사용하여 더 작고 사용하기 쉬운 데이터프레임을 만들 수 있습니다.

```
## R
# 게임 데이터 필터링(Filter out game data)
gb_det_2020_r <-
    pbp_r |>
    filter(home_team == 'GB' & away_team == 'DET')

# 패스 데이터 선택(select pass data)
gb_det_2020_pass_r <-
    gb_det_2020_r |>
    select(posteam, yards_after_catch, air_yards,
           pass_location, qb_scramble)
```

Python은 `query()` 함수를 사용합니다. 입력에는 R과 달리 인용 부호(quotes) 세트가 필요합니다(예를 들어 `pandas`는 `"home_team == 'GB' & away_team == 'DET'"`를 사용함). 또한 `pandas`는 관심 있는 특정 열을 선택하기 위해 열 이름 리스트를 사용합니다.


# 요약 통계 제시에 대한 참고 사항 (A Note About Presenting Summary Statistics)

요약 통계를 제시하기 위한 핵심은 스토리를 효과적으로 전달하기 위해 활용 가능한 정보를 사용하는지 확인하는 것입니다. 먼저 대상 청중을 파악하는 것이 매우 중요합니다. 예를 들어 크리스 콜린스워스(Cris Collinsworth)와 그의 다음 *선데이 나이트 풋볼(Sunday Night Football)* 방송에 대해 이야기하거나(에릭이 이전 직장에서 했던 일) 경기 중에 술집에서 친구들과 이야기할 때는 정보를 다르게 제시할 것입니다.

게다가 NFL 팀의 연구 및 전략 디렉터(director of research and strategy)에게 당신의 작업을 프레젠테이션하는 경우 앞서 언급한 두 가지 예에서보다 다른 정보, 특히 더 많은 정보를 제공해야 할 것입니다. 마찬가지로 연구 및 전략 디렉터와 이야기할 때는 자신의 추정치와 방법론적 선택 모두를 정당화해야 할 가능성이 높습니다. 반대로 에릭, 리차드(또는 다른 퀀트(quants))와 맥주를 마시는 경우가 아니라면 맥주를 마시면서 모델링 선택에 대해 논의하지는 않을 것입니다!

*왜(why)* 가 핵심이며, 데이터에 파고들어 진정으로 그것을 잘 이해해야만 여러 가지 언어(다양한 방식)로 말할 수 있습니다. 예를 들어, 당신이 보고 있는 역동성(dynamic)은 커버리지의 차이 때문입니까, 와이드 리시버 때문입니까, 아니면 쿼터백의 근본적인 능력 변화 때문입니까?

둘째, 통계와 모델링을 스토리를 뒷받침(support)하는 데 사용하되 전체 스토리(entire story)로 사용하지 마십시오. "상황을 감안하더라도 드루 브리스(Drew Brees)는 여전히 풋볼에서 가장 정확한 패서입니다."라고 말하는 것이 "드루 브리스는 기대치를 상회하는 완료율이 가장 높습니다. 끝."이라고 말하는 것보다 낫습니다. 저자로서 우리는 사람들의 작업에 맥락(context)을 더하는 것이, 다른 많은 양적 분석가(quantitative people)들에 비해 최고의 양적 분석가가 눈에 띄는 데 도움이 된다는 사실을 알게 되었습니다. 실제로 숫자와 관련된 의사소통 기술(communication skills)은 우리 두 사람이 현재 직장을 구하는 데 도움이 되었습니다.

셋째, 한 장의 그림이 천 단어의 가치가 있을 수 있지만, 독자에게 그림을 설명해주십시오. 맥락 없는 그래프는 청중을 혼란스럽게 할 뿐이므로 아예 없는 것보다 못할 가능성이 높습니다. 비기술적인(nontechnical) 청중을 위해 그림을 포함하고 글에서 "평균"을 언급할 수 있습니다. 따라서 원시 요약 통계(raw summary statistics)는 글에 표시되지 않을 수도 있습니다. 기술적인(technical) 배경을 가진 청중에게는 하나 또는 두 개의 숫자에 대한 세부 정보와 불확실성을 텍스트에 포함하거나 더 많은 요약 통계의 경우 표 또는 보충 자료에 포함하십시오.

# 프레젠테이션 개선하기 (Improving Your Presentation)

우리는 요약 통계의 프레젠테이션을 개선할 수 있는 두 가지 좋은 방법을 찾았습니다. 첫째, 여러분에게 건설적인 피드백을 줄 사람들에게 일찍, 그리고 자주 프레젠테이션하십시오. 그들이 여러분의 메시지를 이해할 수 있는지 확인하고, 이해할 수 없다면 무엇이 명확하지 않은지 물어보고 여러분의 주장을 더 명확하게 전달할 방법을 찾으십시오. 예를 들어, 우리는 학생들에게 그림을 어떻게 설명할지 묻고 그들이 우리가 데이터에 대해 더 명확하게 생각하도록 돕기 때문에 학생들에게 강의와 세미나를 제공하는 것을 좋아합니다. 또한 고등학생이나 대학생에게 개념을 설명할 수 없다면 아이디어를 명확하게 이해하지 못한 것입니다.

둘째, 다른 사람의 작업을 살펴보십시오. 블로그, 다른 책, 기사를 읽고 팟캐스트를 보거나 들으십시오. 다른 사람의 예시를 보면 무엇이 명확하고 무엇이 그렇지 않은지 파악하는 데 도움이 될 것입니다. 가볍게 읽는 것(casual reading) 외에 비판적으로(critically) 읽으십시오. 무엇이 효과가 있을까요? 무엇이 효과가 없을까요? 저자가 그런 선택을 한 이유는 무엇일까요? 저자가 자신의 결과물을 더 잘 설명하도록 도우려면 어떻게 해야 할까요? 기회가 된다면 저자를 직접 만나거나 소셜 미디어에서 상호 작용할 때 그들에게 물어보십시오. 외교적인(diplomatic) 트윗은 대화를 시작할 가능성이 높습니다. 예를 들어, *금요일 경기에서 당신의 모델 결과와 그 모델이 준 통찰력이 마음에 듭니다. Y 대신 X를 사용한 이유는 무엇입니까?* 와 같이 트윗에 답글을 달 수 있습니다. 반대로, *당신 모델은 엉망이야, 당신은 내가 좋아하는 모델을 써야 해* 라고 트윗에 답글을 달면 무시당하거나 의미 없는 감정싸움(flame war)이 시작될 수 있으며 게시자(original poster)가 당신을 바라보는 시선뿐만 아니라 트윗을 읽는 다른 사람들의 시선도 깎아내릴 가능성이 높습니다.

# 권장 도서 (Suggested Readings)

통계 입문(introductory statistics)을 설명하는 책이 많이 있습니다. 통계에 대해 더 배우고 싶다면 자신에게 와닿는 책을 찾을 때까지 여러 권의 책의 처음 한두 장을 읽어보는 것을 권장합니다. 고려해 볼 만한 몇 권의 책은 다음과 같습니다.

- 조지 마운트(George Mount)의 <a href="https://learning.oreilly.com/library/view/advancing-into-analytics/9781492094333" class="orm:hideurl"><em>Advancing into Analytics: From Excel to Python and R</em></a> (O’Reilly, 2021). 이 책은 독자가 Excel을 잘 알고 있다고 가정하고 R이나 Python으로 전환하는 데 도움을 줍니다. 이 책은 통계의 기초를 다룹니다.

- 체스터 이스메이(Chester Ismay)와 알버트 Y. 김(Albert Y. Kim)의 *Statistical Inference via Data Science: A ModernDive into R and the Tidyverse* (CRC Press, 2019), 책의 홈페이지에서도 업데이트됨. 이 책은 R도 배우고자 하는 사람들을 위해 통계적 추론에 대한 강력한 소개를 제공합니다.

- 피터 브루스(Peter Bruce) 외 공저 <a href="https://learning.oreilly.com/library/view/practical-statistics-for/9781492072935" class="orm:hideurl"><em>Practical Statistics for Data Scientists</em>, 제2판</a> (O’Reilly, 2020). 이 책은 이미 어느 정도의 R이나 Python을 아는 사람들을 위해 통계에 대한 소개를 제공합니다.

- 피터 달가드(Peter Dalgaard)의 *Introductory Statistics with R* (Springer 2008)은 고전적인 책입니다. 코드의 경우 다소 오래되었지만 이 책은 리차드가 처음으로 통계(및 R)를 배울 때 사용한 책입니다.

- 토마스 닐드(Thomas Nield)의 <a href="https://learning.oreilly.com/library/view/essential-math-for/9781098102920" class="orm:hideurl"><em>Essential Math for Data Science</em></a> (O’Reilly, 2022)는 응용 데이터 과학자를 위한 수학과 통계에 대한 부드러운(gentle) 소개를 제공합니다.
