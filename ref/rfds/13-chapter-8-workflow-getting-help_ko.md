# 8장. 워크플로우: 도움 구하기(Workflow: Getting Help)

이 책은 고립된 섬이 아닙니다; 여러분이 R을 마스터할 수 있게 해주는 단일 자원은 없습니다. 이 책에 설명된 기술을 여러분 자신의 데이터에 적용하기 시작하면, 저희가 대답하지 않은 질문들을 곧 발견하게 될 것입니다. 이 섹션에서는 도움을 구하는 방법과 계속 학습하는 데 도움이 되는 몇 가지 팁을 설명합니다.

# 구글은 여러분의 친구입니다 (Google Is Your Friend)

막히면 구글(Google)로 시작하세요. 일반적으로 검색어에 "R"을 추가하면 관련 결과로 제한하기에 충분합니다. 검색이 유용하지 않다면 종종 R과 관련된 결과가 없다는 의미입니다. 또한 "tidyverse"나 "ggplot2" 같은 패키지 이름을 추가하면 여러분에게 더 친숙하게 느껴지는 코드로 결과를 좁히는 데 도움이 될 것입니다. 예를 들어 "how to make a boxplot in R(R에서 상자 그림 그리는 법)"과 "how to make a boxplot in R with ggplot2(ggplot2를 사용하여 R에서 상자 그림 그리는 법)"의 차이입니다. 구글은 오류 메시지(error messages)에 특히 유용합니다. 오류 메시지가 나타났는데 무슨 뜻인지 전혀 모르겠다면 구글에 검색해 보세요! 과거에 다른 누군가도 그 메시지로 혼란스러워했을 가능성이 높으며 웹 어딘가에 도움이 있을 것입니다. (오류 메시지가 영어가 아닌 경우 `Sys.setenv(LANGUAGE = "en")`을 실행한 다음 코드를 다시 실행하세요; 영어 오류 메시지에 대한 도움말을 찾을 가능성이 훨씬 더 높습니다.)

구글로 해결되지 않는다면 [Stack Overflow](https://oreil.ly/RxSNB)를 시도해 보세요. 질문과 답변을 R을 사용하는 것으로 제한하기 위해 `[R]`을 포함하여 기존 답변을 검색하는 데 먼저 약간의 시간을 투자하세요.

# reprex 만들기 (Making a reprex)

구글링을 해도 유용한 것을 찾지 못한다면, 최소한의 재현 가능한 예제(*min*imal *repr*oducible *ex*ample)의 줄임말인 *reprex*를 준비하는 것이 정말 좋은 생각입니다. 훌륭한 reprex는 다른 사람들이 당신을 돕기 더 쉽게 만들어주며, 종종 그것을 만드는 과정에서 스스로 문제를 파악하게 됩니다. reprex를 만드는 데는 두 가지 부분이 있습니다.

- 첫째, 코드를 재현 가능(reproducible)하게 만들어야 합니다. 이는 모든 것을 캡처해야 한다는 뜻입니다. 즉, <a href="https://rdrr.io/r/base/library.html" class="orm:hideurl"><code>library()</code></a> 호출을 포함하고 필요한 모든 객체를 생성해야 합니다. 이 작업을 확실히 했는지 확인하는 가장 쉬운 방법은 reprex 패키지를 사용하는 것입니다.

- 둘째, 그것을 최소한(minimal)으로 만들어야 합니다. 당신의 문제와 직접적으로 관련되지 않은 모든 것을 제거하세요. 여기에는 보통 실생활에서 직면하는 것보다 훨씬 작고 단순한 R 객체를 생성하거나 내장(built-in) 데이터를 사용하는 것이 포함됩니다.

매우 많은 작업처럼 들릴 수 있습니다! 그리고 그럴 수도 있지만 큰 보상이 따릅니다.

- 80%의 경우, 훌륭한 reprex를 만드는 과정에서 문제의 원인이 드러납니다. 모든 것을 포함하는 최소한의 예제를 작성하는 과정에서 스스로 자신의 질문에 대답할 수 있게 되는 경우가 얼마나 잦은지 놀라울 정도입니다.

- 나머지 20%의 경우, 문제의 핵심을 다른 사람들이 다뤄보기 쉬운 방식으로 포착하게 될 것입니다. 이는 도움을 받을 가능성을 상당히 높여줍니다!

수작업으로 reprex를 만들 때 무언가를 우연히 놓치기 쉽고, 이는 다른 사람의 컴퓨터에서 당신의 코드를 실행할 수 없음을 의미합니다. tidyverse의 일부로 설치되는 reprex 패키지를 사용하여 이 문제를 피하세요. 클립보드에 이 코드를 복사(또는 RStudio Server나 Cloud에서는 선택)한다고 가정해 봅시다.

```
y <- 1:4
mean(y)
```

그런 다음 `reprex()`를 호출하면 기본 출력이 GitHub용으로 포맷팅됩니다.

```
reprex::reprex()
```

RStudio에 있는 경우 RStudio의 뷰어(Viewer)에 멋지게 렌더링된 HTML 미리보기가 표시되며, 그렇지 않은 경우 기본 브라우저에 표시됩니다. reprex는 자동으로 클립보드에 복사됩니다(RStudio Server나 Cloud에서는 이를 직접 복사해야 합니다):

    ``` r
    y <- 1:4
    mean(y)
    #> [1] 2.5
    ```

이 텍스트는 Markdown이라는 특별한 방식으로 포맷팅되어 있으며, StackOverflow나 GitHub 같은 사이트에 붙여넣을 수 있고 자동으로 코드처럼 보이도록 렌더링됩니다. GitHub에서 렌더링될 Markdown의 모습은 다음과 같습니다.

```
y <- 1:4
mean(y)
#> [1] 2.5
```

다른 누구든지 이것을 즉시 복사하여 붙여넣고 실행할 수 있습니다.

예제를 재현 가능하게 만들려면 필수 패키지, 데이터, 코드의 세 가지를 포함해야 합니다.

- *패키지(Packages)*는 예제에 어떤 패키지가 필요한지 쉽게 볼 수 있도록 스크립트 상단에서 로드되어야 합니다. 이때 각 패키지의 최신 버전을 사용하고 있는지 확인하는 것이 좋습니다; 패키지를 설치하거나 마지막으로 업데이트한 이후에 수정된 버그를 발견했을 수도 있기 때문입니다. tidyverse의 패키지의 경우, 가장 쉬운 확인 방법은 `tidyverse_update()`를 실행하는 것입니다.

- *데이터(data)*를 포함하는 가장 쉬운 방법은 <a href="https://rdrr.io/r/base/dput.html" class="orm:hideurl"><code>dput()</code></a>을 사용하여 데이터를 다시 만드는 데 필요한 R 코드를 생성하는 것입니다. 예를 들어 R에서 `mtcars` 데이터셋을 다시 만들려면 다음 단계를 수행하세요.
  - R에서 `dput(mtcars)`를 실행합니다.
  - 출력을 복사합니다.
  - reprex에서 `mtcars <-`를 입력한 다음 붙여넣습니다.

  문제를 여전히 드러낼 수 있는 가장 작은 데이터 부분 집합(subset)을 사용하려고 노력하세요.

- 다른 사람들이 코드를 읽기 쉽도록 *코드(code)*를 정리하는 데 약간의 시간을 투자하세요.
  - 공백을 적절히 사용하고 변수 이름이 간결하면서도 정보를 주는지 확인하세요.

  - 주석(comments)을 사용하여 문제가 어디에 있는지 나타내세요.

  - 문제와 관련 없는 모든 것을 제거하기 위해 최선을 다하세요.

  코드가 짧을수록 이해하기 쉽고 수정하기도 쉽습니다.

새 R 세션을 시작하고 스크립트를 복사하여 붙여넣음으로써 실제로 재현 가능한 예제를 만들었는지 확인하는 것으로 마무리하세요.

reprex를 만드는 것은 간단한 일이 아니며 훌륭하고 진정으로 최소한인 reprex를 만드는 방법을 배우려면 약간의 연습이 필요할 것입니다. 하지만 코드가 포함된 질문을 하는 법을 배우고 재현 가능하게 만드는 데 시간을 투자하는 것은 R을 배우고 마스터해 나가는 동안 계속해서 보상을 줄 것입니다.
