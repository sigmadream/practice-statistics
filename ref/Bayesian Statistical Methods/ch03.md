Computing is a key ingredient to any modern statistical application and a Bayesian analysis is no different. As of the late 1980's, the application of Bayesian methods was limited to small problems where conjugacy ([Section 2.1](./10-chapter2.md#sec2_1)) led to a simple posterior or the number of parameters was low enough to permit numerical integration (e.g., [Section 3.1.2](./11-chapter3.md#sec3_1_2)). However, with the advent of Markov Chain Monte Carlo (MCMC) methods (which were developed in the 1950s through 1970s), the popularity of Bayesian methods exploded as it became possible to fit realistic models to complex data sets. This chapter is dedicated to the core Bayesian computational tools that led to this resurgence.

Bayesian methods are often associated with heavy computing. This is not an inherent property of the Bayesian paradigm. Bayesian computing is designed to estimate the posterior distribution, which is analogous to a frequentist estimation of the sampling distribution. Both problems are challenging, but frequentists often make use of large-sample normal approximations to simplify the problem. There is nothing to prohibit a Bayesian from making similar approximations, and this is the topic of [Section 3.1.3](./11-chapter3.md#sec3_1_3). However, these approximations are not common because MCMC produces much richer output, and the accuracy of the approximation is not limited by the sample size of the data, but rather the MCMC approximation can be made arbitrarily precise even for non-Gaussian posteriors by increasing the computational effort.

66\. Bayesian computation boils down to summarizing a high-dimensional posterior distribution ([Section 1.4](./09-chapter1.md#sec1_4)). In this chapter we cover methods that span the spectrum from summaries that are fast to compute (e.g., MAP estimation) but produce only a point estimate to slower methods (e.g., MCMC) that permit full uncertainty quantification. Just as a user of maximum likelihood analysis need not be an expert on the theory and practice of iteratively reweighted least squares optimization, there is software ([Section 3.3](./11-chapter3.md#sec3_3)) available to implement most Bayesian analyses without the user possessing a deep understanding of the algorithms being used under the hood. However, at a minimum, the user should have sufficient understanding of the underlying algorithms to properly inspect the output to determine if it is sensible. In [Sections 3.1](./11-chapter3.md#sec3_1) and [3.2.1](./11-chapter3.md#sec3_2_1), we outline the fundamental algorithms used in Bayesian computing and work through a few small examples for illustration. However, for the remainder of the book, we will use the JAGS package introduced in [Section 3.3](./11-chapter3.md#sec3_3) for computation to avoid writing MCMC code.

## 3.1 Deterministic methods

### 3.1.1 Maximum a posteriori estimation

Most of the computational methods discussed in this chapter attempt to summarize the entire posterior distribution. This allows for full quantification of uncertainty about the parameters and leads to inferences such as the posterior probability that a hypothesis is true. However, summarizing the full posterior distribution can be difficult and in some settings unnecessary. For example, in machine-learning, statistical estimation is used as a filtering process where the sole purpose is prediction of future values using estimates from the current data; accounting for uncertainty and accessing statistical significance are not high priorities. In this case, a single point estimate may be a sufficient summary of the posterior.

The MAP ([Section 1.4.1](./09-chapter1.md#sec1_4_1)) point estimator is

θ^MAP\=argmaxθlog\[p(θ|Y)\]\=argmaxθlog\[f(Y|θ)\]+log\[π(θ)\].(3.1)

The MAP estimator requires optimization of the posterior, unlike the posterior mean which requires integration. Typically optimization is faster than integration, especially in high-dimensions, and therefore MAP estimation can be applied even to hard problems.

The MAP solution can be found using calculus or numerical optimization \[[117](./19-ref01.md#refbib117)\]. The simplest optimization algorithm is gradient ascent (or gradient descent to minimize a function), which is an iterative algorithm that begins with an initial value θ(0) and updates the parameters at iteration _t_ using the rule

θ(t)\=θ(t−1)+γ∇(θ(t−1)),

where the step size _γ_ is a tuning parameter and the gradient vector of the log posterior is ∇(θ)\=\[∇1(θ),...,∇p(θ)\]T for

∇j(θ)\=∂∂θj{log\[f(Y|θ)\]+log\[π(θ)\]}.

67\. This step is repeated until convergence, i.e., θ(t)≈θ(t−1). Gradient ascent is most effective when the posterior is convex, and typically requires several starting values to ensure convergence.

There is a rich literature on optimization in statistical computing. Some other useful methods include Newton's method, the expectation-maximization (EM) algorithm, the majorize-minimization (MM) algorithm, genetic algorithms, etc. R has many optimization routines including the general-purpose algorithm optim, as illustrated in [Listing 3.1](./11-chapter3.md#list3_1) and [Figure 3.1](./11-chapter3.md#fig3_1) for the model Yi|μ,σ∼iid Normal(μ,σ2) with priors μ∼Normal(0,1002) and σ∼Unif(0,10) and data Y\=(2.68,1.18,−0.97,−0.98,−1.03).

### 3.1.2 Numerical integration

Many posterior summaries of interest can be written as _p_\-variate integrals over the posterior, including the posterior means, covariances and probabilities of hypotheses. For example, for _θ_1, the marginal posterior mean, variance and probability that _θ_1 exceeds constant _c_ are

E(θ1|Y)\=∫θ1p(θ|Y)dθVar(θ1|Y)\=∫\[θ1−E(θ1|Y)\]2p(θ|Y)dθProb(θ1\>c|Y)\=∫c∞∫...∫p(θ|Y)dθ1dθ2,...,dθp.(3.2)

68\. 69\. If these summaries are sufficient to describe the posterior, then numerical integration can be used for Bayesian computing.

All of the summaries in (3.2) can be written as E\[g(θ)\] for some function _g_, e.g., Prob(θ1\>c|Y) uses g(θ)\=I(θ1\>c) where I(θ1\>c)\=1 if θ1\>c and zero otherwise. Assume that a grid of points θ1∗,...,θm∗ covers the range of θ with non-zero posterior density. Then

E\[g(θ)\]\=∫g(θ)p(θ|Y)dθ≈∑j\=1mg(θj)Wj(3.3)

where _W_ _j_ is the weight given to grid point _j_. To approximate the posterior mean of g(θ) the weights should be related to the posterior PDF Dj\=f(Y|θj∗)π(θj∗). The normalizing constant m(Y) cannot be computed and so the posterior is normalized at the grid points as Wj\=Dj/∑l\=1mDl.

This provides a very simple approximation to the posterior of θ. Of course, more precise numerical integration can be used, including those in the R function adaptIntegrate as illustrated in [Listing 3.1](./11-chapter3.md#list3_1) and [Figure 3.1](./11-chapter3.md#fig3_1). However, we do not focus on these methods because they do not scale well with the number of parameters, _p_. For example, if we use a grid of 20 points for each of the p\=10 parameters, then there are m\=2010 points in the expanded grid, which is over a trillion points!

### 3.1.3 Bayesian central limit theorem (CLT)

The central limit theorem states that the sampling distribution of the sample mean for a large sample is approximately normal even for non-Gaussian data. This can be extended to the sampling distribution of the MLE. Many frequentist standard error and p-value computations rely on the approximation

θ^MLE∼Normal(θ0,Σ^MLE),(3.4)

where θ0 is the true value and the p×p covariance matrix Σ^MLE\=(−H)−1 and the (j,k) element of the Hessian matrix **H** is

∂2∂θj∂θklog\[f( Y|θ)\]|θ\=θ^MLE.(3.5)

To define the analogous Bayesian approximation, suppose that Yi|θ∼indepf(Yi|θ) for i\=1,...,n and θ∼π(θ). Under general conditions (see [Section 9.2.2](./17-chapter9.md#sec9_2_2)), for large _n_ the posterior is approximately

θ|Y∼Normal(θ^MAP,Σ^MAP)(3.6)

where Σ^MAP\=(−H)−1 is defined the same way as Σ^MLE except that the Hessian **H** is

∂2∂θj∂θklog\[p(θ|Y)\]|θ\=θ^MAP,(3.7)

which will be similar to Σ^MLE for large samples. Of course, this is not appropriate if the parameters are discrete, but the Bayesian CLT can still be used in some cases where the observations are dependent.

70\. For example, consider the beta-binomial model Y|θ∼Binomial(n,θ) with Jeffreys prior θ∼Beta(1/2,1/2). The MAP estimate is θ^MAP\=A/(A+B), and the approximate posterior variance is

\[Aθ^MAP2+B(1−θ^MAP)2\]−1,

where A\=Y−0.5 and B\=n−Y−0.5. Of course, there is no need for an approximation in this simple case because the exact posterior is θ|Y∼Beta(Y+1/2,n−Y+1/2), but [Figure 3.2](./11-chapter3.md#fig3_2) illustrates that the Gaussian approximation works well for large _n_.

![Three panels compare Exact C L T and M A P posterior curves for theta. For Y equal to 3 n equal to 10 the curves peak near 0.3 with small shape differences. For Y equal to 9 n equal to 30 they align more closely. For Y equal to 30 n equal to 100 they almost coincide in a very narrow peak near 0.3.](./images/fig3_2.jpg)

Figure 3.2 **Illustration of the Bayesian CLT.** The exact Beta(Y+1/2,n+1/2) posterior versus the Gaussian approximation for the model Y|θ∼Binomial(n,θ) with prior θ∼Beta(1/2,1/2) for various _Y_ and _n_. [Return to text.⏎](chapter3)

As discussed in [Section 3.1.1](./11-chapter3.md#sec3_1_1), if the prior is uninformative, then the MAP and MLE estimates are similar, and these approximations suggest that the entire posterior will be similar. This is the first glimpse at a recurring theme: Bayesian and maximum likelihood methods give similar results for large sample sizes irrespective of the prior.

Advantages of the Bayesian CLT approximation are that it replaces integration ([Section 3.1.2](./11-chapter3.md#sec3_1_2)) with differentiation, and is thus easier to compute, especially for large _p_, and the method is deterministic rather than stochastic. A disadvantage is that approximation may not be accurate for small or even moderate sample sizes. However, more elaborate approximation methods have been proposed that combine numerical integration with Gaussian approximations, such as the Integrated Nested Laplace Approximation (INLA) of \[[135](./19-ref01.md#refbib135)\] ([Appendix A.4](./18-appA.md#secA_4)). Alternatively, in variational Bayesian inference \[[85](./19-ref01.md#refbib85)\] the user postulates a parametric (potentially non-Gaussian) posterior distribution and then solves for the parameters in the postulated posterior that give the best approximation to the true posterior.

### 3.1.4 Variational Bayesian (VB) Methods

The normal approximation to the joint posterior distribution motivated by the Bayesian CLT is ideal when the sample size (_n_) is large and the model size (_p_) is small and fixed. Under these conditions, the approximation is theoretically justified and computationally efficient. However, for small sizes and/or large models, the posterior may not be well approximated by a normal distribution leading to poor performance. Further, for large models the approximate posterior covariance Σ^MAP is slow to compute because there are on the order of _p_2 elements to be computed; if p\=1,000 then Σ^MAP has 500,500 distinct elements.

71\. Variational Bayesian (VB) approximations address both of these limitations and have thus emerged as one of the leading computational methods for high-dimensional problems. As with the Bayesian CLT approximation, VB presumes the posterior resides in a parametric family of distributions. However, this distribution need not be Gaussian or even the same family for all parameters; e.g., it may be presumed that the posterior of a variance parameter follows a gamma distribution and a mean parameter follows a normal distribution. To avoid computing posterior covariance terms, it can be presumed that some or all parameters are independent in the posterior. These assumptions can lead to massive computational savings but should be applied carefully because gross violations lead to poor performance.

A VB analysis begins by specifying a variational posterior. The variational posterior is the parametric family of distributions that is assumed to include a good approximation to the true posterior. Denote the variational posterior density function as q(θ|v), where v\=(v1,...,vq) are the variational parameters. For example, if there is a single parameter _θ_ with support \[0,1\], then we might select q(θ|v) to be the Beta(v1,v2) PDF and assume that for some value of v\=(v1,v2), p(θ|Y)≈q(θ|v).

The assumption that the posterior resides in a parametric family, _q_, simplifies the problem down to finding the values of the variational parameters, **v**, that give a close approximation. These parameters are chosen to minimize the discrepancy between the variational and true posterior distributions. This requires a measure of the similarity between two distributions, and typically the Kullback–Leibler divergence (KLD) is used ([Figure 3.3](./11-chapter3.md#fig3_3)). The KLD is the

KLD(v)\=Eq\[log{q(θ|v)p(θ|Y )}\]\=∫log{q(θ|v)p(θ|Y)}q(θ|v)dθ.(3.8)

Figure 3.3 **Illustration of the Kullback–Leibler divergence (KLD)** The KLD between the (hypothetical) true posterior (solid line) and the three beta distributions (dashed lines) are 0.74 for Beta(6,3), 0.31 for Beta(60,30) and 0.08 for Beta(55,33). [Return to text.⏎](chapter3)

The KLD is non-negative for any **v** and equals zero if the approximation is perfect and q(θ|v)\=p(θ|Y) for all θ. The VB approximation selects **v** to minimize KLD(v).

Similar to selecting a prior distribution, there is no single correct variational posterior family (with the trivial exception of the true posterior distribution), but families with the same support as the parameters are a good starting place. Especially for high-dimensional problems, postulating a variational distribution that captures the dependence between parameters is difficult, and so the mean-field approximation that assumes the posterior distributions of the parameters are independent is appealing,

q(θ|v)\=∏j\=1pqj(θj|vj).

Finding the optimal **v** requires computing or approximating the integral in (3.8) and then optimizing it with respect to **v**. In some cases, the integral can be solved analytically using similar techniques to find conjugate priors in Chapter 2.1, in others numerical approximation is required (using algorithms mentioned in [3.1.2](./11-chapter3.md#sec3_1_2)). Optimization can also achieved analytically in small problems and numerically (using algorithms mentioned in [Section 3.1.1](./11-chapter3.md#sec3_1_1)) in most cases. Conjugate gradient descent which optimizes over single elements of **v** in sequence is often used when **v** is high-dimensional.

## 3.2 Stochastic methods

Monte Carlo (MC) methods are appealing to statisticians because they mirror the fundamental statistical concept of using a sample to make inferences about a population. A canonical problem in statistics is to estimate a summary of the population, such as the population mean or standard deviation. In most cases (i.e., not a census) we cannot observe the entire population to compute the mean or standard deviation directly, so instead we take samples and use them to make inferences about the population. For example, we use the sample mean to approximate the population mean, and, assuming the sample is sufficiently large, the law of large numbers guarantees the approximation is reliable.

MC sampling from the posterior works the same way. In this analogy, the population of interest is the posterior distribution. We would like to summarize the posterior using its mean and variance, but in most cases these posterior summaries cannot be computed directly, and so we take a sample from the posterior and use the MC sample mean to approximate the posterior mean and the MC sample variance to approximate the posterior variance. Assuming the MC sample is sufficiently large, then the approximation is reliable. This holds for virtually any posterior distribution and any summary of the posterior, even those that are high-dimensional integrals.

Assume that we have generated _S_ posterior samples, θ(1),...,θ(S)∼p(θ|Y), where sample _s_ is θ(s)\=(θ1(s),...,θp(s)). These draws can be used to approximate any posterior summary discussed in [Section 1.4](./09-chapter1.md#sec1_4). For a univariate model with p\=1, we could approximate the posterior density with a histogram of the _S_ samples, the posterior mean with the MC sample mean E(θ1|Y)≈∑s\=1Sθ1(s)/S, the posterior variance with the MC sample variance 74\. Figure on this page. 75\. of the _S_ samples, the probability that θ1\>0 with the MC sample proportion with θ1(s)\>0, etc.

To illustrate convergence of MC sampling, consider the Poisson-gamma model Y|θ∼Poisson(Nθ) with prior θ∼Gamma(a,b). The posterior is then θ|Y∼Gamma(Y+a,N+b). [Figure 3.6](./11-chapter3.md#fig3_6) assumes N\=10, Y\=8 and a\=b\=0.1 and plots the approximate posterior mean and probability that θ\>0.5 as a function of the number of MC iterations. The sample mean and proportion are noisy for a small number of MC samples, but as the number of samples increases, they converge to the true posterior mean and probability that θ\>0.5.

For multivariate models with p\>1 parameters, the samples θj(1),...,θj(S) follow the marginal posterior distribution of _θ_ _j_, p(θj|Y). Critically, we do not need to analytically integrate p(θj|Y)\=∫f(θ|Y)dθ1...dθj−1dθj+1...dθp. Because each sample consists of a random draw from all parameters, MC sampling automatically produces samples from the marginal distribution _θ_ _j_ accounting for uncertainty in the other parameters.

In addition to the marginal distribution, MC sampling can be used to approximate the posterior of parameters defined as transformations of the original parameters. For example, we can approximate the posterior of γ\=g(θ1) for a function _g_ using the MC samples γ(1),...,γ(S) where γ(s)\=g(θ1(s)); that is, we simply transform each sample, and these transformed samples approximate the posterior distribution of _γ_. The posterior of the transformed parameter is summarized like any other, e.g., E(γ|Y)≈∑s\=1Sγ(s)/S. As another example, say we want to test if Δ\=θ1−θ2\>0. The posterior of Δ is approximated by the _S_ samples Δ(s)\=θ1(s)−θ2(s), and thus Prob(Δ\>0|Y) is approximated using the proportion of the _S_ samples for which Δ(s)\>0.

Once we have posterior samples, summarizing the posterior or even complicated functions of the posterior is straightforward, and this is one of the appeals of MC sampling. However, generating valid samples from the posterior distribution is not always straightforward.

### 3.2.1 76\. MCMC sampling

We will focus on two sampling algorithms: Gibbs sampling and Metropolis–Hastings sampling. Gibbs sampling is preferred when it is possible to directly sample from the conditional distribution of each parameter. Metropolis–Hastings is a generalization to more complicated problems. We also briefly mention other more advanced algorithms in [Appendix A.4](./18-appA.md#secA_4) including delayed rejection and adaptive Metropolis (DRAM), the Metropolis-adjusted Langevin algorithm, Hamiltonian MC (HMC) and slice sampling.

#### 3.2.1.1 Gibbs sampling

As a motivating example, consider the Gaussian model

Y1,...,Yn|μ,σ2∼iid Normal(μ,σ2)(3.11)

where the priors are μ∼Normal(γ,τ2) and σ2∼InvGamma(a,b). To study the posterior of θ\=(μ,σ2) we would like to make _S_ draws from the joint posterior distribution p(θ|Y). [Section 2.1.3](./10-chapter2.md#sec2_1_3) provides a means to sample from the posterior of _μ_ with _σ_2 assumed known since μ|σ2,Y follows a Gaussian distribution, and [Section 2.1.4](./10-chapter2.md#sec2_1_4) provides a means to sample from the posterior of _σ_2 with _μ_ assumed known since σ2|μ,Y follows an inverse gamma distribution. Gibbs sampling generates draws from the desired joint posterior of θ using only these univariate conditional distributions.

Gibbs sampling (proposed by \[[59](./19-ref01.md#refbib59)\]) begins with initial values for both parameters and proceeds by alternating between sampling μ|σ2,Y and then sampling σ2|μ,Y until _S_ samples have been collected (for an extensive discussion about selecting _S_, see [Section 3.4](./11-chapter3.md#sec3_4)). For example, we might begin by setting _μ_ to the sample mean of **Y** and _σ_2 to the sample variance of **Y** (for an extensive study of initialization, see [Section 3.4](./11-chapter3.md#sec3_4)). Implementing successive steps requires deriving the full conditional posterior distributions, i.e., the distribution of one parameter conditioned on the data and all other parameters. Following [Section 2.1.3](./10-chapter2.md#sec2_1_3) and [2.1.4](./10-chapter2.md#sec2_1_4) (with slight modification to the prior distributions), the full conditional posterior distributions are

Before continuing with other examples, we pause and discuss the theoretical properties of this algorithm. Why does it work? That is, why does repeated sampling from full conditional distributions lead to samples from the joint posterior distribution? Surely we cannot trust that the initial value is a sample from the posterior because it is selected subjectively by the user. It would also be dangerous to trust that the first random sample follows the posterior distribution because it depends on the initial values, which might be far from the posterior. [Appendix A.3](./18-appA.md#secA_3) provides an argument using stochastic process theory that (1) under general conditions, the samples produced by the algorithm converge to the posterior distribution for any choice of initial values, and (2) once a sample is drawn from the posterior, all subsequent samples are also samples from the posterior.

The theoretical convergence arguments dictate how Gibbs sampling is used in practice. The user follows the chain until it has converged, and discards all previous samples from this burn-in period. Convergence is often assessed by visual inspection of the trace plots (i.e., the a plot of the samples by iteration number), but formal measures are available ([Section 3.4](./11-chapter3.md#sec3_4)). All remaining samples are used to summarize the posterior. It is important to remember that unlike other optimization algorithms, we do not expect Gibbs sampling to converge to a single optimal value. Rather, we hope that after burn-in the algorithm produces samples from the posterior distribution. That is, we hope the samples generated by the algorithm converge in distribution to the posterior, and do not get stuck in one place. [Figure 3.8](./11-chapter3.md#fig3_8) provides idealized output where convergence clearly occurs around iteration 1000 for both parameters and the remaining samples consistently draw from the same distribution after this point and thus the trace plot resembles a “bar code” or “caterpillar.”

**Bivariate normal example**: We will use Gibbs sampling to make draws from posterior distributions, but in fact it can be used to sample from any distribution (so long as we can sample from the full conditional distributions). For example, say θ\=(U,V) is bivariate normal with mean zero and variance 1 for both parameters and correlation _ρ_ between the parameters. This is not a posterior distribution because we are not conditioning on data, but in this toy example we are using Gibbs sampling to draw from this bivariate normal distribution to get a feel for the algorithm and how it converges to the target distribution. As given in (1.26) (see [Figure 1.7](./09-chapter1.md#fig1_7)), the full conditional distributions are U|V∼Normal(ρV,1−ρ2) and V|U∼Normal(ρU,1−ρ2). Given initial values (U(0),V(0)), the first three iterations are:

* 1aDraw U(1)|V(0)∼Normal(ρV(0),1−ρ2)
* 1bDraw V(1)|U(1)∼Normal(ρU(1),1−ρ2)
* 2aDraw U(2)|V(1)∼Normal(ρV(1),1−ρ2)
* 2b80\. Draw V(2)|U(2)∼Normal(ρU(2),1−ρ2)
* 3aDraw U(3)|V(2)∼Normal(ρV(2),1−ρ2)
* 3bDraw V(3)|U(3)∼Normal(ρU(3),1−ρ2).

The algorithm continues until _S_ draws have been made.

It can be shown that the distribution after _s_ iterations is

U(s)∼Normal(ρ2s−1V(0),1−ρ4s−2).

The true marginal distribution of _U_ is Normal(0,1), and since ρ2s−1≈0 and ρ4s−2≈0 for large _s_, for any initial value the MCMC posterior is very close but never exactly equal to the true posterior. Convergence is immediate if ρ\=0 and slow if |ρ|≈1, illustrating how cross-correlation between parameters can hinder MCMC convergence (e.g., [Figure 3.11](./11-chapter3.md#fig3_11) and the discussion of blocked Gibbs sampling below). Nonetheless, for any _ρ_ and large _S_ the approximation is surely sufficient and can be made arbitrarily precise by increasing _S_.

Yi|λi∼indepPoisson(Nλi) λi|γ∼indepGamma(1,γ) γ∼Gamma(a,b)(3.12)

The Gibbs sampler requires the full conditional posterior for each of the five parameters. We first compute the full conditional of _λ_1 given all the other parameters. For this computation, we only need to consider terms that depend on _λ_1, and all other terms can be absorbed in the normalizing constant. For _λ_1 this gives

p(λ1,|λ2,λ3,λ4,γ,Y)∝f(Y1|λ1)π(λ1|γ).(3.14)

p(γ|λ1,λ2,λ3,λ4,Y)∝\[∏i\=14π(λi|γ)\]π(γ).(3.15)

Gibbs sampling has trouble when parameters have strong posterior dependence. To see this, consider the hypothetical example plotted in [Figure 3.11](./11-chapter3.md#fig3_11). #### 3.2.1.2 86\. Metropolis–Hastings (MH) sampling

Each step in Gibbs sampling requires taking a sample from the full conditional distribution of one parameter (or block of parameters) conditional on all other parameters. In the examples in the previous section, all priors were conditionally conjugate, and so we were able to show that the full conditionals were members of familiar families of distributions, and therefore sampling was straightforward. However, it is not always possible to specify a conditionally conjugate prior.

For example, returning to the NFL concussion data ([Figure 3.12](./11-chapter3.md#fig3_12)), suppose we select the model

Yi|β∼Poisson\[Nexp(β1+β2i)\](./3.16)

for year i\=1,...,4 so that the log concussion rate changes linearly in time. The likelihood is then

f(Y|β)∝∏i\=14exp\[−Nexp(β1+β2i)\]exp\[Yi(β1+β2i)\].(3.17)

The parameters appear in the exponential within another exponential, and there is no well-known family of distributions for β with this feature. Therefore, the posterior will not belong to a known distribution, and it is not clear how to directly sample from the posterior.

MH sampling \[[74](./19-ref01.md#refbib74)\] replaces draws from the exact full conditional distribution with a draw from a proposal/candidate distribution followed by an accept/reject step. That is, the Gibbs update of _β_1 is a simple sample β1(s)|β2(s−1),Y, whereas an MH makes a candidate draw β1∗∼q(β1|β1(s−1)) that is conditioned on the current value of _β_1 (and potentially _β_2 and/or **Y**). Of course, the candidate cannot be blindly accepted because the candidate distribution 87\. Figure on this page. 88\. may not be related to the posterior distribution. To correct for this, the candidate is accepted with probability min{1,R} where _R_ is the ratio

R\=p(β1∗|β2,Y)p(β1(s−1)|β2,Y)q(β1(s−1)|β1∗)q(β1∗|β1(s−1)).(3.18)

Equivalently, the accept/reject step generates U∼Uniform(0,1) and accepts the candidate if U<R. [Listing 2](./11-chapter3.md#list3_2) formally describes the MH sampler, which can be justified by following the steps outlined in [Appendix A.3](./18-appA.md#secA_3) for Gibbs sampling.

`11:                       _set_ θj(s)=θj(s−1)`
`12:               **end if**`
`13:          **end for**`
`12:    **end for**`

The acceptance ratio _R_ depends on the ratio of the posteriors of the candidate and current values. For updating parameter _θ_ _j_, terms in the likelihood or prior that do not include _θ_ _j_ cancel and can thus be ignored. Crucially, this includes the often intractable normalizing constant m(Y). Other terms can cancel as well; for example, the entire likelihood for the example in [Listing 3.3](./11-chapter3.md#list3_3) did not depend on one parameter (γ) and would cancel in the posterior ratio for this parameter.

The MH sampler can be applied more generally than Gibbs sampling, but at the cost of having to select and tune a candidate distribution for each parameter (or block of parameters). A common choice is a random-walk Gaussian candidate distribution

θj∗|θj(s−1)∼Normal(θj(s−1),cj2)(3.19)

where _c_ _j_ is the candidate standard deviation. This is called a random-walk proposal distribution because it simply adds Gaussian jitter to the current state of the chain. A Gaussian candidate distribution can be used for any continuous parameter, even for those without a Gaussian prior; however, this is not always ideal. For example, a Gaussian candidate for a variance parameter may propose negative values which will automatically be discarded because the prior density and thus acceptance probability will be zero. Alternatively, a parameter with bounded support (e.g., σ\>0) can be transformed to have support over the whole real line (θ\=log(σ)), and a Gaussian can be used in this transformed space. A Gaussian candidate is not appropriate for a discrete parameter, however, because a Gaussian draw would almost surely not be in the support of the discrete parameter's prior.

89\. The standard deviation of the candidate distribution, _c_ _j_, is a tuning parameter. A rule of thumb is to tune the algorithm so that it accepts 30-50% of the candidates. It is hard to know which value of _c_ _j_ will lead to this acceptance rate before starting the sampling, and so it is common to adapt _c_ _j_ based on batches of samples during the burn-in. For example, if less than 30% of the last 100 candidates were accepted, then you might decrease _c_ _j_ by 20%, and if more than 50% of the last 100 candidates were accepted then you might increase _c_ _j_ by 20%. However, once the burn-in has completed, you must fix the candidate distribution unless you consider more advanced methods ([Appendix A.4](./18-appA.md#secA_4)).

Two benefits of the random-walk candidate distribution are that it does not require knowledge about the form of the posterior, and that the acceptance ratio simplifies. If the candidate PDF _q_ is Gaussian,

q(θj(s−1)|θj∗)\=qj(θj∗|θj(s−1))\=12πcjexp(−(θj(s−1)−θj∗)22cj2),(3.20)

the ratio of candidate distributions in the MH acceptance probabilities cancels. This is called a symmetric candidate distribution. The MH algorithm reduces to the Metropolis algorithm \[[104](./19-ref01.md#refbib104)\] in [Algorithm 3](./11-chapter3.md#algo3_3) if the candidate distribution is symmetric.

A common method for validating code is a simulation study. In a simulation study, we fix the values of the parameters and generate data using these values. The synthetic data are then analyzed, and the posterior distributions are compared with the true values. Unlike a real data analysis, since the true values are known, we can verify that the algorithm is able to recover the true values.

### 3.2.2 Approximate Bayesian Computing (ABC)

Metropolis-Hastings sampling is an incredibly versatile algorithm that can be applied to any statistical model where the PDF/PMF of the likelihood and prior can be computed. This covers the vast majority of, but not all, applications. As a counterexample, if the data are assumed to arise as the solution to a stochastic differential equation such as a population-dynamics model, then the likelihood may be too complicated to evaluate, leading to an intractable likelihood. Approximate Bayesian Computing (ABC; \[[100](./19-ref01.md#refbib100)\]) fills this gap. ABC requires only the ability to generate random draws from the model and not that the likelihood function can be evaluated.

As with MCMC, ABC produces _S_ Monte Carlo draws θ(1),...,θ(S) that can be used to approximate the posterior exactly the same way as MCMC; that is, the sample mean of the _S_ ABC samples approximates the posterior mean, etc. Unlike a Markov chain, for ABC the _S_ samples are independent and identically distributed.

We consider only the most basic version of ABC and refer interested readers to the review of \[[100](./19-ref01.md#refbib100)\] for extensions including combining ABC with MCMC. As sketched in [Algorithm 4](./11-chapter3.md#algo3_4), ABC begins by sampling from the prior distribution, θ∗∼π(θ), and then generating a simulated dataset Y∗ given the parameters θ∗, Y∗|θ∗∼f(Y|θ∗). The simulated dataset should be the same size and design as the original dataset; e.g., in regression the observed covariate values should be used to simulate data, so that observation _i_ in the simulated data corresponds to observation _i_ in the real data. The simulated dataset is then compared to 93\. 94\. the actual dataset using a discrepancy measure

d∗\=D(Y,Y∗).

If _d_\* is less than the threshold _δ_, then θ∗ is retained as a posterior sample; if not, then θ∗ is discarded. This process is repeated until _S_ samples have been collected. The intuition is that parameters that lead to data similar to the observations are more likely to be the true value, which is similar to the intuition behind maximum likelihood estimation.

The choice of discrepancy measure and threshold are critical to the accuracy of the algorithm. If samples θ∗ are retained if and only if Y∗\=Y, then the algorithm produces _S_ draws from the actual posterior without approximation. However, if the response is continuous or _n_ is large, then we cannot expect Y∗ to be exactly equal to **Y** (actually, all that is required is that the sufficient statistics of Y∗ match those of **Y**, but this does not resolve the problem). To sample from an approximate posterior distribution, we can retain samples for which Y∗≠Y but are similar as measured by the discrepancy function _D_. One option is the mean squared differences, D(Y,Y∗)\=∑i\=1n(Yi−Yi∗)2/n. However, for large _n_ it is unlikely that Y∗ will be similar to **Y** for all _n_ observations, and a discrepancy measure more targeted at the parameters is more efficient. For example, if the parameters control the mean and standard deviation of the response distribution, then the

D(Y,Y∗)\=(Y¯−Y¯∗)2+w(s−s∗)2

targets these parameters, for sample means Y¯ and Y¯∗, sample standard deviations _s_ and _s_\*, and weight _w_ chosen to reflect the relative scale and importance of the two parameters. In general, the discrepancy measure should include sufficient information to identify all model parameters. This requires some creativity and may be difficult if there are many parameters, which is a limitation of the method.

[Listing 3.7](./11-chapter3.md#list3_7) provides a worked example of ABC for simulated data. The n\=100 observations are simulated from the logistic regression model with Yi|β∼Bernoulli(pi) with pi\=1/\[1+exp(−ηi)\] for ηi\=β1+β2Xi. The priors are β1,β2∼iid Normal(0,1). Of course, Metropolis-Hastings sampling could be applied for this model as above, but notice how in the likelihood function and prior distribution need not be computed during ABC. The true values used to generate the data are β\=(2,−1) and Xi∼Normal(0,1). Since this model tracks the probability that Yi\=1 as a function of _X_ _i_, one possibility for _D_ is to bin the observations by _X_ _i_ and compute the sample proportion of _Y_ _i_ in each bin. Specifically, we create L\=4 bins formed by equally-spaced quantiles of _X_ _i_, denoted q1,...,qL+1. The sample proportion for bin _l_, Y¯l, is the sample mean of _Y_ _i_ over observations with ql≤Xi<ql+1. The discrepancy measure is then the mean squared error between the bin probabilities,

D(Y,Y∗)\=∑l\=1L(Y¯l−Y¯l∗)2/L.

### 3.2.3 97\. Simulation-based inference

Simulation-based inference (SBI; \[[37](./19-ref01.md#refbib37)\]) is closely related to ABC and also useful in settings where the posterior is challenging to evaluate but sampling is straightforward. As with ABC, SBI begins by sampling from the prior and then the data-generating process,

θ(s)∼π(θ) and Y(s)|θ(s)∼f(Y|θ(s))

for s∈{1,...,S}. SBI departs from ABC because rather than retaining a subset of the samples θ(s) to approximate posterior, SBI uses all _S_ samples and machine learning to build an approximation to the posterior p(θ|Y).

By construction, (θ(s),Y(s)) are samples from the joint distribution of the parameters and the data. These samples can thus be used to build a statistical model to regress θ(s) onto Y(s) to approximate the posterior, p(θ|Y). For a univariate analysis with p\=1, a very crude approximation is the linear regression

θ(s)|Y(s)∼Normal(b0+∑i\=1nYi(s)bj,τ2).

With this (unrealistic) assumption, the _S_ training samples are used to estimate b\=(b0,...,bn) and _τ_2 using least squares, giving estimates b^ and τ^2, and then for the real dataset, **Y**, the posterior is approximated as θ|Y∼Normal(b^0+∑i\=1nYib^j,τ^2). Note the role reversal in this regression with the observed outcomes _Y_ _i_ used as predictors; this illustrates that Bayesian parameter inference is an inverse problem rather than the usual forward prediction problem.

As a toy example, consider [Figure 3.15](./11-chapter3.md#fig3_15) that illustrates SBI for the model Y|θ∼Normal(θ,1) with prior θ∼Normal(0,1). As derived in [Section 2.1](./10-chapter2.md#sec2_1), the exact posterior is θ|Y∼Normal(Y/2,1/2). [Figure 3.15](./11-chapter3.md#fig3_15) (left) plots S\=1,000 samples from the joint density of (θ,Y). To learn the posterior distribution without mathematical derivation, we fit the simple linear regression model θ|Y∼Normal(b0+Yb1,τ2) to these _S_ samples. The least squares analysis gives b^0\=−0.045, b^1\=0.495 and τ^2\=0.488. [Figure 3.15](./11-chapter3.md#fig3_15) (right) shows that SBI provides a close approximation to the true posterior. This approximation is close largely because it relies on the knowledge that the true posterior is Gaussian and linear in the observations, which are both dubious assumptions in non-trivial problems. Therefore, in practice, more flexible statistical modeling of the posterior and a larger number of samples are required.

This approach is appealing to statisticians because it replaces advanced computing with advanced statistical modeling, facilitated by an effectively unlimited number of samples, _S_. Given this large dataset and presumed complex non-linear and non-Gaussian relationship between the data and the parameters, machine learning, in particular deep learning (see Chapter 8.3.4), is typically used to build a model to approximate the posterior rather than the linear regression above. As in ABC or any statistical model-building exercise, summary statistics can replace the full dataset in the approximate posterior and distributions other than the prior can be used to generate the samples (although this must be accounted for later in the analysis).

SBI is an example of amortized inference. That is, while it takes substantial effort to simulate the _S_ samples and build a model relating the parameters and data, once this is completed, inference for a given dataset is immediate. This holds for any dataset generated from the model, not just the dataset that motivated the initial analysis, so the same approximation could be used by any potential user. Thus, by learning the map from the data to the posterior, future users could bypass the challenging computational steps and immediately obtain approximate inference.

### 3.2.4 98\. Sequential Monte Carlo (SMC) sampling

As with MCMC, ABC and SBI, Sequential Monte Carlo (SMC) sampling (also called particle filtering) approximates the posterior distribution using Monte Carlo sampling. SMC resembles ABC in that samples are made from an initial distribution, often the prior distribution, and evaluated based on their fit to the data. However, SMC differs from ABC in two important ways: the exact, not approximate, likelihood is used, and samples are weighted rather than accepted or rejected. Although SMC can be used to analyze a single static dataset, its name derives from the fact that it is conducive to a sequential analysis of streaming data; e.g., each day a new batch of data is collected, and the Bayesian analysis is updated based on this new information.

As with ABC, we present only the simplest version here; we refer to the rich literature on SMC (e.g., \[[45](./19-ref01.md#refbib45)\]) for more advanced algorithms that include targeted initial particle sampling and replacing errant particles. A simple SMC algorithm begins by drawing _S_ samples/particles from the prior distribution

θ(1),...,θ(S)∼iidπ.

The particles are then assigned weights based on the likelihood function, u(s)\=f(Y|θ(s)), and normalized to sum to one as

w(s)\=u(s)∑t\=1Su(t).

Posterior quantities are then computed using weighted averages, e.g., E(θj|Y)≈∑s\=1Sw(s)θj(s) and

Prob(θj\>0|Y)≈∑s\=1Sw(s)I(θj(s)\>0),

99\. i.e., the sum of the weights for particles with θj(s)\>0. Note that particles that do not fit the data well will have weight w(s)≈0 and thus be “filtered out” of the approximate posterior. Therefore, this algorithm will be inefficient if the prior (or another initial distribution) is too diffuse and most particles are filtered out.

The algorithm above approximates the posterior distribution using the entire dataset. However, say the data arrive sequentially and are assumed to be independent over time. Then the unnormalized weights after observing _n_ observations are

un(s)\=∏i\=1nf(Yi|θ(s)).

When an additional observation arrives, the weights are updated as

un+1(s)\=f(Yn+1|θ(s))un(s)

and the normalized weights are wn+1(s)\=un+1(s)/∑t\=1Sun+1(t). Compared to reanalyzing the data at each time step, this saves time and storage because we do not need to recompute the likelihood for, or even store, the data from the first _n_ observations to obtain the current particle weights.

To see why this gives a valid posterior approximation, consider a discrete parameter with support θ∈{θ1,...,θK}. The true posterior probability that θ\=θk is

Prob(θ\=θk|Y)\=f(Y|θk)π(θk)∑l\=1Kf(Y|θl)π(θl).

The SMC approximation is

Prob(θ\=θk|Y)≈∑s\=1SwsI(θ(s)\=θk)\=∑s\=1Sf(Y|θ(s))I(θ(s)\=θk)∑s\=1Sf(Y|θ(s)).

Denoting _p_ _k_ as the proportion of the _S_ terms with θ(s)\=θk and collecting terms gives

Prob(θ\=θk|Y)≈f(Y|θk)pk∑l\=1Kf(Y|θl)pl.

As the sample size _S_ increases, _p_ _k_ converges to π(θk), and the approximate posterior probability converges to true probability. This argument extends to continuous parameters by evaluating the probability that θ is in a small region.

SMC typically considers a large number of particles, _S_, but this only provided a good approximation if many of the particles are supported by the posterior. For example, if S\=10000 but only two of the weights are non-zero, then the effective sample size for the posterior is two, not _S_. This intuition is formalized using the effective sample size statistic,

ESS\=(∑s\=1Sws)2∑s\=1Sws2.

The ESS is between 1 and _S_; in the best case the particles are weighted equally, ws\=w for all _s_, and ESS\=S; in the worst case ws\=1 for one _s_ and ws\=0 for all other _s_, and ESS\=1. Typically, _S_ is increased until _ESS_ is sufficiently large, say ESS\=1000.

[Listing 3.8](./11-chapter3.md#list3_8) and [Figure 3.16](./11-chapter3.md#fig3_16) illustrate SMC for the beta-binomial model Y|θ∼Binomial(n,θ) and θ∼Beta(a,b) with Y\=10, n\=40 and a,b\=1. First, the posterior is approximated using MCMC sampling (in this case just independent samples from 100\. the beta posterior). This produces _S_ samples that are all in the area with high posterior mass and are weighted equally, ws\=1/S, when approximating the posterior mean. The SMC samples, in contrast, are uniformly distributed across the parameter space following the uniform prior and weighted highly for samples with high likelihood. Because many particles have low weight, the effective sample size of the S\=50 particles is only ESS\=9.7; thus additional particles would be needed to provide a precise approximation.

## 3.3 MCMC software options in R

Writing MCMC code step-by-step is great practice and the only way to truly understand the algorithms, and tailoring the code to a specific model can improve speed and stability for complex models. However, coding basic MCMC samplers becomes repetitive. For Gibbs sampling, you must derive and encode the full conditional distribution of each parameter, but there are only a few dozen known conjugacy pairs (e.g., [Appendix A.2](./18-appA.md#secA_2)), and so writing a Gibbs sampler is simply a matter of looking up the correct full conditional distribution and entering this into R. If the parameter's full conditional distribution does not appear in the table of conjugacy pairs, you might use a Metropolis update with Gaussian random walk 101\. 102\. candidate distribution. Each Metropolis update consists of a Gaussian proposal followed by computing the acceptance ratio, which requires only tuning the candidate standard deviation and inserting the specific likelihood and prior chosen for the model into the acceptance ratio. But the tuning step is not model specific, and most models are built using only a few dozen distributions for the likelihood and prior ([Appendix A.1](./18-appA.md#secA_1)), and so writing MH code becomes simply a matter of coding the correct distributions.

Fortunately, this process has been automated! There are several general-purpose MCMC packages that can be called from R, including Just Another Gibbs Sampler (JAGS), OpenBUGS (\[[148](./19-ref01.md#refbib148)\]), STAN (\[[28](./19-ref01.md#refbib28)\]), and NIMBLE (\[[42](./19-ref01.md#refbib42)\]), as well as libraries in python including pymc (\[[121](./19-ref01.md#refbib121)\]) and the SAS procedure PROC MCMC (\[[31](./19-ref01.md#refbib31)\]). These packages are not specific to a single model; rather they take a script specifying the likelihood and prior as input and use this information to construct an MCMC sampler for the specified model. The formats of these packages are similar, and so with a solid understanding of MCMC sampling to interpret the results, switching from one to another is fairly straightforward.

For the remainder of the book we will use JAGS to carry out MCMC sampling. Compared to other packages, JAGS is relatively easy to code and sufficiently fast for the size and complexity of models considered here. JAGS is a very general package that can be used to fit all the models discussed in this book and many more. Of course, for a specific application there may be more focused and thus more efficient code. For example, the BLR package in R surely performs better than JAGS for Bayesian linear regression. However, to avoid having to learn dozens of packages for different models we simply use JAGS throughout.

JAGS must first be downloaded from <http://mcmc-jags.sourceforge.net/>, and installed on your computer. The R package rjags must be downloaded and installed to communicate with JAGS from R. An MCMC analysis using JAGS has five steps:

1. Specify the model as a character string in R;
2. Upload the data, and compile the model using the function jags.model;
3. Perform burn-in sampling using the function update;
4. Generate posterior samples using the function coda.samples;
5. Summarize the results using the functions summarize and plot.

## 3.4 107\. Diagnosing and improving MCMC convergence

### 3.4.1 Selecting initial values

Theoretically, Gibbs and Metropolis–Hastings sampling should converge for any initial values, but in practice the choice of starting values is important. There are two schools of thought on initialization: select initial values close to the posterior mode and run one long chain or run several parallel chains with intentionally diffuse starting values to verify that the algorithm has converged.

Selecting good starting values and running one long chain has the advantage of shortening or eliminating the burn-in period. A common method to select initial values is the MLE or MAP estimates computed using numerical optimization, which is often easier to compute than MCMC sampling. A disadvantage of this approach is that it is hard to rule out the possibility that the chain is stuck in a local mode and is completely missing the bulk of the posterior distribution.

On the other hand, starting multiple (typically 2–5) chains with diffuse starting values requires more burn-in samples, but if all chains give the same results then this provides evidence that the algorithm has properly converged. [Figure 3.18](./11-chapter3.md#fig3_18) shows idealized convergence of three chains around iteration 500\. MCMC is not easily parallelizable because of its sequential nature, but running several independent chains is one way to exploit parallel computing to improve Bayesian computation.

Care should 108\. be taken up front to ensure that the starting values of each chain are sufficiently spread across the posterior distribution so that convergence of the two chains necessarily represents strong evidence of convergence.

The first diagnostic is to plot the trace plots and verify that the chains have all reached the same distribution and have mixed properly. [Figure 3.20](./11-chapter3.md#fig3_20) (top left) provides a good example where the chains for both parameters look like a bar code, while [Figure 3.19](./11-chapter3.md#fig3_19) (top left) is a problematic case where the chains are mixing slowly and likely need many more iterations to provide a good approximation to the posterior. In these small examples it is possible to plot all chains for all parameters, but for more complex models it may be necessary to inspect the chains for only a representative subset of the parameters.

Autocorrelation of the chains provides a numerical measure of how fast the chains are mixing. Ideally, the iterations would be independent of each other, but the Markovian nature of the sampler induces dependence between successive iterations. The lag-_l_ autocorrelation of the chain for parameter _θ_ _j_ is defined as

ρj(l)\=Cor(θj(s),θj(s−l)),(3.22)

and the function ρj(l) is called the autocorrelation function. The right panels of [Figures 3.19](./11-chapter3.md#fig3_19) and [3.20](./11-chapter3.md#fig3_20) plot the sample autocorrelation functions for the two examples. Ideally we find that ρj(l)≈0 for all l\>0, but some correlation is expected. For example, the lag-1 autocorrelation for _μ_1 in [Figure 3.20](./11-chapter3.md#fig3_20) is around 0.4, but the chain converges nicely.

Rather than reporting the entire autocorrelation function for each parameter, the lag-1 autocorrelation is typically sufficient. Another common one-number summary of the entire function is the effective sample size (ESS). Recall that the sample mean of the MCMC samples is only an estimate of the true posterior mean, and we can quantify the uncertainty in this estimate with the standard error of the sample mean. If the samples are independent, then the standard error of the sample mean is sdj/S where sdj is the sample standard deviation of the draws for _θ_ _j_ and _S_ is the number of samples. This is labelled “naive SE” in the JAGS summary output as in [Listing 3.9](./11-chapter3.md#list3_9). However, this underestimates the uncertainty 109\. 110\. in the posterior-mean estimate if the samples have autocorrelation. It can be shown that the actual standard error accounting for autocorrelation is sdj/ESSj where

ESSj\=S1+2∑l\=1∞ρj(l).(3.23)

In practice the infinite sum must be truncated as ∑l\=1Lρj(l) for a large _L_. Assuming the autocorrelation function ρj(l) is non-negative for all _l_, then ESSj≤S and thus the sample size is discounted to adjust for autocorrelation. The standard error sdj/ESSj is labeled “Time-series SE” in the JAGS summary output. One way to determine if the number of samples is sufficient is to increase _S_ until this standard error is acceptably low for all parameters. Another method is to increase _S_ until the effective sample size is acceptably high for all parameters, say ESSj\>1000.

Geweke's diagnostic (\[[61](./19-ref01.md#refbib61)\]) is used to detect non-convergence. It tests for convergence using a two-sample t-test to compare the mean of the chain between batches at the beginning versus the end of the sampler. The default in coda is to test that the mean is the same for the first 10% of the samples and the last 50% of the samples. Let θ¯jb and sejb be the sample mean and standard error, respectively, for _θ_ _j_ in batch b\=1,2. The standard errors are computed accounting for autocorrelation (as in (3.23)) in the chains. The Geweke statistic is then

Z\=θ¯j1−θ¯j2sej12+sej22.(3.24)

Under the null hypothesis that the means are the same for batches (and assuming each batch has large ESS), _Z_ follows a standard normal distribution, and so |Z|\>2 is cause 111\. 112\. for concern. In the two examples in Listings 3.11 and 3.12, |Z| is less than one, and so this statistic does not detect non-convergence.

Geweke's statistic uses only one chain. A multi-chain extension is the Gelman–Rubin statistic (\[[57](./19-ref01.md#refbib57)\]). The Gelman–Rubin statistic measures agreement in the means between _C_ chains. It is essentially an ANOVA test of whether the chains have the same mean, but the statistic is scaled so that 1.0 indicates perfect convergence and values above 1.1 are questionable. The statistic is

Rj\=S−1SW+(1S+1SC)BW(3.25)

where _B_ is _S_ times the variance of the _C_ MCMC sample means for _θ_ _j_ and _W_ is the average of the _C_ MCMC sample variances for _θ_ _j_. The coda package plots the Gelman–Rubin statistic as a function of the iteration, and so when the statistic reaches one this indicates good mixing among the parallel chains and that the chains have possibly reached their stationary distribution. The Gelman–Rubin statistics clearly distinguish between the examples in [Listing 11](./11-chapter3.md#list3_11) and 3.12: Rj\=1.62 in the poor-convergence case and Rj\=1.00 for the good-convergence case.

### 3.4.3 Improving convergence

Armed with these diagnostic tools, if the user honestly inspects the sample output, poor convergence can usually be detected. This leaves the more challenging problem of improving convergence! There is no single step that always resolves convergence problems, but the list below offers some suggestions:

1. 113\. **Increase the number of iterations**: Theoretically MCMC algorithms should converge and cover the posterior distribution as _S_ goes to infinity. Of course, time limits the number of samples that can be generated, but in some cases increasing _S_ can be faster than searching for other improvements. Nonetheless, this is not the most satisfying solution to poor convergence, specifically when the chains move slowly due to high autocorrelation.
2. **Tune the MH candidate distribution**: The acceptance probability can be tuned during burn-in to be around 30-50%, but as the chain evolves the acceptance probability can change. If groups of parameters have strong cross-correlation then updating them in blocks can dramatically improve convergence. Block steps must be carefully tuned however so the candidate correlation matrix approximates the posterior correlation matrix.
3. **Improve initial values**: Often a sampler works well once it finds the posterior distribution, but the posterior PDF may be too flat away from the mode for the sampler to find its center. One way to improve initial values is to use the maximum likelihood estimates, θ(0)\=θ^MLE. Another option is to use simulated annealing during burn-in. In simulated annealing, the MH acceptance rate is raised to the power Ts∈(0,1\], i.e., RTs, where the temperature _T_ _s_ increases to one throughout the burn-in, e.g., Ts\=s/B for s<B and Ts\=1 for s\>B, where _B_ is the number of burn-in samples. The intuition behind this modification is that by raising the acceptance ratio to a power the algorithm is more likely to make big jumps during the burn-in and will slowly settle down in the heart of the posterior as the burn-in period ends.
4. **Use a more advanced algorithm**: [Appendix A.4](./18-appA.md#secA_4) provides several advanced algorithms that can be used for a particularly vexing problem. For example, Hamiltonian Monte Carlo (HMC) is a Metropolis sampler that uses the gradient of the posterior to intelligently propose candidates and adaptive Metropolis estimates allows the proposal distribution to evolve across iterations.
5. **Simplify the model**: Poor convergence often occurs when models are too complex to be fit with the data at hand. Overly complex models often have unidentified parameters that cannot be estimated. For example, in a model with Yi∼iidNormal(θ1+θ2,σ2), the two mean parameters are not identified, meaning that there are infinitely many combinations of the parameters that give the same likelihood (e.g., θ\=(−10,10) or θ\=(10,−10) give the same mean). Of course, no one would fit such a blatantly unidentified model, but in complex models with dozens of parameters, unidentifiability can be hard to detect. Convergence can be improved by simplifying the model by eliminating covariates, removing non-linear terms, reducing the covariance structure to independence, etc.
6. **Pick more informative priors**: Selecting more informative priors has a similar effect to simplifying the model. For example, even in the silly model Yi∼iidNormal(θ1+θ2,σ2), the MCMC algorithm would likely converge quickly with priors θ1∼Normal(−3,1) and θ2∼Normal(3,1). Even a weakly informative prior can stabilize the posterior and improve convergence. As an extreme example, an empirical Bayesian prior ([Chapter 2](./10-chapter2.md)) fixes nuisance parameters at their MAP estimates, which can dramatically improve convergence at the expense of suppressing some uncertainty.
7. **Run a simulation study**: Determining whether a chain has converged can be frustrating for a real data analysis where the true values of the parameters are unknown. Simulating data from the model and then fitting the MCMC algorithm 114\. (as in [Listing 3.6](./11-chapter3.md#list3_6)) for different sample sizes and parameter values can shed light on the properties of the algorithm and build trust that the sampler is producing reliable output.

### 3.4.4 Dealing with large datasets

Big data poses computational challenges to all statistical methods, but its effects are acutely felt by MCMC because MCMC requires thousands of passes through the data. Fortunately, recent years have seen a surge in Bayesian computing methods to handle massive datasets. Likely the next few years will see further developments in this area, but below we outline some of the most useful current approaches.

1. **MAP estimation**: MCMC is the gold standard for Bayesian computing because it returns estimates of the entire joint distribution of all of the parameters. However, if the scope of the analysis is limited to prediction, then it is much faster to simply compute the MAP estimate and ignore uncertainty in parameter estimation.
2. **Gaussian approximation**: The Bayesian CLT states that the posterior is approximately normal if the sample size is large. Therefore, running a long MCMC chain for, say, a logistic regression with n\=1,000,000 observations, p\=50 covariates and flat priors is unjustifiable; it is much faster and equally accurate to approximate the posterior as Gaussian, centered on the MAP estimate with covariance determined by the information matrix. This computation can often be carried out using MLE software, and thus the posterior will be very similar to the approximate sampling distribution of the MLE, but the interpretation of uncertainty remains Bayesian.
3. **Variational Bayesian computing**: Variational Bayesian approximations (Chapter 3.1.4) an be even faster to compute than evoking the Bayesian CLT if you target only the marginal distribution of each parameter. That is, if you assume the posterior (not prior) is independent across parameters and use the best approximation to the true posterior that has this form, the posterior can be approximated without computing the joint distribution. This of course raises questions about properly accounting for uncertainty, but does lead to impressive computational savings.
4. **Parallel computing**: MCMC is inherently sequential; i.e., you generally cannot update the second parameter until after updating the first. In special cases, steps of the MCMC routine can be performed simultaneously in parallel on different cores of a CPU or GPU cluster. For example, if parameters are (conditionally) independent, then they can be updated in parallel. Alternatively, if the data are independent and the likelihood factors as the product of _n_ terms, then likelihood calculations within each MCMC step can be done in parallel, e.g., _n_1 terms computed on core 1, _n_2 terms computed on core 2, etc. While parallelization can theoretically have huge benefits, the overhead associated with passing data across cores can dampen the benefits of using multiple cores unless parallelization is done carefully.
5. **Divide and conquer**: Divide and conquer methods provide an approximation to the posterior that is embarrassingly parallelizable. Say we partition the data into _T_ batches Y1,...,YT that are independent given the model parameters. Then the 115\. posterior can be written  
p(θ|Y)∝f(Y|θ)π(θ)\=∏t\=1T\[f(Yt|θ)π(θ)1/T\].(3.26)  
This decomposition suggests fitting _T_ separate Bayesian analyses (in parallel) with analysis _t_ using data Yt and prior π(θ)1/T and then combining the results. Each of the _T_ analyses uses the original prior π(θ) raised to the 1/T power to spread the prior information across batches; e.g., if θ∼Normal(0,τ2) then the prior to the 1/T power is Normal(0,Tτ2). Scott et al. \[[140](./19-ref01.md#refbib140)\] discuss several ways to combine the _T_ posterior distributions. The simplest method is to assume the posteriors are approximately Gaussian, and thus analysis _t_ returns θ|Yt≈Normal(Mt,Vt). In this case, the posteriors combine as  
p(θ|Y)≈Normal(V∑t\=1TVt−1Mt,V)(3.27)  
where V−1\=∑t\=1TVt−1.
6. **Sequential Monte Carlo**: SMC methods were introduced in Chapter 3.2.4 for streaming data with each additional new batch of data points modifying the weights of the particles used to approximate the posterior. This approach can also be applied for a large datasets by artificially splitting the data into small (mini) batches and analyzing the batches sequentially. An advantage of this approach for large datasets is that only a single batch and the particle weights need to be stored in memory.
7. **Stochastic gradient MCMC**: Splitting data into minibatchs can be extended to MCMC methods \[[115](./19-ref01.md#refbib115)\]. As described in Appendix 9.4, Hamiltonian Monte Carlo methods use the derivative of the posterior to optimize the candidate distribution of the Metropolis-Hastings algorithm. Stochastic gradient MCMC uses only a random subset of the dataset to approximate the gradient, which leads to impressive gains for massive datasets.
