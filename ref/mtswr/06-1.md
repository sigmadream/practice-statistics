#  1.1 Introduction to the R ecosystem 

Before going into the technical part, let’s start with understanding the basics of the R programming ecosystem by answering three initial questions:

-  What is R?
-  What is RStudio?
-  What are R packages?

##  1.1.1 What is R? 

**R** is simultaneously used to indicate a programming language and an environment for statistical computing and graphics. It was developed as a coherent system for statistical analysis with a diverse collection of integrated intermediate tools for data analysis. The first release of R came in 2000 from the R Core Group as an open source project. The creators of R embedded the absolute concept of ‘language’ and ‘environment’ in a software suite. From the beginning until now one motto has been maintained—whatever is implemented in R, the users retain full control. This is highly appreciated by the R users. However, the *anything can be modified after it is created* ( ` `` Wickham, 2014 `` ` ) attitude can be daunting to new users or users coming from a different programming language. It does make R somewhat a quirk as a programming language. Though what is a language without a bit of quirk in it anyway?

##  1.1.2 What is RStudio? 

**RStudio** is an **Integrated Development Environment** ( **IDE** ) that traditionally used R as a computation engine. It provides a user-friendly interface with a collection of tools for data analysis, visualization, automated report writing, debugging, and workspace management. Over time, RStudio expanded its capabilities to support other programming languages such as Python, SQL, and more. You can also create a Jupyter notebook or use code editing software such as Visual Studio Code (VSCode). This not only enhances the capabilities of RStudio itself but also provides users with options to use multiple languages in one data science project to take collaboration to the next level.

In recent developments, the Positron IDE has emerged as a modern alternative, designed to offer a more flexible and language-agnostic environment for data science workflows. It supports seamless integration with R, Python, and other tools, and is built to enhance productivity in collaborative and reproducible research. Throughout this book, we will primarily utilize RStudio; however, the fundamental concepts and workflows presented are readily available and transferable to Positron.

RStudio offers multiple products. The open source RStudio Desktop can run locally and is free. RStudio Desktop Pro is commercially licensed for organizations. There are enterprise-level products such as Posit Team, Posit Workbench and Posit Connect, which organizations could use depending on their requirements and the maturity of their data science journey. You can find the product description on Posit site <a href="https://posit.co/products/" style="text-decoration: none;">  https://posit.co/products/  </a> .

This book references the free version of RStudio Desktop which allows you to run code locally without incurring any costs. Unless otherwise specified, the term RStudio in this book refers specifically to RStudio Desktop.

##  1.1.3 What are R packages? 

**R packages** are extensions of the base R programming language and usually contain a collection of functions, methods, and algorithms to solve problems. R packages are written by a wide community of R users around the globe that comes from all avenues of expertise including both academia and industry. Usually, an R package is focused on solving a particular problem. For example, ` `` dplyr `` ` ( ` `` Wickham et al., 2023 `` ` ) provides functions for data manipulation, ` `` ggplot2 `` ` ( ` `` Wickham, 2016 `` ` ) implements the grammar of graphics for statistics and computing, and the ` `` forecast `` ` package ( ` `` Hyndman et al., 2025 `` ` ) is developed to visualize and analyze univariate time series with particular focus on forecasting. The vast collection of R packages will help you solve problems at hand without reinventing the research and development wheel.

#  1.3 Installing R and RStudio with admin access 

If you have admin access to your machine, the installation method is pretty much a download and click method on Windows and macOS. For Linux-based systems, there are three slightly different ways based on the flavors of the system: Debian, Ubuntu, or Fedora/Red hat. It is important to note that you need to read and follow the instructions that are relevant to your operating system.

##  1.3.1 Windows 

By default, R and RStudio install under ` `` C:\Program `` ` Files. This creates relevant folders for it to get installed in. For package installation, R uses ` `` thelibrary `` ` folder inside the R installation. Follow these steps if you have admin access to the root ` `` C:\ `` ` folder:

1.   Double-click the downloaded ` `` .exe `` ` file for R.

2.   Follow the instructions as they appear in the prompt to install R.

3.   Double-click the downloaded ` `` .exe `` ` file for RStudio and follow the instructions to install.

4.   Open the **RStudio** icon. Depending on the version of RStudio, it may ask you to choose a version of R.

5.   In the RStudio console run (type and hit Enter) following commands:

    ```
    R.home()
    Sys.getenv("R_HOME")

    Sys.getenv("HOME")
    path.expand("~")
    getwd()

    .libPaths()
    ```

These commands point to the folder structure used during installation, such as the following:

- ` `` R.home() `` ` and ` `` Sys.getenv("R_HOME") `` ` return the location where R is installed; this will be ` `` C:/Program Files/R/R-4.2.3 `` ` .
- ` `` Sys.getenv("HOME") `` ` , ` `` path.expand("~") `` ` , ` `` getwd() `` ` returns the user’s home directory, typically ` `` C:/Users//Documents `` ` . It is also the default working directory for R. You can use the shorthand ~ character instead of writing the full path while coding.
- ` `` .libPaths() `` ` returns the default location for package installation, which will be ` `` C:/Program Files/R/R-4.2.3/library `` ` .

In the next section, you will learn how to perform the installation process on macOS.

##  1.3.2 macOS 

When downloading R and RStudio for macOS, make sure to choose the correct architecture that matches your system: Apple Silicon or Intel. The installer for R and RStudio has the .pkg and .dmg extensions, respectively:

1.   Click the downloaded ` `` .pkg `` ` file.

2.   Follow the instructions and prompts (selects Next multiple times) to install R in the default location.

3.   For RStudio, double-click the ` `` .dmg `` ` file. A folder will open with the **Application** and **RStudio** icons next to each other. Drag the **RStudio** icon to the **Application** folder to install it.

4.   Navigate to the **Application** folder to check that both R and RStudio are available to use.

5.   Open **RStudio** and type the following commands in the console to see the **installation** folder, **home** folder, and package installation path.

    ```
    R.home()
    Sys.getenv("HOME")
    .libPaths()
    ```

##  1.3.3 Linux 

On Linux systems, the steps are as follows:

1.   Install a platform-specific system package manager.
2.   Add the CRAN repository in the ` `` /etc/apt/sources.list `` ` file along with the Linux distribution name.
3.   Install R via the linux system package manager and ` `` apt `` ` tool.

If you have writing permission, then you can omit ` `` sudo `` ` from the lines of codes provided in the following system-specific scenarios.

###  1.3.3.1 Ubuntu 

These steps are explained for Ubuntu Jammy Jellyfish (22.04, AMD64). The steps are applicable for any Ubuntu builds by replacing ` `` jammy `` ` or the build name where used:

1.   Install Ubuntu’s helper packages to install R.

    ```
    sudo apt update -qq
    sudo apt install --no-install-recommends software-properties-common dirmngr
    ```

2.   Add CRAN repo in the ` `` /etc/apt/sources.list `` ` by typing below in the terminal.

    ```
    sudo add-apt-repository "deb https://cloud.r-project.org/bin/linux/ubuntu $(lsb_release -cs)-cran40/"
    ```

    The ` `` lsb\_release -cs `` ` replaces the name of the Ubuntu build, such as ` `` jammy `` ` or ` `` focal `` ` .

    Alternatively, open the ` `` /etc/apt/sources.list `` ` file in a text editor (such as ` `` vim `` ` or ` `` nano `` ` ) and manually add ` `` deb \ https://cloud.r-project.org/bin/linux/ubuntu jammy-cran40/ `` ` into it.

3.   Install R and its dependencies by running the following code in the terminal:

    ```
    sudo apt install --no-install-recommends r-base r-base-core r-recommended r-base-dev
    ```

4.   Test the installation by typing R in the terminal. Check the ` `` R.home() `` ` , ` `` Sys.getenv() `` ` and ` `` .libPaths() `` ` within R. Are you surprised there are three different folders in ` `` .libPaths() `` ` ? We will learn more about this in the R package pathways subsection.

5.   To install RStudio, first download it from the Posit site (previously <a href="https://rstudio.org" style="text-decoration: none;">  rstudio.org  </a> ) via the terminal:

    ```
    wget https://download1.rstudio.org/electron/jammy/amd64/rstudio-2023.03.0-386-amd64.deb
    ```

6.   Then, install it after the download is complete:

    ```
    sudo apt install -f ./rstudio-2023.03.0-386-amd64.deb
    ```

7.   Launch installed RStudio either from ` `` Application - `` ` ` `` > `` ` ` `` RStudio `` ` or via the terminal:

    ```
    rstudio
    ```

###  1.3.3.2 Debian 

At the time of writing, Debian Bookworm is the stable version; however, you can replace to other Debian version in the terminal commands when a new one is available in future. The following commands is run in the terminal:

1.   Search ` `` R add-ons `` ` in the Debian package manager:

    ```
    apt search "^r-.*" | sort
    ```

2.   Add the CRAN entry to the ` `` /etc/apt/sources.list.d `` ` file directory and import the GPG key securely:

    ```
    sudo apt update

    sudo apt install --no-install-recommends software-properties-common dirmngr gnupg ca-certificates

    curl -sSL "keyserver.ubuntu.com" | sudo gpg --dearmor -o /usr/share/keyrings/cran-archive-keyring.gpg

    echo "deb [signed-by=/usr/share/keyrings/cran-archive-keyring.gpg] https://cloud.r-project.org/bin/linux/debian bookworm-cran40/" | sudo tee /etc/apt/sources.list.d/cran.list
    ```

3.   Now, install R by running the following command:

    ```
    sudo apt update
    sudo apt install r-base r-base-core r-base-dev
    ```

    The ` `` r-base-dev `` ` is required when you compile R packages from sources that are not available as precompiled Debian or Ubuntu packages.

4.   The RStudio installation is the same in Debian for Ubuntu, except you need to download the appropriate version of RStudio for Debian (e.g., Debian 12+):

    ```
    wget https://rstudio.org/download/latest/stable/desktop/jammy/rstudio-latest-amd64.deb -O rstudio-latest-amd64.deb

    sudo apt install -f ./rstudio-latest-amd64.deb
    rstudio
    ```

The <a href="https://cran.r-project.org/bin/linux" style="text-decoration: none;">  cran.r-project.org/bin/linux  </a> site describes installing R on other Linux distributions, like Fedora, Red Hat, and SUSE. It is also a good resource if you have any issues during the installation process, such as a missing public key, and how to fix it.

While installing RStudio, Linux users may be restricted by the security policy of their operating system and need to import Posit’s public code-signing key. If you have any issue in step 2, then navigate to <a href="https://posit.co/code-signing/" style="text-decoration: none;">  https://posit.co/code-signing/  </a> and follow the instructions on importing the public key.

#  1.4 Installation in a custom location 

On a corporate-managed computer, you may not have admin privileges to install applications in system-level directories such as the root of the drive. While a system administrator can install R and RStudio in the default locations (e.g., ` `` C:\Program `` ` Files on Windows or ` `` /Applications `` ` on macOS), package installation may still fail if you don’t have write access to R’s default library folder. Raising a ticket to get support from an IT admin every time you install a package is not practical. Installing R and RStudio in a custom folder can solve the issue. You could also use a custom folder only for packages where the base R software can be installed in the default location.

Suppose that you have writing permission on the ` `` D:\ `` ` drive in a Windows machine (or ` `` /Users/ `` ` ` `` < `` ` ` `` YourName `` ` ` `` > `` ` ` `` / `` ` for macOS) and you can install R and RStudio there. First, you need to create a folder named R at this location ( ` `` D:\ `` ` ` `` < `` ` ` `` Username `` ` ` `` > `` ` ` `` \R `` ` for Windows or ` `` /Users/ `` ` ` `` < `` ` ` `` YourName `` ` ` `` > `` ` ` `` /R/ `` ` for macOS), and you need to use this path as a destination folder during the R and RStudio standard installation process. The same location can be used for installing R packages. Create a folder called ` `` D:\ `` ` ` `` < `` ` ` `` Username `` ` ` `` > `` ` ` `` \R\RPackages `` ` (or ` `` /Users/ `` ` ` `` < `` ` ` `` YourName `` ` ` `` > `` ` ` `` /R/RPackages/ `` ` for macOS) for installing the personal package library.

The folder tree will look as follow on a Windows:

```
Username/R/
├── R-4.2.3/
├── RPackages/
└── RStudio/
```

Now, you can configure the destination folder for your package installation. Irrespective of whether you are using Windows or macOS, open RStudio and type ` `` .libPaths() `` ` in the console. It will print the default package installation folder path. A custom package installation location can be provided in the ` `` .Rprofile `` ` file. Type the following command in the console:

```
file.edit("~/.Rprofile")
```

The ` `` .Rprofile `` ` file from the default working directory will open, which is an empty file. Write the following snippet of code in it, save it, and close it. Replace the ` `` < `` ` ` `` Username `` ` ` `` > `` ` portion accordingly:

```
.First <- function() {
  path_to_package = "D:/<Username>/R/RPackages"
  .libPaths(c(path_to_package, .libPaths()))
}
```

Restart RStudio. You can check the change by typing ` `` .libPaths() `` ` in the console (the supplied folder name should appear as the first item) or opening ` `` Packages- `` ` ` `` > `` ` ` `` Install `` ` from RStudio.

#  1.5 Installing R packages 

R packages are collections of functions, compiled code, and data bundled nicely together, hosted on CRAN (or GitHub) for you to download and use. At the time of writing this book, there are more than 19 thousand packages available on CRAN. There is no definite list of packages that are in the development stage hosted on GitHub. Looking at this staggering number of packages makes you realize how broadly and deeply the R community has grown over time. Each package is open source and free to use. Born as a statistical computing software, R has come a long way with the help of R packages.

The base R is shipped with about eight packages. You can get other packages from CRAN (the most stable version) or from GitHub (development version).

You need to install and load a package to use its capabilities in your R workspace:

-  First, download and install the desired R package. Installing a package creates a package-specific folder inside the R installation directory, or in the custom directory (as described in *Section 1.4* ) on your machine. This folder contains all binaries, code, and documentation for the specific package.
-  Second, you need to call the package in the R working space to use it actively. There are two methods to install R packages: the RStudio menu and the R console. You will learn how to do both in the next two subsections.

##  1.5.1 Package installation via the RStudio menu 

You can install any number of packages using RStudio’s **Packages** menu. You can set the repository, see the package list as you type (a way to learn what other packages are available), and choose a location to install.

##  1.5.2 Package installation via R console 

To install a package from CRAN, type ` `` install.packages() `` ` in the R console with the package name inside the parentheses enclosed in double quotes. The number of packages installed can vary from one to multiple in one execution:

```
# install a single package
install.packages("dplyr")

# install multiple packages
install.packages(c("DBI", "tibble", "dplyr",
                   "ggplot2", "fst", "knitr"))
```

You can specify a custom location on the fly by providing a path to the ` `` lib `` ` option within the ` `` install.packages() `` ` function if a custom package location has not already been set via ` `` .Rprofile. `` `

Over time, you will have a list of R packages that you will always need. You will need to install those packages when you move to a new R project, update R, change machines, or move to another organization, and it is hard to remember which package is installed where. A way to install missing packages on the fly is using the ` `` p_install() `` ` or ` `` p_load() `` ` function from the ` `` pacman `` ` package which stands for “pac”kage “man”agement. The ` `` p_install() `` ` function installs missing packages, and ` `` p_load() `` ` functions installs and simultaneously loads the packages in the current workspace. Following code shows how to install ` `` pacman `` ` first (if not installed) and then use it to install other packages:

```
if (!requireNamespace("pacman", quietly = TRUE)) {
  install.packages("pacman")
}

pacman::p_load(DBI, tibble, dplyr, ggplot2, fst, knitr)
```

This code should be included at the beginning of any standalone R script or as a script in every R project. In this way you do not need to worry about code breaking due to missing packages when shared with collaborators.

On Linux, you can call the ` `` install.packages() `` ` function from within R. This works assuming that you have installed ` `` r-base-dev `` ` while installing R on the Linux system. First, call R from the terminal:

```
R
```

Then type the following within R:

```
install.packages("dplyr")
```

For the first time, it asks to create a personal library if the default installation path is not writable:

```
Installing packages into '/usr/local/lib/R/site-library'
(as 'lib' is unspecified)
Warning in install.packages("dplyr") :
'lib = "/usr/local/lib/R/site-library"' is not writable
Would like to use a personal library instead? (yes/No/cancel)
```

When you type yes, a folder of the ` `` home/ `` ` ` `` < `` ` ` `` user `` ` ` `` > `` ` ` `` /R/ `` ` ` `` < `` ` ` `` platform name `` ` ` `` > `` ` ` `` -library/ `` ` ` `` < `` ` ` `` R version `` ` ` `` > `` ` type is created and asks for your permission to install into it. The ` `` < `` ` ` `` platform-name `` ` ` `` > `` ` is the Linux system name, such as x86-64-pc-linux-gnu, and the R-version is the version of R installed. This method compiles packages from source using the power of ` `` r-base-dev `` ` .

On Ubuntu you could also use ` `` apt\ install `` ` in the terminal after adding Ubuntu’s R package repository ` `` c2d4u `` ` :

```
sudo add-apt-repository ppa:c2d4u.team/c2d4u4.0+
sudo apt install --no-install-recommends r-cran-dplyr
```

It may ask to create a user specific location for package installation when you don’t have write permission in the default location. There are more than 5000+ R packages available in the ` `` c2d4u `` ` repo. Even though you can use this repo for any Ubuntu builds, the developers strongly suggest using the **Long Time Support** ( **LTS** ) release to receive the full benefit of the c2d4u repository.

You have seen that there are multiple methods to install R packages with their own folder hierarchy when installed. Is one method better than the others? Find the answer in the next section.

##  1.5.3 R package pathways 

We already know that when an R package is installed, it creates a package-specific folder under a directory listed in ` `` .libPaths() `` ` . On Windows and macOS, all packages are installed in the library folder inside the R installation by default. A custom installation path can be used by assigning a folder as the first item in ` `` .libPaths() `` ` . All R packages are installed inside that folder can be found as ` `` .libpaths() `` ` \[1\].

On Windows and macOS there is no dominance in folder structure by package installation methods. Irrespective of the package installation methods, (either RStudio’s Packages menu or using ` `` install.packages() `` ` from R console), all packages are installed under one folder.

On Linux systems, the R package pathways work slightly differently.

- ` `` /usr/lib/R/library `` ` contains binaries and libraries of R build, e.g., ` `` r-base `` ` and ` `` r-recommends `` `
- ` `` /usr/lib/R/site-library `` ` contains binaries and libraries of precompiled Debian (or Ubuntu) R packages installed from ` `` r-cran-* `` ` and ` `` r-bioc-* `` `
- ` `` /usr/local/lib/R/site-library `` ` contains binaries and libraries installed via ` `` install.packages() `` ` function inside R when admin/user has write permission in that folder
- ` `` home/ `` ` ` `` < `` ` ` `` user `` ` ` `` > `` ` ` `` /R/ `` ` ` `` < `` ` ` `` platform-name `` ` ` `` > `` ` ` `` -library/ `` ` ` `` < `` ` ` `` R-version `` ` ` `` > `` ` contains binaries and libraries via ` `` install.packages() `` ` function within R when admin/user do not have write permission in ` `` /usr/local/lib/R/site-library `` ` folder.

The R packages installed from within R take precedence over the packages installed via the Linux platform’s package management system, as shown in ` `` the.libPaths() `` ` hierarchy:

```
[1] "home/<user>/R/x86_64-pc-linux-gnu-library/4.1"
[2] "/usr/local/lib/R/site-library"
[3] "/usr/lib/R/site-library"
[4] "/usr/lib/R/library"
```

The folder structure indicates that you may need to look at different folders depending on the source of packages. One downside is that there may be multiple versions of one R package installed on your machine if you installed from different sources. In such cases, make sure to delete the version no longer in use to reduce complexity while coding.

To explore R packages that are in the development stage, use any of the methods listed in the next section to install them.

##  1.5.4 Installing R packages in development 

There are several ways to install packages that are in development stage (not in CRAN yet) or a newer development version of a ` `` CRAN `` ` package. You can install from GitHub ( ` `` install_github() `` ` ), Bitbucket ( ` `` install_bitbucket() `` ` ), CRAN ( ` `` install_cran() `` ` ), Subversion ( ` `` install_svn() `` ` ) and many other sources. For example, the development version of the ` `` purrr `` ` package can be installed by using any of the following methods:

```
# using remotes package
remotes::install_github(repo = "tidyverse/purrr")

# using devtools package
devtools::install_github(repo = "tidyverse/purrr")

# using xfun package
xfun::install_github(repo = "tidyverse/purrr")

# using pacman package
pacman::p_load_gh(repo = "tidyverse/purrr")
```

The ` `` remotes `` ` package is the parent of the ` `` install_*() `` ` class of functions. The same functions in the ` `` devtools `` ` package allow users to pass additional arguments via the ... along with other base arguments, providing flexibility to users. The function in the ` `` xfun `` ` package provides faster auto-completion, allowing further flexibility to users. Just type ` `` xfun::ig `` ` in your RStudio console and see what happens. The fourth one, from pacman installs and loads simultaneously. Technically, you just need one of these functions that suits your purpose.

You might have noticed ` `` :: `` ` between package name and the function name. This is used for calling a function via a namespace, that is, using the function from a package without loading the package. This is handy when you use only a limited number of functions from a package. It is also useful to avoid conflicts of function names coming from two different packages. For example, when ` `` tidyverse `` ` is loaded, you will notice that the ` `` filter() `` ` function from ` `` dplyr `` ` packages has a conflict with the ` `` filter() `` ` function from the ` `` stats `` ` package. The first one is used for data manipulation and the latter one is used for linear filtering of a time series. To avoid conflict and confusion you can call them via namespace; ` `` dplyr::filter() `` ` and ` `` stats::filter() `` ` when using both of them in one program/script.

After learning about several methods to install R packages, now it is time to load them into the R workspace.

#  1.6 Loading installed packages 

After installation, you need to load/attach a package in your R workspace. The ` `` library() `` ` function is used for that. The function throws an error and stops working if the package is not installed, which is a good way to identify what is missing. You can also specify the custom location via the ` `` lib.loc `` ` argument if have not done via ` `` .libPaths() `` ` already:

```
# load an installed package
library(dplyr)
```

You may have noticed that the ` `` require() `` ` function is also used to load packages. The main distinction is that the ` `` require() `` ` does not throw an error if a package is missing. In the worst case, you may have to spend hours figuring out why scripts that were working on your machine are not running on your colleague’s machine. This was one of the reasons behind the development of the ` `` pacman `` ` package. When the ` `` p_load() `` ` function is used to simultaneously installs and loads packages in the current workspace, the use of the ` `` library() `` ` function for attaching packages becomes redundant.

After loading a package in the R workspace, you can use its’ functionality while programming. However, it is also important to keep track of when an R package gets updated. In the next section you will find some best practices on how to update R suites without much hassle.

#  1.7 Updating software and packages 

R, RStudio and R packages are continuously evolving due to updates, fixing bugs, adding new functionality and so on. It is good to be up to date with the new technologies. However, it will take a fair bit of time to install the full suite again if you decide to update every time a minor release is out, or a newer version of a single package is available. As each component is installed/updated separately, you can update only R, RStudio, or R packages without touching the other two. A commonly fair update time frame may look like this:

-  Update R packages once a month
-  Update R once or twice a year, only when a major release is out. Some advanced packages are built using the most recent R version. You have to update R to enjoy the full functionality of these packages in case your machine’s version is older than what the packages are built on
-  Update RStudio only when a major release is available

Usually, RStudio notifies you when a new release is available and the general dependency when a package is installed. You can get more information from the package-specific CRAN sites too.

Remember to uninstall the previous version of R and RStudio before replacing with the newer version, and update the full list of packages when you update R.

##  1.7.1 Checking and updating R packages 

The easiest way to check and update R packages is via RStudio Packages menu. Click **Packages-** **\>** **Update -** **\>** **Select All -** **\>** **Install Updates** . All packages in the list have updated versions available. Hitting the **Install Update** button updates all packages wherever they are installed in your machine, either in the default or in a custom location.

Packages can be updated from the R console as well. First, make a list of the already installed packages and then re-install them using two lines of code given here:

```
# list of installed packages
pkg_list = as.data.frame(installed.packages(.libPaths()[1]),
                         stringsAsFactors = F)

# re-install packages
install.packages(pkg_list$Package)
```

##  1.7.2 Checking and updating R and RStudio 

The availability of a recent RStudio update can be checked from the Help menu by clicking on **Help-** **\>** **Check for Updates** .

For both R and RStudio, the simplest way is to uninstall the old version, download the newer one and follow steps for installing as you did for the first time. This method reduces the chance of conflicting setups when multiple R versions are present in one machine. You could save the content of an old ` `` .RProfile `` ` file, and copy-paste it into the new ` `` .RProfile `` ` file after re-installation is completed.

You could use a Windows specific package to update R from within R. Follow the instructions that appear after writing the following code snippet in the current R console:

```
install.packages("installr")
installr::updateR()
```

If a custom folder is used for packages, which is the standard case in Linux systems, make sure to update/re-install the full package list after R is updated/re-installed.

#  1.8 How to choose R packages 

It is not simple to pick an R package (packages) given the availability of alternatives to choose from. If you are an experienced R user, there is a high chance you already have a list of packages that you always use. Keeping yourself updated with the existing packages and any new packages in your area of expertise is the key to your success.

For the newcomers, CRAN Task Views ( <a href="https://cran.r-project.org/web/views/" style="text-decoration: none;">  https://cran.r-project.org/web/views/  </a> ) is a great place to start. It provides guidance on package usage by grouping them under certain topics. For example, **Time Series Analysis Task Views** lists packages according to data type, modeling, functionality and applicability.

The short package description provides important information about the methods and algorithms used in the package. The function level descriptions and help file provide more detailed information about function usage and application to data.

You can use the **SMART approach** like any standard goal setting activity.

-  **S** pecific:
  -  What is my purpose for using packages: is it data wrangling, statistical analysis, forecasting, predictive modeling, visualization?
  -  What can the package do that cannot be done in base R?
-  **M** easurable:
  -  Is it available on CRAN? For how long?
  -  What algorithms and methods are used?
  -  Do they appear in peer-reviewed journals, books, R-blogs, or other publications?
-  **A** chievable:
  -  Is there enough documentation available for me to learn?
  -  Do I understand the methodologies and algorithms?
-  **R** elevant:
  -  Is it applicable to my problem?
  -  Am I focused on a certain topic when searching for packages?
-  **T** ime bound:
  -  Can I apply the package to my problem in a reasonably quick time?

By answering these questions and researching package information, you will soon find some packages that will help solve your specific problems.

R packages are developed to make users’ lives easy, productive, and efficient. The best way to learn about a package is by using it. The time you spend researching and learning about a package thoroughly will ultimately give you an edge in long term. When you properly understand a package, you gain knowledge on how to apply the methods to your problem, which provides the wisdom to identify the right situation to apply the package functionality in general.

#  1.9 RStudio for productive programming 

RStudio is an IDE with greater emphasis on the word “integrated”. It does a lot of work that you may not notice under the hood to make you an efficient programmer. You will find plenty of documentation on using the various features of RStudio to reap the maximum benefit. The web page at <a href="https://docs.posit.co/ide/user/" style="text-decoration: none;">  https://docs.posit.co/ide/user/  </a> is a good start. This section will not describe at length how much of a productivity boost RStudio can give you. Rather, it includes some do’s and don’ts that we have found helpful and believe you will benefit from too.

##  1.9.1 Do configure global and project level options 

You can access and configure these options by clicking **Tools-** **\>** **Global** Options and **Tools-** **\>** **Project** Options. Most of the options are self-explanatory, and you can consult the documentation if needed. Some options are selected by default to optimize the user’s experience. However, you should set up the environment that best suits your needs using the wide range of options available. Be aware that the project-level ` `` .Rprofile `` ` file will overwrite the . ` `` Rprofile `` ` file in the ` `` Sys.getenv("HOME") `` ` directory.

##  1.9.2 Do set up a working directory 

We have seen that the default working directory is typically a user’s **Documents** folder. In an organization provided machine, the **Documents** folder is usually mapped to a network storage, such as OneDrive, and constantly updates when it senses the addition or deletion of files. When you save a file frequently (scripts will be saved automatically if code is run when set via **Global Options** ), that action constantly syncs the networked working directory downstream. You may experience that R is becoming slow as more and more projects are piling up in your network **Documents** folder, along with raw and intermediate data. To save yourself from agony, use a different location when creating projects rather than under the Documents folder, and change the default working directory via the **Tools-** **\>** **Global Options-** **\>** **R** menu.

Integration with Git is a better solution for keeping project backup than using network drive anyway.

##  1.9.3 Do start with an RStudio project 

Always begin analysis by setting up a project, even when you will be performing a small data analysis that requires writing a single script. The small amount of time it takes to set up an RStudio project will save you many hours down the track. In business, it is common for stakeholders to come back with a request to re-run an analysis that was done months ago. They also have an eye for detail. You may need to give a good explanation if the numbers in the summary table you supplied last quarter do not match when calculated again from the same data source. Such situations become trivial when code/analysis is developed within a project. In a project, you should have your code, libraries, data sources, SQL, graphs, tables, and, most importantly, your thought process behind the analysis all in one place. It will be easy to perform an analysis again or extend it in various directions when required.

##  1.9.4 Do not preserve the workspace between sessions 

Keep records of everything: used packages, data, data sources, SQL, code, analysis, plots, results, documentation, and presentation, but not the workspace between sessions. The previous session’s objects may jeopardize a new block of code within the same project or cause conflicts when you run scripts from other projects. In both situations, debugging will be harder. You should be able to recreate a computational environment using written scripts, not carrying the environment from session to session. You can achieve this by not restoring ` `` .RData `` ` at start up and never saving ` `` .RData `` ` on exit (available under the **Global Options** menu).
