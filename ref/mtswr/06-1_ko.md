# 1.1 R 생태계 소개

기술적인 부분에 들어가기 전에, 다음의 세 가지 초기 질문에 답하여 R 프로그래밍 생태계의 기본을 이해하는 것부터 시작해 보겠습니다.

- R이란 무엇인가?
- RStudio란 무엇인가?
- R 패키지란 무엇인가?

## 1.1.1 R이란 무엇인가?

R은 통계 계산 및 그래픽을 위한 프로그래밍 언어이자 환경을 동시에 나타내는 데 사용됩니다. 데이터 분석을 위한 다양한 통합 중간 도구 모음과 함께 통계 분석을 위한 일관된 시스템으로 개발되었습니다. R의 첫 번째 릴리스는 2000년 R 핵심 그룹(R Core Group)에서 오픈 소스 프로젝트로 발표했습니다. R의 제작자는 소프트웨어 제품군에 언어 및 환경의 절대적인 개념을 포함시켰습니다. 처음부터 지금까지 한 가지 모토가 유지되어 왔습니다. R에서 구현된 모든 것은 사용자가 완전한 제어권을 갖는다는 것입니다. 이는 R 사용자들에게 높은 평가를 받고 있습니다. 그러나 생성된 후에는 무엇이든 수정할 수 있다는 (Wickham, 2014) 태도는 새로운 사용자나 다른 프로그래밍 언어에서 온 사용자에게는 두려울 수 있습니다. 이로 인해 R은 프로그래밍 언어로서 다소 기이한 면을 갖게 됩니다. 하지만 약간의 기이함이 없는 언어가 과연 언어일까요?

## 1.1.2 RStudio란 무엇인가?

RStudio는 전통적으로 R을 계산 엔진으로 사용하는 통합 개발 환경(IDE)입니다. 데이터 분석, 시각화, 자동화된 보고서 작성, 디버깅 및 작업 공간 관리를 위한 도구 모음과 함께 사용자 친화적인 인터페이스를 제공합니다. 시간이 지남에 따라 RStudio는 Python, SQL 등과 같은 다른 프로그래밍 언어를 지원하도록 기능을 확장했습니다. 또한 Jupyter 노트북을 생성하거나 Visual Studio Code(VSCode)와 같은 코드 편집 소프트움을 사용할 수 있습니다. 이는 RStudio 자체의 기능을 향상시킬 뿐만 아니라 사용자가 하나의 데이터 과학 프로젝트에서 여러 언어를 사용하여 공동 작업을 다음 단계로 끌어올릴 수 있는 옵션을 제공합니다.

최근 개발에서 Positron IDE는 데이터 과학 워크플로를 위한 더 유연하고 언어에 구애받지 않는 환경을 제공하도록 설계된 최신 대안으로 등장했습니다. R, Python 및 기타 도구와의 원활한 통합을 지원하며 공동 작업 및 재현 가능한 연구에서 생산성을 향상시키도록 구축되었습니다. 이 책 전체에서 우리는 주로 RStudio를 활용할 것입니다. 그러나 제시된 기본 개념과 워크플로는 쉽게 사용할 수 있으며 Positron으로 전송할 수 있습니다.

RStudio는 여러 제품을 제공합니다. 오픈 소스 RStudio 데스크톱은 로컬에서 실행할 수 있으며 무료입니다. RStudio 데스크톱 프로는 조직용으로 상업적 라이선스가 부여됩니다. 조직이 요구 사항과 데이터 과학 여정의 성숙도에 따라 사용할 수 있는 Posit Team, Posit Workbench 및 Posit Connect와 같은 엔터프라이즈 수준 제품이 있습니다. Posit 사이트 <a href="https://posit.co/products/" style="text-decoration: none;"> https://posit.co/products/ </a> 에서 제품 설명을 찾을 수 있습니다.

이 책은 로컬에서 코드를 실행할 수 있는 무료 버전의 RStudio 데스크톱을 참조하며 비용이 발생하지 않습니다. 달리 명시되지 않는 한 이 책에서 RStudio라는 용어는 구체적으로 RStudio 데스크톱을 나타냅니다.

## 1.1.3 R 패키지란 무엇인가?

R 패키지는 기본 R 프로그래밍 언어의 확장이며 일반적 으로 문제를 해결하기 위한 함수, 메서드 및 알고리즘의 모음을 포함합니다. R 패키지는 학계와 산업계의 모든 전문 분야에서 온 전 세계의 광범위한 R 사용 커뮤니티에 의해 작성됩니다. 보통 R 패키지는 특정 문제 해결에 중점을 둡니다. 예를 들어, `dplyr` (Wickham et al., 2023)은 데이터 조작을 위한 함수를 제공하고, `ggplot2` (Wickham, 2016)는 통계 및 계산을 위한 그래픽의 문법을 구현하며, `forecast` 패키지 (Hyndman et al., 2025)는 예측에 특별히 중점을 두고 일변량 시계열을 시각화하고 분석하기 위해 개발되었습니다. 방대한 R 패키지 모음은 연구 개발의 수고를 덜고 당면한 문제를 해결하는 데 도움이 될 것입니다.

이제 R, RStudio 및 R 패키지에 대한 기초적인 이해를 마쳤으므로 이 장의 나머지 부분에서는 다양한 운영 체제에서 필요한 소프트웨어에 접근하고 설치하는 방법을 안내할 것입니다.

# 1.3 관리자 권한으로 R 및 RStudio 설치

기기에 대한 관리자 권한이 있는 경우 설치 방법은 Windows 및 macOS에서 다운로드 후 클릭하는 방식과 거의 같습니다. Linux 기반 시스템의 경우 시스템의 종류(Debian, Ubuntu 또는 Fedora/Red hat)에 따라 약간씩 다른 세 가지 방법이 있습니다. 운영 체제와 관련된 지침을 읽고 따르는 것이 중요합니다.

## 1.3.1 Windows

기본적으로 R 및 RStudio는 `C:\Program Files` 아래에 설치됩니다. 이로 인해 설치에 필요한 관련 폴더가 생성됩니다. 패키지 설치를 위해 R은 R 설치 내의 `library` 폴더를 사용합니다. 루트 `C:\` 폴더에 대한 관리자 권한이 있는 경우 다음 단계를 따르세요.

1. R용으로 다운로드한 `.exe` 파일을 두 번 클릭합니다.

2. 프롬프트에 나타나는 지침에 따라 R을 설치합니다.

3. RStudio용으로 다운로드한 `.exe` 파일을 두 번 클릭하고 지침에 따라 설치합니다.

4. RStudio 아이콘을 엽니다. RStudio 버전에 따라 R 버전을 선택하라는 메시지가 표시될 수 있습니다.

5. RStudio 콘솔에서 다음 명령을 실행(입력 후 Enter 키 누름)합니다.

   ```
   R.home()
   Sys.getenv("R_HOME")

   Sys.getenv("HOME")
   path.expand("~")
   getwd()

   .libPaths()
   ```

이 명령은 설치 중에 사용된 폴더 구조를 가리킵니다. 예를 들면 다음과 같습니다.

- `R.home()` 및 `Sys.getenv("R_HOME")`은 R이 설치된 위치를 반환합니다. 이는 `C:/Program Files/R/R-4.2.3` 이 될 것입니다.
- `Sys.getenv("HOME")`, `path.expand("~")`, `getwd()`는 사용자의 홈 디렉터리를 반환하며 일반적으로 `C:/Users//Documents` 입니다. 또한 R의 기본 작업 디렉터리이기도 합니다. 코딩할 때 전체 경로를 작성하는 대신 약어 ~ 문자를 사용할 수 있습니다.
- `.libPaths()`는 패키지 설치를 위한 기본 위치를 반환하며, 이는 `C:/Program Files/R/R-4.2.3/library` 가 될 것입니다.

다음 섹션에서는 macOS에서 설치 과정을 수행하는 방법을 알아봅니다.

## 1.3.2 macOS

macOS용 R과 RStudio를 다운로드할 때 Apple Silicon 또는 Intel 중 시스템에 맞는 올바른 아키텍처를 선택해야 합니다. R 및 RStudio의 설치 관리자에는 각각 .pkg 및 .dmg 확장자가 있습니다.

1. 다운로드한 `.pkg` 파일을 클릭합니다.

2. 지침과 프롬프트를 따라(다음 여러 번 선택) 기본 위치에 R을 설치합니다.

3. RStudio의 경우 `.dmg` 파일을 두 번 클릭합니다. 애플리케이션 및 RStudio 아이콘이 나란히 있는 폴더가 열립니다. RStudio 아이콘을 애플리케이션 폴더로 드래그하여 설치합니다.

4. 애플리케이션 폴더로 이동하여 R과 RStudio를 모두 사용할 수 있는지 확인합니다.

5. RStudio를 열고 콘솔에 다음 명령을 입력하여 설치 폴더, 홈 폴더 및 패키지 설치 경로를 확인합니다.

   ```
   R.home()
   Sys.getenv("HOME")
   .libPaths()
   ```

다음 섹션은 Linux 사용자를 위한 설치 과정에 대해 설명합니다.

## 1.3.3 Linux

Linux 시스템의 단계는 다음과 같습니다.

1. 플랫폼별 시스템 패키지 관리자를 설치합니다.
2. `/etc/apt/sources.list` 파일에 Linux 배포판 이름과 함께 CRAN 저장소를 추가합니다.
3. Linux 시스템 패키지 관리자 및 `apt` 도구를 통해 R을 설치합니다.

쓰기 권한이 있는 경우 다음 시스템별 시나리오에서 제공되는 코드 줄에서 `sudo`를 생략할 수 있습니다.

### 1.3.3.1 Ubuntu

이러한 단계는 Ubuntu Jammy Jellyfish(22.04, AMD64)에 대해 설명됩니다. 사용된 `jammy` 또는 빌드 이름을 교체하여 모든 Ubuntu 빌드에 이 단계를 적용할 수 있습니다.

1. R을 설치하기 위한 Ubuntu의 도우미 패키지를 설치합니다.

   ```
   sudo apt update -qq
   sudo apt install --no-install-recommends software-properties-common dirmngr
   ```

2. 터미널에 아래 내용을 입력하여 `/etc/apt/sources.list`에 CRAN 리포지토리를 추가합니다.

   ```
   sudo add-apt-repository "deb https://cloud.r-project.org/bin/linux/ubuntu $(lsb_release -cs)-cran40/"
   ```

   `lsb_release -cs`는 `jammy` 또는 `focal`과 같은 Ubuntu 빌드의 이름으로 대체됩니다.

   또는 텍스트 편집기(`vim` 또는 `nano` 등)에서 `/etc/apt/sources.list` 파일을 열고 수동으로 `deb \ https://cloud.r-project.org/bin/linux/ubuntu jammy-cran40/` 을 추가합니다.

3. 터미널에서 다음 코드를 실행하여 R 및 해당 종속성을 설치합니다.

   ```
   sudo apt install --no-install-recommends r-base r-base-core r-recommended r-base-dev
   ```

4. 터미널에 R을 입력하여 설치를 테스트합니다. R 내에서 `R.home()`, `Sys.getenv()` 및 `.libPaths()`를 확인합니다. `.libPaths()` 안에 세 개의 다른 폴더가 있어서 놀라셨나요? 우리는 이것에 대해 R 패키지 경로 하위 섹션에서 더 자세히 알아볼 것입니다.

5. RStudio를 설치하려면 먼저 터미널을 통해 Posit 사이트(이전 <a href="https://rstudio.org" style="text-decoration: none;"> rstudio.org </a>)에서 다운로드합니다.

   ```
   wget https://download1.rstudio.org/electron/jammy/amd64/rstudio-2023.03.0-386-amd64.deb
   ```

6. 그런 다음 다운로드가 완료된 후 설치합니다.

   ```
   sudo apt install -f ./rstudio-2023.03.0-386-amd64.deb
   ```

7. 애플리케이션 -> RStudio에서 또는 터미널을 통해 설치된 RStudio를 시작합니다.

   ```
   rstudio
   ```

### 1.3.3.2 Debian

작성 당시 Debian Bookworm이 안정적인 버전입니다. 그러나 향후 새로운 버전을 사용할 수 있게 되면 터미널 명령에서 다른 Debian 버전으로 변경할 수 있습니다. 다음 명령은 터미널에서 실행됩니다.

1. Debian 패키지 관리자에서 `R add-ons`를 검색합니다.

   ```
   apt search "^r-.*" | sort
   ```

2. `/etc/apt/sources.list.d` 파일 디렉터리에 CRAN 항목을 추가하고 GPG 키를 안전하게 가져옵니다.

   ```
   sudo apt update

   sudo apt install --no-install-recommends software-properties-common dirmngr gnupg ca-certificates

   curl -sSL "keyserver.ubuntu.com" | sudo gpg --dearmor -o /usr/share/keyrings/cran-archive-keyring.gpg

   echo "deb [signed-by=/usr/share/keyrings/cran-archive-keyring.gpg] https://cloud.r-project.org/bin/linux/debian bookworm-cran40/" | sudo tee /etc/apt/sources.list.d/cran.list
   ```

3. 이제 다음 명령을 실행하여 R을 설치합니다.

   ```
   sudo apt update
   sudo apt install r-base r-base-core r-base-dev
   ```

   미리 컴파일된 Debian 또는 Ubuntu 패키지로 사용할 수 없는 소스에서 R 패키지를 컴파일할 때 `r-base-dev`가 필요합니다.

4. RStudio 설치는 Debian에 적합한 RStudio 버전(Debian 12+)을 다운로드해야 한다는 점을 제외하면 Ubuntu용 Debian에서 동일합니다.

   ```
   wget https://rstudio.org/download/latest/stable/desktop/jammy/rstudio-latest-amd64.deb -O rstudio-latest-amd64.deb

   sudo apt install -f ./rstudio-latest-amd64.deb
   rstudio
   ```

<a href="https://cran.r-project.org/bin/linux" style="text-decoration: none;"> cran.r-project.org/bin/linux </a> 사이트에서는 Fedora, Red Hat 및 SUSE와 같은 다른 Linux 배포판에 R을 설치하는 방법을 설명합니다. 누락된 공개 키와 이를 수정하는 방법 등 설치 프로세스 중에 문제가 있는 경우에도 좋은 참고 자료입니다.

RStudio를 설치하는 동안 Linux 사용자는 운영 체제의 보안 정책에 의해 제한될 수 있으며 Posit의 공개 코드 서명 키를 가져와야 할 수 있습니다. 2단계에서 문제가 발생하면 <a href="https://posit.co/code-signing/" style="text-decoration: none;"> https://posit.co/code-signing/ </a> 으로 이동하여 공개 키 가져오기에 대한 지침을 따르세요.

지금까지 기본 설치 폴더에 R 제품군을 설치하는 방법을 배웠습니다. 다음으로 사용자 지정 폴더 위치에 R과 RStudio를 설치하는 방법을 살펴보겠습니다.

# 1.4 사용자 지정 위치에 설치

회사에서 관리하는 컴퓨터의 경우 드라이브의 루트와 같은 시스템 수준 디렉터리에 응용 프로그램을 설치할 수 있는 관리자 권한이 없을 수 있습니다. 시스템 관리자가 R 및 RStudio를 기본 위치(Windows의 `C:\Program Files` 또는 macOS의 `/Applications`)에 설치할 수 있지만 R의 기본 라이브러리 폴더에 대한 쓰기 권한이 없으면 패키지 설치가 여전히 실패할 수 있습니다. 패키지를 설치할 때마다 티켓을 제기하여 IT 관리자의 지원을 받는 것은 실용적이지 않습니다. 사용자 지정 폴더에 R 및 RStudio를 설치하면 문제를 해결할 수 있습니다. 기본 R 소프트웨어를 기본 위치에 설치할 수 있는 곳에서는 패키지용으로만 사용자 지정 폴더를 사용할 수도 있습니다.

Windows 컴퓨터의 `D:\` 드라이브(또는 macOS의 경우 `/Users/<YourName>/`)에 쓰기 권한이 있고 거기에 R과 RStudio를 설치할 수 있다고 가정해 보겠습니다. 먼저 이 위치(Windows의 경우 `D:\<Username>\R` 또는 macOS의 경우 `/Users/<YourName>/R/`)에 R이라는 폴더를 만들어야 하며, R 및 RStudio 표준 설치 프로세스 중에 이 경로를 대상 폴더로 사용해야 합니다. R 패키지를 설치할 때도 동일한 위치를 사용할 수 있습니다. 개인 패키지 라이브러리를 설치하기 위해 `D:\<Username>\R\RPackages`(또는 macOS의 경우 `/Users/<YourName>/R/RPackages/`)라는 폴더를 만듭니다.

Windows에서 폴더 트리는 다음과 같습니다.

```
Username/R/
├── R-4.2.3/
├── RPackages/
└── RStudio/
```

이제 패키지 설치를 위한 대상 폴더를 구성할 수 있습니다. Windows를 사용하든 macOS를 사용하든 RStudio를 열고 콘솔에 `.libPaths()`를 입력합니다. 기본 패키지 설치 폴더 경로가 출력됩니다. `.Rprofile` 파일에 사용자 지정 패키지 설치 위치를 제공할 수 있습니다. 콘솔에 다음 명령을 입력합니다.

```
file.edit("~/.Rprofile")
```

기본 작업 디렉터리에서 빈 파일인 `.Rprofile` 파일이 열립니다. 그 안에 다음 코드 스니펫을 작성하고 저장한 다음 닫습니다. `<Username>` 부분을 적절하게 변경하세요.

```
.First <- function() {
  path_to_package = "D:/<Username>/R/RPackages"
  .libPaths(c(path_to_package, .libPaths()))
}
```

RStudio를 다시 시작합니다. 콘솔에 `.libPaths()`를 입력하거나 (제공된 폴더 이름이 첫 번째 항목으로 나타나야 함) RStudio에서 패키지 -> 설치를 열어 변경 사항을 확인할 수 있습니다.

다양한 운영 체제와 상황에 맞게 R과 RStudio를 설치하는 방법을 배웠으므로 이제 패키지를 설치하는 방법을 살펴보겠습니다.

# 1.5 R 패키지 설치

R 패키지는 함수, 컴파일된 코드 및 데이터가 멋지게 번들로 제공되는 모음으로, 다운로드하여 사용할 수 있도록 CRAN(또는 GitHub)에 호스팅됩니다. 이 책을 쓰는 시점에서 CRAN에는 1만 9천 개 이상의 패키지가 제공되고 있습니다. GitHub에서 개발 단계에 있는 패키지의 정확한 목록은 없습니다. 이 엄청난 수의 패키지를 보면 시간이 지남에 따라 R 커뮤니티가 얼마나 넓고 깊게 성장했는지 알 수 있습니다. 각 패키지는 오픈 소스이며 무료로 사용할 수 있습니다. 통계 계산 소프트웨어로 탄생한 R은 R 패키지의 도움으로 먼 길을 왔습니다.

기본 R은 약 8개의 패키지와 함께 제공됩니다. CRAN(안정적인 버전)이나 GitHub(개발 버전)에서 다른 패키지를 가져올 수 있습니다.

R 작업 공간에서 패키지의 기능을 사용하려면 패키지를 설치하고 로드해야 합니다.

- 첫째, 원하는 R 패키지를 다운로드하고 설치합니다. 패키지를 설치하면 R 설치 디렉터리 내에 또는 기기의 사용자 지정 디렉터리(섹션 1.4에 설명됨)에 패키지별 폴더가 생성됩니다. 이 폴더에는 특정 패키지에 대한 모든 바이너리, 코드 및 설명서가 포함되어 있습니다.
- 둘째, 패키지를 적극적으로 사용하려면 R 작업 공간에서 패키지를 호출해야 합니다. R 패키지를 설치하는 방법에는 두 가지가 있습니다. RStudio 메뉴와 R 콘솔입니다. 다음 두 하위 섹션에서 이 두 가지 방법을 모두 수행하는 방법을 배웁니다.

## 1.5.1 RStudio 메뉴를 통한 패키지 설치

RStudio의 패키지 메뉴를 사용하여 원하는 수의 패키지를 설치할 수 있습니다. 저장소를 설정하고 입력할 때 패키지 목록을 보고(사용 가능한 다른 패키지를 알아보는 방법), 설치할 위치를 선택할 수 있습니다.

## 1.5.2 R 콘솔을 통한 패키지 설치

CRAN에서 패키지를 설치하려면 R 콘솔에서 패키지 이름을 큰따옴표로 묶어 괄호 안에 넣은 `install.packages()`를 입력합니다. 한 번의 실행으로 하나에서 여러 개까지 패키지를 설치할 수 있습니다.

```
# 단일 패키지 설치
install.packages("dplyr")

# 여러 패키지 설치
install.packages(c("DBI", "tibble", "dplyr",
                   "ggplot2", "fst", "knitr"))
```

사용자 지정 패키지 위치가 `.Rprofile`을 통해 이미 설정되지 않은 경우 `install.packages()` 함수 내의 `lib` 옵션에 경로를 제공하여 즉시 사용자 지정 위치를 지정할 수 있습니다.

시간이 지남에 따라 항상 필요한 R 패키지 목록이 생길 것입니다. 새 R 프로젝트로 이동하거나, R을 업데이트하거나, 기기를 변경하거나, 다른 조직으로 이동할 때 이러한 패키지를 설치해야 하는데, 어떤 패키지가 어디에 설치되어 있는지 기억하기 어렵습니다. 즉시 누락된 패키지를 설치하는 방법은 패키지 관리를 나타내는 `pacman` 패키지의 `p_install()` 또는 `p_load()` 함수를 사용하는 것입니다. `p_install()` 함수는 누락된 패키지를 설치하고 `p_load()` 함수는 현재 작업 공간에 패키지를 설치하고 동시에 로드합니다. 다음 코드는 먼저 `pacman`을 설치(설치되지 않은 경우)한 다음 다른 패키지를 설치하는 데 사용하는 방법을 보여줍니다.

```
if (!requireNamespace("pacman", quietly = TRUE)) {
  install.packages("pacman")
}

pacman::p_load(DBI, tibble, dplyr, ggplot2, fst, knitr)
```

이 코드는 독립형 R 스크립트의 시작 부분이나 모든 R 프로젝트의 스크립트로 포함되어야 합니다. 이렇게 하면 공동 작업자와 공유할 때 누락된 패키지로 인해 코드가 손상될까 봐 걱정할 필요가 없습니다.

Linux에서는 R 내에서 `install.packages()` 함수를 호출할 수 있습니다. 이는 Linux 시스템에 R을 설치할 때 `r-base-dev`를 설치했다고 가정할 때 작동합니다. 먼저 터미널에서 R을 호출합니다.

```
R
```

그런 다음 R 내에서 다음을 입력합니다.

```
install.packages("dplyr")
```

처음에는 기본 설치 경로에 쓰기 권한이 없는 경우 개인 라이브러리를 만들 것인지 묻습니다.

```
Installing packages into '/usr/local/lib/R/site-library'
(as 'lib' is unspecified)
Warning in install.packages("dplyr") :
'lib = "/usr/local/lib/R/site-library"' is not writable
Would like to use a personal library instead? (yes/No/cancel)
```

예(yes)를 입력하면 `home/<user>/R/<platform name>-library/<R version>` 유형의 폴더가 생성되고 설치 권한을 요청합니다. `<platform-name>`은 x86-64-pc-linux-gnu와 같은 Linux 시스템 이름이고, R-version은 설치된 R의 버전입니다. 이 방법은 `r-base-dev`의 강력한 기능을 사용하여 소스에서 패키지를 컴파일합니다.

Ubuntu의 경우 Ubuntu의 R 패키지 저장소 `c2d4u`를 추가한 후 터미널에서 `apt install`을 사용할 수도 있습니다.

```
sudo add-apt-repository ppa:c2d4u.team/c2d4u4.0+
sudo apt install --no-install-recommends r-cran-dplyr
```

기본 위치에 쓰기 권한이 없는 경우 패키지 설치를 위한 사용자별 위치를 생성하라는 메시지가 표시될 수 있습니다. `c2d4u` 저장소에는 5000개 이상의 R 패키지가 있습니다. 모든 Ubuntu 빌드에 이 저장소를 사용할 수 있지만 개발자는 c2d4u 저장소의 이점을 최대한 활용하려면 장기 지원(LTS) 릴리스를 사용할 것을 강력히 제안합니다.

설치 시 각각 고유한 폴더 계층 구조가 있는 R 패키지를 설치하는 여러 가지 방법이 있음을 살펴보았습니다. 한 방법이 다른 방법보다 나을까요? 다음 섹션에서 답을 찾아보세요.

## 1.5.3 R 패키지 경로

R 패키지가 설치되면 `.libPaths()`에 나열된 디렉터리 아래에 패키지별 폴더가 생성된다는 것을 이미 알고 있습니다. Windows와 macOS에서 모든 패키지는 기본적으로 R 설치 내의 라이브러리 폴더에 설치됩니다. `.libPaths()`의 첫 번째 항목으로 폴더를 할당하여 사용자 지정 설치 경로를 사용할 수 있습니다. 해당 폴더 안에 설치된 모든 R 패키지는 `.libpaths()`[1]로 찾을 수 있습니다.

Windows와 macOS의 경우 패키지 설치 방법에 따른 폴더 구조의 우선순위가 없습니다. 패키지 설치 방법(RStudio의 패키지 메뉴 또는 R 콘솔의 `install.packages()` 사용)에 관계없이 모든 패키지가 하나의 폴더 아래에 설치됩니다.

Linux 시스템에서는 R 패키지 경로가 약간 다르게 작동합니다.

- `/usr/lib/R/library`에는 R 빌드(`r-base` 및 `r-recommends`)의 바이너리 및 라이브러리가 포함됩니다.
- `/usr/lib/R/site-library`에는 `r-cran-*` 및 `r-bioc-*`에서 설치된 사전 컴파일된 Debian(또는 Ubuntu) R 패키지의 바이너리 및 라이브러리가 포함됩니다.
- `/usr/local/lib/R/site-library`에는 관리자/사용자가 해당 폴더에 대한 쓰기 권한이 있을 때 R 내부의 `install.packages()` 함수를 통해 설치된 바이너리 및 라이브러리가 포함됩니다.
- `home/<user>/R/<platform-name>-library/<R-version>`에는 관리자/사용자가 `/usr/local/lib/R/site-library` 폴더에 대한 쓰기 권한이 없을 때 R 내부의 `install.packages()` 함수를 통한 바이너리 및 라이브러리가 포함됩니다.

R 내에서 설치된 R 패키지는 `the.libPaths()` 계층 구조에 표시된 것처럼 Linux 플랫폼의 패키지 관리 시스템을 통해 설치된 패키지보다 우선합니다.

```
[1] "home/<user>/R/x86_64-pc-linux-gnu-library/4.1"
[2] "/usr/local/lib/R/site-library"
[3] "/usr/lib/R/site-library"
[4] "/usr/lib/R/library"
```

폴더 구조는 패키지 소스에 따라 다른 폴더를 살펴보아야 할 수도 있음을 나타냅니다. 한 가지 단점은 다른 소스에서 설치한 경우 기기에 하나의 R 패키지의 여러 버전이 설치되어 있을 수 있다는 것입니다. 이러한 경우 코딩 시 복잡성을 줄이기 위해 더 이상 사용하지 않는 버전을 삭제해야 합니다.

개발 단계에 있는 R 패키지를 탐색하려면 다음 섹션에 나열된 방법 중 하나를 사용하여 설치하십시오.

## 1.5.4 개발 중인 R 패키지 설치

개발 단계(아직 CRAN에 없음)에 있거나 CRAN 패키지의 최신 개발 버전에 있는 패키지를 설치하는 방법에는 여러 가지가 있습니다. GitHub(`install_github()`), Bitbucket(`install_bitbucket()`), CRAN(`install_cran()`), Subversion(`install_svn()`) 및 기타 여러 소스에서 설치할 수 있습니다. 예를 들어, 다음 방법 중 하나를 사용하여 `purrr` 패키지의 개발 버전을 설치할 수 있습니다.

```
# remotes 패키지 사용
remotes::install_github(repo = "tidyverse/purrr")

# devtools 패키지 사용
devtools::install_github(repo = "tidyverse/purrr")

# xfun 패키지 사용
xfun::install_github(repo = "tidyverse/purrr")

# pacman 패키지 사용
pacman::p_load_gh(repo = "tidyverse/purrr")
```

`remotes` 패키지는 `install_*()` 클래스 함수의 부모입니다. `devtools` 패키지의 동일한 기능을 통해 사용자는 다른 기본 인수와 함께 ...을 통해 추가 인수를 전달하여 사용자에게 유연성을 제공할 수 있습니다. `xfun` 패키지의 기능은 더 빠른 자동 완성을 제공하여 사용자에게 더 많은 유연성을 허용합니다. RStudio 콘솔에 `xfun::ig`를 입력하고 어떻게 되는지 확인해 보세요. 네 번째는 pacman에서 동시에 설치하고 로드합니다. 기술적으로는 목적에 맞는 이러한 함수 중 하나만 있으면 됩니다.

패키지 이름과 함수 이름 사이에 `::`가 있는 것을 눈치채셨을 것입니다. 이는 네임스페이스를 통해 함수를 호출하는 데 사용됩니다. 즉, 패키지를 로드하지 않고 패키지의 함수를 사용하는 것입니다. 패키지에서 제한된 수의 함수만 사용할 때 편리합니다. 또한 두 개의 다른 패키지에서 나오는 동일한 이름의 함수 간의 충돌을 피하는 데 유용합니다. 예를 들어 `tidyverse`가 로드되면 `dplyr` 패키지의 `filter()` 함수가 `stats` 패키지의 `filter()` 함수와 충돌하는 것을 볼 수 있습니다. 첫 번째 함수는 데이터 조작에 사용되고 후자는 시계열의 선형 필터링에 사용됩니다. 충돌과 혼동을 피하기 위해 하나의 프로그램/스크립트에서 둘 다 사용할 때 네임스페이스를 통해 호출할 수 있습니다. 즉, `dplyr::filter()` 및 `stats::filter()`와 같이 호출합니다.

R 패키지를 설치하는 여러 방법에 대해 배운 후 이제 R 작업 공간에 로드할 시간입니다.

# 1.6 설치된 패키지 로드

설치 후 R 작업 공간에 패키지를 로드/연결해야 합니다. 이를 위해 `library()` 함수가 사용됩니다. 이 함수는 패키지가 설치되지 않은 경우 오류를 발생시키고 작동을 멈추므로 무엇이 누락되었는지 식별하는 좋은 방법입니다. `.libPaths()`를 통해 아직 수행하지 않은 경우 `lib.loc` 인수를 통해 사용자 지정 위치를 지정할 수도 있습니다.

```
# 설치된 패키지 로드
library(dplyr)
```

`require()` 함수도 패키지를 로드하는 데 사용된다는 것을 알고 계실 것입니다. 큰 차이점은 `require()`는 패키지가 누락된 경우 오류를 발생시키지 않는다는 것입니다. 최악의 경우 내 기기에서는 작동하던 스크립트가 동료의 기기에서는 실행되지 않는 이유를 파악하는 데 몇 시간을 보내야 할 수도 있습니다. 이것이 `pacman` 패키지 개발의 이유 중 하나였습니다. `p_load()` 함수를 사용하여 현재 작업 공간에 패키지를 동시에 설치하고 로드하면 패키지를 연결하기 위해 `library()` 함수를 사용하는 것이 불필요해집니다.

R 작업 공간에 패키지를 로드한 후 프로그래밍할 때 해당 기능을 사용할 수 있습니다. 그러나 R 패키지가 언제 업데이트되는지 추적하는 것도 중요합니다. 다음 섹션에서는 큰 번거로움 없이 R 제품군을 업데이트하는 방법에 대한 몇 가지 모범 사례를 찾을 수 있습니다.

# 1.7 소프트웨어 및 패키지 업데이트

R, RStudio 및 R 패키지는 업데이트, 버그 수정, 새로운 기능 추가 등으로 인해 지속적으로 발전하고 있습니다. 새로운 기술을 최신 상태로 유지하는 것이 좋습니다. 그러나 마이너 릴리스가 나올 때마다 또는 단일 패키지의 최신 버전을 사용할 수 있을 때마다 전체 제품군을 업데이트하기로 결정하면 전체 제품군을 다시 설치하는 데 상당한 시간이 걸립니다. 각 구성 요소는 별도로 설치/업데이트되므로 다른 두 구성 요소를 건드리지 않고 R, RStudio 또는 R 패키지만 업데이트할 수 있습니다. 일반적으로 적절한 업데이트 기간은 다음과 같습니다.

- R 패키지는 한 달에 한 번 업데이트합니다.
- R은 주요 릴리스가 나올 때만 1년에 한두 번 업데이트합니다. 일부 고급 패키지는 최신의 R 버전을 사용하여 구축됩니다. 기기의 버전이 패키지가 구축된 버전보다 오래된 경우 패키지의 전체 기능을 즐기려면 R을 업데이트해야 합니다.
- RStudio는 주요 릴리스를 사용할 수 있을 때만 업데이트합니다.

일반적으로 RStudio는 새 릴리스가 제공될 때 알려주고 패키지가 설치될 때 일반적인 종속성을 알려줍니다. 패키지 전용 CRAN 사이트에서도 더 많은 정보를 얻을 수 있습니다.

새 버전으로 교체하기 전에 이전 버전의 R 및 RStudio를 제거하고, R을 업데이트할 때 패키지의 전체 목록을 업데이트하는 것을 잊지 마십시오.

## 1.7.1 R 패키지 확인 및 업데이트

R 패키지를 확인하고 업데이트하는 쉬운 방법은 RStudio 패키지 메뉴를 사용하는 것입니다. 패키지 -> 업데이트 -> 모두 선택 -> 업데이트 설치를 클릭합니다. 목록에 있는 모든 패키지는 사용 가능한 업데이트 버전이 있습니다. 업데이트 설치 버튼을 누르면 기본 위치나 사용자 지정 위치 등 기기에 설치된 위치에 관계없이 모든 패키지가 업데이트됩니다.

패키지는 R 콘솔에서도 업데이트할 수 있습니다. 먼저 이미 설치된 패키지 목록을 만든 다음 여기에 제공된 두 줄의 코드를 사용하여 다시 설치합니다.

```
# 설치된 패키지 목록
pkg_list = as.data.frame(installed.packages(.libPaths()[1]),
                         stringsAsFactors = F)

# 패키지 다시 설치
install.packages(pkg_list$Package)
```

## 1.7.2 R 및 RStudio 확인 및 업데이트

최신 RStudio 업데이트가 있는지 확인하려면 도움말 메뉴에서 도움말 -> 업데이트 확인을 클릭하면 됩니다.

R과 RStudio 모두 간단한 방법은 이전 버전을 제거하고 최신 버전을 다운로드한 다음 처음 설치할 때 했던 설치 단계를 따르는 것입니다. 이 방법은 하나의 기기에 여러 R 버전이 존재할 때 충돌하는 설정의 가능성을 줄여줍니다. 이전 `.RProfile` 파일의 내용을 저장하고 재설치가 완료된 후 새 `.RProfile` 파일에 복사하여 붙여넣을 수 있습니다.

Windows 전용 패키지를 사용하여 R 내에서 R을 업데이트할 수 있습니다. 현재 R 콘솔에서 다음 코드 스니펫을 작성한 후 나타나는 지침을 따릅니다.

```
install.packages("installr")
installr::updateR()
```

패키지에 사용자 지정 폴더를 사용하는 경우(Linux 시스템의 표준임), R을 업데이트/다시 설치한 후 전체 패키지 목록을 업데이트/다시 설치해야 합니다.

전체 R 제품군과 선택한 R 패키지를 설치한 후 이제 R 패키지에 대해 배우고 사용하는 여정을 시작할 준비가 되었습니다. 단일 작업을 수행하는 데 사용할 수 있는 여러 R 패키지가 있음을 이미 눈치채셨을 것입니다. 어느 패키지가 좋을까요? 선택할 수 있는 대안의 풀에서 배울 R 패키지를 어떻게 선택하시겠습니까? 다음 섹션에서는 R 패키지 선택(따라서 R 학습)을 원활하게 진행할 수 있도록 몇 가지 주요 사항을 강조합니다.

# 1.8 R 패키지 선택 방법

선택할 수 있는 대안이 많기 때문에 R 패키지(패키지들)를 선택하는 것은 간단하지 않습니다. 숙련된 R 사용자라면 항상 사용하는 패키지 목록이 있을 가능성이 높습니다. 전문 분야의 기존 패키지와 새로운 패키지를 최신 상태로 유지하는 것이 성공의 열쇠입니다.

초보자에게는 CRAN Task Views( <a href="https://cran.r-project.org/web/views/" style="text-decoration: none;"> https://cran.r-project.org/web/views/ </a> )가 시작하기에 좋은 곳입니다. 특정 주제로 패키지를 그룹화하여 패키지 사용에 대한 지침을 제공합니다. 예를 들어 시계열 분석 Task Views는 데이터 유형, 모델링, 기능 및 적용 가능성에 따라 패키지를 나열합니다.

짧은 패키지 설명은 패키지에 사용된 방법 및 알고리즘에 대한 중요한 정보를 제공합니다. 함수 수준 설명 및 도움말 파일은 함수 사용 및 데이터 적용에 대한 자세한 정보를 제공합니다.

표준 목표 설정 활동과 마찬가지로 SMART 접근 방식을 사용할 수 있습니다.

- Specific (구체적인):
  - 패키지 사용 목적이 무엇인가: 데이터 랭글링, 통계 분석, 예측, 예측 모델링, 시각화인가?
  - 기본 R에서는 할 수 없는 일 중 패키지가 할 수 있는 일은 무엇인가?
- Measurable (측정 가능한):
  - CRAN에서 사용할 수 있는가? 얼마나 오랫동안?
  - 어떤 알고리즘과 방법을 사용하는가?
  - 동료 평가를 거친 저널, 책, R 블로그 또는 기타 출판물에 게재되는가?
- Achievable (달성 가능한):
  - 내가 배울 수 있는 충분한 문서가 있는가?
  - 방법론과 알고리즘을 이해하고 있는가?
- Relevant (관련성 있는):
  - 내 문제에 적용할 수 있는가?
  - 패키지를 검색할 때 특정 주제에 집중하고 있는가?
- Time bound (기한이 있는):
  - 합리적으로 빠른 시간 내에 내 문제에 패키지를 적용할 수 있는가?

이러한 질문에 답하고 패키지 정보를 조사하면 특정 문제를 해결하는 데 도움이 되는 몇 가지 패키지를 곧 찾을 수 있습니다.

R 패키지는 사용자의 삶을 쉽고 생산적이며 효율적으로 만들기 위해 개발되었습니다. 패키지에 대해 배우는 좋은 방법은 패키지를 사용하는 것입니다. 패키지를 철저히 조사하고 학습하는 데 보내는 시간은 궁극적으로 장기적으로 여러분에게 이점을 제공할 것입니다. 패키지를 제대로 이해하면 문제에 메서드를 적용하는 방법에 대한 지식을 얻게 되며, 이는 일반적으로 패키지 기능을 적용할 적절한 상황을 식별하는 지혜를 제공합니다.

이제 RStudio에 초점을 맞춰보겠습니다. 개발 환경 없이 R을 사용할 수 있습니다. RStudio는 특히 R과 대화식으로 작동하도록 구축되었으며 이제 다른 프로그래밍 언어로 확장되었습니다. 다음 섹션에서는 RStudio가 프로그래머 및/또는 데이터 전문가로서 생산성과 효율성을 어떻게 향상시킬 수 있는지 알아봅니다.

# 1.9 생산적인 프로그래밍을 위한 RStudio

RStudio는 통합(integrated)이라는 단어를 크게 강조한 IDE입니다. 여러분이 눈치채지 못할 수도 있는 이면의 많은 작업을 수행하여 여러분을 효율적인 프로그래머로 만듭니다. 최대의 이점을 얻기 위해 RStudio의 다양한 기능을 사용하는 방법에 대한 많은 설명서를 찾을 수 있습니다. <a href="https://docs.posit.co/ide/user/" style="text-decoration: none;"> https://docs.posit.co/ide/user/ </a> 의 웹 페이지에서 시작하는 것이 좋습니다. 이 섹션에서는 RStudio가 생산성을 얼마나 향상시킬 수 있는지에 대해 길게 설명하지는 않겠습니다. 오히려 도움이 되었고 여러분에게도 도움이 될 것이라고 믿는 해야 할 일과 하지 말아야 할 일을 몇 가지 포함합니다.

## 1.9.1 전역 및 프로젝트 수준 옵션 구성하기

도구 -> 전역 옵션 및 도구 -> 프로젝트 옵션을 클릭하여 이러한 옵션에 액세스하고 구성할 수 있습니다. 대부분의 옵션은 자명하며 필요한 경우 설명서를 참조할 수 있습니다. 사용자 경험을 최적화하기 위해 일부 옵션이 기본적으로 선택되어 있습니다. 그러나 사용 가능한 다양한 옵션을 사용하여 요구 사항에 적합한 환경을 설정해야 합니다. 프로젝트 수준 `.Rprofile` 파일은 `Sys.getenv("HOME")` 디렉터리의 `.Rprofile` 파일을 덮어쓴다는 점을 유의하십시오.

## 1.9.2 작업 디렉터리 설정하기

기본 작업 디렉터리는 일반적으로 사용자의 문서(Documents) 폴더임을 확인했습니다. 조직에서 제공하는 기기에서 문서 폴더는 보통 OneDrive와 같은 네트워크 스토리지에 매핑되어 있으며 파일이 추가되거나 삭제되는 것을 감지하면 지속적으로 업데이트됩니다. 파일을 자주 저장하면(전역 옵션을 통해 설정한 경우 코드가 실행될 때 스크립트가 자동으로 저장됨) 해당 작업은 네트워크로 연결된 작업 디렉터리를 지속적으로 동기화합니다. 원본 데이터 및 중간 데이터와 함께 네트워크 문서 폴더에 더 많은 프로젝트가 쌓이면서 R이 느려지는 것을 경험할 수 있습니다. 이런 고통에서 벗어나려면 프로젝트를 만들 때 문서 폴더 아래가 아닌 다른 위치를 사용하고 도구 -> 전역 옵션 -> R 메뉴를 통해 기본 작업 디렉터리를 변경하십시오.

어쨌든 프로젝트 백업을 유지하는 데에는 네트워크 드라이브를 사용하는 것보다 Git과의 통합이 더 나은 솔루션입니다.

## 1.9.3 RStudio 프로젝트로 시작하기

단일 스크립트 작성이 필요한 작은 데이터 분석을 수행할 때도 항상 프로젝트 설정부터 분석을 시작하십시오. RStudio 프로젝트를 설정하는 데 걸리는 약간의 시간은 나중에 많은 시간을 절약해 줄 것입니다. 비즈니스 환경에서는 이해관계자가 몇 달 전에 수행한 분석을 다시 실행해 달라고 요청하는 경우가 흔합니다. 그들은 또한 세부 사항에 대한 안목도 있습니다. 동일한 데이터 소스에서 다시 계산할 때 지난 분기에 제공한 요약표의 숫자가 일치하지 않는 경우 타당한 설명을 제공해야 할 수도 있습니다. 프로젝트 내에서 코드/분석이 개발되면 이러한 상황은 사소해집니다. 프로젝트에는 코드, 라이브러리, 데이터 소스, SQL, 그래프, 표, 그리고 중요한 것은 분석 이면의 사고 과정이 한곳에 있어야 합니다. 필요한 경우 분석을 다시 수행하거나 여러 방향으로 확장하는 것이 쉬울 것입니다.

## 1.9.4 세션 간에 작업 공간을 보존하지 않기

사용된 패키지, 데이터, 데이터 소스, SQL, 코드, 분석, 플롯, 결과, 설명서 및 프레젠테이션과 같은 모든 기록을 보관하되 세션 간에 작업 공간은 보존하지 마십시오. 이전 세션의 개체는 동일한 프로젝트 내에서 새로운 코드 블록을 위태롭게 하거나 다른 프로젝트에서 스크립트를 실행할 때 충돌을 일으킬 수 있습니다. 두 상황 모두에서 디버깅이 더 어려워집니다. 세션 간에 환경을 옮기는 것이 아니라 작성된 스크립트를 사용하여 컴퓨팅 환경을 다시 만들 수 있어야 합니다. 시작 시 `.RData`를 복원하지 않고 종료 시 `.RData`를 저장하지 않음으로써 이를 달성할 수 있습니다(전역 옵션 메뉴에서 사용 가능).

RStudio가 생산성을 높이고 프로그래밍 효율성을 높일 수 있는 방법은 이 외에도 많습니다. R만 사용할 때도 이미 훌륭한 도구였습니다. RStudio(또는 Positron)가 다른 프로그래밍 언어를 포함하도록 기능을 확장함에 따라 이제 환상적인(supercalifragilisticexpialidocious) IDE가 되었습니다. 끝.

다양한 R 구성 요소를 설치하고 각각이 데이터 분석 여정에서 어떻게 가치를 창출하는지 간단히 배운 후 이제 tidyverse 패키지 모음을 살펴볼 시간입니다. tidyverse 패키지는 모듈식이고 응집력이 높다는 동일한 설계 원칙을 공유합니다. 이러한 패키지 중 일부는 책 전체에서 사용됩니다.

# 1.10 tidyverse 패키지 모음

R의 수명은 tidyverse 이전과 tidyverse 이후 두 부분으로 나눌 수 있습니다. tidyverse 모음은 R에서 프로그램을 생각하고, 설계하고, 작성하는 방식을 변화시켰습니다. tidyverse의 모든 패키지는 공유된 설계 철학, 문법 및 데이터 구조를 기반으로 구축되었습니다.

`tidyverse` 모음에는 30개의 패키지가 포함되어 있습니다. 다음을 실행하여 한 번에 모두 설치할 수 있습니다.

```
install.packages("tidyverse")
```

`tidyverse`에 포함된 모든 패키지의 이름을 확인할 수 있습니다.

```
tidyverse::tidyverse_packages(include_self = FALSE)
```

모든 R 프로젝트에서 `tidyverse` 패키지가 모두 필요한 것은 아닙니다. 이 책에서 사용할 일반적인 4가지 `tidyverse` 패키지는 다음과 같습니다.

- `dplyr`: 데이터 조작의 문법
- `ggplot2`: 그래픽 문법을 사용하여 우아한 데이터 시각화 생성
- `tibble`: 간단한 데이터 프레임
- `lubridate`: 날짜 처리를 쉽게 해줌

`dlstats` 패키지를 사용하여 통계를 가져오고 `ggplot2`를 사용하여 선형 플롯을 만들면 CRAN에서 월별 다운로드 수를 볼 수 있습니다. 데이터 조작 및 시각화는 이후 장에서 자세히 다루어지기 때문에 플롯 생성을 위한 코드는 의도적으로 생략되었습니다.
