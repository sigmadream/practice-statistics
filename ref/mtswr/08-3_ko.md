# 3.1 입출력 함수의 일반적인 구조

R에서 입출력과 관련된 많은 함수들은 직관적인 이름을 가지고 있습니다. 주로 R로 불러올 때는 `read`로 시작하고, R에서 저장할 때는 `write`로 시작합니다. 다양한 함수들이 존재하며, 이들은 모두 다음 키워드 중 하나를 포함합니다.

- `read` 또는 `load`: 이 함수들이 객체를 R로 가져온다는 것을 지정합니다.
- `write` 또는 `save`: 이 함수들이 객체를 R에서 내보낸다는 것을 나타냅니다.

이 함수들에는 입력 또는 출력 위치를 지정하기 위해 필수적인 `file` 또는 `path` 인수가 포함되며, 파일 경로 문자열이나 연결(connection) 객체를 허용할 수 있습니다. 이러한 함수들은 `col_names` 또는 `compression`과 같은 다양한 선택적 인수를 통해 유연성을 제공합니다.

`path` 또는 `file` 인수는 보통 프로젝트 폴더를 루트 디렉터리로 가정합니다. `getwd()` 함수를 통해 루트 디렉터리를 확인할 수 있습니다. 그 전에, 콘솔에 `ls()`를 입력하여 R 전역 환경에 어떤 객체들이 있는지 확인하고, `rm(list=ls())`를 사용하여 세션을 지워보세요.

```
# 전역 환경의 객체 목록
ls()

# R 작업 공간 지우기
rm(list = ls())

# 루트 디렉터리 출력
getwd()
```

프로젝트 폴더 내에 data라는 폴더가 없다면 하나 만들어 보겠습니다.

```
# data 폴더 존재 여부 확인
dir.exists("data")
dir.create("data")
```

`dir.exists()` 함수는 data 폴더의 존재 여부를 확인하고, `dir.create()` 함수는 폴더 생성합니다. 이 장에서는 data 폴더 안에 있는 `data_chap3`라는 폴더를 사용할 것입니다. 다음 코드는 폴더의 존재 여부를 확인합니다. 만약 존재한다면, 전체 경로를 `data_path`로 설정하고, 존재하지 않는다면, 폴더를 생성한 다음 `data_path`에 저장합니다.

```
# 폴더가 존재하는지 확인하고 없다면 생성

if (dir.exists(file.path(getwd(), "data", "data_chap3"))){
  data_path <- file.path(getwd(), "data", "data_chap3")
} else {
  dir.create(
    file.path(getwd(), "data", "data_chap3"),
    recursive = TRUE
  )
  data_path <- file.path(getwd(), "data", "data_chap3")
}
```

폴더의 존재 여부를 확인한 후 폴더를 생성할 때, if-else 블록 내에 동작을 감싸면 실수로 폴더를 삭제하거나 덮어쓸 가능성이 줄어듭니다. 기존 폴더와 그 구성 요소를 그대로 유지하면서 이 코드 블록을 여러 번 실행할 수 있습니다.

이 장의 나머지 부분에서는 읽기 및 쓰기 파일의 위치로 `data_path`를 사용할 것입니다. 위치를 객체에 저장하면 이어지는 예제에서 타이핑하는 시간을 크게 절약할 수 있습니다. 함수 내에서 경로(path)나 파일(file) 인수를 변경하여 원하는 다른 위치를 사용할 수도 있습니다.

이제 프로그래밍 방식으로 폴더의 존재를 확인하고 필요한 경우 생성할 수 있습니다. 다음으로, R 데이터 파일을 R 작업 공간에 저장하고 불러오는 방법을 알아보겠습니다.

# 3.2 R에서 생성된 파일 저장 및 불러오기

`saveRDS()` 및 `readRDS()` 함수는 확장자가 `.rds` 또는 `.RDS`인 R 객체를 저장하고 불러옵니다. 이 함수들은 일반적으로 모델 객체를 저장한 후 추가 분석을 위해 나중에 불러올 때 사용됩니다. Windows와 macOS는 대소문자를 구분하지 않는 파일 시스템을 사용하므로 두 파일 확장자가 동일하게 취급됩니다. 그러나 Linux/Unix 파일 시스템은 대소문자를 구분하는 파일 시스템을 사용하므로 `.RDS`를 `.rds`와 다르게 취급합니다.

`saveRDS()` 함수는 주로 단일 객체를 저장합니다. 다음 코드를 사용하여 `mtcars` 데이터를 로컬에 저장해 보겠습니다.

```
saveRDS(mtcars,
        file = file.path(data_path,"mtcars.rds"))
```

다음 코드 출력에 나타난 것처럼 목록(list)으로 구성하여 여러 객체를 저장할 수 있습니다.

```
saveRDS(list(mtcars, austres),
        file = file.path(data_path, "mtcars_austres.rds"))
```

단지 출력만 하고 아무 작업도 하지 않을 것이 아니라면, 불러온 객체에 이름을 할당하는 것이 항상 좋습니다.

```
singl_obj <- readRDS(file.path(data_path, "mtcars.rds"))
singl_obj
```

동일한 RDS 파일에서 여러 객체를 불러올 때는, 리스트에서 요소를 추출하는 표준적인 방법으로 객체에 접근합니다.

```
mult_obj <- readRDS(file.path(data_path,"/mtcars_austres.rds"))
df1 <- mult_obj[[1]]
df2 <- mult_obj[[2]]
```

이 절에서는 R 데이터 파일을 읽고 쓰는 방법을 배웠습니다. 또한 단일 명령으로 여러 RDS 파일을 불러오는 방법도 배웠습니다.

다음으로, R 패키지에서 제공되는 데이터셋에 접근하는 방법을 살펴보겠습니다.

# 3.4 외부 파일 가져오기

R로 파일을 가져오거나 R에서 파일을 내보내는 데 전용으로 사용할 수 있는 여러 가지 편리한 패키지가 있습니다. 패키지 선택은 다음 사항에 따라 달라질 수 있습니다.

- 파일 형식
- 데이터를 R로 불러올 때 구문 분석(parsing)이 어떻게 일어나는지
- 파일의 크기
- 읽기/쓰기 속도

이것은 외부 파일을 가져오기 위한 패키지를 선택할 때 고려할 지침일 뿐입니다.

몇 가지 주요 패키지의 파일 입출력 기능에 대해 다음 섹션에서 설명합니다. 이는 R이 데이터 입출력을 위해 제공하는 패키지의 전체 목록은 아닙니다. 그러나 이 논의와 예제는 R 워크플로에 맞춰 적절한 함수를 선택하는 데 도움이 될 것입니다.

## 3.4.1 readr 패키지

tidyverse의 `readr` 패키지는 다양한 유형의 직사각형 데이터를 빠르고 유연하게 불러오고 구문 분석할 수 있는 편리한 함수를 제공합니다. 구문 분석은 모든 형식의 플랫 파일(flat file)을 가져와 각 열이 올바른 데이터 유형을 갖도록 보장하면서 티블(tibble) 객체로 출력하는 과정을 포함합니다.

함수 세트는 `read_*()` 및 `write_*()`이며, 여기서 밑줄 뒤의 두 번째 부분은 쉼표로 구분된 값(csv), 탭으로 구분된 값(tsv), 고정 너비 텍스트 파일(fwf)과 같이 함수가 적용될 수 있는 파일 형식을 나타냅니다. 기본 `saveRDS()` 및 `readRDS()` 함수의 `readr` 버전은 각각 `write_rds()` 및 `read_rds()`입니다.

행 이름을 취하여 `mtcars` 데이터에 문자형 열을 추가하고 이를 `mtcars2`로 저장해 보겠습니다. `write_csv()` 함수를 사용하여 `mtcars2` 객체를 외부로 csv 형식으로 저장합니다. 전역 환경에서 `mtcars2`를 제거합니다. 다음 코드 블록은 해당 작업들을 보여줍니다.

```
mtcars2 <-
  rownames_to_column(mtcars, "make") |>
  as_tibble()

write_csv(
  mtcars2,
  file = file.path(data_path,"mtcars2.csv"))

rm("mtcars2")
```

이제 작업 공간으로 `mtcars2` 객체를 불러옵니다. `read_csv()` 함수가 1개의 문자형 열과 11개의 숫자형 열을 정확하게 구문 분석한 것을 확인할 수 있습니다.

```
mtcars2 <- read_csv(
  file.path(data_path,"mtcars2.csv"))
```

다음 출력과 같이 `spec_csv()` 함수를 적용하여 작업 공간으로 불러오기 전에 데이터 파일의 열 유형을 확인할 수 있습니다.

```

  cyl = col_double(),

```

`spec_*()` 함수는 처음 1,000행을 확인하여 열의 형식을 추측합니다.

`readr`은 한 열의 유형을 다른 유형으로 구문 분석하는 편리한 함수를 제공합니다. 외부 파일의 날짜/시간 형식이 R이 기대하는 것과 다른 것은 흔한 문제입니다. 패키지는 날짜/시간 벡터를 구문 분석하기 위한 세 가지 함수를 제공합니다.

- `parse_date()`: 1970-01-01을 기준(epoch)으로 사용하며 `locale()`에 의해 지정된 형식을 사용합니다. 기본값은 자동 날짜 구문 분석기를 사용하며 출력을 `Y-m-d` 또는 `Y/m/d` 형식으로 제공합니다. 여기서 `Y`는 4자리 연도, `m`은 2자리 월, `d`는 2자리 일입니다. 함수 내부의 format 인수에 입력 날짜의 형식을 제공해야 하며, 출력 날짜 형식이 아닙니다. 몇 가지 예는 다음 코드 스니펫에 나와 있습니다.

  입력 날짜가 월/일/연도 형식입니다. format 인수는 이를 반영해야 합니다. `%Y`는 연도를 4자리 문자로 서식을 지정합니다.

  ```
  parse_date("10/05/2023", format="%m/%d/%Y")
  # [1] "2023-10-05"
  ```

  여기서는 입력 날짜가 일/월/연도 형식이며 그에 대응하는 `%d/%m/%Y` 형식이 사용됩니다.

  ```
  parse_date("20/05/2023", format="%d/%m/%Y")
  # [1] "2023-05-20"
  ```

  다음 형식은 입력 날짜 형식과 요청된 구문 분석 형식 간의 불일치로 인해 입력 날짜를 구문 분석할 수 없었습니다.

  ```
  parse_date("10/05/2023", format="%Y-%m-%d")
  # [1] NA
  ```

  구분 기호인 하이픈(`-`)이나 슬래시(`/`)는 아래와 같이 요청된 형식이 입력 날짜와 일치하는 한 정확한 날짜 구문 분석에 아무런 역할을 하지 않습니다.

  ```
  parse_date("2023-05-10", format = "%Y-%m-%d")
  # [1] "2023-05-10"
  ```
