# 시계열 데이터 랭글링 및 시각화

이 장에서는 시계열 데이터를 위한 일반적인 데이터 랭글링 및 시각화 기법을 제시합니다. 데이터 랭글링은 원시 데이터를 다루어 추가 분석을 위한 형태로 만드는 필수적이지만 종종 간과되는 과정입니다. 이 중추적인 단계에는 분석 목적에 맞게 데이터를 정리, 변환, 정제 및 요약하는 작업이 포함됩니다. 또한 시각화는 시계열 데이터를 다룰 때 중요한 역할을 합니다. 관측된 데이터 내에서 기존 패턴을 인식하고 이들의 조합을 이해하는 데 도움이 됩니다. 숙련된 시각화는 당면한 작업에 가장 적합한 예측 모델을 선택하는 데 도움이 됩니다.

시계열 데이터 랭글링의 복잡성은 주로 (a) 원시 데이터의 복잡성, (b) 다음 단계 분석의 목적이라는 두 가지 요소에 따라 달라집니다. 예를 들어, 일별 데이터가 있고 실험 단계에 있는 경우 주별 데이터를 사용하는 모델이 더 통찰력이 있을지 아니면 월별 데이터를 사용하는 모델이 더 통찰력이 있을지 알 수 없습니다. 이러한 상황에서는 일별 데이터를 최대한 정리하고 모델링 직전에 원하는 수준으로 집계해야 합니다. 다른 시나리오에서는 받은 데이터가 이미 원하는 수준으로 요약되어 있을 수 있지만 여전히 적절하게 정리하고 변환해야 할 수 있습니다.

# 5.1 날짜-시간 변수 파싱

데이터 랭글링 과정에서 R에서 날짜/날짜-시간 변수를 포맷하는 것이 오류를 발생시키지 않고 바람직한 결과를 제공하는지 확인하는 일종의 메커니즘이 필요합니다. 안타깝게도 모든 상황에 맞는 단일 방법은 없습니다. 하지만 간단한 로직을 검증하면 나중에 시간과 좌절을 줄일 수 있습니다. 예를 들어, 고유 연도를 계산하고 정렬하면 포맷이 예상대로 수행되는지 확인할 수 있습니다. 또 다른 옵션은 각 연도의 관측치 수를 계산하는 것입니다. 너무 낮거나 너무 높은 수치(일별 데이터의 경우 365 초과, 월별 데이터의 경우 12 초과)는 잠재적인 문제를 식별할 수 있습니다.

토이 데이터셋으로 이에 대해 자세히 알아보겠습니다. `read_csv()` 함수를 사용하여 `mismatch_date.csv` 파일을 로드하고 변수 유형을 확인하세요:

```
mismatch_dt <- read_csv("data/data_chap5/mismatch_date.csv")
glimpse(mismatch_dt)
```

날짜 열이 문자형으로 로드된 다음 출력을 볼 수 있습니다:

```
Rows: 9
Columns: 2
$ date  <chr> "1/01/2015", "1/02/2015", "1/03…
$ value <dbl> 1630, 826, 567, 139, 256, 113, …
```

데이터 프레임은 9개의 행을 가지며 날짜 열은 `DD-MM-YYYY` 형식일 수 있습니다. 이제 다음 코드를 사용하여 날짜 형식을 지정하고 각 연도의 관측치 수를 계산하세요:

```
year_count <- mismatch_dt |>
  mutate(date = as.Date(date, format = "%d/%m/%Y")) |>
  mutate(year = year(date)) |>
  group_by(year) |>
  tally()
year_count
```

다음 출력은 날짜에 두 개의 다른 연도 항목이 있음을 보여줍니다:

```
# A tibble: 2 × 2
   year     n
  <dbl> <int>
1    15     1
2  2015     8
```

대용량 파일에서 소수의 잘못된 데이터 입력조차도 미치는 영향이 클 수 있으며, 특히 데이터를 주별 또는 월별과 같은 더 높은 수준으로 요약할 때 그렇습니다. 이 문제는 데이터 처리 시 여러 출처에서 파일을 로드하고 병합할 때 확대될 수 있습니다. 조직 전체에서 통합된 날짜-시간 입력이 항상 지켜지는 것은 아닙니다. 데이터베이스 내의 여러 스키마 및 테이블에서 데이터를 가져올 때도 유사한 문제가 발생할 수 있습니다. 이러한 불일치 및 차이는 부정확한 분석, 오해의 소지가 있는 결론, 잠재적으로 비용이 많이 드는 결정으로 이어질 수 있습니다. 이는 데이터 집계 및 분석을 진행하기 전에 엄격한 데이터 검증 및 정리 절차의 중요성을 강조합니다.

`lubridate` 패키지는 일관되지 않은 날짜-시간 형식을 쉽고 빠르게 파싱할 수 있는 다양한 도우미 함수를 제공합니다. 함수의 선택은 R에서 어떻게 나타날 것으로 예상하는지가 아니라 소스 파일의 형식에 따라 달라집니다. 설명을 위해 다음 코드와 같이 `dmy()` 및 `ymd()`를 적용하여 `mismatch_dt`의 날짜 열을 파싱합니다:

```
mismatch_dt |>
  mutate(date_accurate = dmy(date),
         date_inaccurate = ymd(date))
```

이 코드는 경고와 함께 다음 출력을 생성합니다:

```
# A tibble: 9 × 4

1 1/01/2015  1630 2015-01-01    NA
2 1/02/2015   826 2015-02-01    NA
3 1/03/2015   567 2015-03-01    NA
4 1/04/2015   139 2015-04-01    NA

`mismatch_dt.csv` 파일에서 날짜 열은 일/월/연도 스타일로 입력되었습니다. `dmy()` 함수는 이를 정확하게 파싱한 반면, `ymd()` 함수는 파싱에 실패하여 경고 메시지와 함께 NA를 생성했습니다.

`ymd()` 함수는 1/8/15 또는 1/08/2015가 아니라 2015-08-01, 2015080 또는 2015/08/01과 같은 형식을 기대합니다. `lubridate` 패키지에는 `ymd()`, `mdy()`, `dmy()`, `ymd_hms()`, `dmy_hms()` 등 다양한 파싱 함수가 포함되어 있습니다. R에서 어떻게 보고 싶은지가 아니라 소스의 날짜-시간 서식 스타일에 따라 적절한 함수를 사용하세요. 경고 메시지나 NA 인스턴스는 파싱 함수가 적합한지 바람직한 결과를 내는지 나타냅니다.

R에서 데이터를 로드할 때 날짜-시간 변수를 올바르게 파싱한 후에는 날짜에서 요일이나 역년의 주 번호와 같이 날짜-시간 변수에서 다양한 부분을 추출해야 할 수 있습니다. 날짜-시간 변수의 구성 요소를 설정하거나 추출하는 데 사용할 수 있는 많은 도우미 함수가 있습니다. 다음 섹션에서는 이러한 도우미 함수 중 일부에 대해 논의합니다.

# 5.2 날짜-시간 구성요소 설정

때로는 날짜-시간 변수에서 다른 구성요소를 추출해야 할 때가 있습니다. 예를 들어 날짜에서 연도나 월을 추출합니다. `lubridate` 및 `tsibble` 패키지는 이러한 작업을 수행하는 도우미 함수를 제공합니다.

`lubridate` 패키지의 일부 함수를 자세히 살펴보겠습니다:

- `week()`, `month()`, `year()` 함수는 날짜의 해당 부분을 정수로 반환합니다. `label=TRUE` 옵션을 사용하면 요일/월 이름을 반환할 수 있습니다.
- `day()`, `wday()`, `mday()`, `qday()`, `yday()` 함수는 해당 일수를 반환합니다.
- `hour()`, `minute()`, `second()` 함수는 시간 인덱스의 해당 부분을 추출합니다.

다음 코드 스니펫에서 앞서 언급한 기능 중 일부가 작동하는 것을 확인할 수 있습니다:

```
set.seed(45)
test_df <- tibble(
  date = as.Date(c("2019-01-01",
                   "2019-09-12",
                   "2020-01-01",
                   "2020-05-10")),
  value = runif(4) )

test_df |>
  mutate(year=year(date)
         ,day_year=yday(date)
         ,day_month=mday(date)
         ,month_name=month(date, label=TRUE))
```

다음 출력을 검토하여 각 함수의 결과를 이해할 수 있습니다:

```
# A tibble: 4 × 6
  date       value  year day_year day_month month_name
  <date>     <dbl> <dbl>    <dbl>     <int> <ord>
1 2019-01-01 0.633  2019        1         1 Jan
2 2019-09-12 0.318  2019      255        12 Sep
3 2020-01-01 0.241  2020        1         1 Jan
4 2020-05-10 0.378  2020      131        10 May
```

`tsibble` 패키지의 함수는 다음과 같습니다:

`yearmonth()`, `yearquarter()`, `yearweek()`는 해당 구성 요소를 추출하고 연도 부분과 멋지게 정렬합니다. 다음 코드 스니펫은 이러한 함수를 적용하는 방법을 보여줍니다:

```
test_df |>
  mutate(year_month=yearmonth(date)
         ,year_quarter=yearquarter(date)
         ,year_week=yearweek(date))
```

다음 출력이 생성됩니다:

```
# A tibble: 4 × 5
  date       value year_month year_quarter year_week
  <date>     <dbl>      <mth>        <qtr>    <week>
1 2019-01-01 0.633   2019 Jan      2019 Q1  2019 W01
2 2019-09-12 0.318   2019 Sep      2019 Q3  2019 W37
3 2020-01-01 0.241   2020 Jan      2020 Q1  2020 W01
4 2020-05-10 0.378   2020 May      2020 Q2  2020 W19
```

관측치는 특정 시간 단위에 대해 수집될 수 있지만 그렇다고 해서 R의 정의에 따라 이미 시계열 객체인 것은 아닙니다. R에 로드하자마자 시간적 데이터를 시계열 객체로 변환하시겠습니까? 대답은 분석 목표에 따라 다릅니다. 다음 섹션에서 이 질문을 명확히 해보겠습니다.

# 5.3 데이터를 시계열 객체로 변환해야 하는 시기

분석에서 시계열 객체에 대한 필요성은 특정 모델이 입력으로 시계열 데이터를 요구할 때 발생합니다. 하지만 일부 모델은 시계열 객체를 필요로 하지 않습니다. 이러한 경우 시간적 데이터는 `tibble` 객체에 보관될 수 있으므로 시계열 객체로 변환할 필요 없이 데이터 정리 및 요약과 같은 랭글링 작업을 허용합니다. 따라서 데이터 랭글링을 위한 함수 선택은 다운스트림 분석 요구사항에 따라 달라집니다.

향후 모델링 선택에 관계없이 데이터 랭글링 시 시간적 데이터를 `tsibble` 객체로 파싱하는 것은 특히 수많은 시계열을 동시에 처리할 때 효율적임이 입증되었습니다. 이 형식은 시계열 구조를 유지하면서 다양한 분석을 위한 유연성을 제공하므로 시간적 데이터를 관리하는 데 유용한 옵션이 됩니다.

2장에서 데이터를 시계열 객체로 변환하는 다양한 방법에 대해 논의했습니다. 참조를 위해 표 5.1에 요약되어 있습니다.

| 패키지 | 함수 | 활용 |
|----|----|----|
| `forecast` | `ts()` | 단일 시계열 변환 |
| `tsibble` | `tsibble()` 또는 `as_tsibble()` | 여러 시계열을 한 번에 변환, `ts`, `tibble` 또는 `data.frame` 형식과 함께 작동 |

표 5.1: 데이터를 시계열 객체로 변환하는 함수

`forecast` 및 `tsibble` 패키지는 모두 시계열 데이터를 관리하는 데 유용한 도구를 제공합니다.

`tsibble` 패키지는 기본적으로 tidy data 원칙을 준수하는 tibble 위에 구축됩니다. 이는 시간적 데이터를 저장하고 랭글링하는 체계적이고 효율적인 방법을 제공함을 의미합니다. tsibble을 사용하면 여러 시계열을 구조화된 방식으로 쉽게 관리할 수 있어 집계, 변환 및 분석과 같은 작업을 용이하게 합니다.

반면 `forecast` 패키지의 `ts()` 함수는 단일 계열에 적용되도록 설계되었습니다. 그러나 for 루프 또는 `purrr` 패키지를 사용한 함수형 프로그래밍과 같은 기법을 사용하여 여러 계열을 처리하도록 확장할 수 있습니다. 이러한 방법은 효과적이지만 여러 시계열을 동시에 처리하기 위해 `tsibble` 객체를 사용하는 것만큼 간소화되거나 직관적이지 않을 수 있습니다.

따라서 시계열 데이터의 복잡성과 당면한 작업에 따라 `tsibble`은 여러 시계열을 관리하고 랭글링하기 위한 보다 통합되고 효율적인 솔루션을 제공하는 반면 기본 `ts()` 객체는 단일 계열에 효과적으로 사용되거나 여러 계열에 대한 추가 프로그래밍 노력을 통해 여전히 사용될 수 있습니다.

다음 섹션에서는 `dplyr` 및 `tsibble` 패키지의 몇 가지 일반적인 데이터 랭글링 함수를 소개합니다. `dplyr`의 함수는 `tsibble`에서도 사용할 수 있으며 후자에는 시계열 데이터를 랭글링하는 데 필요한 특수 함수도 포함되어 있습니다.

데이터 랭글링 단계의 시작 시점에 목표와 예상 결과에 대한 명확한 아이디어가 없을 수 있습니다. 그러나 다음에 나열된 사항에 대한 약간의 명확성은 장기적으로 시간, 노력 및 좌절을 덜어줄 것입니다:

데이터 및 모델링 파이프라인을 모두 다루는 데이터 과학자에게 재현성은 가장 중요합니다. 코드는 다른 사람(미래의 자신 포함)이 초기 데이터 탐색에서 모델 개발에 이르기까지 수행된 단계를 따라갈 수 있는 방식으로 구성되어야 합니다. 이는 진행 과정에서 내린 결정을 이해하는 데 도움이 되며 분석의 조정 또는 확장을 용이하게 합니다.

모델을 프로덕션화하는 작업을 하는 머신러닝(ML) 엔지니어의 경우, 재현성은 데이터 정리, 기능 엔지니어링 및 모델 훈련을 포함한 전체 파이프라인이 프로덕션 환경에서 복제될 수 있도록 보장합니다. 이는 일관된 결과를 보장하고 문제가 발생할 경우 문제 해결을 쉽게 해 줍니다.

재현 가능한 코드를 개발하면 분석의 일관성과 신뢰성을 보장할 뿐만 아니라 다른 사람들이 작업 내용을 쉽게 이해하고 발전시킬 수 있습니다.

# 5.5 시각화 함수

기본 R에서는 `type=l` 옵션이 있는 `plot()` 함수를 사용하여 시간 플롯을 생성합니다. R에서 시각화를 생성하는 데 널리 사용되는 유명한 `ggplot2` 패키지도 시계열 데이터를 다룹니다. `ggplot2` 패키지는 `tidyverse` 패키지 제품군에 포함되어 있습니다. `ggplot2` 패키지만 로드할 수도 있습니다. `ggplot2`를 처음 사용하는 드문 경우를 위해 다음과 같은 간략한 개요가 도움이 될 것입니다.

`ggplot2` 패키지의 함수를 사용하여 플롯을 생성할 때 다양한 유형의 정보를 전달해야 합니다:

- 데이터: 일반적으로 긴 형식의 데이터가 더 잘 작동합니다(예: 열에 변수가 있고 행에 관측치가 있는 형태).
- 매핑: 변수를 가로(x) 또는 세로(y) 축에 할당하고, 그룹화(있는 경우)를 적용하고, 크기, 모양 및 색상과 같은 플로팅 특성을 나타냅니다. 이는 `aes()`(aesthetic의 줄임말) 함수를 통해 수행됩니다.
- Geom 함수: 데이터를 그래픽으로 표현하는 방법을 정의합니다. 많은 geom이 있으며 새로운 것이 자주 도입됩니다. 일반적인 geom으로는 산점도 및 점 플롯을 위한 `geom_point()`, 막대 플롯을 위한 `geom_bar()`, 시계열에 대한 선 플롯을 생성하는 `geom_line()`이 있습니다.
- 테마: 그래픽을 사용자 정의하는 옵션입니다.

먼저 `ggplot()` 함수를 사용하여 플로팅 객체를 생성합니다. 이 함수의 이름과 패키지 이름인 `ggplot2`의 차이에 유의하세요. 플롯을 생성하려면 `ggplot()` 함수에 적어도 하나의 geom과 함께 데이터 및 매핑을 전달합니다.

하나의 플롯에 여러 geom을 사용할 수 있습니다. 테마, 크기 조정 및 패싯 함수를 사용하는 등 플롯을 사용자 정의하는 많은 옵션이 있습니다. geom 및 사용자 정의 함수는 각 함수 사이에 `+`를 연결한 레이어로 간주됩니다. `ggplot` 객체에 사용되는 레이어 수에는 제한이 없습니다. 그러나 레이어의 순서는 최종 출력에 영향을 미칠 수 있습니다.

`ggplot`을 통해 생성된 플롯의 표준 템플릿은 다음과 같습니다:

```
ggplot(data = <DATA>, mapping = aes(x,y)) +
  <GEOM_FUNCITONS>() +
  <THEME_FUNCTIONS>()
```

`ggplot2` 패키지의 `autoplot()` 함수는 특정 클래스의 플롯을 위해 선별된 유연하고 간단한 단일 명령입니다. 원시 데이터를 전달하는 대신 출력 플롯을 결정하는 정의된 클래스가 있는 객체를 전달해야 합니다.

`autoplot()`의 유연한 특성은 많은 패키지에서 기본적인 객체별 플로팅을 생성하는 매력적인 시각화 도구가 됩니다. forecast 및 `fabletools` 패키지에는 모두 특정 객체에 적용하여 특정 플롯을 생성하는 여러 버전의 `autoplot()` 및 `autolayer()`가 있습니다. 예를 들어, 시계열을 플로팅하기 위해 `forecast::autoplot()`은 `ts` 클래스 객체가 필요한 반면 `fabletools::autoplot()`은 `tsibble` 객체와 함께 작동합니다.

간단히 말해서, `autoplot()`을 사용하는 장점은 다양한 시각화를 생성하는 데 하나의 함수만 있으면 된다는 것입니다. 적절한 객체를 함수에 전달하기만 하면 됩니다.

다음 섹션에서는 `autoplot()`과 `ggplot()`을 모두 사용하여 시간 플롯을 만듭니다.

# 5.6 시간 플롯

시계열 시각화에서는 다양한 구성요소를 시각적으로 식별하는 데 초점을 맞춥니다. 4장에서는 시계열의 특성을 논의하면서 시간 플롯의 몇 가지 예제를 이미 보았습니다. 시간 플롯은 선 플롯으로도 알려져 있습니다.

시간 플롯에서는 시간에 대해 관측치를 플로팅합니다. 시간이 연속형 변수라는 사실을 반영하여 관측치가 선으로 연결됩니다. 데이터의 클래스에 따라 시간 플롯을 생성하는 방법에는 여러 가지가 있습니다:

- `tsibble` 클래스: 데이터가 tsibble 형식인 경우 `autoplot()` 함수가 시간 플롯을 자동으로 생성합니다.

  다음 예제에서는 `tsibbledata` 패키지의 `aus_production` 데이터셋을 사용합니다. 이 데이터셋은 패키지와 함께 로드됩니다. 이 데이터셋에는 1956년 1분기부터 2010년 2분기까지 호주의 맥주, 담배, 벽돌, 시멘트, 전기 및 가스에 대한 분기별 생산 수치가 포함되어 있습니다. 다음과 같이 데이터의 클래스를 먼저 확인하세요:

  ```
  class(aus_production)
  # [1] "tbl_ts"     "tbl_df"     "tbl"        "data.frame"
  ```

  `aus_production`은 tsibble 형식입니다. `fabletools::autoplot()` 함수는 가스 생산 계열을 시각화하기 위해 두 가지 다른 방식으로 사용할 수 있습니다. 첫 번째 예제에서는 다음과 같이 플로팅할 열이 명시적으로 지정되어 플로팅 함수에 전달됩니다:

  ```
  autoplot(aus_production, Gas)
  ```

  두 번째 예제에서는 시간 변수(Quarter)와 계열(Gas)이 선택되며 플로팅할 변수를 명시적으로 언급하지 않고 `autoplot()` 함수가 체인으로 연결됩니다. 이 함수는 변수 유형을 식별하고 적절한 축에 플로팅할 만큼 똑똑합니다:

  ```
  aus_production |>
    select(Quarter, Gas)  |>
  autoplot()
  ```

  두 코드 예제 모두 그림 5.1에 제시된 것과 정확히 동일한 플롯을 생성합니다. `autoplot()`에 대한 경험 법칙은 데이터셋에 동일한 유형의 변수가 여러 개 있을 때 사용자가 플로팅 시계열을 명시적으로 호출해야 한다는 것입니다.

- `ts` 클래스: `forecast` 패키지의 `autoplot()` 함수를 사용합니다. 다른 두 가지 변형도 작동해야 합니다.

다음 예제에서 날짜 변수인 `sched_dep_date`는 `make_datetime()` 및 `date()` 함수를 사용하여 연, 월, 일, 시, 분 구성요소를 추출하여 얻습니다. 데이터가 이상한 형식으로 기록되었기 때문에 산술 모듈로가 사용됩니다. 이는 시계열 데이터 랭글링에서 이상한 형식의 날짜-시간 기반 변수를 다루는 예제입니다. 항공편이 지연되었는지 여부를 나타내는 표시 변수 `is_delayed`가 생성됩니다:

```
flights <-
  nycflights13::flights |>
  filter(!is.na(dep_time), !is.na(arr_time)) |>
  mutate(sched_dep_datetime = make_datetime(
    year, month, day,
    sched_dep_time %/% 100,
    sched_dep_time %% 100)
  ) |>
  mutate(sched_dep_date = date(sched_dep_datetime)) |>
  select(carrier, origin, dest, sched_dep_date, dep_delay) |>

# 5.8 시계열 간의 관계 시각화

상관관계는 변수 간의 선형 관계 강도를 식별하는 일반적인 기법입니다. 변수를 모델에 포함할지 여부를 확인하기 위해 변수 간의 상관관계를 계산하는 것은 통계 및 ML 모델링의 표준 관행입니다. 시계열 모델링에서는 계열과 전력 수요 및 온도와 같은 기타 설명 변수 간의 상관관계를 확인할 수 있습니다. 마찬가지로 다중 시계열 간의 상관관계를 분석하여 이들이 얼마나 밀접하게 패턴을 나타내는지 평가할 수 있습니다. 산점도는 변수 간의 상관관계를 시각적으로 검사하는 가장 간단한 방법입니다. 이제 시계열에 대한 산점도를 만드는 방법을 배웁니다.

## 5.8.1 산점도

일반적으로 산점도는 하나의 종속 변수와 하나의 설명 변수, 즉 두 변수 간의 상관관계를 조사하는 데 사용됩니다. `GGally` 패키지는 여러 계열에 대한 쌍별 산점도를 그리는 `ggpairs()` 함수를 제공합니다. 동일한 플롯은 대각선 상단 패널에 의미와 함께 쌍별 상관관계 값을 인쇄하고 대각선에 분포를 인쇄합니다.

다음 예제에서는 호주 소매 데이터에서 빅토리아 주의 2015년에서 2022년 사이 6개 산업의 매출을 사용합니다. 긴 산업 이름은 `str_split()` 함수와 정규식(공백 또는 쉼표로 분할) 패턴을 적용한 후 `sapply`를 사용하여 해당 첫 번째 단어를 추출하여 바꿉니다:

```
vic_retail <-
  readRDS("data/data_chap5/abs_retail.rds") |>
  filter(
    industry %in% c(
      "Clothing retailing",
      "Food retailing",
      "Electrical and electronic goods retailing",
      "Hardware, building and garden supplies retailing",
      "Newspaper and book retailing",
      "Supermarket and grocery stores"
    ),
    state == "Victoria" ,
    year(month) >= 2015 ,
    year(month) <= 2022
  ) |>
  select(month, industry, turnover) |>
  mutate(industry = sapply(
    str_split(string = industry,pattern = "[, ]+") ,'[', 1))
```

그림 5.9에 제시된 것처럼 수년에 걸친 개별 산업의 매출을 살펴보겠습니다:

```
vic_retail |>
  ggplot(aes(x = month, y = turnover)) +
  geom_line(size = 0.7) +
  facet_grid(vars(industry), scales = "free_y") +
  labs(x = " ")
```

식품-하드웨어 쌍은 가장 강한 양의 선형 상관관계를 가지며, 식품-신문 쌍은 음의 상관관계를 나타냅니다. 이는 식품 지출이 증가하면 신문과 서적 지출이 감소하는 경향이 있으며 소비자의 우선순위 변화를 반영할 수 있음을 시사할 수 있습니다.

## 5.8.2 시차 플롯

4장에서 시계열의 과거 값에 대한 직렬 의존성을 검토할 때 자기 상관에 대해 배웠습니다. 지연된 값이 있는 산점도(시차 플롯이라고도 함)는 시계열 분석에서 변수와 특정 시간 지연에 따른 과거 관측치 간의 관계를 시각화하는 데 사용되는 그래픽 표현입니다. 시차 플롯에서 변수의 현재 값은 특정 시간 지연의 이전 값과 대조되어 플로팅됩니다. 이는 시간이 지남에 따라 데이터에 존재할 수 있는 패턴, 추세 또는 상관관계를 드러내는 데 도움이 됩니다. 시계열의 자기 상관 또는 의존성 구조를 탐색하는 또 다른 방법입니다.

시차 플롯을 만드는 데 사용할 수 있는 두 패키지에는 함수가 있습니다. `forecast` 패키지에는 `gglagplot()` 함수가 있고 `feasts` 패키지는 `gg_lag()` 함수를 제공합니다. 후자는 다음 예제에서 사용됩니다:

```
vic_retail |>
  filter(industry == "Clothing") |>
  gg_lag(turnover, lags = 1:12, geom = "point") +
  labs(x = "lag(Turnover,l)",
       y = "Turnover")
```

그림 5.11은 대부분의 관측치가 상향선 주변에 모여 있어 시차 1과 시차 12에서 강한 양의 의존성을 보여줍니다.

관측치는 다른 시차에 분산되어 있으며 강한 의존성을 나타내지 않습니다.

의존성 패턴을 교차 확인하기 위해 동일한 데이터의 자기 상관 함수를 조사하고 싶다면 `forecast` 패키지의 `ggAcf()` 함수를 사용하거나 `feasts::ACF` 객체에 `autoplot()`을 적용하여 플로팅할 수 있습니다:

```
vic_retail |>
  filter(industry == "Clothing") |>
  ACF(turnover) |>
  autoplot() +
  labs(title = "" )
```

시계열 데이터에서 산점도와 시차 플롯을 사용하면 여러 시계열 간의 관계와 계열 내의 의존성을 검사할 수 있습니다. 대화형 플로팅 기능을 제공하는 여러 R 패키지가 있습니다. 다음 섹션에서는 `Plotly` 패키지를 사용하여 정적 그래픽을 대화형 그래픽으로 바꾸는 방법을 배웁니다.

# 5.9 대화형 플롯

`Plotly` 패키지는 대화형 플롯을 생성하는 기능으로 잘 알려져 있습니다. `Plotly` 패키지의 `ggplotly()` 함수는 모든 정적 `ggplot` 객체를 대화형의 동적 시각화로 바꿉니다. 이를 위해서는 다음 예제와 같이 `ggplot`을 객체에 저장한 다음 `ggplotly()` 함수 내에 전달해야 합니다:

```
lag_turnover <- vic_retail |>
  filter(industry=="Clothing") |>
  gg_lag(turnover, lags = 1:12, geom = "point") +
  labs(x="lag(Turnover,l)",
       y="Turnover")

ggplotly(lag_turnover)
```

이 코드는 사용자가 데이터 포인트를 이동, 확대/축소하고 포인터를 올려놓을 수 있는 대화형 플롯을 R 환경에 생성합니다. 이를 통해 사용자는 참여하고 더 많은 정보에 액세스할 수 있습니다.

대화형 시각화에 관심이 있는 분들을 위해 `dygraphs` 패키지는 `dygraphs()` 함수를 사용하여 동적 시계열 차트를 만드는 데 매우 효과적인 방법을 제공합니다. 이를 통해 사용자는 브라우저나 IDE 뷰어에서 직접 데이터를 이동하고 확대/축소할 수 있습니다. 이러한 기능은 직접 탐색해 볼 수 있습니다.
