#  Basics of Forecasting 

Forecasting models are specifically designed for time series data, where the order of observations matters. The inherent time dependency should be maintained in time series modeling. The predictive models that are commonly used on cross-sectional data can be used for forecasting when this time dependency in the data is respected and addressed appropriately. In statistical models, the focus is on how well the existing relationship between variables can be explained, which is captured in estimated parameters. The statistical tests conducted on these parameters assess the validity of modeling assumptions and offer confidence regarding the persistence of the identified relationship.

In contrast, machine learning or deep learning models do not rely on specific modeling assumptions. Instead, these models aim to make precise predictions without the requirement to explain the underlying relationship between variables. Some ML models, such as tree-based models, do capture some form of feature interactions and relationships.

#  10.2 Forecasting workflow 

A centralized workflow ensures consistency in modeling approaches and methodologies used in a forecasting problem. This leads to uniformity in results and easier comparison between different models when applied to a dataset.

When developing solutions to business forecasting problems, you should adopt a workflow from the beginning of a project to streamline processes that cover all aspects of forecasting. By adopting a forecasting workflow, you will be able to collaborate better, increase efficiency, maintain consistency, and deploy models from proof-of-concept to production in a short time. A minimal forecasting workflow includes the following steps. You can add further granularity into it depending on the problem at hand.

1.   Tidy data
2.   Visualize
3.   Build forecasting models
4.   Check model performance
    -  Residual diagnostics
    -  Evaluate model fit
5.   Generate forecasts
6.   Measure forecast accuracy
7.   Forecast generalizability via time series cross-validation

You learned how to create tidy time series for modeling through data cleaning and transforming, and specialized visualization in *<a href="Chapter_5.xhtml#h1_129" class="chapref"> Chapter 5 </a>* .

In this chapter, steps 3 to 7 in the preceding workflow are demonstrated repeatedly as we discuss three simple forecasting methods. This is to nudge you into the habit of adopting best practices while building forecasting models. The model fit evaluation is discussed in later chapters, when advanced statistical forecasting models are presented.

Efficiency and success are ensured when appropriate tools are used for the task at hand. Let’s have a brief look at the functions from two R packages that will support you running end-to-end forecasting analysis.

#  10.3 fable for forecasting 

A ` `` fable `` ` is a collection of stories that teaches moral lessons, and the term moral pertains to the principles of right and wrong behavior. When weaving forecasting storytelling from time series data, it’s essential to adhere to the correct structure by adopting a forecasting workflow. Similar to a fable, the R packages ` `` fable `` ` and ` `` fabletools `` ` are a collection of functions developed upon shared forecasting morals and workflows.

The ` `` fable `` ` ( **Forecasting Models for Tidy Time Series** ) (O’Hara-Wild et al., 2023) and ` `` fabletools `` ` (Core Tools for Packages in the fable Framework) (O’Hara-Wild et al., 2021) packages provide a centralized process and interface for univariate and multivariate time series forecasting models. The ` `` fable `` ` package includes functions to fit models, whereas ` `` fabletools `` ` provide an integrated workflow for time series modeling and analysis.

The functions from these two packages follow a format consistent with the ` `` tidyverse `` ` workflow. They provide tools for the estimation of forecasting models, comparison, combination, visualization and forecast generation within a consistent framework.

The individual model functions from ` `` fable `` ` will be discussed in dedicated sections. Here is a list of some overarching functions from the ` `` fabletools `` ` package that you will frequently use in forecast modeling.

- ` `` model() `` ` : Fit a model on a single series. This can be extended to multiple models on a single series to multiple models on multiple series.
- ` `` coef() `` ` or ` `` tidy() `` ` : Extract the coefficients from fitted model(s).
- ` `` glance() `` ` : Provides one row summary of each fitted model, including residual variance, information criteria, and in-sample forecast errors.
- ` `` report() `` ` : Returns detailed information for a single model fit.
- ` `` fitted() `` ` : Returns in-sample fitted values.
- ` `` residuals() `` ` : Returns residuals from a fitted model.
- ` `` augment() `` ` : Provides the original series along with both fitted values and residuals.
- ` `` accuracy() `` ` : Returns common accuracy measures for a fitted model.
- ` `` forecast() `` ` : Generates both point forecasts and forecast distribution directly from the model fit.
- ` `` hilo() `` ` : Extracts multiple forecast intervals at once from a forecast distribution.
- ` `` generate() `` ` : Produces simulated paths from a model.
- ` `` equation() `` ` : Displays a model’s equation.

Some functions are supported by particular models and are more suited in a production workflow, such as the following:

- ` `` refit() `` ` : Updates a model to new data
- ` `` stream() `` ` : Supplies new data to extend a model fit by bypassing the whole process of re-fitting a model
- ` `` interpolate() `` ` : Interpolates missing values in a series
- ` `` components() `` ` : Extracts various components from a fitted model

Most of these functions are used throughout this book. The forecasting workflow is easier to grasp when presented using simple methods. We will begin with the naïve forecasting method in the next section.

#  10.4 Naïve forecasting method 

The naïve method uses the most recent observed value as a forecast for the upcoming periods. This approach allocates all the weight to the current observation in the series. Often referred to as random walk forecasts, this method essentially replicates the last observation as a forecast for the next period. This is the simplest method for a non-seasonal series when you have limited to no knowledge about the underlying data-generating process.

The normality assumption is verified by a histogram plot of the residuals. Whereas an ACF plot confirms the existence of autocorrelation.

This indicates that the naïve model is not enough to capture the data dimensions, and another model type could better fit the data.

Instead of visualization, statistical tests are commonly used to check the hypothesis that the autocorrelations in the residuals are similar to a white-noise series. These tests make the model diagnostics an objective and automated process. Either the Box-Pierce test or the Ljung-Box test from the feasts package is used. These tests assume a null hypothesis that the autocorrelation in the residuals is similar to a white-noise series, and a p-value smaller than the common significance level, <span class="image placeholder" data-original-image-src="../Images/B21040_10_051.png" data-original-image-title="">B21040_10_051.png</span> , will reject the null hypothesis. We can compute both the test statistics and corresponding p-values using the following code:

```
nv_aug |>
  features(.innov,list(box_pierce,ljung_box),lag = 10)
```

The output returns information in a ` `` tibble `` ` format with shorthand names, ` `` bp `` ` (Box-Pierce) and ` `` lb `` ` (Ljung-Box):

  <chr>    <dbl>     <dbl>   <dbl>     <dbl>

  -  Even though it’s overly simplistic, the naïve method provides good forecasts for many economic and financial time series.

  -  The naïve method is not usable beyond one-step ahead forecasts, as the method uses a flat forecasting function.

#  10.7 Time Series Linear Model (TSLM) 

In a linear regression model, we examine the relationship between a dependent variable ( <span class="image placeholder" data-original-image-src="../Images/B21040_10_083.png" data-original-image-title="">B21040_10_083.png</span> ) with one or more explanatory variables ( <span class="image placeholder" data-original-image-src="../Images/B21040_10_084.png" data-original-image-title="">B21040_10_084.png</span> ’s). Usually, in a regression model, both the dependent and the independent variables are cross-sectional. The model is called a **Time Series Linear Model** ( **TSLM** ) when a time series is used as a dependent variable. The independent variables may or may not be a time series, but they must be measured at the same time period as <span class="image placeholder" data-original-image-src="../Images/B21040_10_085.png" data-original-image-title="">B21040_10_085.png</span> . A TSLM model is represented by *Equation (10.1)* .

<span class="image placeholder" data-original-image-src="../Images/B21040_10_086.png" data-original-image-title="">B21040_10_086.png</span>

where, <span class="image placeholder" data-original-image-src="../Images/B21040_10_087.png" data-original-image-title="">B21040_10_087.png</span> are the explanatory variables. Time series components, such as trend and seasonal dummies can be used as explanatory variables.

<span class="image placeholder" data-original-image-src="../Images/B21040_10_088.png" data-original-image-title="">B21040_10_088.png</span> is the intercept term, which measures the average level of the dependent variable in the absence of any explanatory variable,

<span class="image placeholder" data-original-image-src="../Images/B21040_10_089.png" data-original-image-title="">B21040_10_089.png</span> are the parameters that measure the impact of corresponding explanatory variable on the dependent variable,

<span class="image placeholder" data-original-image-src="../Images/B21040_10_090.png" data-original-image-title="">B21040_10_090.png</span> is the model’s error term, which follows these assumptions:

-  They have zero mean
-  Not autocorrelated
-  Unrelated to the predictor variables

The zero mean assumption of the error term assures that the forecasts are not systematically biased. Forecasts become inefficient if there is autocorrelation among residuals because, in that scenario, there was information in the data that was not captured by the model and, as a result, it ends up as residuals. The third assumption makes sure that no systematic information is left out by the model.

Along with these base assumptions, it is also assumed that the errors are normally distributed, so that prediction intervals can be easily calculated. *Equation (10.1)* does not have any lagged term of the forecast variable, <span class="image placeholder" data-original-image-src="../Images/B21040_10_091.png" data-original-image-title="">B21040_10_091.png</span> , or any of the predictors <span class="image placeholder" data-original-image-src="../Images/B21040_10_092.png" data-original-image-title="">B21040_10_092.png</span> . Adding lag terms would violate the no autocorrelation assumption.

-  Advantages:

  -  The TSLM model provides interpretable insights into the relationship between the forecast variable and predictors. The estimated coefficients, along with the statistical tests, provide an impact and variable importance on generated forecasts.
  -  The model can capture the underlying behavior better when the forecast variable exhibits a strong linear relationship with predictors.
  -  The TSLM model facilitates scenario-based forecasting, which is crucial to make important business decisions.
-  Limitations:
  -  A key drawback of TSLM is that it requires accessible predictor data to generate forecasts beyond the observed period.   -  The non-linear relationship between the forecast variable and predictors is not captured by the linear model. However, transforming the variables before modeling could help.

#  10.8 Evaluating point forecast accuracy 

Accuracy measures provide a quantitative way to evaluate the performance of forecasting models. They assess how well a model is capturing the underlying pattern and trends in the data. However, a well-fitted model does not guarantee accurate forecasts. That’s why it is important to compare both the in-sample and out-of-sample accuracy of a single model to identify whether the model is over-fitted (i.e., fits well in the training data but has poor performance in the test set).

If you have competing models for a dataset, then you can objectively compare the performance of each model using forecast accuracy measures at different horizons and choose the most effective one.

The point forecast metrics are also called errors, as they are usually computed on the one-step ahead forecast errors, calculated as follows:

<span class="image placeholder" data-original-image-src="../Images/B21040_10_118.png" data-original-image-title="">B21040_10_118.png</span>

For the training set, <span class="image placeholder" data-original-image-src="../Images/B21040_10_119.png" data-original-image-title="">B21040_10_119.png</span> , and for the test set, <span class="image placeholder" data-original-image-src="../Images/B21040_10_120.png" data-original-image-title="">B21040_10_120.png</span> is replaced by <span class="image placeholder" data-original-image-src="../Images/B21040_10_121.png" data-original-image-title="">B21040_10_121.png</span> , which varies <span class="image placeholder" data-original-image-src="../Images/B21040_10_122.png" data-original-image-title="">B21040_10_122.png</span> .

The formulas for computing accuracy metrics are the same in both the training and the test set. For simplicity, we will use the subscript <span class="image placeholder" data-original-image-src="../Images/B21040_10_123.png" data-original-image-title="">B21040_10_123.png</span> irrespective of the dataset used.

There are many forecast accuracy measures available in the literature. However, we will look deeper into five of them as they are widely used in business. Based on how they are computed, they are categorized into three categories.

-  Scaled-dependent errors:

  -  Mean Absolute Error (MAE): A magnitude-driven measure that provides equal weight to all errors.

  <span class="image placeholder" data-original-image-src="../Images/B21040_10_124.png" data-original-image-title="">B21040_10_124.png</span>

  MAE is easy to interpret and less sensitive to outliers. The metric has the same scale as the data, allowing it to compare multiple forecasting models for a single series.

-  Root Mean Squared Error(RMSE): A metric that puts a heavy penalty on larger errors.

  <span class="image placeholder" data-original-image-src="../Images/B21040_10_125.png" data-original-image-title="">B21040_10_125.png</span>

  RMSE is on the same scale as the data and is used to compare competing models for a series. It is well-suited for situations where a small number of large errors have greater business consequences.

  The main drawback of the scale-dependent measures is that they are not suitable for comparing the forecasting performance of a model across multiple series with different units.

-  Percentage errors:

  -  Mean Absolute Percentage Errors (MAPE): This is a scale-free measure that first transforms forecast errors as a percentage of the observed value, and then the mean is computed over the percentages.

  <span class="image placeholder" data-original-image-src="../Images/B21040_10_126.png" data-original-image-title="">B21040_10_126.png</span>

  Being a unit-free metric, MAPE is widely used to compare forecast performance across many datasets. However, this cannot be used when <span class="image placeholder" data-original-image-src="../Images/B21040_10_127.png" data-original-image-title="">B21040_10_127.png</span> , which is a common scenario in demand forecasting.

-  Scaled errors:

  Scaled errors tackle issues in scaled metrics and the <span class="image placeholder" data-original-image-src="../Images/B21040_10_128.png" data-original-image-title="">B21040_10_128.png</span> denominator problem in the percentage error metric by using a scaling factor.

  <span class="image placeholder" data-original-image-src="../Images/B21040_10_129.png" data-original-image-title="">B21040_10_129.png</span>

  where, <span class="image placeholder" data-original-image-src="../Images/B21040_10_130.png" data-original-image-title="">B21040_10_130.png</span> is the number of seasonal periods.

  The quantity <span class="image placeholder" data-original-image-src="../Images/B21040_10_131.png" data-original-image-title="">B21040_10_131.png</span> is scale-free as both the numerator and denominator are computed at the same scale as the original data. The denominator in <span class="image placeholder" data-original-image-src="../Images/B21040_10_132.png" data-original-image-title="">B21040_10_132.png</span> is nothing but the MAE of naïve forecasts in the training data. Using the scaling factor <span class="image placeholder" data-original-image-src="../Images/B21040_10_133.png" data-original-image-title="">B21040_10_133.png</span> , the following two metrics are proposed by Hyndman et al. (2006).

-  Mean Absolute Scaled Error (MASE): The average of the absolute forecast errors scaled by the MAE in the training dataset.

  <span class="image placeholder" data-original-image-src="../Images/B21040_10_134.png" data-original-image-title="">B21040_10_134.png</span>

-  Root Mean Squared Scaled Error (RMSSE): The same as RMS,E where the forecast errors are scaled using the MAE of naïve forecasts.

  <span class="image placeholder" data-original-image-src="../Images/B21040_10_135.png" data-original-image-title="">B21040_10_135.png</span>

The primary benefit of scaled errors is the ability to compare the forecasting performance of numerous models across datasets.

In the previous sections, forecast accuracy measures were compared for a single forecasting method on a single series. Let’s see an example in which forecasts are obtained from multiple methods on a single series and out-of-sample performance is compared. #  10.9 Time series cross-validation 

Cross-validation is a standard method of performance comparison in any modeling framework. In cross-validation, observations are randomly allocated in cross-sectional data and corresponding models. However, for time series forecasting, preserving the time index is crucial during cross-validation due to temporal-dependency. A rolling window-based approach is used for time series cross-validation by expanding observations in the training set, allocating successive observations in the corresponding test set.

Using the ` `` stret `` ` ` `` c `` ` ` `` h_tsibble() `` ` function, you can create multiple training sets for time series data. The options:

- ` `` .init `` ` : Requires that the number of observations belongs to the original training set
-  . ` `` step `` ` : Specifies the increment in observations between successive training sets.

We will cross-validate the performance of the Random Walk with the drift model (RW) on WWWusage data. Even though this model performed better on one occasion, it is important to check how this model’s forecasting performance is impacted when the data window changes.

To facilitate cross-validation, we first need to generate multiple training and test datasets, then fit the model on each training set, and generate a forecast for the corresponding test set. Finally, compute accuracy metrics are averaged over all test windows to evaluate the model’s forecasting performance.

The WWWusage series has <span class="image placeholder" data-original-image-src="../Images/B21040_10_137.png" data-original-image-title="">B21040_10_137.png</span> observations. The first training set will have <span class="image placeholder" data-original-image-src="../Images/B21040_10_138.png" data-original-image-title="">B21040_10_138.png</span> observations and will increase by <span class="image placeholder" data-original-image-src="../Images/B21040_10_139.png" data-original-image-title="">B21040_10_139.png</span> observations in the successive training sets. The ` `` stretch_tsibble() `` ` function facilitates this operation in a single call, as shown in the following code snippet:

The cross-validated RMSE and MASE are reliable measures to select a final model when multiple alternative forecasting models’ performance is evaluated on a single series. From the cross-validated forecasting performance, we see that RW forecasting performance degraded as the forecast horizon increases irrespective of metrics.

The WWWusage data has a significant structural break near the end of the series, which affected the overall forecasting performance. This highlights the model’s inability to adapt quickly to new, unobserved patterns based solely on older data.

The training sets in the cross-validation are shorter compared to the full dataset. It is important to note that shorter training sets can lead to higher variance in performance because the model has less data to learn long-term trends and complex patterns. The initial cross-validation metrics might overestimate the error rate compared to a model trained on a full dataset.

Time series cross-validation provides a robust way to evaluate performance across different time periods, especially how the model handles new data, closely simulating a real-world forecasting exercise.
