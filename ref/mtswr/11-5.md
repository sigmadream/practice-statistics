#  Time Series Data Wrangling and Visualization 

In this chapter, some common data wrangling and visualization techniques for time series are presented. Data wrangling is an essential yet often overlooked process of grappling with raw data, getting it into shape for further analysis. This pivotal stage includes cleaning, transforming, refining, and summarizing data in alignment with analysis objectives. In addition, visualization plays a significant role when working with time series data. It aids in recognizing existing patterns and understanding their combinations within the observed data. Skillful visualization is instrumental in selecting the most suitable forecasting model for the task at hand.

The complexity of time series data wrangling largely depends on two things: (a) the messiness of the raw data, and (b) the objectives of next-stage analysis. For example, if you have daily data and in the experiment phase, you do not know whether a model with weekly data or a model with monthly data will be more insightful. In such a situation, you need to clean the daily data as much as possible and aggregate it to the desired level just before modeling. In other scenarios, the data you have received could already be summarized at the desired level, but you may still need to clean and transform it appropriately.

#  5.1 Parsing date-time variables 

During the data wrangling process, you need some kind of mechanism to check whether formatting date/date-time variables in R produces no error and gives desirable results. Unfortunately, there is no one-size-fits-all method. However, validating simple logic will save time and frustration later. For example, calculating unique years and sorting them enables us to check whether formatting performs as expected. Another option is to calculate the number of observations in each year. A too-low number or too-high number (more than 365 for daily data, or more than 12 for monthly data) would identify any potential issues.

Let’s elaborate on this with a toy dataset. Load the ` `` mismatch_date. `` ` ` `` csv `` ` file using the ` `` read_csv() `` ` function and check the variables type:

```
mismatch_dt <- read_csv("data/data_chap5/mismatch_date.csv")
glimpse(mismatch_dt)
```

You will see the following output where the date column is loaded as character type:

```

Columns: 2
$ date  <chr> "1/01/2015", "1/02/2015", "1/03…
$ value <dbl> 1630, 826, 567, 139, 256, 113, …
```

The data frame has nine rows and the date column could be in ` `` DD-MM-YYYY `` ` format. Now format the date and compute the number of observations in each year using the following code:

```
year_count <- mismatch_dt |>
  mutate(date = as.Date(date, format = "%d/%m/%Y")) |>

The impact of even a small number of incorrect data entries in a large file can be significant, especially when summarizing data at higher levels, such as weekly, or monthly. This issue can escalate when data processing includes loading and merging files from multiple sources. It is unlikely that a unified date-time input is always followed across an organization. Similar challenges can arise when sourcing data from multiple schemas and tables within a database. These inconsistencies and discrepancies can lead to inaccurate analyses, misleading conclusions, and potentially costly decisions. It highlights the critical importance of rigorous data validation and cleaning procedures before proceeding with data aggregation and analysis.

Observations may be collected against some units of time, but that does not necessarily mean that they are already a time series object by the definition of R. Will you transform any temporal data into a time series object as soon as you load it into R? The answer depends on the objectives of your analysis. Let’s clarify this question in the next section.

#  5.3 When to transform data into time series object? 

In an analysis, the need for a time series object arises when specific models require time series data as input. However, some models do not necessitate a time series object. In such cases, temporal data can be kept in a ` `` tibble `` ` object, allowing for wrangling tasks, such as cleaning and summarizing without the need for transformation into a time series object. Therefore, your choice of functions for data wrangling depends on the downstream analysis requirements.

Regardless of the future modeling choice, parsing temporal data into a ` `` tsibble `` ` object when data wrangling proves efficient, especially when handling numerous series simultaneously. This format retains the time series structure while offering flexibility for various analyses, making it a valuable option for managing temporal data.

In *C* *hapter 2* , we discussed various ways to transform data into a time series object. They are summarized in *Table 5.1* for your reference.

|  **Package** |  **Function** |  **Application** |
|----|----|----|
| ` `` forecast `` ` | ` `` ts() `` ` |  Transform a single series |
| ` `` tsibble `` ` | ` `` tsibble() `` `  or  ` `` as_tsibble() `` ` |  Transform many series at once, works with  ` `` ts `` `  ,  ` `` tibble `` `  or  ` `` data.frame `` `  format |

Table 5.1: Functions to transform data into a time series object

Both the ` `` forecast `` ` and ` `` tsibble `` ` packages provide helpful tools for managing time series data.

The ` `` tsibble `` ` package is constructed on top of tibble, which adheres to the tidy data principle by default. This means it provides an organized and efficient ways to store and wrangle temporal data. With tsibble, you can easily manage multiple time series in a structured manner, facilitating tasks, such as aggregation, transformation, and analysis.

On the other hand, the ` `` ts() `` ` function from the ` `` forecast `` ` package is designed to be applied on a single series. However, it can be extended to handle multiple series using techniques, such as *for loops* or functional programming with the ` `` purrr `` ` package. While these methods are effective, they might not always be as streamlined or intuitive as using a ` `` tsibble `` ` object for handling multiple time series simultaneously.

So, depending on the complexity of your time series data and the tasks at hand, ` `` tsibble `` ` offers a more integrated and efficient solution for managing and wrangling multiple time series, while the base ` `` ts() `` ` object can still be used effectively for single series or with additional programming effort for multiple series.

-  Is it a one-off analysis or do you need to repeat it at regular frequency?
-  Is it exploratory work versus potential to be part of a data and/or modeling pipeline in production?

Maintaining reproducibility in the data preparation process is crucial, regardless of your role in an organization.

For a data analyst preparing data for monthly board meetings, it’s essential to have a clear and reproducible workflow. As a data scientist handling both data and modeling pipelines, reproducibility is of utmost importance. Your code should be organized in a way that anyone (including your future self) can follow the steps taken from initial data exploration to model development. This helps in understanding decisions made along the way and allows for easy adjustment or expansion of the analysis.

For a machine learning (ML) engineer working on productionizing a model, reproducibility ensures that the entire pipeline, including data cleaning, feature engineering, and model training, can be replicated in a production environment. This guarantees consistent results and easier troubleshooting if issues arise.

In all these scenarios, using version control systems, such as Git and documenting code with comments and clear explanations helps maintain reproducibility. Creating modular and reusable functions for common data cleaning and transformation tasks also streamlines the process and reduces the chances of errors.

By developing reproducible code, you not only ensure consistency and reliability in your analyses but also make it easier for others to understand and build upon your work.

#  5.5 Visualization functions 

In base R, the ` `` plot() `` ` function with ` `` type=l `` ` is used to generate a time plot. The famous ` `` ggplot2 `` ` package is widely used to create visualizations in R, and also has time series data covered. The ` `` ggplot2 `` ` package is included in the ` `` tidyverse `` ` package suite. You can also load only the ` `` ggplot2 `` ` package. In the rare scenario that you are using ` `` ggplot2 `` ` for the first time, the brief overview that follows will be helpful.

When creating a plot using functions from the ` `` ggplot2 `` ` package, you need to pass various types of information:

-  **Data** : Usually long-format data works better (i.e., variables in columns and observations in row).
-  **Mapping** : Assign variables to horizontal (x) or vertical (y) axis, apply groupings (if any), and indicate plotting characteristics, such as size, shape and color. This is done via the ` `` aes() `` ` (short for aesthetic) function.
-  **Geom functions** : Define how to represent data graphically. There are many geoms available and new ones are introduced frequently. Some common geoms are ` `` geom_point() `` ` for scatter plot and dot plots, ` `` geom_bar() `` ` for bar plots, and ` `` geom_line() `` ` to create a line plot for a time series.
-  **Theme** : Options to customize graphics.

First, a plotting object is created using the ` `` ggplot() `` ` function. Note the difference between this function’s name and the name of the package ` `` , ggplot2 `` ` . In the ` `` ggplot() `` ` function, pass the data and mapping along with at least one geom to create a plot.

Multiple geoms can be used in one plot. There are many options to customize a plot, such as using theme, scaling and faceting functions. The geom and the customization functions are considered as layers that are chained by a ‘‘ ` `` + `` ` ’’ in between each function. There is no limit on the number of layers used in a ` `` ggplot `` ` object. However, the ordering of layers may impact the final output.

The standard template for a plot created via ` `` ggplot `` ` is as follows:

```
ggplot(data = <DATA>, mapping = aes(x,y)) +
  <GEOM_FUNCITONS>() +
  <THEME_FUNCTIONS>()
```

The ` `` autoplot() `` ` function from the ` `` ggplot2 `` ` package is a flexible, short-hand, single command curated for plot for a particular class. Instead of passing raw data, you need to pass an *object with a defined class* , which determines the output plot.

The flexible nature of ` `` autoplot() `` ` makes it an attractive visualization tool to create default object-specific plotting in many packages. Both the forecast and ` `` fabletools `` ` packages have multiple versions of ` `` autoplot() `` ` and ` `` autolayer() `` ` that are applied on specific object to create a specific plot. For example, to plot a time series, ` `` forecast::autoplot() `` ` requires a ` `` ts `` ` class object whereas ` `` fabletools::autoplot() `` ` works with a ` `` tsibble `` ` object.

In short, the advantage of using ` `` autoplot() `` ` is that you need only one function to generate many different visualizations; all you need is to pass an appropriate object into it.

In the next section, you will use both the ` `` autoplot() `` ` and ` `` ggplot() `` ` to make a time plot.

#  5.6 Time plots 

In time series visualization, the focus is on visually identifying the various components. You already saw some examples of time plots in *<a href="Chapter_4.xhtml#h1_113" class="chapref"> Chapter 4 </a>* , where we discussed the characteristics of a time series. Time plots are also known as line plots.

In a time plot, observations are plotted against time. The observations are joined by a line, reflecting the fact that time is a continuous variable. There are multiple ways you can create a time plot based on the class of your data:

- ` `` tsibble class `` ` : The ` `` autoplot() `` ` function automatically creates a time plot if the data is in tsibble format.

  In the following examples, we will be using the ` `` aus_production `` ` dataset from the ` `` tsibbledata `` ` package. The dataset is loaded along with the package. This dataset contains quarterly production figures for beer, tobacco, bricks, cement, electricity and gas in Australia from 1956 Q1 to 2010 Q2. First check the class of the data as follows:

- ` `` tibble `` ` or ` `` data frame `` ` : Use the ` `` ggplot() `` ` function along with ` `` geom_line() `` ` to produce time plots. First, you need to transform the time variable into a proper date/date-time variant if you haven’t already done so.

In the following example, the date variable, ` `` sched_dep_date `` ` , is obtained by extracting the year, month, day, hour, and minute components using the ` `` make_datetime() `` ` and ` `` date() `` ` functions. The data was recorded in an odd format, hence the arithmetic modulus is used. This is an example of handling odd formatting of date-time based variables in time series data wrangling. An indicator variable, ` `` is_delayed `` ` , is created to flag whether a flight was delayed or not:

```
flights <-
  nycflights13::flights |>
  filter(!is.na(dep_time), !is.na(arr_time)) |>
  mutate(sched_dep_datetime = make_datetime(
    year, month, day,
    sched_dep_time %/% 100,
    sched_dep_time %% 100)
  ) |>
  mutate(sched_dep_date = date(sched_dep_datetime)) |>
  select(carrier, origin, dest, sched_dep_date, dep_delay) |>
  mutate(is_delayed = ifelse(dep_delay > 0, 'y', 'n'))
```

The total number of delayed flights is calculated and plotted for two carriers, ` `` American Airlines `` ` ( ` `` AA `` ` ) and ` `` Delta Airlines `` ` ( ` `` DL `` ` ).

```
flights |>
  filter(carrier %in% c("AA", "DL"),
         is_delayed == 'y') |>
  count(sched_dep_date, carrier) |>
  ggplot(aes(x = sched_dep_date, y = n,
             group = carrier,
             linetype = carrier)) +
  geom_line() +
  labs(x = " " ,
       y = "delayed flights") +
  theme(legend.position = "top")
```

Now, discrepancies in weekly delayed flights between the two airlines are better visible from the plot. Since we are showcasing ` `` ggplot `` ` functionality, we applied weekly aggregation in the tibble dataframe. The ` `` lubridate::ceiling_date() `` ` function is used to round a date up to the end date of the week (technically, the start of the next week). The ` `` floor_date() `` ` function rounds a date down to the start date of a week. Alternatively, you can transform the data to a ` `` tsibble `` ` format and then use the corresponding functions to calculate the week end date.

Another common aggregation level in time series data is statistical aggregation. For example, you may be interested in comparing the weekly average delayed time between these two carriers and examining any impact of the origin of the flights.

The following code first computes the weekly average delay time of all carriers that took off from John F Kennedy International Airport (JFK). Then, it computes the weekly average delay time for AA and DL:

```
# weekly average delayed time of all carriers from JFK
jfk_delay <- flights |>
  filter(origin == "JFK" ,
         is_delayed == 'y' ) |>
  mutate(sched_dep_week = ceiling_date(sched_dep_date, "week")) |>
  group_by(sched_dep_week) |>
  summarise(avg_jfk = mean(dep_delay, na.rm = T)) |>
  ungroup()


flight2_delay <- flights |>
  filter(carrier %in% c("AA", "DL"),
         is_delayed == 'y' ,
         origin == "JFK"
  ) |>
  mutate(sched_dep_week = ceiling_date(sched_dep_date, "week")) |>
  group_by(sched_dep_week, carrier, origin, dest) |>
  summarise(avg_delay = mean(dep_delay, na.rm = T)) |>
  ungroup()

The ` `` gg_season() `` ` function from the ` `` feasts `` ` package provides a seasonal plot for a ` `` tsibble `` ` data object as shown in the following code:

```
aus_production |>

  gg_season(Gas)
```

#  5.8 Visualizing relationships among time series 

Correlation is a common technique to identify the strength of a liner relationship among variables. A standard practice in statistical and ML modeling is to compute the correlation between variables to check whether to include them in a model. In time series modeling, you could check the correlation between a series and other explanatory variables, such as electricity demand and temperature. Similarly, you could analyze the correlation among multiple time series to assess how closely they manifest patterns. A scatter plot is the simplest way to visually inspect the correlation among variables. Now you will learn to make scatter plots for time series.

##  5.8.1 Scatter plots 

Usually, a scatter plot is used to examine the correlation between two variables, one dependent and one explanatory. The ` `` GGally `` ` package offers the ` `` ggpairs() `` ` function to plot a pairwise scatter plot for multiple series. The same plot also prints the pairwise correlation value along with its significance in the top diagonal panels, and distribution in the diagonal line.

In the following example, you will use the turnover from six industries between 2015 and 2022 for Victoria from Australian retail data. The long industry names are replaced by extracting the corresponding first word using ` `` sapply `` ` after applying the ` `` str_split `` ` ` `` () `` ` function and a regex (split in white space or comma) pattern:

```
vic_retail <-
  readRDS("data/data_chap5/abs_retail.rds") |>
  filter(
    industry %in% c(
      "Clothing retailing",
      "Food retailing",
      "Electrical and electronic goods retailing",
      "Hardware, building and garden supplies retailing",
      "Newspaper and book retailing",
      "Supermarket and grocery stores"
    ),
    state == "Victoria" ,
    year(month) >= 2015 ,
    year(month) <= 2022
  ) |>
  select(month, industry, turnover) |>
  mutate(industry = sapply(
    str_split(string = industry,pattern = "[, ]+") ,'[', 1))
```

Let’s see the turnover from individual industries over the years as presented in *Figure 5.9* :

vic_retail |>

##  5.8.2 Lag plots 

You learned about autocorrelation in *<a href="Chapter_4.xhtml#h1_113" class="chapref"> Chapter 4 </a>* when examining serial dependency on the past values of a time series. Scatter plots with a lagged value, also known as lag plots, are graphical representations used in time series analysis to visualize the relationship between a variable and its lagged observations. In a lag plot, the current value of a variable is plotted against its previous value(s) at a certain time lag. This helps reveal patterns, trends, or correlations that might exist in the data over time. It is another way to explore the autocorrelation or dependence structure of a time series.

There are functions in the two packages that you can use to create lag plots. The ` `` forecast `` ` package has the ` `` gglagplot() `` ` function and the ` `` feasts `` ` package offers the ` `` gg_lag() `` ` function. The latter is used in the following example:

```
vic_retail |>
  filter(industry == "Clothing") |>
  gg_lag(turnover, lags = 1:12, geom = "point") +
  labs(x = "lag(Turnover,l)",
       y = "Turnover")
```

*Figure 5.11* shows a strong positive dependency at lag 1 and lag 12, as most observations are gathered around the upward line.

<figure class="mediaobject">
 <span class="image placeholder" data-original-image-src="../Images/B21040_5_11.png" data-original-image-title="">Image 11</span> 
</figure>

Figure 5.11: Lag plot of Clothing turnover in Victoria during 2015-2022

The observations are scattered in other lags and do not indicate any strong dependency.

In case you are curious to examine the autocorrelation function of the same data to cross-check the dependency pattern, you could plot that by either using the ` `` ggAcf() `` ` function from the ` `` forecast `` ` package or applying ` `` autoplot() `` ` on a ` `` feasts::ACF `` ` object:

```
vic_retail |>
  filter(industry == "Clothing") |>
  ACF(turnover) |>
  autoplot() +
  labs(title = "" )
```

The autocorrelation function in *Figure 5.12* shows significant spikes at lags 1 and 12.

A strong spike at lag 1 suggests that the current month’s value is strong and positively correlated with the previous month’s value. The significant spike at 12 indicates a strong seasonal pattern; that is, the current month’s value is positively correlated with the same month in the previous year’s value.

By using scatter plots and lag plots on time series data, you can examine the relationship between multiple time series as well as dependency within a series. There are a handful of R packages that offer interactive plotting functionality. #  5.9 Interactive plots 

The ` `` Plotly `` ` package is well renowned for its capability in producing interactive plots. The ` `` ggplotly() `` ` function from the ` `` Plotly `` ` package turns any static ` `` ggplot `` ` object into an interactive and dynamic visualization. To do this, you need to save ` `` ggplot `` ` into an object and then pass it inside the ` `` ggplotly() `` ` function, as shown in the following example:

```
lag_turnover <- vic_retail |>
  filter(industry=="Clothing") |>
  gg_lag(turnover, lags = 1:12, geom = "point") +
  labs(x="lag(Turnover,l)",
       y="Turnover")

ggplotly(lag_turnover)
```

The code will generate an interactive plot in your R environment where you can pan, zoom, and hover over data points. This enables users to get engaged and access more information.

For those interested in interactive visualization, the ` `` dygraphs `` ` package provides a highly effective method for creating dynamic time series charts using the ` `` dygraphs() `` ` function. This allows users to pan and zoom through data directly in a browser or IDE viewer. You can explore such functionality on your own.
