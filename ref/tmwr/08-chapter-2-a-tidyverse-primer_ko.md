# 2장. Tidyverse 기초 입문 (A Tidyverse Primer)

tidyverse란 무엇이며, tidymodels 프레임워크는 어디에 속할까요? tidyverse는 공통된 아이디어와 규범으로 개발된 데이터 분석용 R 패키지 모음입니다. Wickham 등 (2019)에 따르면:

> 큰 틀에서 볼 때, tidyverse는 R 코드로 데이터 과학 문제를 해결하기 위한 언어입니다. 그것의 주요 목표는 데이터에 대한 인간과 컴퓨터 간의 대화를 원활하게 하는 것입니다. 덜 추상적으로 말하자면, tidyverse는 높은 수준의 설계 철학과 낮은 수준의 문법 및 데이터 구조를 공유하는 R 패키지 모음으로, 한 패키지를 배우면 다음 패키지를 더 쉽게 배울 수 있도록 합니다.

이 장에서는 tidyverse 설계 철학의 중요한 원칙들과, 이러한 원칙들이 [1장](ch01.xhtml#software-modeling)에서 설명한 바와 같이 적절하게 사용하기 쉽고 좋은 통계적 관행을 지원하는 모델링 소프트웨어의 맥락에 어떻게 적용되는지 간략하게 논의합니다. 다음 장에서는 핵심 R 언어의 모델링 규약을 다룹니다. 이러한 논의를 종합하여 tidyverse, tidymodels, 그리고 핵심 또는 기본 R 언어 간의 관계를 이해할 수 있습니다. tidymodels와 tidyverse 모두 R 언어를 기반으로 구축되었으며, tidymodels는 모델 구축에 tidyverse 원칙을 적용합니다.

# Tidyverse 원칙 (Tidyverse Principles)

tidyverse 스타일로 R 코드를 작성하기 위한 전략과 전술의 전체 세트는 [tidyverse 웹사이트](https://oreil.ly/09DEV)에서 찾을 수 있습니다. 여기서는 일반적인 tidyverse 설계 원칙 몇 가지, 그 동기, 그리고 이러한 원칙의 적용으로서 모델링에 대해 어떻게 생각하는지 간략하게 설명합니다.

## 인간을 위한 설계 (Design for Humans)

tidyverse는 광범위한 사람들이 쉽게 이해하고 사용할 수 있는 R 패키지 및 함수를 설계하는 데 중점을 둡니다. 역사적으로나 오늘날이나 R 사용자의 상당 비율은 소프트웨어나 도구를 만드는 사람이 아니라 분석이나 모델을 만드는 사람들입니다. 따라서 R 사용자는 일반적으로 컴퓨터 과학 배경 지식을 가지고 있지 않으며(필요로 하지도 않음), 상당수는 자신만의 R 패키지를 작성하는 데 관심이 없습니다.

이러한 이유로 R 코드는 여러분의 목표를 달성하기 위해 사용하기 쉬워야 합니다. 문서화, 교육, 접근성 및 기타 요소가 이를 달성하는 데 중요한 역할을 합니다. 그러나 구문 자체를 사람들이 쉽게 이해하기 어렵다면 문서화는 부족한 해결책일 뿐입니다. 소프트웨어 자체는 직관적이어야 합니다.

tidyverse 접근 방식을 보다 전통적인 R 의미론(semantics)과 대조하기 위해, 데이터 프레임을 정렬하는 것을 고려해 보십시오. 데이터 프레임은 각 열(column)에 서로 다른 데이터 유형을 나타낼 수 있고, 각 행(row)에 여러 값을 가질 수 있습니다. 핵심 언어만 사용하여 데이터 프레임을 하나 이상의 열을 기준으로 정렬하려면, `order()`와 함께 R의 인덱싱(subscripting) 규칙을 통해 행을 재정렬할 수 있습니다. 이런 상황에서 이름 때문에 시도하고 싶을 수 있는 함수인 `sort()`를 성공적으로 사용할 수는 없습니다. 두 개의 열을 기준으로 `mtcars` 데이터를 정렬하려면 다음과 같이 호출해야 합니다:

```
mtcars[order(mtcars$gear, mtcars$mpg), ]
```

이는 계산상으로는 매우 효율적이지만 직관적인 사용자 인터페이스라고 주장하기는 어려울 것입니다. 이와 대조적으로 dplyr에서는 tidyverse 함수인 `arrange()`가 변수 이름 집합을 입력 인수로 직접 사용합니다:

```
library(dplyr)
arrange(.data = mtcars, gear, mpg)
```

###### 참고 (Note)

여기에 사용된 변수 이름은 "따옴표가 생략된(unquoted)" 상태입니다. 전통적인 R 함수 중 상당수는 변수를 지정하기 위해 문자열이 필요하지만, tidyverse 함수는 따옴표 없는 이름이나 *선택자 함수(selector functions)*를 사용합니다. 선택자는 열 이름에 적용할 수 있는 하나 이상의 읽기 쉬운 규칙을 허용합니다. 예를 들어 `ends_with("t")`는 `mtcars` 데이터 프레임의 `drat` 및 `wt` 열을 선택할 것입니다.

또한 이름 지정은 매우 중요합니다. R을 처음 접하고 선형 대수와 관련된 데이터 분석이나 모델링 코드를 작성하는 경우, 행렬의 역행렬을 계산하는 함수를 찾을 때 난관에 부딪힐 수 있습니다. `apropos("inv")`를 사용하면 아무런 후보도 나오지 않습니다. 선형 방정식의 시스템을 풀기 위한 이 작업의 기본 R 함수는 `solve()`로 밝혀졌습니다. 행렬 `X`의 경우 `solve(X)`를 사용하여 `X`를 반전시킵니다(방정식 우변에 벡터가 없음). 이것은 도움말 파일의 *인수(arguments)* 중 하나에 대한 설명에만 기록되어 있습니다. 본질적으로 해답(solution)을 찾기 위해서는 그 해답의 이름을 알아야 합니다.

tidyverse 접근 방식은 짧고 암묵적인 이름보다는 설명적이고 명시적인 함수 이름을 사용하는 것입니다. 일반적인 메소드의 경우 동사(예: `fit`, `arrange` 등)에 초점을 맞춥니다. 동사-명사 쌍은 특히 효과적입니다. 가상의 함수 이름으로 `invert_matrix()`를 생각해 보세요. 모델링 맥락에서 이름에 그리스 문자나 모호한 용어와 같은 고도의 기술 전문 용어(jargon)를 피하는 것도 중요합니다. 이름은 가능한 한 스스로 설명 가능(self-documenting)해야 합니다.

패키지에 유사한 함수들이 있을 때, 함수 이름은 탭 완성(tab-completion)에 최적화되도록 설계됩니다. 예를 들어, glue 패키지에는 공통 접두사(`glue_`)로 시작하는 함수 모음이 있어 사용자가 찾고 있는 함수를 빠르게 찾을 수 있도록 합니다.

## 기존 데이터 구조 재사용 (Reuse Existing Data Structures)

가능할 때마다 함수는 새로운 형태의 데이터 구조를 반환하는 것을 피해야 합니다. 결과가 기존 데이터 구조에 도움이 된다면 이를 사용해야 합니다. 이렇게 하면 소프트웨어를 사용할 때 인지 부하가 줄어듭니다. 즉, 추가적인 구문이나 방법론이 필요하지 않습니다.

데이터 프레임(data frame)은 구조가 광범위한 데이터 과학 작업에 잘 맞기 때문에 tidyverse 및 tidymodels 패키지에서 선호되는 데이터 구조입니다. 특히 tidyverse 및 tidymodels는 R의 데이터 프레임을 현대적으로 재해석한 *tibble*을 선호하며, 이는 tidyverse 구문 예시에 관한 다음 섹션에서 설명합니다.

예를 들어 rsample 패키지는 교차 검증(cross-validation)이나 부트스트랩([10장](ch10.xhtml#resampling)에서 설명됨)과 같이 데이터 세트의 *리샘플(resamples)*을 생성하는 데 사용할 수 있습니다. 리샘플링 함수는 리샘플링된 데이터 세트를 정의하는 객체들의 열(`splits`라고 함)이 포함된 tibble을 반환합니다. 데이터 세트의 부트스트랩 샘플 3개는 다음과 같을 수 있습니다:

```
boot_samp <- rsample::bootstraps(mtcars, times = 3)
boot_samp
#> # Bootstrap sampling
#> # A tibble: 3 × 2
#>   splits          id
#>   <list>          <chr>
#> 1 <split [32/15]> Bootstrap1
#> 2 <split [32/12]> Bootstrap2
#> 3 <split [32/10]> Bootstrap3
class(boot_samp)
#> [1] "bootstraps" "rset"       "tbl_df"     "tbl"        "data.frame"
```

이 접근 방식을 사용하면, `vapply()` 또는 `purrr::map()`과 같이 벡터 기반 함수를 이러한 열과 함께 사용할 수 있습니다.<sup>[1](ch02.xhtml#idm45881872874080-marker)</sup> 이 `boot_samp` 객체는 여러 클래스를 갖지만 데이터 프레임(`"data.frame"`) 및 tibble(`"tbl_df"`)에 대한 메소드를 상속합니다. 또한 데이터의 클래스에 영향을 주지 않고 결과에 새로운 열을 추가할 수 있습니다. 이는 데이터 구조가 분명하지 않은 완전히 새로운 객체 유형에 비해 사용자가 다루기에 훨씬 쉽고 다재다능합니다.

일반적인 데이터 구조에 의존할 때의 한 가지 단점은 연산 성능이 저하될 가능성이 있다는 점입니다. 일부 상황에서는 데이터를 더 효율적으로 표현하는 특수한 형식으로 데이터를 인코딩할 수 있습니다. 예를 들어:

- 계산 화학(computational chemistry)에서 구조-데이터 파일 형식(structure-data file format, SDF)은 화학 구조를 취하여 컴퓨팅 측면에서 작업하기 효율적인 형식으로 인코딩하는 도구입니다.

- 동일한 값이 다수 존재하는 데이터(예: 이진 데이터의 경우 0)는 희소 행렬(sparse matrix) 형식으로 저장할 수 있습니다. 이 형식은 데이터 크기를 줄이고 계산 기법을 더 효율적으로 활성화할 수 있습니다.

이러한 형식들은 문제가 잘 규정되어 있고, 잠재적인 데이터 처리 방법이 모두 잘 정의되어 있으며 이러한 형식에 적합한 경우 유리합니다.<sup>[2](ch02.xhtml#idm45881872893984-marker)</sup> 그러나 이러한 제약 조건이 위반되면 특수 데이터 형식의 유용성은 떨어집니다. 예를 들어 데이터를 소수로 변환하는 데이터 변환을 수행하면 출력은 더 이상 희소(sparse)하지 않게 됩니다. 즉, 희소 행렬 표현은 모델링의 특정 알고리즘 단계 하나에는 유용하지만, 그 특정 단계 전이나 후에는 그렇지 않은 경우가 많습니다.

###### 경고 (Warning)

특수 데이터 구조는 일반적인 데이터 구조가 그러하듯 전체 모델링 워크플로에 대해 충분히 유연하지 않습니다.

rsample에서 생성된 tibble의 한 가지 중요한 특징은 `splits` 열이 리스트(list)라는 점입니다. 이 경우 리스트의 각 요소는 동일한 객체 유형을 갖습니다: 바로 `mtcars`의 어떤 행이 부트스트랩 샘플에 속하는지에 대한 정보를 포함하는 `rsplit` 객체입니다. *리스트 열(List columns)*은 데이터 분석에서 매우 유용할 수 있으며 이 책 전반에서 볼 수 있듯이 tidymodels에서 중요합니다.

## 파이프 및 함수형 프로그래밍을 위한 설계 (Design for the Pipe and Functional Programming)

magrittr 파이프 연산자(`%>%`)는 R 함수의 시퀀스를 함께 연결하기 위한 도구입니다.<sup>[3](ch02.xhtml#idm45881872860416-marker)</sup> 이를 증명하기 위해, 데이터 프레임을 정렬한 다음 처음 10개 행을 유지하는 다음 명령을 고려해 보십시오:

```
small_mtcars <- arrange(mtcars, gear)
small_mtcars <- slice(small_mtcars, 1:10)

# 또는 더 간결하게:
small_mtcars <- slice(arrange(mtcars, gear), 1:10)
```

파이프 연산자는 연산자 좌변의 값을 우변의 첫 번째 인수로 대체하므로 다음과 같이 이전과 동일한 결과를 구현할 수 있습니다:

```
small_mtcars <-
  mtcars %>%
  arrange(gear) %>%
  slice(1:10)
```

이 시퀀스의 파이프 버전은 가독성이 더 좋습니다. 이러한 가독성은 시퀀스에 연산이 더 많이 추가될수록 향상됩니다. 이 예제에서 프로그래밍에 대한 이러한 접근 방식이 효과적인 이유는, 우리가 사용한 모든 함수가 다음 함수의 첫 번째 인수가 되는 동일한 데이터 구조(데이터 프레임)를 반환하기 때문입니다. 이는 의도적으로 설계된 것입니다. 가능한 한 여러 작업의 파이프라인(pipeline)에 통합될 수 있는 함수를 만드십시오.

ggplot2를 사용해 본 적이 있다면, 이것은 `+` 연산자를 사용하여 플롯 구성 요소를 `ggplot` 객체에 겹겹이 쌓는 것과 크게 다르지 않습니다. 회귀선이 포함된 산점도를 만들기 위해 초기 `ggplot()` 호출은 두 개의 추가 연산으로 보강됩니다:

```
library(ggplot2)
ggplot(mtcars, aes(x = wt, y = mpg)) +
  geom_point() +
  geom_smooth(method = lm)
```

dplyr 파이프라인과 유사하지만, 이 파이프라인의 첫 번째 인수는 데이터 세트(`mtcars`)이고 각 함수 호출이 `ggplot` 객체를 반환한다는 점에 유의하세요. 모든 파이프라인이 반환된 값(플롯 객체)을 초깃값(데이터 프레임)과 동일하게 유지할 필요는 없습니다. dplyr 연산에 파이프 연산자를 사용하는 것은 많은 R 사용자가 파이프라인이 사용될 때 데이터 프레임을 반환할 것으로 예상하도록 순응시켰습니다. ggplot2에서 보듯이 반드시 그래야 하는 것은 아닙니다. 파이프라인은 모델링 워크플로에서 놀라울 정도로 유용하지만, 모델링 파이프라인은 데이터 프레임 대신 모델 컴포넌트와 같은 객체를 반환할 수 있습니다.

R에는 함수를 생성, 변경 및 조작할 수 있는 훌륭한 도구가 있어 함수형 프로그래밍에 훌륭한 언어입니다. 이 접근 방식은 함수가 다른 부작용(side effects) 없이 값을 반환하는 경우와 같은 많은 상황에서 반복 루프(iterative loops)를 대체할 수 있습니다.<sup>[4](ch02.xhtml#idm45881872180240-marker)</sup>

예를 살펴보겠습니다. 차량 무게에 대한 연비 비율의 로그(logarithm)에 관심이 있다고 가정해 보겠습니다. R을 처음 접하거나 다른 프로그래밍 언어에서 온 사람들에게는 루프가 좋은 옵션처럼 보일 수 있습니다:

```
n <- nrow(mtcars)
ratios <- rep(NA_real_, n)
for (car in 1:n) {
  ratios[car] <- log(mtcars$mpg[car]/mtcars$wt[car])
}
head(ratios)
#> [1] 2.081 1.988 2.285 1.896 1.693 1.655
```

R 경험이 많은 사람은 다음과 같이 계산할 수 있는 훨씬 더 간단하고 빠른 벡터화된(vectorized) 버전이 있다는 것을 알 수 있습니다:

```
ratios <- log(mtcars$mpg/mtcars$wt)
```

그러나 실제 사례에서는 우리가 관심 있는 원소별(element-wise) 연산이 벡터화된 솔루션을 쓰기에는 너무 복잡한 경우가 많습니다. 이런 경우 좋은 접근 방식은 연산을 수행할 함수를 작성하는 것입니다. 함수형 프로그래밍을 위해 설계할 때, 출력은 입력에만 의존해야 하며 함수에 부작용이 없어야 한다는 것이 중요합니다. 다음 함수에서 이러한 개념을 위반하는 경우가 주석과 함께 표시됩니다:

```
compute_log_ratio <- function(mpg, wt) {
  log_base <- getOption("log_base", default = exp(1)) # 외부 데이터를 가져옴
  results <- log(mpg/wt, base = log_base)
  print(mean(results))                                # 콘솔에 출력함
  done <<- TRUE                                       # 외부 데이터를 설정함
  results
}
```

더 나은 버전은 다음과 같을 것입니다:

```
compute_log_ratio <- function(mpg, wt, log_base = exp(1)) {
  log(mpg/wt, base = log_base)
}
```

purrr 패키지에는 함수형 프로그래밍을 위한 도구가 포함되어 있습니다. 벡터에서 연산하고 항상 동일한 유형의 출력을 반환하는 `map()` 함수 계열에 초점을 맞추겠습니다. 가장 기본적인 함수인 `map()`은 항상 리스트를 반환하며 `map(vector, function)`의 기본 구문을 사용합니다. 예를 들어 데이터의 제곱근을 구하려면 다음과 같이 할 수 있습니다:

```
map(head(mtcars$mpg, 3), sqrt)
#> [[1]]
#> [1] 4.583
#>
#> [[2]]
#> [1] 4.583
#>
#> [[3]]
#> [1] 4.775
```

우리가 특정 함수가 기본 벡터 유형 중 하나를 생성할 것임을 알거나 예상할 때, 해당 값을 반환하는 특수한 `map()` 변형(variants)이 있습니다. 예를 들어 제곱근은 배정밀도(double-precision) 숫자를 반환하므로:

```
map_dbl(head(mtcars$mpg, 3), sqrt)
#> [1] 4.583 4.583 4.775
```

여러 벡터에 걸쳐 동작하는 매핑 함수(mapping functions)도 있습니다:

```
log_ratios <- map2_dbl(mtcars$mpg, mtcars$wt, compute_log_ratio)
head(log_ratios)
#> [1] 2.081 1.988 2.285 1.896 1.693 1.655
```

`map()` 함수는 또한 물결표(`~`) 문자를 사용하여 정의된 임시 익명 함수(temporary, anonymous functions)를 허용합니다. `map2()`의 경우 인수 값은 `.x`와 `.y`입니다.

```
map2_dbl(mtcars$mpg, mtcars$wt, ~ log(.x/.y)) %>%
  head()
#> [1] 2.081 1.988 2.285 1.896 1.693 1.655
```

이러한 예제들은 단순했지만 이후 섹션에서는 더 복잡한 문제에 적용될 것입니다.

###### 참고 (Note)

Tidy 모델링의 함수형 프로그래밍을 위해, `map()`과 같은 함수가 반복적인 계산에 사용될 수 있도록 함수가 정의되어야 합니다.

# Tidyverse 구문 예시 (Examples of Tidyverse Syntax)

tibble이 무엇인지, 그리고 tibble이 어떻게 작동하는지 더 깊이 탐구함으로써 tidyverse 구문에 대한 논의를 시작해 봅시다. Tibble은 R의 기본 데이터 프레임과는 약간 다른 규칙을 가지고 있습니다. 예를 들어, tibble은 구문적으로 유효한 변수 이름이 아닌 열 이름에서도 자연스럽게 작동합니다:

```
# 유효한 이름을 원함:
data.frame(`variable 1` = 1:2, two = 3:4)
#>   variable.1 two
#> 1          1   3
#> 2          2   4
# 그러나 추가 옵션을 사용하면 이를 사용하도록 강제할 수 있음:
df <- data.frame(`variable 1` = 1:2, two = 3:4, check.names = FALSE)
df
#>   variable 1 two
#> 1          1   3
#> 2          2   4

# 하지만 tibble은 그냥 잘 작동함:
tbbl <- tibble(`variable 1` = 1:2, two = 3:4)
tbbl
#> # A tibble: 2 × 2
#>   `variable 1`   two
#>          <int> <int>
#> 1            1     3
#> 2            2     4
```

표준 데이터 프레임은 인수의 *부분 일치(partial matching)*를 허용하므로 열 이름의 일부만 사용하는 코드도 여전히 작동합니다. Tibble은 이것이 우발적인 오류로 이어질 수 있으므로 이러한 일이 발생하지 않도록 방지합니다:

```
df$tw
#> [1] 3 4

tbbl$tw
#> Warning: Unknown or uninitialized column: `tw`.
#> NULL
```

Tibble은 또한 R에서 가장 일반적인 오류 중 하나인 차원(dimensions) 삭제를 방지합니다. 표준 데이터 프레임이 열들을 단일 열로 서브셋(subset)하면 객체는 벡터로 변환됩니다. Tibble은 결코 이런 일을 하지 않습니다:

```
df[, "two"]
#> [1] 3 4

tbbl[, "two"]
#> # A tibble: 2 × 1
#>     two
#>   <int>
#> 1     3
#> 2     4
```

데이터 프레임 대신 tibble을 사용하면 인쇄 형태 개선 등과 같은 여러 다른 이점도 있습니다.<sup>[5](ch02.xhtml#idm45881871864336-marker)</sup>
구문을 시연하기 위해, 모델링에 사용될 수 있는 데이터를 읽어들이는 tidyverse 함수를 사용해 보겠습니다. 데이터 세트는 시카고 시의 데이터 포털(data portal)에서 가져온 것으로, 시내 고가 철도 역의 일일 승객 데이터를 포함합니다. 이 데이터 세트에는 다음 열이 있습니다:

- 역 식별자 (숫자)

- 역 이름 (문자)

- 날짜 (`mm/dd/yyyy` 형식의 문자)

- 요일 (문자)

- 승객 수 (숫자)

우리의 tidyverse 파이프라인은 다음 순서로 작업을 수행합니다:

1.  tidyverse 패키지 readr을 사용하여 소스 웹사이트에서 데이터를 읽고 이를 tibble로 변환합니다. 이를 위해 `read_csv()` 함수는 초기 몇 행을 읽어 데이터 유형을 결정할 수 있습니다. 대안으로 열 이름과 유형이 이미 알려진 경우 R에서 열 명세(column specification)를 만들어 `read_csv()`에 전달할 수 있습니다.

2.  데이터를 필터링하여 필요하지 않은 몇 개의 열(예: 역 ID)을 제거하고 `stationname` 열을 `station`으로 변경합니다. 이를 위해 `select()` 함수가 사용됩니다. 필터링 시 열 이름이나 dplyr 선택자 함수를 사용합니다. 이름을 선택할 때 `new_name = old_name` 인수 형식을 사용하여 새 변수 이름을 선언할 수 있습니다.

3.  lubridate 패키지의 `mdy()` 함수를 사용하여 날짜 필드를 R 데이터 형식으로 변환합니다. 승객 수치도 천 단위로 변환합니다. 이 두 가지 연산은 모두 `dplyr::mutate()` 함수를 사용하여 실행됩니다.

4.  역과 날짜의 각 조합에 대해 최대 승객 수를 사용합니다. 이는 소수의 요일에 특정 역에서 승객 수 기록이 두 개 이상 있는 문제를 완화합니다. 승객 데이터를 역과 날짜별로 그룹화(group by)한 다음, 1,999개의 고유한 조합 각각 내에서 최댓값 통계(maximum statistic)로 요약합니다.

이러한 단계를 위한 tidyverse 코드는 다음과 같습니다:

```
library(tidyverse)
library(lubridate)

url <- "http://bit.ly/raw-train-data-csv"

all_stations <-
  # 단계 1: 데이터를 읽어들입니다.
  read_csv(url) %>%
  # 단계 2: 열을 필터링하고 stationname의 이름을 변경합니다.
  dplyr::select(station = stationname, date, rides) %>%
  # 단계 3: 문자열 날짜 필드를 날짜 인코딩으로 변환합니다.
  # 또한 데이터를 1K 승객 단위로 변환합니다.
  mutate(date = mdy(date), rides = rides / 1000) %>%
  # 단계 4: 최댓값을 사용하여 여러 레코드를 요약합니다.
  group_by(date, station) %>%
  summarize(rides = max(rides), .groups = "drop")
```

이 연산 파이프라인은 왜 tidyverse가 인기 있는지 보여줍니다. 파이프라인은 각 변환에 대해 간단하고 이해하기 쉬운 함수를 사용하는 일련의 데이터 조작(data manipulations)을 사용하며, 이 시리즈는 능률적이고 읽기 쉬운 방식으로 묶여 있습니다. 초점은 사용자가 소프트웨어와 상호 작용하는 방식에 있습니다. 이 접근 방식을 통해 더 많은 사람들이 R을 배우고 분석 목표를 달성할 수 있으며, R에서의 모델링에 이러한 동일한 원칙을 적용하는 것도 같은 이점을 갖습니다.

# 이 장의 요약 (Chapter Summary)

이 장에서는 모델링에 대한 적용과 tidyverse 설계 원칙이 어떻게 tidymodels 프레임워크에 영향을 주는지에 초점을 맞추어 tidyverse를 소개했습니다. tidymodels 프레임워크는 모델 구축 영역에 tidyverse 원칙을 적용한 것으로 생각하십시오. tidyverse와 기본 R 간의 규약 차이를 설명하고, tidyverse 시스템의 두 가지 중요한 구성 요소인 tibble과 파이프 연산자 `%>%`를 소개했습니다. 데이터 정제(cleaning) 및 처리(processing)는 때때로 따분하게 느껴질 수 있지만, 이러한 작업은 실제 세계에서의 모델링에 중요합니다. 우리는 예제 데이터 가져오기 및 처리 실습에서 tibble, 파이프, 그리고 tidyverse 함수를 사용하는 방법을 설명했습니다.
