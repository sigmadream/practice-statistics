# 5장. 데이터 소비하기 (Spending Our Data)

파라미터 추정(parameter estimation), 모델 선택 및 튜닝(model selection and tuning), 성능 평가(performance assessment) 등 유용한 모델을 생성하는 데에는 여러 단계가 있습니다. 새로운 프로젝트를 시작할 때, 보통 이러한 모든 작업에 사용할 수 있는 한정된 초기 데이터 풀(pool)이 있으며, 이를 사용 가능한 데이터 예산(data budget)이라고 생각할 수 있습니다. 데이터를 서로 다른 단계나 작업에 어떻게 할당(apply)해야 할까요? *데이터 소비(data spending)*라는 아이디어는 특히 경험적 검증(empirical validation)과 관련되어 있으므로 모델링 시 고려해야 할 중요한 첫 번째 사항입니다.

###### 경고 (Warning)

데이터를 한정된 데이터 예산에서 신중하게 "소비"하지 않고 여러 작업에 재사용할 경우, 편향(bias)이 강조되거나 방법론적 오류로 인한 효과가 복합적으로 작용할 위험과 같은 특정 위험이 증가합니다.

사용 가능한 데이터가 아주 많을 때 현명한 전략은 가능한 한 많은 양(또는 심지어 전체)의 데이터를 모델 파라미터 추정에만 할당하는 대신 서로 다른 작업에 데이터의 특정 하위 집합(subsets)을 할당하는 것입니다. 예를 들어, (데이터와 예측 변수가 모두 풍부한 경우) 가능한 한 가지 전략은 파라미터 추정을 고려하기 전에 어떤 예측 변수가 정보력이 있는지(informative) 결정하기 위해 데이터의 특정 하위 집합을 소비하는 것입니다. 초기 사용 가능한 데이터 풀이 방대하지 않다면 데이터를 언제 어떻게 소비하거나 할당할지에 약간의 중복이 있을 것이며, 데이터 소비를 위한 탄탄한 방법론이 중요합니다.

이 장에서는 여러 목적을 위한 초기 샘플 풀의 _분할(splitting)_ (즉, 데이터 예산 생성)의 기초를 보여줍니다.

# 데이터 분할을 위한 일반적인 방법 (Common Methods for Splitting Data)

경험적 모델 검증을 위한 주된 접근 방식은 기존 데이터 풀을 훈련 세트(training set)와 테스트 세트(test set)라는 두 개의 뚜렷한 세트로 분할하는 것입니다. 데이터의 한 부분은 모델을 개발하고 최적화하는 데 사용됩니다. 이 *훈련 세트*는 보통 데이터의 대부분을 차지합니다. 이 데이터는 다양한 모델을 피팅하고 특징 공학(feature engineering) 전략을 조사하는 등 모델 구축을 위한 샌드박스(sandbox)입니다. 모델링 실무자로서 우리는 모델링 프로세스의 대부분을 훈련 세트를 기질(substrate)로 사용하여 모델을 개발하는 데 소비합니다.

데이터의 나머지 부분은 *테스트 세트*에 배치됩니다. 이것은 성공 가능성이 가장 높다고 판단된 한두 개의 모델이 선택될 때까지 예비로(in reserve) 보관됩니다. 그런 다음 테스트 세트는 모델의 효능을 결정하는 최종 중재자(arbiter)로 사용됩니다. 테스트 세트는 단 한 번만 살펴보는 것이 매우 중요합니다. 그렇지 않으면 테스트 세트가 모델링 프로세스의 일부가 되어버립니다.

###### 참고 (Note)

이러한 데이터 분할을 어떻게 수행해야 할까요? 대답은 컨텍스트에 따라 다릅니다.

데이터의 80%를 훈련 세트에 할당하고 나머지 20%를 테스트에 할당한다고 가정해 봅시다. 가장 일반적인 방법은 단순 무작위 샘플링(simple random sampling)을 사용하는 것입니다. [rsample 패키지](https://oreil.ly/a9sWI)에는 이와 같은 데이터 분할을 만드는 도구가 있습니다. `initial_split()` 함수가 이러한 목적으로 만들어졌습니다. 이 함수는 데이터 프레임과 훈련에 배치될 비율(proportion)을 인수로 사용합니다. [4장](ch04.xhtml#ames) 끝부분의 요약에 있는 코드 스니펫에서 생성된 데이터 프레임을 사용하여 분할을 설정할 수 있습니다.

```
library(tidymodels)
tidymodels_prefer()

# 나중에 결과를 재현(reproduced)할 수 있도록 `set.seed()`를 사용하여
# 난수 스트림을 설정합니다.
set.seed(501)

# 데이터의 80/20 분할을 위한 분할 정보를 저장합니다.
ames_split <- initial_split(ames, prop = 0.80)
ames_split
#> <Analysis/Assess/Total>
#> <2344/586/2930>
```

출력된 정보는 훈련 세트의 데이터 양($`n = 2,344`$), 테스트 세트의 양($`n = 586`$) 및 원본 샘플 풀의 크기($`n = 2,930`$)를 나타냅니다.

객체 `ames_split`은 `rsplit` 객체이며 파티셔닝 정보만 포함합니다. 결과 데이터 세트를 얻기 위해 두 가지 함수를 더 적용합니다.

```
ames_train <- training(ames_split)
ames_test  <- testing(ames_split)

dim(ames_train)
#> [1] 2344   74
```

이 객체들은 원본 데이터와 동일한 열을 가지지만, 각 세트에 적절한 행만 갖는 데이터 프레임입니다.

단순 무작위 샘플링은 많은 경우에 적절하지만 예외가 있습니다. 분류 문제에서 심각한 *클래스 불균형(class imbalance)*이 있는 경우 한 클래스가 다른 클래스보다 훨씬 덜 자주 발생합니다. 단순 무작위 샘플을 사용하면 이처럼 드문 샘플이 훈련 세트나 테스트 세트에 불균형적으로(disproportionately) 아무렇게나 할당될 수 있습니다. 이를 피하기 위해 *층화 샘플링(stratified sampling)*을 사용할 수 있습니다. 훈련/테스트 분할은 각 클래스 내에서 개별적으로 수행된 다음, 이러한 하위 샘플들(subsamples)이 결합되어 전체 훈련 및 테스트 세트가 됩니다. 회귀 문제의 경우 결과 변수 데이터를 인위적으로 4분위수(quartiles)로 구간화(binned)한 다음, 층화 샘플링을 4번 개별적으로 수행할 수 있습니다. 이것은 훈련 세트와 테스트 세트 간에 결과 변수의 분포를 유사하게 유지하는 효과적인 방법입니다. Ames 주택 데이터에 대한 판매 가격 결과 변수의 분포는 [그림 5-1](#figure-5-1.-the-distribution-of-the-sale-price-in-log-units-for-the-ames-housing-data.-the-vertical-lines-indicate-the-quartiles-of-the-data.)에 나타나 있습니다.

[4장](ch04.xhtml#ames)에서 논의했듯이 판매 가격 분포는 오른쪽으로 치우쳐 있으며 분포의 중앙을 기준으로 양쪽에 비싼 주택보다 저렴한 주택이 비율적으로 더 많습니다. 단순 분할에서 여기서의 걱정은 더 비싼 주택이 훈련 세트에 잘 표현되지 않을 것이라는 점입니다. 이는 우리의 모델이 그러한 부동산의 가격을 예측하는 데 비효과적일 위험을 증가시킬 것입니다. [그림 5-1](#figure-5-1.-the-distribution-of-the-sale-price-in-log-units-for-the-ames-housing-data.-the-vertical-lines-indicate-the-quartiles-of-the-data.)의 점선으로 된 수직선은 이 데이터에 대한 4개의 4분위수를 나타냅니다. 층화 무작위 샘플은 이러한 각 데이터 하위 집합 내에서 80/20 분할을 수행한 다음 결과를 풀링(pool)합니다. rsample에서는 `strata` 인수를 사용하여 이를 달성합니다.

```
set.seed(502)
ames_split <- initial_split(ames, prop = 0.80, strata = Sale_Price)
ames_train <- training(ames_split)
ames_test  <- testing(ames_split)

dim(ames_train)
#> [1] 2342   74
```

층화에는 단일 열만 사용할 수 있습니다.

###### 참고 (Note)

층화 샘플링을 사용할 때의 단점은 거의 없습니다.

무작위 샘플링이 최선의 선택이 아닌 상황이 있습니까? 시계열 데이터(time series data)와 같이 데이터에 상당한 시간 구성 요소(time component)가 있는 경우가 있습니다. 여기서는 가장 최근의 데이터를 테스트 세트로 사용하는 것이 더 일반적입니다. rsample 패키지에는 `initial_split()`과 매우 유사한 `initial_time_split()`이라는 함수가 포함되어 있습니다. 무작위 샘플링을 사용하는 대신 `prop` 인수는 데이터의 첫 번째 부분 중 얼마만큼의 비율이 훈련 세트로 사용되어야 하는지를 나타냅니다. 이 함수는 데이터가 적절한 순서로 사전 정렬(presorted)되어 있다고 가정합니다.

###### 참고 (Note)

분할을 위해 할당되어야 하는 데이터의 비율은 당면한 문제의 컨텍스트에 따라 크게 달라집니다. 훈련 세트에 데이터가 너무 적으면 모델이 적절한 파라미터 추정치를 찾는 능력이 저해됩니다. 반대로 테스트 세트에 데이터가 너무 적으면 성능 추정치의 품질이 저하됩니다. 통계 커뮤니티의 일부에서는 파라미터 추정을 위해 모든 데이터를 사용해야 한다고 믿기 때문에 일반적으로 테스트 세트를 기피합니다. 이 주장에 장점이 있긴 하지만 모델 품질의 최종 결정자로서 편향되지 않은 관측치 집합을 갖는 것이 좋은 모델링 관행입니다. 테스트 세트는 데이터 세트가 병적으로(pathologically) 작은 경우에만 피해야 합니다.

# 검증 세트는 어떨까요? (What About a Validation Set?)

데이터 분할의 목표를 설명할 때, 최종 모델(들)에서 모델 성능을 적절하게 평가하는 데 사용해야 하는 데이터로서 테스트 세트를 지목(singled out)했습니다. 이것은 질문을 던집니다. "테스트 세트까지 성능을 측정하지 않는다면 무엇이 최고인지 어떻게 알 수 있을까?"

특히 신경망(neural network) 및 딥러닝(deep learning) 문헌에서 이 질문에 대한 대답으로 *검증 세트(validation sets)*에 대해 듣는 것이 일반적입니다. 신경망 초창기에 연구자들은 훈련 세트 샘플을 다시 예측(repredicting)하여 성능을 측정하면 너무 낙관적인 (비현실적일 정도로) 결과로 이어진다는 것을 깨달았습니다. 이는 훈련 세트에서는 매우 우수한 성능을 발휘하지만 테스트 세트에서는 성능이 떨어지는 과적합(overfit)된 모델로 이어졌습니다.<sup>[1](ch05.xhtml#idm45881872960224-marker)</sup> 이 문제를 해결하기 위해 네트워크가 훈련될 때 작은 검증 데이터 세트를 따로 남겨두고(held back) 성능을 측정하는 데 사용했습니다. 검증 세트의 오류율(error rate)이 상승하기 시작하면 훈련이 중단됩니다. 즉, 검증 세트는 테스트 세트 이전에 모델이 얼마나 잘 수행되는지에 대한 대략적인 감을 얻는 수단이었습니다.

###### 참고 (Note)

검증 세트가 훈련 세트의 하위 집합인지 아니면 데이터 초기 분할의 세 번째 할당인지는 대체로 의미론(semantics)의 문제입니다.

검증 세트에 대해서는 훈련 세트에 사용되는 _리샘플링(resampling)_ 방법의 특수한 경우로 [10장](ch10.xhtml#resampling)에서 더 논의됩니다.

# 다수준 데이터 (Multilevel Data)

Ames 주택 데이터에서 각 부동산은 *독립적인 실험 단위(independent experimental unit)*로 간주됩니다. 통계적으로 한 부동산의 데이터가 다른 부동산과 독립적이라고 가정하는 것이 안전합니다. 다른 애플리케이션의 경우 항상 그렇지는 않습니다.

- 예를 들어 종단적(longitudinal) 데이터의 경우 동일한 독립적 실험 단위가 여러 시점에 걸쳐 측정될 수 있습니다. 의학 시험의 피험자(human subject)가 그 예가 될 수 있습니다.

- 제조된 제품의 배치(batch)도 독립적인 실험 단위로 간주될 수 있습니다. 반복 측정(repeated measures) 설계에서는 하나의 배치에서 반복되는 데이터 포인트가 여러 번 수집됩니다.

- Johnson 등 (2018)은 줄기(stem)의 상단과 하단 부분에 걸쳐 여러 다른 나무들을 샘플링한 실험을 보고합니다. 여기서 나무는 실험 단위이고 데이터 계층(hierarchy)은 나무(tree) 내의 줄기 위치(stem position) 내의 샘플입니다.

[Kuhn과 Johnson (2020)의 9장](https://oreil.ly/bbEW1)에 다른 예가 포함되어 있습니다.

이러한 상황에서 데이터 세트는 실험 단위당 여러 행을 갖게 됩니다. 행에 걸쳐 단순한 리샘플링을 하면 실험 단위 내의 일부 데이터는 훈련 세트에 있고 다른 데이터는 테스트 세트에 있게 될 것입니다. 데이터 분할은 데이터의 독립적인 실험 단위 수준에서 이루어져야 합니다. 예를 들어 Ames 주택 데이터 세트의 80/20 분할을 생성하려면 부동산의 80%가 훈련 세트에 할당되어야 합니다.

# 데이터 예산에 대한 다른 고려 사항 (Other Considerations for a Data Budget)

사용 가능한 데이터를 어떻게 소비할지 결정할 때 몇 가지 사항을 더 염두에 두십시오. 첫째, 모든 모델 구축 활동으로부터 테스트 세트를 격리(quarantine)하는 것이 중요합니다. 이 책을 읽을 때 주어진 시점에 모델에 어떤 데이터가 노출되는지 확인하십시오.

###### 경고 (Warning)

훈련 세트 외부의 데이터가 모델링 프로세스에 사용될 때 _정보 유출(information leakage)_ 문제가 발생합니다.

예를 들어 머신러닝 대회에서 모델의 점수를 매기고 순위를 매길 수 있도록 테스트 세트 데이터가 실제 결과 변수값 없이 제공될 수 있습니다. 점수를 개선하기 위한 한 가지 잠재적인 방법은 테스트 세트 값과 가장 유사한 훈련 세트 포인트를 사용하여 모델을 피팅하는 것일 수 있습니다. 테스트 세트가 모델 피팅에 직접적으로 사용되지는 않지만 여전히 큰 영향을 미칩니다. 일반적으로 이 기술은 특정 데이터 세트에서의 성능을 최적화하기 위해 모델의 *일반화 오차(generalization error)*를 줄이기 때문에 매우 문제가 많습니다. 훈련 중에 테스트 세트 데이터가 사용될 수 있는 더 미묘한 방법들이 있습니다. 훈련 데이터를 테스트 세트와 별도의 데이터 프레임에 보관하는 것은 정보 유출이 우연히 발생하지 않도록 하기 위한 하나의 작은 점검 방법입니다.

둘째, 훈련 세트를 서브샘플링(subsample)하는 기술은 특정한 문제(클래스 불균형)를 완화할 수 있습니다. 이는 훈련 세트 데이터가 추출된(drawn) 모집단에서 일부러 벗어나게(diverging) 만드는 유효하고 일반적인 기술입니다. 테스트 세트가 야생(in the wild)에서 모델이 접하게 될 것(실제 상황)을 계속해서 모방하는 것이 매우 중요합니다. 즉, 테스트 세트는 항상 모델에 주어질 새로운 데이터와 닮아 있어야 합니다.

다음으로, 이 장의 시작 부분에서 동일한 데이터를 다른 작업에 사용하는 것에 대해 경고했습니다. [10장](ch10.xhtml#resampling)에서는 편향(bias), 과적합 및 기타 문제와 관련된 위험을 줄일 데이터 사용을 위한 탄탄하고 데이터 기반의(data-driven) 방법론을 논의할 것입니다. 이들 방법 중 다수는 이 장에서 소개된 데이터 분할 도구를 적용합니다.

마지막으로 이 장의 고려 사항은 이 책의 주요 주제인 신뢰할 수 대 모델을 개발하고 선택하는 데 적용됩니다. 프로덕션을 위해 최종적으로 선택된 모델을 훈련할 때, 새로운 데이터에 대한 예상 성능을 확인한 후 실무자는 종종 더 나은 파라미터 추정을 위해 사용 가능한 모든 데이터를 사용합니다.

# 이 장의 요약 (Chapter Summary)

데이터 분할은 모델의 경험적 검증을 위한 기본적인 전략입니다. 제한 없는 데이터 수집의 시대에도 일반적인 모델링 프로젝트는 적절한 양의 데이터가 한정되어 있으며 프로젝트 데이터의 현명한 소비가 필요합니다. 이 장에서는 모델링 및 평가를 위해 데이터를 별개의 그룹으로 나누기 위한 여러 전략을 논의했습니다.

이 체크포인트에서 준비 및 분할을 위한 중요한 코드 스니펫은 다음과 같습니다.

```
library(tidymodels)
data(ames)
ames <- ames %>% mutate(Sale_Price = log10(Sale_Price))

set.seed(502)
ames_split <- initial_split(ames, prop = 0.80, strata = Sale_Price)
ames_train <- training(ames_split)
ames_test  <- testing(ames_split)
```
