# 모델 성능 평가하기

부유한 사람들만이 교육을 감당할 수 있었을 때, 시험과 평가는 학생들을 평가하는 데 사용되지 않았습니다. 그 대신, 그들의 자녀가 강사의 임금을 정당화할 만큼 충분히 배웠는지 알고 싶어 하는 학부모를 위해 시험은 교사를 평가했습니다. 명백하게도 오늘날에는 다릅니다. 지금은 그러한 평가가 성취도가 높은 학생과 낮은 학생을 구분하는 데 사용되어 그들을 직업 및 다른 기회들로 걸러냅니다(Filtering).

이 과정의 중요성을 고려할 때 정확한 학생 평가를 개발하는 데 많은 노력이 투자됩니다. 공정한 평가에는 광범위한 주제를 다루고 운 좋게 찍은 것보다 진정한 지식을 보상하는 수많은 질문이 있습니다. 좋은 평가를 위해서는 학생들이 이전에 직면해 본 적이 없는 문제에 대해서도 생각해야 합니다. 따라서 올바른 응답은 지식을 더 넓게 일반화(Generalize)할 수 있는 능력을 반영합니다.

머신러닝 알고리즘을 평가하는 과정은 학생을 평가하는 과정과 매우 유사합니다. 알고리즘마다 강점과 약점이 다르기 때문에 테스트는 학습자를 구별해야 합니다. 학습자가 미래의 데이터에서 어떻게 수행할지 이해하는 것도 중요합니다.

이 장은 다음과 같이 기계 학습자를 평가하는 데 필요한 정보를 제공합니다:

- 예측 정확도(Predictive accuracy)가 성능을 측정하는 데 충분하지 않은 이유와 대신 사용할 수 있는 성능 척도(Performance measures)
- 보이지 않는 사례들을 예측하거나 전망하는 모델의 능력을 성능 척도가 합리적으로 반영하도록 보장하는 방법
- R을 사용하여 이러한 더 유용한 척도 및 방법들을 이전 장들에서 다룬 예측 모델에 적용하는 방법

어떤 주제를 배우는 가장 좋은 방법이 다른 사람에게 가르치려고 시도하는 것인 것과 마찬가지로, 기계 학습자를 가르치고 평가하는 과정은 지금까지 여러분이 배운 방법에 대한 더 깊은 통찰력을 제공할 것입니다.

# 분류를 위한 성능 측정하기

이전 장들에서 우리는 정확한 예측의 수를 총 예측 수로 나누어 분류기(Classifier)의 정확도(Accuracy)를 측정했습니다. 이것은 학습자가 맞힌 사례의 비율을 찾으며, 틀린 사례의 비율은 직접적으로 따라옵니다. 예를 들어 어떤 분류기가 신생아가 치료 가능하지만 치명적일 수 있는 유전적 결함의 보균자인지 여부를 100,000건 중 99,990건에서 정확하게 예측했다고 가정해 보겠습니다. 이는 정확도 99.99%와 오류율(Error rate) 0.01%만을 암시할 것입니다.

언뜻 보기에 이것은 매우 가치 있는 분류기처럼 보입니다. 그러나 아이의 생명을 이 검사에 맡기기 전에 추가 정보를 수집하는 것이 현명할 것입니다. 만약 유전적 결함이 신생아 100,000명 중 단 10명에게서만 발견된다면 어떻게 될까요? 예외 없이 결함이 없다고 예측하는 검사는 전체 사례의 99.99%에서 정확할 것이지만, 가장 중요한 사례에 대해서는 100% 틀릴 것입니다. 다시 말해 분류기가 극도로 정확하더라도 치료 가능한 선천적 결함을 예방하는 데는 별로 유용하지 않습니다.

이것은 대다수의 레코드가 단일 클래스에 속하는 데이터와 관련된 문제를 나타내는 **클래스 불균형 문제(Class imbalance problem)**의 한 가지 결과입니다.

분류기의 성능을 측정하는 방법은 여러 가지가 있지만 가장 좋은 측정 방법은 항상 분류기가 의도한 목적에 성공했는지 여부를 포착하는 것입니다. 원시 정확도(Raw accuracy)보다는 유용성(Utility)의 관점에서 성능 척도를 정의하는 것이 매우 중요합니다. 이를 위해 오차 행렬(Confusion matrix)에서 도출된 다양한 대안적 성능 척도를 살펴볼 것입니다. 그러나 시작하기 전에 평가를 위해 분류기를 어떻게 준비할지 고려해야 합니다.

## 분류기의 예측 이해하기

분류 모델(Classification model) 평가의 목표는 향후 사례에 대한 성능이 어떻게 외삽(Extrapolate, 추정)될지 더 잘 이해하는 것입니다. 입증되지 않은 모델을 실제 라이브 환경에서 테스트하는 것은 대개 실현 불가능하므로, 일반적으로 우리는 모델에게 미래에 요구될 작업과 닮은 사례들로 구성된 데이터 세트에서 사례들을 분류하도록 요청함으로써 미래 조건을 시뮬레이션(Simulate)합니다. 이 시험에 대한 학습자의 반응을 관찰함으로써 우리는 그 강점과 약점에 대해 배울 수 있습니다.

이전 장들에서 분류기를 평가해 왔지만, 우리가 마음대로 사용할 수 있는 데이터의 유형들을 되돌아볼 가치가 있습니다:

- 실제(Actual) 클래스 값
- 예측된(Predicted) 클래스 값
- 예측의 추정 확률

실제 클래스 값과 예측된 클래스 값은 자명할 수 있지만 평가의 핵심입니다. 교사가 정답 목록인 답안지를 사용하여 학생의 답안을 평가하는 것처럼, 우리는 기계 학습자의 예측에 대한 정답을 알아야 합니다. 목표는 두 개의 데이터 벡터(Vectors)를 유지하는 것입니다. 하나는 정확한(Correct) 또는 실제(Actual) 클래스 값을 보유하고 다른 하나는 예측된(Predicted) 클래스 값을 보유합니다. 두 벡터 모두 동일한 순서로 저장된 동일한 개수의 값을 가져야 합니다. 예측값과 실제값은 별개의 R 벡터로 저장되거나 단일 R 데이터 프레임의 열(Columns)로 저장될 수 있습니다.

이 데이터를 얻는 것은 쉽습니다. 실제 클래스 값은 테스트 데이터 세트의 목표(Target)에서 직접 가져옵니다. 예측된 클래스 값은 훈련 데이터를 기반으로 구축된 분류기에서 얻어지며, 그런 다음 테스트 데이터에 적용됩니다. 대부분의 머신러닝 패키지의 경우 이것은 `predict()` 함수를 모델 객체와 테스트 데이터의 데이터 프레임에 적용하는 것을 수반합니다(예: `predictions <- predict(model, test_data)`).

지금까지 우리는 이러한 두 가지 데이터 벡터만을 사용하여 분류 예측을 살펴보았지만 대부분의 모델은 다른 유용한 정보를 제공할 수 있습니다. 비록 분류기가 각 예제에 대해 단일 예측을 내리더라도 일부 결정에 대해서는 다른 결정보다 더 확신을 가질 수 있습니다.

예를 들어, 분류기는 "free(무료)" 및 "ringtones(벨소리)"라는 단어가 포함된 SMS가 스팸이라고 99% 확신할 수 있지만 "tonight(오늘 밤)"이라는 단어가 포함된 SMS가 스팸이라는 확신은 51%에 불과할 수 있습니다. 두 경우 모두 분류기는 메시지를 스팸으로 분류하지만, 한 가지 결정에 대해 다른 결정보다 훨씬 더 확신하고 있습니다.

이러한 내부 예측 확률을 연구하면 모델의 성능을 평가하는 데 유용한 데이터를 얻을 수 있습니다. 두 모델이 동일한 횟수의 실수를 하지만, 한 모델이 불확실성을 더 정확하게 평가할 수 있다면 그 모델이 더 똑똑한 모델입니다. 올바른 예측을 할 때는 극도로 확신하지만 의심이 들 때는 조심스러운(Timid) 학습자를 찾는 것이 이상적입니다. 확신(Confidence)과 조심성(Caution) 사이의 균형은 모델 평가의 핵심 부분입니다.

내부 예측 확률을 얻기 위한 함수 호출은 R 패키지마다 다릅니다. 대부분의 분류기에서 `predict()` 함수는 원하는 예측 유형을 지정하기 위해 추가 매개변수를 허용합니다. 스팸 또는 햄과 같이 단일 예측 클래스를 얻으려면 일반적으로 `type = "class"` 매개변수를 설정합니다. 예측 확률을 얻으려면 사용된 분류기에 따라 `type` 매개변수를 `"prob"`, `"posterior"`, `"raw"` 또는 `"probability"` 중 하나로 설정해야 합니다.

이 책에 제시된 모든 분류기는 예측 확률을 제공할 수 있습니다. `type` 매개변수의 올바른 설정은 각 모델을 소개하는 구문 상자(Syntax box)에 포함되어 있습니다.

예를 들어 *5장, 분할 정복 - 의사결정 트리 및 규칙을 사용한 분류*에서 구축된 C5.0 분류기에 대한 예측 확률을 출력하려면 다음과 같이 `type = "prob"`와 함께 `predict()` 함수를 사용하십시오:

```
> predicted_prob <- predict(credit_model, credit_test, type = "prob")
```

*4장, 확률적 학습 - 나이브 베이즈를 사용한 분류*에서 개발된 SMS 스팸 분류 모델에 대한 나이브 베이즈 예측 확률을 출력하려면 다음과 같이 `type = "raw"`와 함께 `predict()`를 사용하십시오:

```
> sms_test_prob <- predict(sms_classifier, sms_test, type = "raw")
```

대부분의 경우 `predict()` 함수는 결과의 각 범주에 대한 확률을 반환합니다. 예를 들어 SMS 분류기와 같은 두 가지 결과(Two-outcome) 모델의 경우 여기에 표시된 것처럼 예측 확률이 행렬이나 데이터 프레임에 저장될 수 있습니다:

```
> head(sms_test_prob)
```

```
              ham         spam
[1,] 9.999995e-01 4.565938e-07
[2,] 9.999995e-01 4.540489e-07
[3,] 9.998418e-01 1.582360e-04
[4,] 9.999578e-01 4.223125e-05
[5,] 4.816137e-10 1.000000e+00
[6,] 9.997970e-01 2.030033e-04
```

이 출력의 각 줄은 스팸과 햄에 대해 분류기가 예측한 확률을 보여줍니다. 확률 규칙에 따라 이것들은 상호 배타적이고 철저한(Mutually exclusive and exhaustive) 결과이므로 각 행을 가로지르는 확률의 합은 1입니다. 편의를 위해 평가 프로세스 중에 예측된 클래스, 실제 클래스, 그리고 관심 있는 클래스 수준(들)의 예측 확률을 수집하는 데이터 프레임을 구성하는 것이 도움이 될 수 있습니다.

이 장의 GitHub 저장소에서 사용할 수 있는 `sms_results.csv` 파일은 정확히 이러한 형식의 데이터 프레임의 한 예이며, *4장, 확률적 학습 - 나이브 베이즈를 사용한 분류*에서 구축된 SMS 분류기의 예측을 통해 만들어졌습니다. 이 평가 데이터 세트를 구성하는 데 필요한 단계는 간결함을 위해 생략되었으므로, 여기 예제를 따라 하려면 파일을 다운로드하고 다음 명령을 사용하여 데이터 프레임으로 불러오기만 하면 됩니다:

```
> sms_results <- read.csv("sms_results.csv", stringsAsFactors = TRUE)
```

생성된 `sms_results` 데이터 프레임은 간단합니다. 1,390개의 값으로 이루어진 4개의 벡터를 포함합니다. 한 열에는 SMS 메시지의 실제 유형(스팸 또는 햄)을 나타내는 값이 포함되어 있고, 다른 열에는 나이브 베이즈 모델이 예측한 메시지 유형이 표시되며, 세 번째와 네 번째 열에는 각각 메시지가 스팸 또는 햄일 확률이 표시됩니다:

```
> head(sms_results)
```

이러한 6가지 테스트 사례에 대해 예측된 SMS 메시지 유형과 실제 SMS 메시지 유형이 일치합니다; 즉, 모델이 메시지 상태를 올바르게 예측했습니다. 나아가 예측 확률은 모델이 이러한 예측에 대해 극도로 확신했음을 시사하는데, 왜냐하면 모든 확률이 0 또는 1에 가깝거나 정확히 0 또는 1이기 때문입니다.

예측된 값과 실제 값이 0과 1에서 더 멀어지면 어떻게 될까요? `subset()` 함수를 사용하여 우리는 이러한 레코드 몇 가지를 식별할 수 있습니다. 다음 출력은 모델이 스팸일 확률을 40%에서 60% 사이로 추정한 테스트 사례를 보여줍니다:

```
> head(subset(sms_results, prob_spam > 0.40 & prob_spam < 0.60))
```

```
     actual_type predict_type prob_spam prob_ham
377         spam          ham   0.47536  0.52464
717          ham         spam   0.56188  0.43812
1311         ham         spam   0.57917  0.42083
```

모델 자체의 추정에 따르면 이것들은 올바른 예측이 사실상 동전 던지기나 다름없는 경우들이었습니다. 그러나 이 세 가지 예측은 모두 틀렸습니다—운이 나쁜 결과입니다. 모델이 틀린 몇 가지 사례를 더 살펴보겠습니다:

```
> head(subset(sms_results, actual_type != predict_type))
```


이 사례들은 모델이 극도로 확신할 수도 있지만 여전히 극도로 틀릴 수도 있다는 중요한 사실을 예증합니다. 이 6개의 테스트 사례는 모두 분류기가 햄일 확률이 98% 이상이라고 믿었던 스팸 메시지들이었습니다.

이러한 실수에도 불구하고 이 모델은 여전히 유용할까요? 우리는 이 평가 데이터에 다양한 오차 측정 기준(Error metrics)을 적용하여 이 질문에 대답할 수 있습니다. 사실, 그러한 많은 기준은 이전 장에서 우리가 이미 광범위하게 사용했던 도구를 기반으로 합니다.

## 오차 행렬(Confusion matrices) 자세히 살펴보기

**오차 행렬(Confusion matrix, 혼동 행렬)**은 예측이 실제 값과 일치하는지에 따라 예측을 범주화하는 표입니다. 표의 차원 중 하나는 예측된 값의 가능한 범주를 나타내고, 다른 차원은 실제 값에 대해 동일한 것을 나타냅니다. 지금까지 우리는 주로 2x2 오차 행렬을 다루었지만, 임의의 개수의 클래스 값을 예측하는 모델에 대해서도 행렬을 생성할 수 있습니다. 다음 그림은 3클래스 모델의 3x3 오차 행렬뿐만 아니라 2클래스 이진 모델의 익숙한 오차 행렬을 묘사합니다.

예측값이 실제값과 동일한 경우 올바른 분류에 해당합니다. 올바른 예측은 오차 행렬의 대각선에 속합니다(**O**로 표시됨). 비대각선 행렬 셀(**X**로 표시됨)은 예측값이 실제값과 다른 경우를 나타냅니다. 이것들은 잘못된 예측입니다. 분류 모델의 성능 척도는 이 표에서 대각선에 속하거나 속하지 않는 예측 횟수를 기반으로 합니다:

그림 10.2: 오차 행렬은 예측된 클래스가 실제 값과 일치하거나 일치하지 않는 사례의 수를 셉니다

가장 일반적인 성능 척도는 하나의 클래스를 다른 모든 클래스와 식별(Discern)하는 모델의 능력을 고려합니다. 관심 있는 클래스를 **긍정(Positive, 양성)** 클래스라고 하고, 나머지 모든 클래스를 **부정(Negative, 음성)**이라고 합니다.

긍정과 부정이라는 용어의 사용이 어떤 가치 판단(즉, 좋고 나쁨)을 암시하려는 의도는 아니며, 결과가 존재하거나 부재(예를 들어 선천적 결함이 있는 것과 없는 것)한다는 것을 반드시 시사하는 것도 아닙니다. 긍정 결과의 선택은 맑음 대 비, 개 대 고양이와 같은 범주를 예측하는 모델의 경우처럼 임의적일 수도 있습니다.

긍정 클래스와 부정 클래스 예측 간의 관계는 예측이 다음 네 가지 범주 중 하나에 속하는지 여부를 도표로 만드는 2x2 오차 행렬로 묘사될 수 있습니다:

- **진양성(True positive, TP)**: 관심 있는 클래스로 올바르게 분류됨
- **진음성(True negative, TN)**: 관심 있는 클래스가 아닌 것으로 올바르게 분류됨
- **위양성(False positive, FP)**: 관심 있는 클래스로 잘못 분류됨
- **위음성(False negative, FN)**: 관심 있는 클래스가 아닌 것으로 잘못 분류됨

스팸 분류기의 경우, 긍정 클래스는 스팸인데 왜냐하면 이것이 우리가 탐지하고자 하는 결과이기 때문입니다. 그러면 우리는 *그림 10.3*에 표시된 오차 행렬을 상상해 볼 수 있습니다:

## 정확도를 넘어서 – 기타 성능 척도

수많은 성능 척도가 의학, 정보 검색, 마케팅, 신호 탐지 이론(Signal detection theory) 등 다양한 분야에서 특정 목적을 위해 개발되고 사용되어 왔습니다. 이 모든 것을 다루려면 수백 페이지가 채워질 수 있으므로, 여기에서 포괄적인 설명을 하는 것은 실현 불가능합니다. 그 대신, 우리는 머신러닝 문헌에서 가장 유용하고 가장 많이 인용되는 일부 척도들만을 살펴볼 것입니다.

막스 쿤(Max Kuhn)이 만든 `caret` 패키지에는 이러한 많은 성능 척도를 계산하는 기능이 포함되어 있습니다. 이 패키지는 머신러닝 모델과 데이터를 준비하고 훈련, 평가, 시각화하는 도구를 제공합니다; "caret"이라는 이름은 "분류 및 회귀 훈련(Classification And Regression Training)"을 단순화한 것입니다. 이 패키지는 여기에서 사용하는 것 외에도 모델을 튜닝하는 데 가치가 있기 때문에 우리는 *14장, 더 나은 학습자 구축하기(Building Better Learners)*에서도 `caret` 패키지를 광범위하게 사용할 것입니다. 진행하기 전에 `install.packages("caret")` 명령을 사용하여 패키지를 설치해야 합니다.

`caret`에 대한 자세한 내용은 *Building Predictive Models in R Using the caret Package, Kuhn, M, Journal of Statistical Software, 2008, Vol. 28*이나 <http://topepo.github.io/caret/index.html>에 있는 패키지의 매우 유익한 문서 페이지를 참조하십시오.

### 카파 통계량(Kappa statistic)

**카파 통계량**(이전 출력에 `Kappa`로 레이블이 지정됨)은 우연에 의한 올바른 예측의 가능성을 고려하여 정확도를 조정합니다. 분류기가 단순히 가장 빈번한 클래스를 항상 추측함으로써 높은 정확도를 얻을 수 있기 때문에 이는 극심한 클래스 불균형이 있는 데이터 세트에서 특히 중요합니다. 카파 통계량은 이 지나치게 단순한 전략보다 자주 맞힐 경우에만 분류기에 보상을 줄 것입니다.

카파 통계량을 정의하는 방법은 두 가지 이상입니다. 여기에 설명된 가장 일반적인 방법은 다음 논문에서 설명한 바와 같이 **코헨의 카파 계수(Cohen’s kappa coefficient)**를 사용합니다: *A coefficient of agreement for nominal scales, Cohen, J, Education and Psychological Measurement, 1960, Vol. 20, pp. 37-46*.

카파 값은 일반적으로 0에서 최대 1까지의 범위를 가지며 값이 클수록 모델의 예측과 실제 값 간의 더 강력한 일치를 반영합니다. 만약 예측이 일관되게 잘못된 방향으로 이루어진다면—즉, 예측이 실제 값과 일치하지 않거나 무작위 추측으로 예상되는 것보다 더 자주 틀린다면 0보다 작은 값을 관찰할 수 있습니다. 이는 머신러닝 모델에서는 거의 발생하지 않으며 대개 코딩 문제(Coding issue)를 반영하는데, 이는 단순히 예측을 반대로 함으로써 수정할 수 있습니다.

모델이 어떻게 사용되는지에 따라 카파 통계량의 해석이 달라질 수 있습니다. 일반적인 해석 중 하나는 다음과 같습니다:

- 불량한 일치(Poor agreement) = 0.2 미만
- 약간의 일치(Fair agreement) = 0.2에서 0.4 사이
- 적당한 일치(Moderate agreement) = 0.4에서 0.6 사이
- 상당한 일치(Good agreement) = 0.6에서 0.8 사이
- 거의 완벽한 일치(Very good agreement) = 0.8에서 1.0 사이

이러한 범주들은 주관적이라는 점에 유의하는 것이 중요합니다. 누군가가 가장 좋아하는 아이스크림 맛을 예측하는 데에는 "상당한 일치(Good agreement)"가 충분할 수 있지만, 목표가 선천적 결함을 식별하는 것이라면 "거의 완벽한 일치(Very good agreement)"로도 충분하지 않을 수 있습니다.

이전의 척도(Scale)에 대한 자세한 내용은 다음을 참조하십시오: *The measurement of observer agreement for categorical data, Landis, JR, Koch, GG. Biometrics, 1997, Vol. 33, pp. 159-174*.

이러한 비율은 어디를 찾아봐야 할지 안다면 오차 행렬에서 쉽게 얻을 수 있습니다. 편의를 위해 여기에 반복 표시되는, `CrossTable()` 함수로 생성된 SMS 분류 모델의 오차 행렬을 살펴보겠습니다:

```
                       | sms_results$predict_type 
sms_results$actual_type |       ham |      spam | Row Total | 
------------------------|-----------|-----------|-----------|
                    ham |      1203 |         4 |      1207 | 
                        |    16.128 |   127.580 |           | 
                        |     0.997 |     0.003 |     0.868 | 
                        |     0.975 |     0.026 |           | 
                        |     0.865 |     0.003 |           |
```

각 셀의 하단 값이 해당 셀에 속하는 모든 인스턴스의 비율을 나타낸다는 점을 기억하십시오. 따라서 관찰된 일치 Pr(*a*)를 계산하기 위해 예측된 유형과 실제 SMS 유형이 일치하는 모든 인스턴스의 비율을 단순히 더하기만 하면 됩니다.

따라서 우리는 다음과 같이 Pr(*a*)를 계산할 수 있습니다:

```
> pr_a <- 0.865 + 0.109
> pr_a
```

```
[1] 0.974
```

이 분류기의 경우 관찰된 값과 실제 값이 97.4% 횟수로 일치합니다—이것이 정확도와 동일하다는 것을 눈치채실 것입니다. 카파 통계량은 예상 일치 Pr(*e*)에 상대적으로 정확도를 조정하는데, 이는 관찰된 비율에 따라 둘 다 무작위로 선택된다는 가정하에 우연히 예측 값과 실제 값이 일치할 확률입니다.

이러한 관찰된 비율을 찾기 위해 *4장, 확률적 학습 - 나이브 베이즈를 사용한 분류*에서 배운 확률 규칙을 사용할 수 있습니다. 두 사건이 독립적(즉, 하나가 다른 하나에 영향을 미치지 않음)이라고 가정할 때, 확률 규칙은 두 사건이 모두 발생할 확률은 각 사건이 발생할 확률의 곱과 같다고 지적합니다. 예를 들어 둘 다 햄을 선택할 확률이 다음과 같다는 것을 우리는 알고 있습니다:

Pr(*실제 유형이 햄임*) \* Pr(*예측 유형이 햄임*)

그리고 둘 다 스팸을 선택할 확률은 다음과 같습니다:

Pr(*실제 유형이 스팸임*) \* Pr(*예측 유형이 스팸임*)

예측된 유형이나 실제 유형이 스팸 또는 햄일 확률은 행 또는 열 합계에서 얻을 수 있습니다. 예를 들어 Pr(*실제 유형이 햄임*) = 0.868 및 Pr(*예측 유형이 햄임*) = 0.888입니다.

Pr(*e*)는 예측값과 실제값이 메시지를 스팸 또는 햄으로 일치하게 지정할 확률의 합으로 계산할 수 있습니다. 상호 배타적인(Mutually exclusive) 사건(동시에 발생할 수 없는 사건)의 경우 둘 중 하나가 발생할 확률은 각각의 확률의 합과 같다는 것을 기억하십시오. 따라서 최종 Pr(*e*)를 얻으려면 다음과 같이 두 곱을 더하기만 하면 됩니다:

```
> pr_e <- 0.868 * 0.888 + 0.132 * 0.112
> pr_e
```

```
[1] 0.785568
```

Pr(*e*)가 0.786이므로 우연에 의해서만 관찰된 값과 실제 값이 78.6% 횟수로 일치할 것으로 예상할 수 있습니다.

이것은 이제 카파 공식을 완성하는 데 필요한 모든 정보를 확보했음을 의미합니다. 카파 공식에 Pr(*a*)와 Pr(*e*) 값을 연결하면 다음과 같은 결과를 얻을 수 있습니다:

```
> k <- (pr_a - pr_e) / (1 - pr_e) 
> k
```

```
[1] 0.8787494
```

카파는 약 0.88이며 이는 이전 `caret`의 `confusionMatrix()` 출력과 일치합니다(약간의 차이는 반올림 때문입니다). 제안된 해석을 사용하면 분류기의 예측과 실제 값 간에 거의 완벽한 일치(Very good agreement)가 존재함을 알 수 있습니다.

R에는 카파를 자동으로 계산하는 몇 가지 함수가 있습니다. **시각적 범주형 데이터(Visualizing Categorical Data, VCD)** 패키지의 `Kappa()` 함수(대문자 "K"에 주의하십시오)는 예측값과 실제값의 오차 행렬을 사용합니다. `install.packages("vcd")`를 입력하여 패키지를 설치한 후 다음 명령을 사용하여 카파를 얻을 수 있습니다:

```
> library(vcd)
> Kappa(table(sms_results$actual_type, sms_results$predict_type))
```

```
            value     ASE     z Pr(>|z|)
Unweighted 0.8825 0.01949 45.27        0
Weighted   0.8825 0.01949 45.27        0
```

우리는 가중치 없는(Unweighted) 카파에 관심이 있습니다. 0.88이라는 값은 우리가 수동으로 계산한 값과 일치합니다.

가중치 있는(Weighted) 카파는 일치 정도가 다를 때 사용됩니다. 예를 들어 차가움(Cold), 시원함(Cool), 따뜻함(Warm), 뜨거움(Hot)이라는 척도를 사용할 때 따뜻함이라는 값은 차가움이라는 값보다 뜨거움에 더 잘 부합합니다. 스팸 및 햄과 같이 결과가 2개인 사건의 경우 가중치 있는 카파 통계량과 가중치 없는 카파 통계량은 동일합니다.

**평가자 간 신뢰도(Interrater Reliability, irr)** 패키지의 `kappa2()` 함수를 사용하여 데이터 프레임에 저장된 예측값과 실제값의 벡터로부터 카파를 계산할 수 있습니다. `install.packages("irr")`를 사용하여 패키지를 설치한 후 다음 명령을 사용하여 카파를 얻을 수 있습니다:

```
> library(irr)
> kappa2(sms_results[1:2])
```

```
Cohen's Kappa for 2 Raters (Weights: unweighted)
 Subjects = 1390 
   Raters = 2 
    Kappa = 0.883 
        z = 33 
  p-value = 0
```

`Kappa()` 함수와 `kappa2()` 함수는 동일한 카파 통계량을 보고하므로 둘 중 더 편한 옵션을 사용하십시오.

내장된 `kappa()` 함수를 사용하지 않도록 주의하십시오. 이것은 앞서 보고된 카파 통계량과 전혀 무관합니다!

### 매튜스 상관계수(Matthews correlation coefficient)

정확도(Accuracy)와 카파(Kappa)는 수년 동안 대중적인 성능 척도였지만, 세 번째 옵션이 빠르게 머신러닝 분야의 사실상(De facto) 표준이 되었습니다. 이전의 두 가지 측정 기준과 마찬가지로, **매튜스 상관계수(Matthews correlation coefficient, MCC)**는 분류 모델의 전반적인 성능을 반영하기 위한 단일 통계량입니다. 추가적으로, MCC는 카파와 마찬가지로 데이터 세트가 심하게 불균형한 경우(전통적인 정확도 척도가 매우 오도할 수 있는 상황의 유형)에도 유용합니다.

MCC는 해석이 용이할 뿐만 아니라 카파보다 다양한 상황에서 더 나은 성능을 낸다는 증거가 늘어나면서 인기를 얻고 있습니다. 최근의 경험적 연구(Empirical research)에 따르면 MCC가 이진 분류 모델의 실세계 성능을 설명하는 데 가장 좋은 단일 지표일 수 있음을 시사했습니다. 다른 연구에서는 카파 통계량이 모델 성능에 대해 오도하거나 잘못된 묘사를 제공할 수 있는 잠재적인 상황을 확인했습니다. 이러한 경우 MCC와 카파가 일치하지 않을 때 MCC 지표가 모델의 진정한 성능에 대해 더 합리적인 평가를 제공하는 경향이 있습니다.

카파와 비교한 매튜스 상관계수의 상대적인 장점에 대한 자세한 내용은 다음 문헌을 참조하십시오: *The Matthews correlation coefficient (MCC) is more informative than Cohen’s kappa and brier score in binary classification assessment, Chicco D, Warrens MJ, Jurman G, IEEE Access, 2021, Vol. 9, pp. 78368-78381*. 또는 다음 문헌을 참조하십시오: *Why Cohen’s Kappa should be avoided as performance measure in classification, Delgado R, Tibau XA, PLoS One, 2019, Vol. 14(9):e0222916*.

MCC 값은 *6장, 수치 데이터 예측 - 회귀 방법*에서 소개된 피어슨 상관계수(Pearson's correlation coefficient)와 동일한 척도로 해석됩니다. 이 값은 -1에서 +1 사이이며, 이는 각각 완벽하게 부정확한 예측과 완벽하게 정확한 예측을 나타냅니다. 0 값은 모델의 성능이 무작위 추측보다 나을 것이 없음을 나타냅니다. 대부분의 MCC 점수가 0에서 1 사이의 값 범위에 속하므로 어떤 점수가 "좋은" 점수인지 아는 데에는 어느 정도의 주관성이 개입됩니다. 피어슨 상관관계에 사용되는 척도와 마찬가지로 한 가지 잠재적인 해석은 다음과 같습니다:

- 완벽하게 틀림(Perfectly incorrect) = -1.0
- 매우 틀림(Strongly incorrect) = -0.5에서 -1.0 사이
- 적당히 틀림(Moderately incorrect) = -0.3에서 -0.5 사이
- 약간 틀림(Weakly incorrect) = -0.1에서 -0.3 사이
- 무작위로 맞음(Randomly correct) = -0.1에서 0.1 사이
- 약간 맞음(Weakly correct) = 0.1에서 0.3 사이
- 적당히 맞음(Moderately correct) = 0.3에서 0.5 사이
- 매우 맞음(Strongly correct) = 0.5에서 1.0 사이
- 완벽하게 맞음(Perfectly correct) = 1.0

가장 성능이 나쁜 모델이 척도의 중간에 위치한다는 점에 유의하십시오. 다시 말해 척도의 부정적 측면에 있는 모델(완벽하게에서 약간 틀림까지)은 무작위로 예측하는 모델보다 여전히 더 나은 성능을 발휘합니다. 예를 들어 매우 틀린(Strongly incorrect) 모델의 정확도가 좋지 않더라도 예측을 단순히 역전시켜(Reversed) 올바른 결과를 얻을 수 있습니다.

이러한 모든 척도와 마찬가지로 이들은 대략적인 지침(Rough guidelines)으로만 사용되어야 합니다. 게다가 MCC와 같은 측정 기준의 주요 이점은 모델의 성능을 고립시켜 이해하는 것이 아니라, 여러 모델 간의 성능 비교를 용이하게 하는 것입니다.

MCC는 다음 공식과 같이 이진 분류기의 오차 행렬에서 계산할 수 있습니다:

<span class="image placeholder" data-original-image-src="../Images/B17290_10_004.png" data-original-image-title=""></span>

SMS 스팸 분류 모델의 오차 행렬을 사용하면 다음과 같은 값을 얻을 수 있습니다:

- TN = 1203
- FP = 4
- FN = 31
- TP = 152

그런 다음 MCC는 R에서 수동으로 계산할 수 있습니다:

```
> (152 * 1203 - 4 * 31) /
    sqrt((152 + 4) * (152 + 31) * (1203 + 4) * (1203 + 31))
```

```
[1] 0.8861669
```

벤 고먼(Ben Gorman)의 `mltools` 패키지는 예측값과 실제값의 벡터를 사용하여 MCC 계산을 수행할 수 있는 `mcc()` 함수를 제공합니다. 패키지를 설치한 후 다음 R 코드는 수작업으로 계산한 결과와 동일한 결과를 출력합니다:

```
> library(mltools)
> mcc(sms_results$actual_type, sms_results$predict_type)
```

```
[1] 0.8861669
```

대안으로, 긍정 클래스가 1로 코딩되고 부정 클래스가 0으로 코딩되는 이진 분류기의 경우 MCC는 예측값과 실제값 간의 피어슨 상관관계와 동일합니다. 다음 코드처럼 `ifelse()`를 사용하여 범주형(`"spam"` 또는 `"ham"`) 값을 이진(`1` 또는 `0`) 값으로 변환한 후, R의 `cor()` 함수를 사용하여 이를 증명할 수 있습니다:

```
> cor(ifelse(sms_results$actual_type == "spam", 1, 0),
      ifelse(sms_results$predict_type == "spam", 1, 0))
```

```
[1] 0.8861669
```

1800년대 후반에 도입된 피어슨의 상관관계의 단순한 변형으로서, 이렇게 명백한 분류 성능 지표가 눈에 띄게 숨겨져 있었다는 사실은 MCC가 최근 수십 년 동안에야 대중화되었다는 점을 꽤나 놀랍게 만듭니다! 생화학자인 브라이언 W. 매튜스(Brian W. Matthews)가 1975년에 두 가지 결과가 나오는 분류 문제에 사용하도록 이 지표를 대중화한 공로를 인정받아 이 특정 응용 분야의 명명권(Naming credit)을 얻었습니다. 그러나 이 척도는 훨씬 나중까지 큰 관심을 끌지 못했을지라도 이미 널리 사용되고 있었을 가능성이 상당히 높습니다. 오늘날 그것은 산업계, 학술 연구, 심지어 머신러닝 대회의 벤치마크로도 사용됩니다. 이진 분류 모델의 전반적인 성능을 더 잘 포착하는 단일 지표는 없을 수도 있습니다. 그러나 잠시 후에 살펴보겠지만, 지표들의 조합을 사용하면 모델 성능에 대해 더 깊이 이해할 수 있습니다.

여기서 MCC는 이진 분류를 위해 정의되어 있지만 이것이 다중 클래스 결과에 가장 적합한 측정 기준인지는 불분명합니다. 이에 대한 논의와 기타 대안에 대해서는 다음 문헌을 참조하십시오: *A comparison of MCC and CEN error measures in multi-class prediction, Jurman G, Riccadonna S, Furlanello C, 2012, PLOS One 7(8): e41882*.

### 민감도(Sensitivity)와 특이도(Specificity)

유용한 분류기를 찾는 것은 대개 지나치게 보수적인 예측과 지나치게 공격적인 예측 사이의 균형을 맞추는 것을 포함합니다. 예를 들어, 이메일 필터는 거의 모든 햄 메시지를 공격적으로 필터링함으로써 모든 스팸 메시지를 제거하도록 보장할 수 있습니다. 반면에 실수로 필터링되는 햄 메시지가 없도록 보장하려면 허용할 수 없는 양의 스팸이 필터를 통과하도록 허용해야 할 수 있습니다. 한 쌍의 성능 척도가 이러한 트레이드오프(Tradeoff)를 포착합니다: 민감도(Sensitivity)와 특이도(Specificity).

모델의 **민감도**(또는 **진양성률(True positive rate)**)는 정확하게 분류된 긍정 예제의 비율을 측정합니다. 따라서 다음 공식에 나타난 바와 같이, 진양성의 수를 긍정의 총 개수, 즉 정확하게 분류된 긍정(진양성)과 잘못 분류된 긍정(위음성)의 합으로 나누어 계산합니다:

<span class="image placeholder" data-original-image-src="../Images/B17290_10_005.png" data-original-image-title=""></span>

모델의 **특이도**(또는 **진음성률(True negative rate)**)는 정확하게 분류된 부정 예제의 비율을 측정합니다. 민감도와 마찬가지로 이것은 진음성의 수를 부정의 총 개수, 즉 진음성과 위양성의 합으로 나누어 계산됩니다.

<span class="image placeholder" data-original-image-src="../Images/B17290_10_006.png" data-original-image-title=""></span>

SMS 분류기의 오차 행렬이 주어지면 우리는 이러한 척도를 직접 쉽게 계산할 수 있습니다. 스팸이 긍정 클래스라고 가정하면 `confusionMatrix()` 출력의 숫자가 올바른지 확인할 수 있습니다. 예를 들어 민감도 계산은 다음과 같습니다:

```

```

마찬가지로 특이도에 대해 다음을 계산할 수 있습니다:

```
> spec <- 1203 / (1203 + 4)
> spec
```

```
[1] 0.996686
```

`caret` 패키지는 예측값과 실제값의 벡터에서 직접 민감도와 특이도를 계산하는 함수를 제공합니다. 다음 코드에 표시된 대로 `positive` 또는 `negative` 매개변수를 적절하게 지정하도록 주의하십시오:

```

```

```

```

```
[1] 0.996686
```

민감도와 특이도의 범위는 0에서 1까지이며, 1에 가까운 값이 더 바람직합니다. 물론 두 가지 사이에서 적절한 균형을 찾는 것이 중요하며, 이는 흔히 꽤 상황 특정적(Context-specific)인 작업입니다.

예를 들어 이 경우의 0.831 민감도는 스팸 메시지의 83.1%가 올바르게 분류되었음을 암시합니다. 마찬가지로 0.997의 특이도는 스팸이 아닌 메시지의 99.7%가 올바르게 분류되었거나 대안적으로 유효한 메시지의 0.3%가 스팸으로 거부되었음을 암시합니다. 유효한 SMS 메시지의 0.3%를 거부한다는 생각은 받아들일 수 없거나, 혹은 스팸 감소를 고려할 때 합리적인 트레이드오프일 수 있습니다.

민감도와 특이도는 이러한 트레이드오프에 대해 생각할 수 있는 도구를 제공합니다. 일반적으로 원하는 민감도 및 특이도 임곗값(Threshold)을 충족하는 모델을 찾을 때까지 모델을 변경하고 여러 모델을 테스트합니다. 이 장의 후반부에서 논의할 시각화(Visualizations) 역시 민감도와 특이도 사이의 균형을 이해하는 데 도움이 될 수 있습니다.

### 정밀도(Precision)와 재현율(Recall)
민감도 및 특이도와 밀접하게 관련이 있는 것은 분류 시 이루어지는 절충(Compromises)과 관련된 두 가지 다른 성능 척도인 정밀도(Precision)와 재현율(Recall)입니다. 주로 정보 검색(Information retrieval)의 문맥에서 사용되는 이러한 통계는 모델의 결과가 얼마나 흥미롭고 관련성이 있는지, 또는 예측이 무의미한 노이즈로 희석되었는지 여부를 나타내기 위한 것입니다.

**정밀도**(**양성 예측도(Positive predictive value)**라고도 함)는 진양성인 긍정 예측의 비율로 정의됩니다. 다시 말해 모델이 긍정 클래스를 예측할 때 얼마나 자주 올바른지를 묻는 것입니다. 정밀한 모델은 긍정일 가능성이 매우 높은 사례에서만 긍정 클래스를 예측할 것입니다. 그것은 매우 신뢰할 수 있을 것입니다.

<span class="image placeholder" data-original-image-src="../Images/B17290_10_007.png" data-original-image-title=""></span>

모델이 매우 정밀하지 않을 경우 어떤 일이 일어날지 생각해 보십시오. 시간이 지남에 따라 결과를 신뢰할 가능성이 낮아질 것입니다. 정보 검색의 맥락에서 이것은 구글과 같은 검색 엔진이 관련 없는 결과를 반환하는 것과 유사할 것입니다. 결국 사용자는 빙(Bing)과 같은 경쟁사로 전환할 것입니다. SMS 스팸 필터의 경우 높은 정밀도는 모델이 햄에서 위양성(False positives)을 피하면서 스팸만을 신중하게 타겟팅할 수 있음을 의미합니다.

반면에 **재현율**은 결과가 얼마나 완전한지(Complete)를 측정하는 것입니다. 다음 공식에 나타난 바와 같이 이는 긍정의 총 개수에 대한 진양성의 수로 정의됩니다. 이것이 민감도와 동일하다는 것을 이미 눈치채셨을 수 있습니다. 그러나 해석은 약간 다릅니다.

<span class="image placeholder" data-original-image-src="../Images/B17290_10_008.png" data-original-image-title=""></span>

재현율이 높은 모델은 긍정 예제의 많은 부분을 포착(Captures)하는데, 이는 폭이 넓음(Wide breadth)을 의미합니다. 예를 들어 재현율이 높은 검색 엔진은 검색 쿼리와 관련된 많은 수의 문서를 반환합니다. 마찬가지로 SMS 스팸 필터는 대다수의 스팸 메시지를 정확하게 식별하는 경우 높은 재현율을 갖습니다.

우리는 오차 행렬에서 정밀도와 재현율을 계산할 수 있습니다. 스팸이 긍정 클래스라고 다시 가정하면 정밀도는 다음과 같습니다:

```
> prec <- 152 / (152 + 4)
> prec
```

```
[1] 0.974359
```

그리고 재현율은 다음과 같습니다:

```
> rec <- 152 / (152 + 31)
> rec
```

```
[1] 0.8306011
```

`caret` 패키지를 사용하여 예측된 클래스와 실제 클래스의 벡터에서 이 두 가지 척도 중 하나를 계산할 수 있습니다. 정밀도는 `posPredValue()` 함수를 사용합니다:

```
> library(caret)
> posPredValue(sms_results$predict_type, sms_results$actual_type,
               positive = "spam")
```

```
[1] 0.974359
```

재현율은 이전에 사용한 `sensitivity()` 함수를 사용합니다:

```
> sensitivity(sms_results$predict_type, sms_results$actual_type,
              positive = "spam")
```

```
[1] 0.8306011
```

민감도와 특이도 간의 트레이드오프(Tradeoff)와 마찬가지로 대부분의 실세계 문제에서 높은 정밀도와 높은 재현율을 모두 갖춘 모델을 구축하는 것은 어렵습니다. 분류하기 가장 쉬운 예제인 따기 쉬운 열매(Low-hanging fruit)만을 타겟팅한다면 정밀하기는 쉽습니다. 마찬가지로 모델이 매우 넓은 그물을 던져서 결과적으로 긍정 사례를 식별하는 데 지나치게 공격적이라면 높은 재현율을 갖기 쉽습니다. 대조적으로 높은 정밀도와 재현율을 동시에 갖는 것은 매우 까다롭습니다. 따라서 프로젝트의 요구 사항을 충족하는 정밀도와 재현율의 조합을 찾으려면 다양한 모델을 테스트하는 것이 중요합니다.

### F-척도(F-measure)

정밀도와 재현율을 단일 숫자로 결합하는 모델 성능의 척도를 **F-척도**(때로는 **F<sub>1</sub> 점수** 또는 **F-점수(F-score)**라고도 함)라고 합니다. F-척도는 변화율에 사용되는 평균의 한 유형인 **조화 평균(Harmonic mean)**을 사용하여 정밀도와 재현율을 결합합니다. 정밀도와 재현율 모두 0과 1 사이의 비율(Proportions)로 표현되며 이는 비율(Rates)로 해석될 수 있으므로, 더 일반적인 산술 평균(Arithmetic mean)이 아닌 조화 평균이 사용됩니다. 다음은 F-척도에 대한 공식입니다:

<span class="image placeholder" data-original-image-src="../Images/B17290_10_009.png" data-original-image-title=""></span>

F-척도를 계산하려면 이전에 계산한 정밀도 및 재현율 값을 사용하십시오:

```
> f <- (2 * prec * rec) / (prec + rec) 
> f
```

```
[1] 0.8967552
```

이것은 오차 행렬의 개수를 사용하는 것과 정확히 동일하게 나옵니다:

```
> f <- (2 * 152) / (2 * 152 + 4 + 31)
> f
```

```
[1] 0.8967552
```

F-척도는 모델 성능을 단일 숫자로 설명하므로 여러 모델을 직접 비교할 수 있는 편리하고 정량적인 지표를 제공합니다. 참으로, 한때 F-척도는 모델 성능에 있어서 거의 황금 표준(Gold standard)이었지만, 오늘날에는 과거보다 훨씬 덜 널리 사용되는 것 같습니다. 한 가지 잠재적인 설명은 그것이 위양성 및 위음성의 실제 비용(Real-world costs)에 따라 항상 유효하지는 않은 가정인, 정밀도와 재현율에 동일한 가중치가 할당되어야 한다고 가정한다는 것입니다. 물론 정밀도와 재현율에 다른 가중치를 사용하여 F-점수를 계산할 수 있지만, 가중치를 선택하는 것은 기껏해야 까다롭고 최악의 경우 임의적일 수 있습니다. 그렇기는 하지만 이 지표가 인기를 잃은 더 중요한 이유는 아마도 다음 섹션에 설명된 것과 같이 다양한 데이터 하위 집합에 대한 모델의 성능을 시각적으로 묘사하는 방법들이 채택되었기 때문일 것입니다.

## ROC 곡선을 사용하여 성능 트레이드오프 시각화하기

시각화는 기계 학습 알고리즘의 성능을 더 자세히 이해하는 데 도움이 됩니다. 민감도 및 특이도, 또는 정밀도 및 재현율과 같은 통계가 모델 성능을 단일 숫자로 요약하려고 시도하는 반면, 시각화는 학습자가 광범위한 조건에 걸쳐 어떻게 수행하는지를 묘사합니다.

학습 알고리즘은 각기 다른 편향(Biases)을 갖기 때문에 비슷한 정확도를 가진 두 모델이라 하더라도 정확도를 달성하는 방식에서는 급격한 차이가 있을 수 있습니다. 어떤 모델은 다른 모델이 쉽게 만들어내는 특정 예측으로 고군분투하는 반면 다른 모델이 맞추려고 고군분투하는 사례를 쉽게 통과할 수도 있습니다. 시각화는 단일 차트에서 학습자를 나란히 비교함으로써 이러한 트레이드오프를 이해하는 방법을 제공합니다.

**수신자 조작 특성(Receiver Operating Characteristic, ROC)** 곡선은 일반적으로 위양성을 피하면서 진양성의 탐지 간의 트레이드오프를 검사하는 데 사용됩니다. 이름에서 짐작할 수 있듯이 ROC 곡선은 통신 분야의 엔지니어에 의해 개발되었습니다. 제2차 세계대전 무렵, 레이더 및 무선 통신 기사들은 ROC 곡선을 사용하여 수신기가 실제 신호와 잘못된 경보를 구별하는 능력을 측정했습니다. 오늘날 동일한 기술이 머신러닝 모델의 효능을 시각화하는 데 유용합니다.

ROC 곡선에 대한 자세한 내용은 다음 문헌을 참조하십시오: *An introduction to ROC analysis, Fawcett T, Pattern Recognition Letters, 2006, Vol. 27, pp. 861–874*.

ROC 곡선을 구성하는 지점은 다양한 위양성 임곗값(False positive thresholds)에서의 진양성률을 나타냅니다. 이 개념을 설명하기 위해 가상의 분류기 세 가지가 이전 도표에서 대조되었습니다. 첫째, *완벽한 분류기(Perfect classifier)*는 100% 진양성률과 0% 위양성률에 해당하는 점을 통과하는 곡선을 갖습니다. 부정 결과를 잘못 분류하기 전에 모든 진양성을 올바르게 식별할 수 있습니다. 다음으로, 다이어그램의 왼쪽 아래에서 오른쪽 위 모서리까지의 대각선은 *예측 가치가 없는 분류기(Classifier with no predictive value)*를 나타냅니다. 이 유형의 분류기는 진양성과 위양성을 정확히 동일한 비율로 감지하며, 이는 분류기가 둘을 구별할 수 없음을 암시합니다. 이것은 다른 분류기를 판단하는 베이스라인(Baseline, 기준선)입니다. 이 선에 가깝게 떨어지는 ROC 곡선은 별로 유용하지 않은 모델을 나타냅니다. 마지막으로 대부분의 실세계 분류기는 *테스트 분류기(Test classifier)*와 같아서 완벽함과 쓸모없음 사이 영역 어딘가에 속합니다.

ROC 곡선이 어떻게 구성되는지 이해하는 가장 좋은 방법은 수작업으로 직접 만들어보는 것입니다. *그림 10.5*에 묘사된 표의 값들은 6개는 긍정 클래스(스팸)이고 14개는 부정 클래스(햄)인 20개의 예제를 포함하는 테스트 세트에 적용된 가상의 스팸 모델에 대한 예측을 나타냅니다.

### ROC 곡선 비교하기

ROC 곡선이 단일 모델을 평가하는 데 도움이 된다면, 여러 모델을 비교하는 데에도 유용하다는 사실은 놀라운 일이 아닙니다. 직관적으로 도표 영역의 왼쪽 상단에 가까운 곡선이 더 우수하다는 것을 우리는 알고 있습니다. 실제 환경에서 비교는 종종 이보다 더 까다로운데, 곡선 간의 차이가 명백하기보다는 미묘한 경우가 많고 모델이 어떻게 사용되는지에 따라 해석에 미묘한 차이가 있기 때문입니다.

이러한 뉘앙스(Nuances)를 이해하기 위해 두 모델이 ROC 도표에서 서로 다른 곡선을 그리는 이유를 살펴보는 것부터 시작하겠습니다. 원점에서 시작하여 추가 테스트 세트 예제가 긍정으로 예측됨에 따라 곡선의 길이가 늘어납니다. *y*축이 진양성률을 나타내고 *x*축이 위양성률을 나타내기 때문에 더 가파른 상승 궤적은 암묵적인 비율(Implicit ratio)로서, 모델이 긍정 예제를 식별하는 데 있어 실수를 덜 하면서도 더 능숙함을 암시합니다. 이것은 두 가지 가상 모델의 ROC 곡선의 시작을 그리는 *그림 10.9*에 예증되어 있습니다. 동일한 횟수의 예측(원점에서 나오는 벡터의 동일한 길이로 표시됨)에 대해 첫 번째 모델은 더 높은 진양성률과 더 낮은 위양성률을 가지며, 이는 두 모델 중 더 나은 성능을 보여줌을 암시합니다:

예를 들어, 다이렉트 메일 광고 캠페인에 응답할 가능성이 가장 높은 고객을 식별하는 데 사용되는 모델을 고려해 보십시오. 모든 잠재 고객에게 우편물을 발송할 여유가 있다면 모델은 필요하지 않을 것입니다. 그러나 모든 주소로 광고를 보낼 예산이 없기 때문에 모델을 사용하여 수신자가 광고를 본 후 제품을 구매할 확률을 추정합니다. 가장 가능성이 높은 실제 구매자를 목록의 앞쪽으로 정렬(Sorting)하는 데 능숙한 모델일수록 ROC 곡선 초반에 더 큰 기울기(Slope)를 갖게 되며 구매자를 확보하는 데 필요한 마케팅 예산을 줄일 수 있습니다. *그림 10.11*에서 첫 번째 모델은 이러한 작업에 더 적합할 것입니다.

이 접근 방식과 대조적으로, 또 다른 고려 사항은 다양한 유형의 오류에 대한 상대적 비용입니다. 실제 환경에서는 위양성과 위음성이 미치는 영향이 각기 다른 경우가 많습니다. 만약 스팸 필터나 암 검진이 90% 또는 99%와 같은 특정 진양성률을 목표로 해야 한다는 것을 안다면, 원하는 수준에서 더 낮은 위양성률을 가진 모델을 선호할 것입니다. 둘 다 높은 위양성률 때문에 매우 좋지는 않겠지만 *그림 10.11*은 이러한 애플리케이션들에 두 번째 모델이 조금 더 선호될 것임을 시사합니다.

이러한 예제들이 보여주듯이 ROC 곡선을 사용하면 모델이 어떻게 사용될지도 고려하여 모델 성능 비교를 할 수 있습니다. 이러한 유연성은 정확도나 카파와 같은 단순한 숫자 측정 기준보다 높게 평가되지만, 이러한 통계와 마찬가지로 정량적으로 비교할 수 있는 단일 지표로 ROC 곡선을 수량화(Quantify)하는 것이 바람직할 수도 있습니다. 다음 섹션에서는 바로 이러한 유형의 척도를 소개합니다.

### ROC 곡선 아래 영역(Area under the ROC curve, AUC)

ROC 곡선을 비교하는 것은 다소 주관적이고 상황에 따라 달라질 수 있으므로, 성능을 단일 수치 값으로 줄이는 측정 기준은 비교를 단순화하고 객관성을 가져오기 위해 항상 요구됩니다. 무엇이 "좋은" ROC 곡선을 만드는지 말하기는 어려울 수 있지만, 일반적으로 ROC 곡선이 도표의 왼쪽 상단에 가까울수록 긍정 값을 식별하는 데 더 우수하다는 것을 우리는 알고 있습니다. 이는 **ROC 곡선 아래 영역(Area Under the ROC Curve, AUC)**으로 알려진 통계를 사용하여 측정할 수 있습니다. AUC는 ROC 다이어그램을 2차원 사각형으로 취급하고 ROC 곡선 아래의 전체 면적(Area)을 측정합니다. AUC 범위는 (예측 가치가 없는 분류기의 경우) 0.5에서 (완벽한 분류기의 경우) 1.0까지입니다. AUC 점수를 해석하는 관례(Convention)는 학문적인 문자 성적(Letter grades)과 유사한 시스템을 사용합니다:

- **A**: 탁월함(Outstanding) = 0.9에서 1.0 사이
- **B**: 우수/상당함(Excellent/Good) = 0.8에서 0.9 사이
- **C**: 수용 가능/적당함(Acceptable/Fair) = 0.7에서 0.8 사이
- **D**: 불량(Poor) = 0.6에서 0.7 사이
- **E**: 구별할 수 없음(No Discrimination) = 0.5에서 0.6 사이

이와 같은 대부분의 척도와 마찬가지로 척도의 각 레벨은 특정 작업에 다른 작업보다 더 잘 작동할 수 있습니다; 범주 간의 경계는 자연스럽게 다소 모호(Fuzzy)합니다.
드물기는 하지만 ROC 곡선이 대각선 아래로 떨어져 AUC가 0.50 미만이 되는 것이 가능합니다. 이는 분류기가 무작위보다 더 나쁜 성능을 보인다는 것을 의미합니다. 일반적으로 이것은 코딩 오류에 의해 발생하는데, 왜냐하면 지속적으로 잘못된 예측을 하는 모델은 데이터에 대해 유용한 무언가를 확실히 학습했으며, 단지 예측을 잘못된 방향으로 적용하고 있을 뿐이기 때문입니다. 이 문제를 해결하려면 긍정 사례가 올바르게 코딩되었는지 확인하거나 모델이 부정 클래스를 예측할 때 대신 긍정 클래스를 선택하도록 예측을 역전(Reverse)시키기만 하면 됩니다.

AUC의 사용이 널리 퍼지기 시작했을 때 일부 사람들은 이를 모델 성능의 결정적인 척도로 취급했지만, 유감스럽게도 이것이 모든 경우에 해당되는 것은 아닙니다. 일반적으로 높은 AUC 값은 무작위 긍정 예제를 무작위 부정 예제보다 더 높게 정렬(Sorting)하는 데 능숙한 분류기를 반영합니다. 그러나 *그림 10.12*는 두 ROC 곡선이 매우 다르게 생겼으면서도 동일한 AUC를 가질 수 있다는 중요한 사실을 예증합니다:

AUC는 ROC 곡선의 단순화(Simplification)이므로 AUC만으로는 모든 사용 사례에 대해 "최고의" 모델을 식별하기에 불분명합니다. 가장 안전한 관행은 이 장의 앞부분에서 설명한 바와 같이 ROC 곡선의 정성적인(Qualitative) 검토와 AUC를 조합하여 사용하는 것입니다. 두 모델의 AUC가 동일하거나 유사한 경우 일반적으로 초반(Early)에 성능이 더 좋은 모델을 선택하는 것이 선호됩니다. 나아가, 한 모델이 전반적으로 더 나은 AUC를 갖는 경우에도 가장 확신하는(Confident) 예측들의 하위 집합만을 사용하는 애플리케이션의 경우 초기 진양성률이 더 높은 모델이 선호될 수 있습니다.

### R에서 ROC 곡선 생성 및 AUC 계산하기

`pROC` 패키지는 ROC 곡선을 생성하고 AUC 계산하기 위한 사용하기 쉬운 함수 집합을 제공합니다. `pROC` 웹사이트(<https://web.expasy.org/pROC/>)에는 전체 기능 집합의 목록뿐만 아니라 시각화 기능의 몇 가지 예제도 포함되어 있습니다. 계속하기 전에 `install.packages("pROC")` 명령을 사용하여 패키지를 설치했는지 확인하십시오.

`pROC` 패키지에 대한 자세한 내용은 다음 문헌을 참조하십시오: *pROC: an open-source package for R and S+ to analyze and compare ROC curves, Robin, X, Turck, N, Hainard, A, Tiberti, N, Lisacek, F, Sanchez, JC, and Mueller M, BMC Bioinformatics, 2011, pp. 12-77*.

`pROC`를 사용하여 시각화를 생성하려면 데이터의 두 벡터가 필요합니다. 첫 번째 벡터에는 긍정 클래스의 추정 확률(Estimated probability)이 포함되어야 하고 두 번째 벡터에는 예측된 클래스 값(Predicted class values)이 포함되어야 합니다.

SMS 분류기의 경우 다음과 같이 추정된 스팸 확률과 실제 클래스 레이블을 `roc()` 함수에 제공합니다:

# 미래 성능 추정(Estimating future performance)

일부 R 머신러닝 패키지는 모델 구축 프로세스 중에 오차 행렬과 성능 척도를 제시합니다. 이러한 통계의 목적은 모델의 **재대입 오류(Resubstitution error)**에 대한 통찰력을 제공하는 것입니다. 재대입 오류는 이 데이터에 대해 훈련되었음에도 불구하고 훈련 예제의 타겟 값을 잘못 예측할 때 발생합니다. 이것은 명백히 성능이 나쁜 모델을 식별하기 위한 대략적인 진단(Rough diagnostic)으로 사용될 수 있습니다. 훈련된 데이터에서 충분히 좋은 성능을 내지 못하는 모델은 미래 데이터에서도 좋은 성능을 발휘할 가능성이 낮습니다.

그 역은 성립하지 않습니다(The opposite is not true). 다시 말해 훈련 데이터에서 좋은 성능을 보이는 모델이 미래 데이터 세트에서도 좋은 성능을 보일 것이라고 가정할 수는 없습니다. 예를 들어 무조건 암기(Rote memorization)를 사용하여 모든 훈련 인스턴스를 완벽하게(재대입 오류 없이) 분류한 모델은 예측을 이전에 한 번도 본 적 없는 데이터로 일반화(Generalize)할 수 없을 것입니다. 이런 이유로 훈련 데이터에 대한 오류율은 모델의 미래 성능에 대해 낙관적(Optimistic)인 것으로 가정할 수 있습니다.

재대입 오류에 의존하는 대신 모델이 아직 보지 못한 데이터에 대해 모델의 성능을 평가하는 것이 더 나은 관행입니다. 우리는 이전 장에서 사용 가능한 데이터를 훈련 세트와 테스트 세트로 나눌 때 이러한 방법을 사용했습니다. 그러나 일부 경우에는 훈련 및 테스트 데이터 세트를 생성하는 것이 항상 이상적인 것은 아닙니다. 예를 들어 작은 데이터 풀(Pool)만 있는 상황에서는 표본(Sample)을 더 이상 줄이고 싶지 않을 수 있습니다.

다행히 곧 알게 되겠지만 보이지 않는 데이터에 대한 모델의 성능을 추정하는 다른 방법들이 있습니다. 성능 척도를 계산하기 위해 사용한 `caret` 패키지는 미래 성능을 추정하는 기능도 제공합니다. R 코드 예제를 따라하고 있는데 아직 `caret` 패키지를 설치하지 않았다면 설치해 주십시오. `library(caret)` 명령을 사용하여 R 세션에 패키지를 로드해야 합니다.

## 홀드아웃(Holdout) 방법

이전 장에서 사용한 데이터를 훈련 및 테스트 데이터 세트로 분할(Partitioning)하는 절차를 **홀드아웃 방법(Holdout method)**이라고 합니다. *그림 10.15*에 나타난 바와 같이 **훈련 데이터 세트(Training dataset)**를 사용하여 모델을 생성하고 그 후 평가용 예측을 생성하기 위해 모델을 **테스트 데이터 세트(Test dataset)**에 적용합니다. 일반적으로 데이터의 3분의 1은 테스트용으로 분리되고(Held out) 3분의 2는 훈련용으로 사용되지만 이 비율은 사용 가능한 데이터의 양이나 학습 작업의 복잡성에 따라 달라질 수 있습니다. 훈련 데이터 세트와 테스트 데이터 세트에 체계적인 차이가 없도록 예제는 무작위로 두 그룹으로 나뉩니다.

홀드아웃 방법이 진정으로 정확한 미래 성능 추정(Estimate)을 얻으려면 어떤 경우에도 테스트 데이터 세트에 대한 성능이 모델링 프로세스에 영향을 미치도록 허용해서는 안 됩니다. 스탠포드 교수이자 저명한 머신러닝 전문가인 트레버 해스티(Trevor Hastie)의 말을 빌리자면, "*이상적으로 테스트 세트는 '금고(Vault)'에 보관되어야 하며 데이터 분석의 맨 마지막에만 꺼내져야 합니다.*" 다시 말해 테스트 데이터는 오로지 단 하나의 최종 모델을 평가하기 위한 유일한 목적 외에는 건드리지 않은 채로 두어야 합니다.

자세한 내용은 다음 문헌을 참조하십시오: *The Elements of Statistical Learning (2nd edition), Hastie, Tibshirani, and Friedman (2009), p. 222*.

여러 모델 중 하나를 선택하거나 반복된 테스트 결과를 바탕으로 단일 모델을 변경할 때, 모르는 사이에 이 규칙을 위반하여 은유적인 "금고" 안을 들여다보기 쉽습니다. 예를 들어 훈련 데이터에 대해 여러 모델을 구축하고 테스트 데이터에서 정확도가 가장 높은 모델을 선택했다고 가정해 보겠습니다. 이 경우 테스트 데이터 세트를 사용하여 최고의 결과를 선별(Cherry-pick)했기 때문에 테스트 성능은 보이지 않는 데이터에 대한 미래 성능의 편향되지 않은 측정(Unbiased measure)이 아닙니다.

통찰력 있는 독자라면 이전 장에서 홀드아웃 테스트 데이터가 모델 평가와 모델 성능 향상 모두에 사용되었다는 점에 주목할 것입니다. 이는 설명을 위해 수행된 것이지만 실제로 앞에서 언급한 규칙을 위반하는 행위였습니다. 결과적으로 제시된 모델 성능 통계는 보이지 않는 데이터에 대한 미래 성능의 진정 편향되지 않은(Unbiased) 추정치가 아니었습니다.

.

홀드아웃 표본(Samples)을 생성하는 간단한 방법은 난수 생성기(Random number generators)를 사용하여 파티션에 레코드를 할당하는 것입니다. 이 기법은 *5장, 분할 정복 - 의사결정 트리와 규칙을 사용한 분류*에서 훈련 및 테스트 데이터 세트를 생성하는 데 처음 사용되었습니다.

다음 예제를 따라 하려면 Packt Publishing의 웹사이트에서 `credit.csv` 데이터 세트를 다운로드하고 `credit <- read.csv("credit.csv", stringsAsFactors = TRUE)` 명령을 사용하여 데이터 프레임으로 로드하십시오.

1,000개의 데이터 행을 포함하는 `credit`라는 이름의 데이터 프레임이 있다고 가정해 보겠습니다. 우리는 이것을 다음과 같이 3개의 파티션으로 나눌 수 있습니다. 먼저 `runif()` 함수를 사용하여 1부터 1,000까지 무작위로 정렬된 행 ID 벡터를 생성합니다. 이 함수는 기본적으로 0과 1 사이의 무작위 값(Random values)을 지정된 개수만큼 생성합니다. `runif()` 함수는 *2장, 데이터 관리 및 이해하기*에서 논의되었던 랜덤 균일 분포(Random uniform distribution)에서 이름을 따왔습니다.

그런 다음 `order()` 함수는 1,000개 난수의 순위 순서(Rank order)를 나타내는 벡터를 반환합니다. 예를 들어, `order(c(0.5, 0.25, 0.75, 0.1))`은 0.1(가장 작은 수)이 네 번째에 나타나고 0.25(두 번째로 작은 수)가 두 번째에 나타나는 식이기 때문에 수열 `4 2 1 3`을 반환합니다:

```
> random_ids <- order(runif(1000))
```

다음으로 이 임의 ID를 사용하여 credit 데이터 프레임을 500개, 250개, 250개 레코드로 분할하여 훈련, 검증, 테스트 데이터 세트를 구성합니다:

```
> credit_train <- credit[random_ids[1:500], ]
> credit_validate <- credit[random_ids[501:750], ]
> credit_test <- credit[random_ids[751:1000], ]
```

홀드아웃 샘플링의 한 가지 문제는 각 파티션에 일부 클래스의 비율이 크거나 작게 분포할 수 있다는 것입니다. 하나(또는 여러 개)의 클래스가 데이터 세트에서 차지하는 비율이 매우 작은 경우 훈련 데이터 세트에서 누락될 수 있으며, 모델이 해당 클래스를 학습할 수 없게 되므로 이는 상당한 문제입니다.

이러한 현상이 발생할 가능성을 줄이기 위해 **층화 무작위 샘플링(Stratified random sampling)**이라는 기술을 사용할 수 있습니다. 일반적으로 무작위 표본에는 전체 데이터 세트와 대략적으로 동일한 비율의 각 클래스 값이 포함되어야 하지만, 층화 무작위 샘플링은 일부 클래스가 작더라도 무작위 파티션이 전체 데이터 세트와 거의 동일한 비율의 각 클래스를 갖도록 보장합니다.

`caret` 패키지는 계층화된 홀드아웃 샘플링을 기반으로 파티션을 생성하는 `createDataPartition()` 함수를 제공합니다. `credit` 데이터 세트에 대한 훈련 및 테스트 데이터의 계층화된 표본을 생성하는 단계는 다음 명령에 표시되어 있습니다. 이 함수를 사용하려면 파티션에 포함될 인스턴스의 비율을 지정하는 `p` 매개변수와 더불어 클래스 값의 벡터(여기서 `default`는 대출의 채무 불이행(Default) 여부를 나타냄)를 지정해야 합니다. `list = FALSE` 매개변수는 결과가 목록(List) 객체로 저장되는 것을 방지합니다(이러한 기능은 더 복잡한 샘플링 기술에 필요하지만 여기서는 불필요합니다):

```
> in_train <- createDataPartition(credit$default, p = 0.75, list = FALSE)
> credit_train <- credit[in_train, ]
> credit_test <- credit[-in_train, ]
```

`in_train` 벡터는 훈련 표본에 포함된 행 번호를 나타냅니다. 이 행 번호를 사용하여 `credit_train` 데이터 프레임에 대한 예제를 선택할 수 있습니다. 유사하게 마이너스(-) 기호를 사용하여 `credit_test` 데이터 세트에 대해 `in_train` 벡터에서 찾을 수 없는 행을 사용할 수 있습니다.

층화 샘플링은 클래스를 고르게 분배하지만, 다른 유형의 대표성(Representativeness)을 보장하지는 않습니다. 일부 표본에는 예측하기 어려운 사례, 예측하기 쉬운 사례 또는 이상치(Outliers)가 너무 많거나 너무 적을 수 있습니다. 이는 특히 더 작은 데이터 세트의 경우에 해당하며, 훈련 및 테스트 세트로 나눌 수 있을 만큼 충분한 부분의 그러한 사례가 없을 수 있습니다.

잠재적으로 편향된 표본 외에도, 홀드아웃 방법의 또 다른 문제는 모델을 테스트하고 검증하기 위해 상당한 양의 데이터를 유보해(Reserved) 두어야 한다는 점입니다. 이 데이터는 성능이 측정될 때까지 모델 훈련에 사용할 수 없으므로 성능 추정치는 지나치게 보수적(Conservative)일 가능성이 높습니다.

일반적으로 더 큰 데이터 세트에서 훈련된 모델이 더 나은 성능을 발휘하기 때문에, 일반적인 관행은 최종 모델을 선택하고 평가한 후 전체 데이터 세트(즉, 훈련에 더하여 테스트 및 검증 세트)에서 모델을 다시 훈련(Retrain)시키는 것입니다.

무작위로 구성된 훈련 데이터 세트의 문제를 완화하기 위해 **반복 홀드아웃(Repeated holdout)**이라는 기술이 종종 사용됩니다. 반복 홀드아웃 방법은 여러 무작위 홀드아웃 표본의 평균 결과를 사용하여 모델 성능을 평가하는 홀드아웃 방법의 특별한 경우입니다. 여러 개의 홀드아웃 표본이 사용되므로 모델이 대표성이 없는(Non-representative) 데이터에 대해 훈련되거나 테스트될 가능성이 적습니다. 다음 섹션에서 이 아이디어에 대해 자세히 설명하겠습니다.

## 교차 검증(Cross-validation)

반복 홀드아웃은 모델 성능 추정을 위한 업계 표준이 된 **k-폴드 교차 검증(k-fold cross-validation, k-fold CV)**으로 알려진 기법의 기반입니다. k-폴드 교차 검증은 동일한 레코드를 두 번 이상 잠재적으로 사용할 수 있는 무작위 표본을 반복적으로 취하는 대신에, 데이터를 **폴드(Folds)**라고 하는 *k*개의 개별 무작위 파티션으로 무작위 분할(Divides)합니다.

*k*는 임의의 숫자로 설정할 수 있지만, 단연 가장 일반적인 관행은 10-폴드 CV를 사용하는 것입니다. 왜 10개의 폴드일까요? 그 이유는 실증적 증거(Empirical evidence)에 따르면 더 많은 수를 사용해도 추가되는 이점이 거의 없기 때문입니다. 10개의 폴드(각 폴드는 전체 데이터의 10%를 차지함) 각각에 대해 나머지 90%의 데이터를 기반으로 머신러닝 모델을 구축합니다. 그런 다음 폴드의 10% 표본은 모델 평가에 사용됩니다. 모델을 훈련하고 평가하는 과정을 10번(서로 다른 10개의 훈련/테스트 조합을 사용하여) 수행한 후, 모든 폴드에 걸친 평균 성능이 보고됩니다.

k-폴드 CV의 극단적인 경우는 데이터의 각 예제마다 폴드를 하나씩 사용하여 k-폴드 CV를 수행하는 **단일 관측치 제거(Leave-one-out) 방법**입니다. 이렇게 하면 모델 훈련에 가장 많은 양의 데이터가 사용되도록 보장합니다. 이는 유용해 보일 수 있지만 계산 비용(Computationally expensive)이 너무 많이 들어서 실제로는 거의 사용되지 않습니다.

CV를 위한 데이터 세트는 `caret` 패키지의 `createFolds()` 함수를 사용하여 생성할 수 있습니다. 층화 무작위 홀드아웃 샘플링과 마찬가지로 이 함수는 원래 데이터 세트에서와 동일한 클래스 균형(Class balance)을 각 폴드에서 유지하려고 시도합니다. 다음은 결과를 재현할 수 있도록 `set.seed(123)`을 사용하여 10개의 폴드를 생성하는 명령입니다:

```
> set.seed(123)
> folds <- createFolds(credit$default, k = 10)
```

`createFolds()` 함수의 결과는 요청된 `k = 10` 폴드 각각에 대한 행 번호를 저장하는 벡터들의 리스트입니다. `str()`을 사용하여 내용을 엿볼 수 있습니다:

```
> str(folds)
```

```

 $ Fold01: int [1:100] 14 23 32 42 51 56 65 66 77 95 ...
 $ Fold02: int [1:100] 21 36 52 55 96 115 123 129 162 169 ...
 $ Fold03: int [1:100] 3 22 30 34 37 39 43 58 70 85 ...
 $ Fold04: int [1:100] 12 15 17 18 19 31 40 45 47 57 ...
 $ Fold05: int [1:100] 1 5 7 20 26 35 46 54 106 109 ...
 $ Fold06: int [1:100] 6 27 29 48 68 69 72 73 74 75 ...
 $ Fold07: int [1:100] 10 38 49 60 61 63 88 94 104 108 ...
 $ Fold08: int [1:100] 8 11 24 53 71 76 89 90 91 101 ...
 $ Fold09: int [1:100] 2 4 9 13 16 25 28 44 62 64 ...
 $ Fold10: int [1:100] 33 41 50 67 81 82 100 105 107 118 ...
```

여기서 우리는 첫 번째 폴드의 이름이 `Fold01`이고 100개의 정수를 저장하며, 이것이 첫 번째 폴드에 대한 `credit` 데이터 프레임의 100개 행을 나타냄을 알 수 있습니다. 모델을 만들고 평가하기 위해 훈련 및 테스트 데이터 세트를 생성하려면 추가 단계가 필요합니다. 다음 명령은 첫 번째 폴드에 대한 데이터를 생성하는 방법을 보여줍니다. 우리는 선택된 10%를 테스트 데이터 세트에 할당하고 마이너스(-) 기호를 사용하여 나머지 90%를 훈련 데이터 세트에 할당할 것입니다:
```
> credit01_test <- credit[folds$Fold01, ]
> credit01_train <- credit[-folds$Fold01, ]
```

전체 10-폴드 CV를 수행하려면 먼저 모델을 구축한 다음 매번 모델의 성능을 계산하는 이 단계를 총 10번 반복해야 합니다. 결국 전반적인 성능을 얻기 위해 성능 척도들을 평균화하게 됩니다. 다행히 앞서 배운 몇 가지 기법을 적용하여 이 작업을 자동화할 수 있습니다.

이 프로세스를 설명하기 위해 10-폴드 CV를 사용하여 신용 데이터의 C5.0 의사결정 트리 모델에 대한 카파(Kappa) 통계량을 추정해 보겠습니다. 먼저 (폴드를 생성하기 위한) `caret`, (의사결정 트리를 구축하기 위한) `C50`, (카파를 계산하기 위한) `irr` 등의 R 패키지를 로드해야 합니다. 후자의 두 패키지는 설명의 목적으로 선택되었습니다; 원한다면 동일한 일련의 단계를 거쳐 다른 모델이나 다른 성능 척도를 사용할 수 있습니다:

```
> library(caret)
> library(C50)
> library(irr)
```

다음으로 이전에 수행한 대로 10개의 폴드 목록을 생성합니다. 이전과 마찬가지로 `set.seed()` 함수는 동일한 코드를 다시 실행할 경우 결과가 일관되게 유지되도록 보장하기 위해 여기서 사용되었습니다:

```
> set.seed(123)
> folds <- createFolds(credit$default, k = 10)
```

마지막으로 `lapply()` 함수를 사용하여 폴드 리스트에 일련의 동일한 단계를 적용할 것입니다. 다음 코드에 표시된 것처럼 우리가 정확히 필요로 하는 작업을 수행하는 기존 함수가 없기 때문에 `lapply()`에 전달할 고유한 함수를 정의해야 합니다. 사용자 지정 함수는 `credit` 데이터 프레임을 훈련 및 테스트 데이터로 나누고, 훈련 데이터에 `C5.0()` 함수를 사용하여 의사결정 트리를 구축하고, 테스트 데이터에서 일련의 예측을 생성한 다음, `kappa2()` 함수를 사용하여 예측값과 실제값을 비교합니다:

```
> cv_results <- lapply(folds, function(x) {
    credit_train <- credit[-x, ]
    credit_test <- credit[x, ]
    credit_model <- C5.0(default ~ ., data = credit_train)
    credit_pred <- predict(credit_model, credit_test)
    credit_actual <- credit_test$default
    kappa <- kappa2(data.frame(credit_actual, credit_pred))$value
    return(kappa)
  })
```

결과적인 카파 통계량들은 `cv_results` 객체에 저장된 목록으로 컴파일(Compiled)되며, `str()`을 사용하여 검사할 수 있습니다:

```
> str(cv_results)
```

```
List of 10
 $ Fold01: num 0.381
 $ Fold02: num 0.525
 $ Fold03: num 0.247
 $ Fold04: num 0.316
 $ Fold05: num 0.387
 $ Fold06: num 0.368
 $ Fold07: num 0.122
 $ Fold08: num 0.141
 $ Fold09: num 0.0691
 $ Fold10: num 0.381
```

10-폴드-CV 프로세스에는 단 한 단계만 남았습니다. 바로 이 10개 값의 평균을 계산해야 합니다. 비록 `mean(cv_results)`를 입력하고 싶겠지만, `cv_results`가 숫자형 벡터가 아니기 때문에 결과는 에러가 될 것입니다. 대신 리스트 구조를 제거하고 `cv_results`를 숫자형 벡터로 축소하는 `unlist()` 함수를 사용하십시오. 거기서부터 우리는 예상대로 평균 카파를 계산할 수 있습니다:

```
> mean(unlist(cv_results))
```

```
[1] 0.2939567
```

이 카파 통계량은 해석 척도(Interpretation scale)에서 "적당함(Fair)"에 해당하는 비교적 낮은 수준으로, 신용 점수 모델의 성능이 무작위 우연보다 약간 더 나을 뿐이라는 점을 시사합니다. *14장, 더 나은 학습자 구축하기*에서 우리는 이 모델의 성능을 향상시키는 데 도움을 줄 수 있는 10-폴드 CV에 기반한 자동화된 방법들을 검토할 것입니다.

CV는 여러 테스트 세트로부터 얻은 성능 추정치를 제공하므로 추정치의 변동성(Variability)도 계산할 수 있습니다. 예를 들어 10번 반복에 대한 표준 편차는 다음과 같이 계산할 수 있습니다:

```
> sd(unlist(cv_results))
```

```
[1] 0.1448565
```

성능 지표의 평균과 표준 편차를 찾은 후에는 신뢰 구간(Confidence interval)을 계산하거나 두 모델의 성능에 **통계적으로 유의미한(Statistically significant)** 차이가 있는지(즉, 차이가 무작위 변동에 기인한 것이 아니라 실제(Real)일 가능성이 높은지) 판별할 수 있습니다.

유감스럽게도 최근 연구에 따르면 CV가 이러한 통계적 검정의 가정들(Assumptions), 특히 데이터가 독립적인(Independent) 무작위 표본으로부터 도출되어야 한다는 필요조건을 위반하는 것으로 나타났는데, 이는 정의상 서로 연결되어 있는 CV 폴드의 경우에는 명백히 사실이 아닙니다.

10-폴드 CV에서 얻은 성능 추정치의 한계에 대한 논의는 다음 문헌을 참조하십시오: *Cross-validation: what does it estimate and how well does it do it?, Bates S, Hastie T, and Tibshirani R, 2022, https://arxiv.org/abs/2104.00673*.

모델 성능 추정치의 견고함(Robustness)을 향상시키기 위해 CV의 더 정교한 변형이 개발되었습니다. 이러한 기법 중 하나는 **반복된 k-폴드 CV(Repeated k-fold CV)**로, 이는 k-폴드 CV를 반복적으로 적용하고 그 결과를 평균내는 과정을 수반합니다. 흔한 전략은 10-폴드 CV를 10번 수행하는 것입니다. 계산 집약적(Computationally intensive)이기는 하지만 훨씬 더 많은 시험(Trials)에 대해 성능을 평균내기 때문에 표준적인 10-폴드 CV보다 더욱 견고한 성능 추정치를 제공합니다. 그러나 이 역시 통계적 가정을 위반하므로 결과에 대해 수행되는 통계적 검정이 약간 편향(Biased)될 수 있습니다.

아마도 모델 성능 추정을 위한 현재의 황금 표준은 또 다른 k-폴드 CV 프로세스 내에서 글자 그대로(Literally) k-폴드 CV를 수행하는 **중첩(Nested) 교차 검증**일 것입니다. 이 기법은 *11장, 머신러닝으로 성공하기*에 설명되어 있으며 계산 비용이 매우 비쌀 뿐만 아니라 구현 및 해석이 더 까다롭습니다. 중첩 k-폴드 CV의 장점은 통계적 가정 위반으로 인해 편향된 표준 k-폴드 CV와 비교할 때 모델 성능에 대한 진정으로 유효한(Valid) 비교를 생성한다는 것입니다. 반면에 이 문제로 인한 편향성은 매우 큰 데이터 세트의 경우에는 덜 중요해 보이므로, 보다 간단한 CV 접근 방식에서 도출된 신뢰 구간 또는 유의성 검정을 사용하여 "최고" 모델을 식별하는 데 도움을 받는 것은 여전히 합리적일 수 있으며 지속적으로 흔한 관행입니다.

## 부트스트랩 샘플링(Bootstrap sampling)

조금 덜 대중적이지만 매우 중요한 k-폴드 CV의 대안은 **부트스트랩 샘플링**, **부트스트랩(Bootstrap)**, 또는 줄여서 **부트스트래핑(Bootstrapping)**이라고 알려져 있습니다. 일반적으로 이들은 데이터의 무작위 표본을 사용하여 더 큰 집합의 속성을 추정하는 통계적 방법을 가리킵니다. 이 원리를 기계 학습 모델 성능에 적용하면 무작위로 선택된 여러 개의 훈련 및 테스트 데이터 세트를 생성하고 이를 사용하여 성능 통계량을 추정함을 암시합니다. 그런 다음 다양한 무작위 데이터 세트의 결과를 평균내어 미래 성능에 대한 최종 추정치를 얻습니다.

그렇다면 이 절차가 k-폴드 CV와 다른 점은 무엇일까요? CV가 데이터를 각 예제가 한 번만 나타날 수 있는 별도의 파티션으로 분할하는 반면, 부트스트랩은 **복원 추출(Sampling with replacement)** 과정을 통해 예제가 여러 번 선택될 수 있도록 허용합니다. 즉, *n*개의 예제로 구성된 원본 데이터 세트에서 부트스트랩 절차는 일부가 반복되는 상태로 역시 *n*개의 예제를 포함하는 하나 이상의 새로운 훈련 데이터 세트를 생성합니다.

해당 테스트 데이터 세트들은 그 후 각각의 훈련 데이터 세트들에 대해 선택되지 않은 예제들의 집합으로부터 구성됩니다.

부트스트랩된 데이터 세트에서 특정 인스턴스가 훈련 데이터 세트에서 제외될 확률은 36.8%입니다. 우리는 훈련 데이터 세트에 *n*개의 행 중 하나가 추가될 때마다 각 예제가 1/*n* 확률로 샘플링된다는 점을 인지하여 이를 수학적으로 증명할 수 있습니다. 따라서 테스트 세트에 포함되기 위해 예제는 *n*번 선택되지 *않아야* 합니다. 선택될 확률이 1/*n*이므로 선택되지 *않을* 확률은 따라서 1 - 1/*n*이며 *n*번 선택되지 않을 확률은 다음과 같습니다:

이 공식을 사용하면 부트스트랩할 데이터 세트에 1,000개의 행이 포함되어 있는 경우, 임의의 레코드가 선택되지 않을 확률은 다음과 같습니다:

```

```


마찬가지로 행 수가 100,000개인 데이터 세트의 경우:

```

```

```
[1] 0.3678776
```

그리고 *n*이 무한대에 가까워지면 여기에 표시된 것처럼 수식은 1/*e*로 수렴합니다(Reduces):

```
> 1 / exp(1)
```

```
[1] 0.3678794
```

선택되지 않을 확률이 36.8%라는 점을 감안할 때 인스턴스가 훈련 데이터 세트에 대해 선택될 확률은 100 - 36.8 = 63.2%입니다. 다시 말해 훈련 데이터는 사용 가능한 전체 예제의 63.2%만을 나타내며, 그중 일부는 반복됩니다. 예제의 90%를 훈련에 사용하는 10-폴드 CV와 대조적으로 부트스트랩 표본은 전체 데이터 세트를 덜 대표(Less representative)합니다.

훈련 데이터의 63.2%에 대해서만 훈련된 모델은 더 큰 훈련 세트에 대해 훈련된 모델보다 성능이 떨어질 가능성이 높기 때문에 부트스트랩의 성능 추정치는 나중에 모델이 전체 데이터 세트에 대해 훈련될 때 얻을 결과보다 상당히 낮을 수 있습니다.

**0.632 부트스트랩(0.632 bootstrap)**으로 알려진 부트스트래핑의 특별한 경우는 훈련 데이터(지나치게 낙관적임)와 테스트 데이터(지나치게 비관적임) 모두에 대한 성능의 함수(Function)로서 최종 성능 척도를 계산함으로써 이를 해결(Accounts for)합니다. 최종 오류율은 그런 다음 다음과 같이 추정됩니다:

# 요약

이 장에서는 머신러닝 분류 모델의 성능을 평가하기 위한 가장 일반적인 척도와 기술 중 몇 가지를 제시했습니다. 정확도(Accuracy)는 모델이 얼마나 자주 맞는지 조사하는 간단한 방법을 제공하지만 드문 사건의 경우에는 이런 사건의 실생활에서의 중요성이 데이터에 나타나는 빈도와 반비례할 수 있기 때문에 오도(Misleading)할 수 있습니다.

오차 행렬에 기반한 몇몇 지표들은 모델의 성능과 다양한 종류의 오차 비용 간의 균형(Balance)을 더 잘 포착합니다. 카파 통계량(Kappa statistic)과 매튜스 상관계수(Matthews correlation coefficient)는 심하게 불균형한 데이터 세트에서도 잘 작동하는, 보다 정교한 두 가지 성능 지표입니다. 덧붙여 민감도(Sensitivity)와 특이도(Specificity) 또는 정밀도(Precision)와 재현율(Recall) 간의 트레이드오프를 면밀히 검토하는 것은 현실 세계에서 발생하는 오차의 함의(Implications)에 대해 생각할 수 있는 유용한 도구가 될 수 있습니다. ROC 곡선과 같은 시각화 또한 이러한 목적에 유용합니다.

때로는 모델 성능에 대한 최고의 척도가 다른 목적을 얼마나 잘 충족하는지 또는 충족하지 못하는지를 고려하는 것이라는 점도 언급할 가치가 있습니다. 예를 들어 모델의 논리를 쉬운 언어로 설명해야 할 수도 있는데, 그러면 일부 모델을 고려 대상에서 제외하게 될 것입니다. 덧붙여, 성능이 매우 좋더라도 프로덕션(Production) 환경으로 확장(Scale)하기가 너무 느리거나 어려운 모델은 완전히 무용지물(Useless)입니다.

이후의 장들을 미리 내다보면 성능 *측정(Measuring)*의 명백한 확장은 성능을 *개선(Improve)*하는 방법을 찾는 것입니다. 이 책을 계속 읽으면서 머신러닝 능력을 강화하고 더 고급 기술을 추가하는 동시에 이 장의 원칙 중 많은 부분을 적용하게 될 것입니다. CV 기법, ROC 곡선, 부트스트래핑, `caret` 패키지는 다음 페이지에서 규칙적으로 다시 등장할 것이며, 우리는 학습 알고리즘을 체계적으로 반복(Iterating), 개선, 결합함으로써 더 스마트한 모델을 만드는 방법을 조사하기 위해 지금까지의 작업을 바탕으로(Build upon) 계속 나아갈 것입니다.
