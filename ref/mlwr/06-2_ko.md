# 데이터 관리와 이해

모든 머신러닝 프로젝트의 초반 핵심 요소는 데이터를 관리하고 이해하는 과정을 포함합니다. 노력의 결실을 보기 시작하는 단계인 모델을 구축하고 배포하는 것만큼 만족스럽지는 않을 수 있지만, 이 중요한 준비 작업을 무시하는 것은 현명하지 않습니다.

모든 학습 알고리즘의 성능은 훈련 데이터의 질에 달려 있으며, 많은 경우 이 데이터는 복잡하고 지저분하며 다양한 출처와 형식에 걸쳐 분산되어 있습니다. 이러한 복잡성으로 인해 머신러닝 프로젝트에 투자되는 노력 중 가장 큰 비중이 종종 데이터 준비와 탐색에 사용됩니다.

이 장에서는 세 가지 방식으로 데이터 준비에 접근합니다. 첫 번째 섹션에서는 R이 데이터를 저장하는 데 사용하는 기본 데이터 구조를 다룹니다. 데이터셋을 만들고 조작하면서 이러한 구조에 매우 익숙해질 것입니다. 두 번째 섹션은 데이터를 R로 가져오고 R에서 내보내는 데 사용되는 여러 함수를 다루는 실용적인 부분입니다. 세 번째 섹션에서는 실제 데이터셋을 탐색하면서 데이터를 이해하는 방법론을 보여줍니다.

이 장이 끝날 무렵에는 다음 사항을 이해하게 될 것입니다.

- 값을 저장하고 조작하기 위해 R의 기본 데이터 구조를 사용하는 방법
- 일반적인 소스 형식에서 R로 데이터를 가져오기 위한 간단한 함수
- 복잡한 데이터를 이해하고 시각화하는 일반적인 방법론

R이 데이터를 처리하는 방식은 여러분이 데이터를 다뤄야 하는 방식을 좌우하므로 바로 데이터 전처리로 넘어가기 전에 R의 데이터 구조를 이해하는 것이 도움이 됩니다. 그러나 이미 R 프로그래밍에 익숙하다면 데이터 전처리 섹션으로 넘어가도 무방합니다.

이 책의 모든 코드 파일은 <https://github.com/PacktPublishing/Machine-Learning-with-R-Fourth-Edition>에서 찾을 수 있습니다.

# R 데이터 구조

프로그래밍 언어에는 수많은 유형의 데이터 구조가 있으며, 각각의 구조는 특정 작업에 적합한 장단점을 가지고 있습니다. R은 통계적 데이터 분석에 널리 사용되는 프로그래밍 언어이므로, 여기서 활용하는 데이터 구조는 이러한 유형의 작업을 염두에 두고 설계되었습니다.

머신러닝에서 가장 자주 사용되는 R 데이터 구조는 벡터(Vectors), 팩터(Factors), 리스트(Lists), 배열(Arrays), 행렬(Matrices) 및 데이터 프레임(Data frames)입니다. 각 구조는 특정 데이터 관리 작업에 맞게 조정되어 있으므로 R 프로젝트에서 이들이 어떻게 상호 작용할지 이해하는 것이 중요합니다. 이어지는 섹션에서는 이들의 유사점과 차이점을 살펴볼 것입니다.

## 벡터

가장 기본적인 R 데이터 구조는 **벡터(Vector)**로, **요소(Elements)**라고 불리는 값의 정렬된 세트를 저장합니다. 벡터는 임의의 수의 요소를 포함할 수 있습니다. 그러나 벡터의 모든 요소는 동일한 유형이어야 합니다. 예를 들어 하나의 벡터에 숫자와 텍스트가 모두 포함될 수는 없습니다. `v`라는 벡터의 유형을 확인하려면 `typeof(v)` 명령을 사용합니다. R은 **대소문자를 구분(Case-sensitive)**하는 언어이므로 소문자 `v`와 대문자 `V`는 두 개의 다른 벡터를 나타낼 수 있다는 점에 유의하십시오. 이는 R의 내장 함수와 키워드에도 적용되므로 R 명령이나 표현식을 입력할 때 항상 정확한 대소문자를 사용해야 합니다.

머신러닝에서는 몇 가지 벡터 유형이 일반적으로 사용됩니다: `integer`(소수점 없는 숫자), `double`(소수점 있는 숫자), `character`(텍스트 데이터, 흔히 "문자열(String)" 데이터라고도 함), 그리고 `logical`(`TRUE` 또는 `FALSE` 값). 일부 R 함수는 `integer`와 `double` 벡터를 모두 `numeric`으로 보고하는 반면, 다른 함수는 이 둘을 구분합니다. 일반적으로 이러한 구분은 중요하지 않습니다. 논리형(Logical) 값의 벡터는 R에서 자주 사용되지만 `TRUE` 및 `FALSE` 값은 모두 대문자로 작성해야 한다는 점에 유의하십시오. 이는 다른 일부 프로그래밍 언어와 약간 다릅니다.

모든 벡터 유형과 관련된 두 가지 특수한 값도 있습니다: *누락된* 값을 나타내는 `NA`와 *아무* 값도 없음을 나타내는 `NULL`입니다. 이 둘이 동의어인 것처럼 보일 수 있지만, 사실 조금 다릅니다. `NA` 값은 다른 무언가를 위한 자리 표시자(Placeholder)이므로 길이가 1인 반면 `NULL` 값은 진정으로 비어있으며 길이가 0입니다.

방대한 양의 데이터를 손으로 입력하는 것은 번거롭지만 `c()` 결합 함수를 사용하여 간단한 벡터를 생성할 수 있습니다. 벡터는 화살표 `<-` 연산자를 사용하여 이름을 부여할 수도 있습니다. 이것은 R의 할당 연산자로, 많은 다른 프로그래밍 언어에서 사용되는 `=` 할당 연산자와 매우 유사하게 사용됩니다.

R에서는 할당을 위해 `=` 연산자를 사용하는 것도 허용하지만, 일반적으로 받아들여지는 스타일 가이드라인에 따르면 이는 좋지 않은 코딩 스타일로 간주됩니다.

예를 들어 세 명의 의료 환자에 대한 데이터를 포함하는 벡터 세트를 만들어 보겠습니다. 세 명의 환자 이름을 저장할 `subject_name`이라는 문자형 벡터(Character vector), 화씨온도 기준으로 각 환자의 체온을 저장할 `temperature`라는 숫자형 벡터(Numeric vector), 각 환자의 진단 결과(독감에 걸렸으면 `TRUE`, 그렇지 않으면 `FALSE`)를 저장할 `flu_status`라는 논리형 벡터(Logical vector)를 만듭니다. 다음 코드에 나와 있듯이 세 개의 벡터는 다음과 같습니다.

```
> subject_name <- c("John Doe", "Jane Doe", "Steve Graves")
> temperature <- c(98.1, 98.6, 101.4)
> flu_status <- c(FALSE, FALSE, TRUE)
```

R 벡터에 저장된 값은 순서를 유지합니다. 따라서 벡터의 이름 뒤에 대괄호(즉, `[` 및 `]`) 안에 숫자를 제공하여 `1`부터 시작하는 세트 내 위치를 사용해 각 환자의 데이터에 접근할 수 있습니다. 예를 들어 두 번째 환자인 Jane Doe의 체온 값을 얻으려면 다음과 같이 입력하기만 하면 됩니다.

```
> temperature[2]
```

```
[1] 98.6
```

R은 벡터에서 데이터를 추출하는 다양한 방법을 제공합니다. 콜론 연산자를 사용하여 값의 범위를 얻을 수 있습니다. 예를 들어, 두 번째 및 세 번째 환자의 체온을 얻으려면 다음과 같이 입력합니다.

```
> temperature[2:3]
```

```
[1] 98.6 101.4
```

음수의 항목 번호를 지정하여 항목을 제외할 수 있습니다. 두 번째 환자의 체온 데이터를 제외하려면 다음과 같이 입력합니다.

```
> temperature[-2]
```

```
[1]  98.1 101.4
```

각 항목을 포함해야 할지 여부를 나타내는 논리형 벡터를 지정하는 것이 때로는 유용합니다. 예를 들어 처음 두 번의 체온 판독값을 포함하고 세 번째는 제외하려면 다음과 같이 입력합니다.

```
> temperature[c(TRUE, TRUE, FALSE)]
```

```
[1] 98.1 98.6
```

이러한 유형의 연산의 중요성은 `temperature > 100`과 같은 논리 표현식의 결과가 논리형 벡터라는 사실을 깨달을 때 더 명확해집니다. 이 표현식은 온도가 화씨 100도(열이 있음을 나타냄)보다 높은지 여부에 따라 `TRUE` 또는 `FALSE`를 반환합니다. 따라서 다음 명령은 발열이 있는 환자를 식별합니다.

```
> fever <- temperature > 100
> subject_name[fever]
```

```
[1] "Steve Graves"
```

대안적으로, 논리 표현식을 대괄호 안으로 이동시켜 단일 단계로 동일한 결과를 반환할 수도 있습니다.

```
> subject_name[temperature > 100]
```

```
[1] "Steve Graves"
```

곧 보게 되겠지만 벡터는 많은 다른 R 데이터 구조의 기반을 제공하며 데이터를 선택하고 새로운 특징을 구성하기 위한 더 복잡한 연산을 완료하기 위해 프로그래밍 표현식과 결합할 수 있습니다. 따라서 데이터를 R에서 다루기 위해 다양한 벡터 연산을 아는 것은 매우 중요합니다.

## 팩터

*1장, 머신러닝 소개*에서 명목형 특징이 값의 범주를 가진 특성을 나타낸다는 것을 떠올려 보십시오. 비록 명목형 데이터를 저장하기 위해 문자형 벡터를 사용할 수 있지만 R은 이 작업을 위해 구체적으로 데이터 구조를 제공합니다.

**팩터(Factor)**는 오로지 범주형 또는 순서형 데이터를 나타내는 데 사용되는 특수한 유형의 벡터입니다. 우리가 구축하고 있는 의료 데이터셋에서 환자의 생물학적 성별을 나타내기 위해 팩터를 사용하여 남성과 여성이라는 두 가지 범주를 기록할 수 있습니다.

왜 문자형 벡터 대신 팩터를 사용할까요? 팩터의 한 가지 이점은 범주 라벨(Category labels)이 한 번만 저장된다는 것입니다. `MALE`, `MALE`, `FEMALE`을 저장하는 대신 컴퓨터는 `1`, `1`, `2`를 저장하여 값을 저장하는 데 필요한 메모리를 줄일 수 있습니다. 게다가 많은 머신러닝 알고리즘은 명목형 특징과 숫자형 특징을 다르게 처리합니다. 범주형 특징을 팩터로 코딩하면 R이 범주형 특징을 적절하게 처리할 수 있습니다.

값들이 진정으로 범주에 속하지 않는 문자형 벡터에는 팩터를 사용해서는 안 됩니다. 벡터가 주로 이름이나 사회 보장 번호와 같은 식별 코드와 같이 고유한 값을 저장하는 경우에는 문자형 벡터로 유지하십시오.

문자형 벡터에서 팩터를 생성하려면 `factor()` 함수를 적용하기만 하면 됩니다. 예를 들면 다음과 같습니다.

```
> gender <- factor(c("MALE", "FEMALE", "MALE"))
> gender
```

```
[1] MALE   FEMALE MALE
Levels: FEMALE MALE
```

`gender` 팩터가 표시되었을 때 R은 해당 레벨(Levels)에 대한 추가 정보를 출력했다는 점에 유의하십시오. 레벨은 팩터가 취할 수 있는 가능한 범주의 집합으로, 이 경우에는 `MALE` 또는 `FEMALE`입니다.

팩터를 만들 때 원래 데이터에는 나타나지 않을 수 있는 추가 레벨을 더할 수 있습니다. 다음 예제와 같이 혈액형에 대한 또 다른 팩터를 생성했다고 가정해 보겠습니다.

```
> blood <- factor(c("O", "AB", "A"),
            levels = c("A", "B", "AB", "O"))
> blood
```

```
[1] O  AB A
Levels: A B AB O
```

`blood` 팩터를 정의할 때 `levels` 매개변수를 사용하여 가능한 4가지 혈액형에 대한 추가 벡터를 지정했습니다. 그 결과, 출력에서 보여지듯 비록 우리의 데이터에는 O, AB, A 혈액형만 포함되어 있음에도 불구하고 `blood` 팩터에는 4가지 유형이 모두 유지됩니다. 추가 레벨을 저장하면 향후 다른 혈액형을 가진 환자를 추가할 수 있는 가능성을 열어둘 수 있습니다. 또한 혈액형 테이블을 만든다면 초기 데이터에서 발견되지 않았음에도 불구하고 B형이 존재한다는 것을 알 수 있게 보장해줍니다.

팩터 데이터 구조는 명목형 특징의 범주 순서에 대한 정보를 포함할 수 있도록 하여 순서형 특징을 생성하는 방법도 제공합니다. 예를 들어, 가벼움부터 중간, 심각함까지 심각도 증가 순서로 코딩된 환자 증상의 심각도 데이터가 있다고 가정해 보겠습니다. 표시된 것처럼 가장 낮은 것부터 가장 높은 것까지 오름차순으로 원하는 순서대로 팩터의 레벨을 제공하고 `ordered` 매개변수를 `TRUE`로 설정하여 순서형 데이터의 존재를 나타냅니다.

```
> symptoms <- factor(c("SEVERE", "MILD", "MODERATE"),
               levels = c("MILD", "MODERATE", "SEVERE"),
               ordered = TRUE)
```

결과적인 `symptoms` 팩터에는 이제 요청된 순서에 대한 정보가 포함됩니다. 이전의 팩터들과 달리 이 팩터의 레벨은 `MILD`부터 `SEVERE`까지의 순차적 순서의 존재를 나타내기 위해 `<` 기호로 구분됩니다.

```
> symptoms
```

```
[1] SEVERE   MILD     MODERATE
Levels: MILD < MODERATE < SEVERE
```

순서형 팩터의 유용한 특징은 예상대로 논리 검사가 작동한다는 것입니다. 예를 들어 각 환자의 증상이 중간 수준보다 더 심각한지 테스트할 수 있습니다.

```
> symptoms > "MODERATE"
```

```
[1]  TRUE FALSE FALSE
```

순서형 데이터를 모델링할 수 있는 머신러닝 알고리즘은 순서형 팩터를 기대할 것이므로 이에 따라 데이터를 코딩해야 합니다.

## 리스트

**리스트(List)**는 정렬된 요소 세트를 저장하는 데 사용된다는 점에서 벡터와 매우 유사한 데이터 구조입니다. 그러나 벡터는 모든 요소가 동일한 유형이어야 하는 반면 리스트는 서로 다른 R 데이터 유형을 수집할 수 있습니다. 이러한 유연성으로 인해 리스트는 종종 머신러닝 모델의 다양한 유형의 입력 및 출력 데이터와 구성 매개변수 세트를 저장하는 데 사용됩니다.

리스트를 설명하기 위해, 세 명의 환자에 대한 데이터가 6개의 벡터에 저장되어 있는 우리가 구축하고 있는 의료 환자 데이터셋을 생각해 보십시오. 첫 번째 환자의 모든 데이터를 표시하려면 5개의 R 명령을 입력해야 합니다.

```
> subject_name[1]
```

```
[1] "John Doe"
```

```
> temperature[1]
```

```
[1] 98.1
```

```
> flu_status[1]
```

```
[1] FALSE
```

```
> gender[1]
```

```
[1] MALE
Levels: FEMALE MALE
```

```
> blood[1]
```

```
[1] O
Levels: A B AB O
```

```
> symptoms[1]
```

```
[1] SEVERE
Levels: MILD < MODERATE < SEVERE
```

나중에 해당 환자의 데이터를 다시 검사할 것으로 예상된다면, 이 명령들을 다시 입력하는 대신 리스트를 사용하여 반복적으로 사용할 수 있는 하나의 객체로 모든 값을 그룹화할 수 있습니다.

`c()`를 사용하여 벡터를 만드는 것과 유사하게, 리스트는 다음 예제와 같이 `list()` 함수를 사용하여 생성됩니다. 한 가지 주목할 만한 차이점은 리스트가 구성될 때 시퀀스의 각 구성 요소에 이름을 지정해야 한다는 것입니다. 이름이 엄격하게 요구되는 것은 아니지만, 나중에 번호가 매겨진 위치와 복잡한 대괄호 대신 이름으로 값에 접근할 수 있게 해줍니다. 첫 번째 환자의 값을 위해 명명된 구성 요소가 포함된 리스트를 생성하려면 다음과 같이 입력합니다.

```
> subject1 <- list(fullname = subject_name[1],
                   temperature = temperature[1],
                   flu_status = flu_status[1],
                   gender = gender[1],
                   blood = blood[1],
                   symptoms = symptoms[1])
```

이제 이 환자의 데이터는 `subject1` 리스트에 수집됩니다.

```
> subject1
```

```
$fullname
[1] "John Doe"
$temperature
[1] 98.1
$flu_status
[1] FALSE
$gender
[1] MALE
Levels: FEMALE MALE
$blood
[1] O
Levels: A B AB O
$symptoms
[1] SEVERE
Levels: MILD < MODERATE < SEVERE
```

값에는 이전 명령에서 지정한 이름이 레이블(Labels)로 지정되어 있습니다. 리스트는 벡터처럼 순서를 유지하므로 여기의 `temperature` 값에 대해 표시된 것처럼 숫자 위치를 사용하여 구성 요소에 접근할 수 있습니다.

```
> subject1[2]
```

```
$temperature
[1] 98.1
```

리스트 객체에 벡터 스타일 연산자를 사용한 결과는 원본 리스트의 하위 집합인 또 다른 리스트 객체입니다. 예를 들어 앞의 코드는 단일 `temperature` 구성 요소가 있는 리스트를 반환했습니다. 대신 단일 리스트 항목을 **기본(Native)** 데이터 유형으로 반환하려면 리스트 구성 요소를 선택할 때 이중 대괄호(`[[` 및 `]]`)를 사용합니다. 예를 들어 다음 명령은 길이가 1인 숫자형 벡터를 반환합니다.

```
> subject1[[2]]
```

```
[1] 98.1
```

명확성을 위해 종종 리스트 이름에 `$`와 구성 요소 이름을 다음과 같이 추가하여 이름으로 리스트 구성 요소에 접근하는 것이 좋습니다.

```
> subject1$temperature
```

```
[1] 98.1
```

이중 대괄호 표기법과 마찬가지로 이것은 리스트 구성 요소를 기본 데이터 유형(이 경우 길이가 1인 숫자형 벡터)으로 반환합니다.

또한 이름으로 값에 접근하면 나중에 리스트 요소의 순서가 변경되더라도 올바른 항목이 검색되도록 보장합니다.

이름의 벡터를 지정하여 여러 리스트 항목을 얻는 것이 가능합니다. 다음은 `temperature` 및 `flu_status` 구성 요소만 포함하는 `subject1` 리스트의 하위 집합(Subset)을 반환합니다.

```
> subject1[c("temperature", "flu_status")]
```

```
$temperature
[1] 98.1
$flu_status
[1] FALSE
```

리스트와 리스트의 리스트를 사용하여 전체 데이터셋을 구성할 수 있습니다. 예를 들어 `subject2` 및 `subject3` 리스트를 생성하고 이들을 `pt_data`라는 리스트 객체로 그룹화하는 것을 고려할 수 있습니다. 그러나 이 방식으로 데이터셋을 구성하는 것은 충분히 일반적이므로 R은 이 작업을 위해 특별히 전문화된 데이터 구조를 제공합니다.

## 데이터 프레임

머신러닝에서 단연 가장 중요한 R 데이터 구조는 데이터 행과 열을 모두 가지고 있다는 점에서 스프레드시트나 데이터베이스와 유사한 구조인 **데이터 프레임(Data frame)**입니다. R 용어에서 데이터 프레임은 정확히 동일한 수의 값을 갖는 벡터 또는 팩터의 리스트로 이해할 수 있습니다. 데이터 프레임은 말 그대로 벡터 유형 객체의 리스트이기 때문에 벡터와 리스트의 측면을 모두 결합합니다.

환자 데이터셋에 대한 데이터 프레임을 만들어 보겠습니다. 이전에 만든 환자 데이터 벡터를 사용하여 `data.frame()` 함수는 이들을 데이터 프레임으로 결합합니다.

```
> pt_data <- data.frame(subject_name, temperature, 
                        flu_status, gender, blood, symptoms)
```

`pt_data` 데이터 프레임을 표시하면 그 구조가 우리가 이전에 다루었던 데이터 구조와 상당히 다르다는 것을 알 수 있습니다.

```
> pt_data
```

```
  subject_name temperature flu_status gender blood symptoms
1     John Doe        98.1      FALSE   MALE     O   SEVERE
2     Jane Doe        98.6      FALSE FEMALE    AB     MILD
3 Steve Graves       101.4       TRUE   MALE     A MODERATE
```

1차원 벡터, 팩터 및 리스트와 비교할 때 데이터 프레임은 2차원이며 표(Tabular) 형식으로 표시됩니다. 데이터 프레임에는 환자당 하나의 행과 환자 측정 벡터당 하나의 열이 있습니다. 머신러닝 측면에서 데이터 프레임의 행은 사례(Examples)이고 열은 특징(Features) 또는 속성(Attributes)입니다.

데이터의 전체 열(벡터)을 추출하기 위해 데이터 프레임이 단순히 벡터의 리스트라는 사실을 활용할 수 있습니다. 리스트와 마찬가지로 단일 요소를 추출하는 가장 직접적인 방법은 이름으로 요소를 참조하는 것입니다. 예를 들어 `subject_name` 벡터를 가져오려면 다음을 입력합니다.

```
> pt_data$subject_name
```

```
[1] "John Doe"     "Jane Doe"     "Steve Graves"
```

리스트와 마찬가지로 이름 벡터를 사용하여 데이터 프레임에서 여러 열을 추출할 수 있습니다.

```
> pt_data[c("temperature", "flu_status")]
```

```
  temperature flu_status
1        98.1      FALSE
2        98.6      FALSE
3       101.4       TRUE
```

이름으로 데이터 프레임 열을 요청하면 지정된 열에 대한 모든 데이터 행이 포함된 데이터 프레임이 결과로 반환됩니다. 명령 `pt_data[2:3]` 역시 `temperature` 및 `flu_status` 열을 추출합니다. 그러나 이름으로 열을 참조하면 명확하고 유지 관리하기 쉬운 R 코드가 생성되며 나중에 데이터 프레임의 순서가 변경되더라도 코드가 깨지지 않습니다.

데이터 프레임에서 특정 값을 추출하려면 벡터의 값에 접근하는 것과 유사한 방법이 사용됩니다. 그러나 중요한 차이점이 있습니다. 데이터 프레임은 2차원이기 때문에 원하는 행과 열을 모두 지정해야 합니다. 행을 먼저 지정하고 쉼표를 입력한 다음 열을 `[rows, columns]` 형식으로 지정합니다. 벡터와 마찬가지로 행과 열은 1부터 시작하여 계산됩니다.

예를 들어 환자 데이터 프레임의 첫 번째 행과 두 번째 열에 있는 값을 추출하려면 다음 명령을 사용합니다.

```
> pt_data[1, 2]
```

```
[1] 98.1
```

데이터의 단일 행 또는 열 이상을 원할 경우 원하는 행과 열을 나타내는 벡터를 지정하십시오. 다음 구문은 첫 번째와 세 번째 행, 두 번째와 네 번째 열에서 데이터를 가져옵니다.

```
> pt_data[c(1, 3), c(2, 4)]
```

```
  temperature gender
1        98.1   MALE
3       101.4   MALE
```

모든 행 또는 모든 열을 참조하려면 단순히 행 또는 열 부분을 비워 둡니다. 예를 들어 첫 번째 열의 모든 행을 추출하려면 다음과 같이 입력합니다.

```
> pt_data[, 1]
```

```
[1] "John Doe"     "Jane Doe"     "Steve Graves"
```

첫 번째 행에 대한 모든 열을 추출하려면 다음과 같이 입력합니다.

```
> pt_data[1, ]
```

```
  subject_name temperature flu_status gender blood symptoms
1     John Doe        98.1      FALSE   MALE     O   SEVERE
```

그리고 모든 것을 추출하려면 다음과 같이 입력합니다.

```
> pt_data[ , ]
```

```
  subject_name temperature flu_status gender blood symptoms
1     John Doe        98.1      FALSE   MALE     O   SEVERE
2     Jane Doe        98.6      FALSE FEMALE    AB     MILD
3 Steve Graves       101.4       TRUE   MALE     A MODERATE
```

물론 열은 위치보다 이름으로 접근하는 것이 더 좋으며 데이터의 행이나 열을 제외하기 위해 음수 기호를 사용할 수 있습니다. 따라서 이 명령의 출력은 다음과 같습니다.

```
> pt_data[c(1, 3), c("temperature", "gender")]
```

```
  temperature gender
1        98.1   MALE
3       101.4   MALE
```

이는 다음과 같습니다.

```
> pt_data[-2, c(-1, -3, -5, -6)]
```

```
  temperature gender
1        98.1   MALE
3       101.4   MALE
```

우리는 기존 열들의 함수로 데이터 프레임에 새로운 열을 만들어야 하는 경우가 종종 있습니다. 예를 들어, 환자 데이터 프레임에 있는 화씨온도 판독값을 섭씨 눈금으로 변환해야 할 수도 있습니다. 이를 위해 할당 연산자를 사용하여 다음과 같이 새로운 열 이름에 변환 계산 결과를 할당하기만 하면 됩니다.

```
> pt_data$temp_c <- (pt_data$temperature - 32) * (5 / 9)
```

계산이 잘 되었는지 확인하기 위해 섭씨를 기반으로 한 새로운 `temp_c` 열을 이전 화씨를 사용한 `temperature` 열과 비교해 보겠습니다.

```
> pt_data[c("temperature", "temp_c")]
```

```
  temperature   temp_c
1        98.1 36.72222
2        98.6 37.00000
3       101.4 38.55556
```

이 두 가지를 나란히 보면 계산이 올바르게 수행되었음을 확인할 수 있습니다.

이러한 유형의 작업은 다음 장에서 수행할 많은 작업에 매우 중요하므로 데이터 프레임에 매우 익숙해지는 것이 중요합니다. 환자 데이터셋을 사용하여 유사한 연산을 연습해 볼 수도 있고 더 나은 방법으로는 자신의 프로젝트 중 하나의 데이터를 사용할 수도 있습니다. 자체 데이터 파일을 R에 로드하는 함수는 이 장의 뒷부분에서 설명합니다.

## 행렬 및 배열

데이터 프레임 외에도 R은 데이터를 테이블 형식으로 저장하는 다른 구조를 제공합니다. **행렬(Matrix)**은 데이터 행과 열이 있는 2차원 테이블을 나타내는 데이터 구조입니다. 벡터와 마찬가지로 R 행렬은 주로 수학 연산에 사용되므로 전형적으로 숫자만 저장하지만 한 가지 유형의 데이터만 포함할 수 있습니다.

행렬을 생성하려면 데이터 벡터를 `matrix()` 함수에 제공하고 행 수(`nrow`) 또는 열 수(`ncol`)를 지정하는 매개변수를 함께 제공하기만 하면 됩니다. 예를 들어 숫자 1부터 4까지를 저장하는 2x2 행렬을 생성하려면 `nrow` 매개변수를 사용하여 데이터를 두 행으로 나누도록 요청할 수 있습니다.

```
> m <- matrix(c(1, 2, 3, 4), nrow = 2)
> m
```

```
     [,1] [,2]
[1,]    1    3
[2,]    2    4
```

이것은 `ncol = 2`를 사용하여 생성된 행렬과 같습니다.

```
> m <- matrix(c(1, 2, 3, 4), ncol = 2)

```
> m
```

```
     [,1] [,2]
[1,]    1    3
[2,]    2    4
```

R이 두 번째 열을 로드하기 전에 행렬의 첫 번째 열을 먼저 로드했다는 것을 알 수 있을 것입니다. 이를 **열 우선 순서(Column-major order)**라고 하며 행렬을 로드하는 R의 기본 방식입니다.

이 기본 설정을 무시하고 행(Row)별로 행렬을 로드하려면 행렬을 생성할 때 `byrow = TRUE` 매개변수를 설정하십시오.

이를 더 자세히 설명하기 위해 행렬에 더 많은 값을 추가하면 어떻게 되는지 살펴보겠습니다. 6개의 값이 있는 상태에서 두 개의 행을 요청하면 3개의 열이 있는 행렬이 생성됩니다.

```
> m <- matrix(c(1, 2, 3, 4, 5, 6), nrow = 2)
> m
```

```
     [,1] [,2] [,3]
[1,]    1    3    5
[2,]    2    4    6
```

두 개의 열을 요청하면 세 개의 행이 있는 행렬이 생성됩니다.

```
> m <- matrix(c(1, 2, 3, 4, 5, 6), ncol = 2)
> m
```

```
     [,1] [,2]
[1,]    1    4
[2,]    2    5
[3,]    3    6
```

데이터 프레임과 마찬가지로 행렬의 값은 `[row, column]` 표기법을 사용하여 추출할 수 있습니다. 예를 들어 `m[1, 1]`은 `1`이라는 값을 반환하는 반면 `m[3, 2]`는 `m` 행렬에서 `6`을 추출합니다. 또한 전체 행이나 열을 요청할 수 있습니다.

```
> m[1, ]
```

```
[1] 1 4
```

```
> m[, 1]
```

```
[1] 1 2 3
```

행렬 구조와 밀접하게 관련된 것은 데이터의 다차원 테이블인 **배열(Array)**입니다. 행렬이 값의 행과 열을 갖는 경우, 배열은 행, 열, 그리고 하나 이상의 추가적인 값의 층(Layers)을 갖습니다. 비록 이후 장에서 간혹 행렬을 사용하겠지만, 이 책의 범위 내에서 배열의 사용은 불필요합니다.

# R을 활용한 데이터 관리

거대한 데이터셋을 다룰 때 직면하는 문제 중 하나는 다양한 소스에서 데이터를 수집, 준비 및 관리하는 것을 포함합니다. 비록 이후 장들에서 실제 머신러닝 과제를 수행하며 데이터 준비, 데이터 정제(Data cleaning) 및 데이터 관리에 대해 깊이 다루겠지만 이 섹션에서는 R로 데이터를 가져오고 내보내는 기본적인 기능을 강조합니다.

## R 데이터 구조 저장, 로드 및 제거

원하는 형태로 데이터 프레임을 만들기 위해 많은 시간을 투자했다면, R 세션을 다시 시작할 때마다 작업을 다시 만들 필요가 없어야 합니다.

나중에 다시 로드하거나 다른 시스템으로 전송할 수 있는 파일에 데이터 구조를 저장하기 위해 `save()` 함수를 사용할 수 있는데 이는 `file` 매개변수에 의해 지정된 위치에 하나 이상의 R 데이터 구조를 씁니다. R 데이터 파일은 `.RData` 또는 `.rda` 확장자를 가집니다.

영구적인 파일에 저장하고 싶은 `x`, `y`, `z`라는 이름의 세 객체가 있다고 가정해 봅시다. 이들은 벡터, 팩터, 리스트, 데이터 프레임 또는 기타 다른 R 객체일 수 있습니다. 이들을 `mydata.RData`라는 이름의 파일에 저장하려면 다음 명령을 사용합니다.

```
> save(x, y, z, file = "mydata.RData")
```

`load()` 명령은 `.RData` 파일에 저장된 모든 데이터 구조를 다시 만들 수 있습니다. 앞선 코드에서 생성한 `mydata.RData` 파일을 로드하려면 다음과 같이 입력하기만 하면 됩니다.

```
> load("mydata.RData")
```

이렇게 하면 R 환경에 `x`, `y`, `z` 데이터 구조가 다시 생성됩니다.

무엇을 로드하고 있는지 주의하십시오! `load()` 명령으로 가져오고 있는 파일에 저장된 모든 데이터 구조는 작업 중인 다른 항목을 덮어쓰더라도 작업 영역(Workspace)에 추가됩니다.

대안적으로, 단일 R 객체를 파일에 저장하기 위해 `saveRDS()` 함수를 사용할 수 있습니다. `save()` 함수와 매우 유사하지만 중요한 차이점은 해당하는 `loadRDS()` 함수를 사용하면 원래 객체와 다른 이름으로 객체를 로드할 수 있다는 것입니다. 이러한 이유로 프로젝트 간에 R 객체를 전송할 때 `saveRDS()`를 사용하는 것이 더 안전할 수 있습니다. 이는 R 환경에서 기존 객체를 실수로 덮어쓸 위험을 줄여주기 때문입니다.

`saveRDS()` 함수는 특히 머신러닝 모델 객체를 저장하는 데 유용합니다. 일부 머신러닝 알고리즘은 모델을 훈련하는 데 오랜 시간이 걸리므로 모델을 `.rds` 파일로 저장하면 프로젝트를 재개할 때 긴 재훈련 과정을 피하는 데 도움이 될 수 있습니다. 예를 들어 `my_model`이라는 이름의 모델 객체를 `my_model.rds`라는 이름의 파일로 저장하려면 다음 구문을 사용합니다.

```
> saveRDS(my_model, file = "my_model.rds")
```

모델을 로드하려면 `readRDS()` 함수를 사용하고 결과에 다음과 같이 객체 이름을 할당합니다.

```
> my_model <- readRDS("my_model.rds")
```

R 세션에서 한동안 작업하고 나면 사용되지 않는 데이터 구조가 누적되었을 수 있습니다. RStudio에서 이러한 객체는 인터페이스의 **Environment(환경)** 탭에 표시되지만 `ls()` 나열 함수를 사용하여 프로그래밍 방식으로 이러한 객체에 접근할 수도 있습니다. 이 함수는 현재 메모리에 있는 모든 데이터 구조의 벡터를 반환합니다.

예를 들어 이 장의 코드를 따라 하고 있다면 `ls()` 함수는 다음을 반환합니다.

```
> ls()
```

```
 [1] "blood"        "fever"        "flu_status"   "gender"      
 [5] "m"            "pt_data"      "subject_name" "subject1"    
 [9] "symptoms"     "temperature"
```

R은 세션을 종료할 때 메모리에서 모든 데이터 구조를 자동으로 지우지만 객체가 큰 경우 더 일찍 메모리를 해제하고 싶을 수 있습니다. `rm()` 제거 함수를 이 목적으로 사용할 수 있습니다. 예를 들어 `m`과 `subject1` 객체를 제거하려면 다음과 같이 입력하기만 하면 됩니다.

```
> rm(m, subject1)
```

`rm()` 함수에 제거할 객체 이름의 문자형 벡터를 제공할 수도 있습니다. 이것은 `ls()` 함수와 함께 작동하여 전체 R 세션을 지웁니다.

```
> rm(list = ls())
```

이전 코드를 실행할 때는 객체가 제거되기 전에 알림이 표시되지 않으므로 매우 주의하십시오!

R 세션을 서둘러 마무리해야 하는 경우 `save.image()` 명령은 단순히 `.RData`라는 이름의 파일에 전체 세션을 씁니다. 기본적으로 R 또는 RStudio를 종료할 때 이 파일을 생성할지 묻는 메시지가 표시됩니다. 다음에 R을 시작할 때 R은 이 파일을 찾고 만약 존재한다면 세션은 남겨두었던 것과 똑같이 다시 생성될 것입니다.

## CSV 파일에서 데이터셋 가져오기 및 저장

공개 데이터셋은 텍스트 파일로 저장되는 것이 일반적입니다. 텍스트 파일은 사실상 모든 컴퓨터나 운영 체제에서 읽을 수 있어 형식이 거의 보편적입니다. 또한 Microsoft Excel과 같은 프로그램에서 가져오거나 내보낼 수 있어 스프레드시트 데이터로 빠르고 쉽게 작업할 수 있는 방법을 제공합니다.

**표 형식(Tabular)** 데이터 파일은 텍스트의 각 줄이 하나의 사례(Example)를 반영하고 각 사례가 동일한 수의 특징을 갖도록 행렬 형태로 구성됩니다. 각 줄의 특징 값은 **구분 기호(Delimiter)**로 알려진 사전 정의된 기호로 분리됩니다. 종종 표 형식 데이터 파일의 첫 번째 줄에는 데이터 열의 이름이 나열됩니다. 이를 **헤더(Header)** 줄이라고 합니다.

가장 흔한 표 형식 텍스트 파일 형식은 **쉼표로 구분된 값(CSV, Comma-separated values)** 파일일 것입니다. 이름에서 알 수 있듯이 쉼표를 구분 기호로 사용합니다. CSV 파일은 많은 일반적인 애플리케이션으로 가져오거나 내보낼 수 있습니다. 이전에 구성한 의료 데이터셋을 나타내는 CSV 파일은 다음과 같이 저장될 수 있습니다.

```
subject_name,temperature,flu_status,gender,blood_type
John Doe,98.1,FALSE,MALE,O
Jane Doe,98.6,FALSE,FEMALE,AB
Steve Graves,101.4,TRUE,MALE,A
```

R 작업 디렉터리에 위치한 `pt_data.csv`라는 이름의 환자 데이터 파일이 주어지면, 파일을 R로 로드하기 위해 `read.csv()` 함수를 다음과 같이 사용할 수 있습니다.

```
> pt_data <- read.csv("pt_data.csv")
```

그러면 CSV 파일을 읽어 `pt_data`라는 제목의 데이터 프레임에 넣습니다. 데이터셋이 R 작업 디렉터리 외부에 상주하는 경우 `read.csv()` 함수를 호출할 때 CSV 파일에 대한 전체 경로(예: `"/path/to/mydata.csv"`)를 사용할 수 있습니다.

기본적으로 R은 CSV 파일에 데이터셋 내 특징의 이름이 나열된 헤더 줄이 포함되어 있다고 가정합니다. 만약 CSV 파일에 헤더가 없다면, 다음 명령과 같이 `header = FALSE` 옵션을 지정하십시오. 그러면 R은 열 번호를 순차적으로 `V1`, `V2` 등으로 매겨 일반적인 특징 이름을 할당할 것입니다.

```
> pt_data <- read.csv("pt_data.csv", header = FALSE)
```

중요한 역사적 참고 사항으로 4.0 이전 버전의 R에서 `read.csv()` 함수는 기본적으로 `TRUE`로 설정된 `stringsAsFactors` 매개변수로 인해 모든 문자 유형 열을 팩터로 자동 변환했습니다. 이 기능은 특히 초기 R 시절에 사용된 더 작고 덜 복잡한 데이터셋에 유용했습니다. 그러나 데이터셋이 더 커지고 더 복잡해지면서 이 기능은 해결하는 것보다 더 많은 문제를 일으키기 시작했습니다. 이제 버전 4.0부터 R은 기본적으로 `stringsAsFactors = FALSE`로 설정합니다. CSV 파일의 모든 문자 열이 진정으로 팩터라고 확신하는 경우 다음 구문을 사용하여 변환할 수 있습니다.

```
> pt_data <- read.csv("pt_data.csv", stringsAsFactors = TRUE)
```

이 책 전체에서 모든 문자 열이 진정으로 팩터인 데이터셋을 다룰 때 간간이 `stringsAsFactors = TRUE`로 설정할 것입니다.

결과 데이터를 R에서 내보내는 것은 가져오는 것만큼이나 중요할 수 있습니다! 데이터 프레임을 CSV 파일로 저장하려면 `write.csv()` 함수를 사용합니다. `pt_data`라는 이름의 데이터 프레임에 대해 단순히 다음을 입력합니다.

```
> write.csv(pt_data, file = "pt_data.csv", row.names = FALSE)
```

이렇게 하면 이름이 `pt_data.csv`인 CSV 파일이 R 작업 폴더에 작성됩니다. `row.names` 매개변수는 CSV 파일에 행 이름을 출력하는 R의 기본 설정을 재정의합니다. 일반적으로 이 출력은 불필요하며 결과 파일의 크기만 부풀립니다.

파일 읽기에 대한 더 정교한 제어를 원한다면 `read.csv()`가 표 형식의 데이터를 다양한 형식으로 읽을 수 있는 `read.table()` 함수의 특별한 사례라는 점에 유의하십시오. 여기에는 **탭으로 구분된 값(TSV, Tab-separated values)**과 수직선(`|`)으로 구분된 파일과 같은 다른 구분 기호 형식이 포함됩니다. `read.table()` 함수 계열에 대한 자세한 내용은 `?read.table` 명령을 사용하여 R 도움말 페이지를 참조하십시오.

## 데이터 구조 탐색하기

새로운 데이터셋 조사에서 가장 먼저 해야 할 질문은 데이터셋이 어떻게 구성되어 있는지에 대한 것이어야 합니다. 운이 좋다면 데이터 출처에서 데이터셋의 특징을 설명하는 문서인 **데이터 사전(Data dictionary)**을 제공할 것입니다. 우리 사례의 경우 중고차 데이터에는 이 문서가 제공되지 않으므로 우리만의 사전을 만들어야 합니다.

`str()` 함수는 데이터 프레임, 벡터 또는 리스트와 같은 R 객체의 구조를 표시하는 메서드를 제공합니다. 이 함수를 사용하여 데이터 사전의 기본 윤곽을 만들 수 있습니다.

```
> str(usedcars)
```

```
'data.frame':    150 obs. of  6 variables:
 $ year        : int  2011 2011 2011 2011 ...
 $ model       : chr  "SEL" "SEL" "SEL" "SEL" ...
 $ price       : int  21992 20995 19995 17809 ...
 $ mileage     : int  7413 10926 7351 11613 ...
 $ color       : chr  "Yellow" "Gray" "Silver" "Gray" ...
 $ transmission: chr  "AUTO" "AUTO" "AUTO" "AUTO" ...
```

이렇게 간단한 명령 하나로 우리는 데이터셋에 대한 풍부한 정보를 알게 됩니다. `150 obs`라는 문장은 데이터에 150개의 **관측치(Observations)**가 포함되어 있음을 알려주며, 이는 데이터셋에 150개의 행 또는 사례가 포함되어 있다는 것을 말하는 또 다른 방법일 뿐입니다. 관측치의 수는 종종 단순하게 *n*으로 축약됩니다.

이 데이터가 중고차를 설명한다는 것을 알고 있기 때문에 이제 판매용 자동차 사례가 n = 150대라고 가정할 수 있습니다.

`6 variables` 문장은 데이터에 기록된 6개의 특징(Features)을 의미합니다. **변수(Variable)**라는 용어는 통계학 분야에서 빌려온 것으로, 대수 방정식에서 여러분이 풀고자 하는 *x*와 *y* 변수처럼 다양한 값을 가질 수 있는 수학적 대상을 의미할 뿐입니다. 이러한 특징이나 변수들은 분리된 행(Lines)에 이름별로 나열됩니다. `color`라는 특징의 줄을 살펴보면 몇 가지 추가 세부 사항을 확인할 수 있습니다.

```

 $ color       : chr  "Yellow" "Gray" "Silver" "Gray" ...
```

변수 이름 뒤에 나오는 `chr` 라벨은 특징(Feature)이 문자(Character) 유형임을 알려줍니다. 이 데이터셋에서 세 개의 변수는 문자형인 반면, 세 개의 변수는 정수(Integer) 유형을 나타내는 `int`로 표시됩니다. 비록 `usedcars` 데이터셋에는 문자와 정수 특징만 포함되어 있지만 비정수형 데이터를 사용할 때는 `num` 또는 숫자(Numeric) 유형도 마주치게 될 것입니다. 팩터는 `factor` 유형으로 나열됩니다. 각 변수의 유형 다음에는 R이 처음 몇 개의 특징 값을 순서대로 제시합니다. `"Yellow" "Gray" "Silver" "Gray"` 값은 `color` 특징의 처음 4개 값입니다.

특징 이름과 값에 대해 분야에 대한 약간의 지식을 적용하면 특징이 무엇을 나타내는지에 대한 몇 가지 가정을 할 수 있습니다. `year`는 차량이 제조된 연도를 나타내거나 광고가 게시된 연도를 명시할 수 있습니다. 4개의 예시 값(`2011 2011 2011 2011`)이 두 가능성 중 하나를 주장하는 데 사용될 수 있기 때문에 이 특징은 나중에 자세히 조사해야 합니다. `model`, `price`, `mileage`, `color` 및 `transmission`은 가장 큰 가능성으로 판매용 자동차의 특성을 나타냅니다.

비록 우리 데이터에 의미 있는 이름이 부여된 것처럼 보이지만 항상 그런 것은 아닙니다. 때로는 데이터셋의 특징에 `V1`처럼 말도 안 되는 이름이나 코드가 있을 수 있습니다. 이러한 경우 특징이 무엇을 나타내는지 알아내기 위해 추가적인 조사가 필요할 수 있습니다. 의미 있는 특징 이름이 있더라도 제공된 라벨에 대해서는 항상 회의적인 태도를 취하는 것이 현명합니다. 더 자세히 살펴보겠습니다.

## 숫자형 특징 탐색하기

중고차 데이터에서 숫자형 특징을 조사하기 위해 **요약 통계(Summary statistics)**라고 알려진 값을 설명하는 일반적인 측정 세트를 사용할 것입니다. `summary()` 함수는 몇 가지 일반적인 요약 통계를 표시합니다. 단일 특징인 `year`를 살펴보겠습니다.

```
> summary(usedcars$year)
```

```
   Min. 1st Qu.  Median    Mean  3rd Qu.   Max.
   2000    2008    2009    2009    2010    2012
```

지금은 값의 의미를 무시하고 `2000`, `2008` 및 `2009`와 같은 숫자가 표시된다는 사실은 `year`가 광고가 게시된 연도라기보다 제조 연도를 나타낸다고 믿게 합니다. 차량 목록이 2012년에 수집되었다는 것을 알고 있기 때문입니다.

열 이름의 벡터를 제공함으로써 `summary()` 함수를 사용하여 여러 숫자 열에 대한 요약 통계를 동시에 얻을 수도 있습니다.

```
> summary(usedcars[c("price", "mileage")])
```

```
     price          mileage      
 Min.   : 3800   Min.   :  4867  
 1st Qu.:10995   1st Qu.: 27200  
 Median :13592   Median : 36385  
 Mean   :12962   Mean   : 44261  
 3rd Qu.:14904   3rd Qu.: 55124  
 Max.   :21992   Max.   :151479  
```

`summary()` 함수가 제공하는 6가지 요약 통계는 데이터를 조사하는 데 간단하면서도 강력한 도구입니다. 이들은 중심 위치 척도(Measures of center)와 산포 척도(Measures of spread)라는 두 가지 유형으로 나눌 수 있습니다.

### 중심 경향 측정 – 평균과 중앙값

**중심 경향성(Central tendency)** 척도는 데이터 집합의 중간에 해당하는 값을 식별하는 데 사용되는 통계의 한 부류입니다. 여러분은 중심 척도 중 가장 흔한 것인 평균에 대해 이미 친숙할 가능성이 높습니다. 일반적인 용례에서 무언가가 평균으로 간주될 때는 양극단의 어딘가에 속합니다. 평범한 학생은 학급 친구들 중간 어디쯤의 점수를 받을 수 있습니다. 평균 체중은 비정상적으로 가볍지도 무겁지도 않습니다. 일반적으로 평균 항목은 그룹 내 다른 항목들과 크게 다르지 않고 전형적입니다. 다른 모든 것들을 판단하는 기준이 되는 전형으로 생각할 수 있습니다.

통계학에서 평균은 **산술 평균(Mean)**으로도 알려져 있으며 모든 값의 합을 값의 개수로 나눈 척도로 정의됩니다. 예를 들어 소득이 \$36,000, \$44,000, \$56,000인 3명의 그룹에서 평균 소득을 계산하려면 다음과 같이 입력할 수 있습니다.

```
> (36000 + 44000 + 56000) / 3
```

```
[1] 45333.33
```

R은 숫자 벡터에 대한 평균을 계산하는 `mean()` 함수도 제공합니다.

```
> mean(c(36000, 44000, 56000))
```

```
[1] 45333.33
```

이 사람들의 평균 소득은 약 \$45,333입니다. 개념적으로 이것은 총 소득이 모든 사람에게 균등하게 분배될 경우 각 사람이 가질 소득으로 상상할 수 있습니다.

앞선 `summary()` 출력이 `price`와 `mileage`에 대한 평균값을 나열했음을 떠올려 보십시오. 이러한 값은 이 데이터셋의 전형적인 중고차가 \$12,962의 가격으로 나열되었으며 44,261의 주행 거리를 가졌음을 시사합니다. 이것은 데이터에 대해 무엇을 말해줄까요? 평균 가격이 비교적 낮기 때문에 데이터셋에 이코노미 클래스 차량이 포함될 것으로 예상할 수 있습니다. 물론 주행 거리가 높은 최신 고급차가 데이터에 포함될 수도 있지만, 상대적으로 낮은 주행 거리 평균 통계는 이 가설을 뒷받침할 만한 증거를 제공하지 않습니다. 반면에 그 가능성을 무시할 증거를 제공하지도 않습니다. 데이터를 자세히 조사할 때 이 점을 명심해야 합니다.

비록 평균은 데이터셋의 중심을 측정할 때 가장 많이 인용되는 통계이기는 하지만 항상 가장 적절한 통계는 아닙니다. 일반적으로 사용되는 또 다른 중심 경향성 척도는 정렬된 값 목록의 중간에 나타나는 값인 **중앙값(Median)**입니다. 평균과 마찬가지로 R은 `median()` 함수를 제공하며 다음 예제와 같이 소득 데이터에 적용할 수 있습니다.

```
> median(c(36000, 44000, 56000))
```

```
[1] 44000
```

따라서 중간 값이 `44000`이므로 중앙값 소득은 \$44,000입니다.

만약 데이터셋에 짝수 개의 값이 있다면 중간 값이 없습니다. 이 경우 중앙값은 대개 정렬된 리스트 중앙에 있는 두 값의 평균으로 계산됩니다. 예를 들어 값 1, 2, 3, 4의 중앙값은 2.5입니다.

언뜻 보기에 중앙값과 평균은 매우 유사한 척도인 것 같습니다. 확실히 평균값인 \$45,333과 중앙값인 \$44,000은 서로 크게 다르지 않습니다. 왜 두 가지 중심 경향 척도가 있을까요? 그 이유는 범위의 양쪽 끝에 있는 값이 평균과 중앙값에 다르게 영향을 미친다는 사실과 관련이 있습니다. 특히 평균은 **이상치(Outliers)**, 즉 대다수의 데이터에 비해 비정상적으로 높거나 낮은 값에 매우 민감합니다. 이상치에 대한 좀 더 세심한 견해는 *11장, 머신러닝으로 성공하기*에서 제시될 것이지만, 일단 여기서는 그것들을 극단적인 값으로 간주할 수 있습니다. 중앙값은 이상치에 크게 민감하지 않으므로, 이 극단적인 값들은 중앙값 대비 평균을 높거나 낮게 이동시키는 경향이 있습니다.

중고차 데이터셋에 대한 `summary()` 출력에서 보고된 중앙값을 다시 떠올려 보십시오. 비록 가격에 대한 평균과 중앙값은 비슷하지만(약 5% 차이) 주행 거리에 대한 평균과 중앙값 사이에는 훨씬 더 큰 차이가 있습니다. 주행 거리의 경우 평균인 44,261은 중앙값인 36,385보다 20% 이상 더 큽니다. 평균은 중앙값보다 극단적인 값에 더 민감하기 때문에 평균이 중앙값보다 훨씬 높다는 사실은 데이터셋의 다른 자동차들에 비해 주행 거리 값이 극단적으로 높은 중고차가 일부 있을 수 있다고 의심하게 만들 수 있습니다. 이것을 더 조사하려면 분석에 요약 통계를 추가해야 합니다.

### 산포 측정 – 사분위수 및 5개 수치 요약

평균과 중앙값은 값을 빠르게 요약하는 방법을 제공하지만 이러한 중심 척도는 측정값에 다양성이 있는지 여부에 대해서는 거의 알려주지 않습니다. 다양성을 측정하기 위해 데이터의 **산포(Spread)** 즉, 값들이 얼마나 촘촘하게 혹은 느슨하게 간격을 두고 있는지와 관련된 또 다른 유형의 요약 통계를 사용해야 합니다. 산포에 대해 알면 데이터의 고저(Highs and lows)에 대한 감을 얻을 수 있으며 대부분의 값이 평균 및 중앙값과 비슷한지 아니면 다른지를 파악할 수 있습니다.

**5개 수치 요약(Five-number summary)**은 특징 값들의 산포를 대략적으로 보여주는 5가지 통계의 집합입니다. 5개 통계가 모두 `summary()` 함수의 출력에 포함되어 있습니다. 순서대로 작성하면 다음과 같습니다.

1. 최솟값 (`Min.`)
2. 제1사분위수 또는 Q1 (`1st Qu.`)
3. 중앙값 또는 Q2 (`Median`)
4. 제3사분위수 또는 Q3 (`3rd Qu.`)
5. 최댓값 (`Max.`)

짐작하셨겠지만 최솟값과 최댓값은 가장 극단적인 특징값으로 각각 가장 작은 값과 가장 큰 값을 나타냅니다. R은 벡터에 대해 이를 계산하는 `min()` 및 `max()` 함수를 제공합니다.

최솟값과 최댓값 사이의 간격을 범위(Range)라고 합니다. R에서 `range()` 함수는 최솟값과 최댓값을 모두 반환합니다.

```
> range(usedcars$price)
```

```
[1]  3800 21992
```

`range()`를 차이(Difference) 함수 `diff()`와 결합하면 한 줄의 코드로 범위 통계를 계산할 수 있습니다.

```
> diff(range(usedcars$price))
```

```
[1] 18192
```

데이터셋 값의 4분의 1은 제1사분위수(Q1) 아래에 속하고 다른 4분의 1은 제3사분위수(Q3) 위에 속합니다. 데이터 값의 중간점인 중앙값과 함께 사분위수는 데이터셋을 4개의 부분으로 나누며 각각에는 값의 25%가 포함됩니다.

사분위수는 데이터를 동일한 크기의 수량으로 나누는 숫자인 **분위수(Quantiles)**라는 통계 유형의 특별한 사례입니다. 사분위수 외에 흔히 사용되는 분위수에는 **3분위수(Tertiles)**(3등분), **5분위수(Quintiles)**(5등분), **10분위수(Deciles)**(10등분), **백분위수(Percentiles)**(100등분)가 포함됩니다. 백분위수는 값의 순위를 설명하는 데 자주 사용됩니다. 예를 들어 시험 점수가 99번째 백분위수에 속한 학생은 다른 시험 응시자의 99퍼센트보다 뛰어나거나 같은 성적을 낸 것입니다.

제1사분위수와 제3사분위수 사이에서 발견되는 중간 50퍼센트의 데이터는 산포의 간단한 척도이기 때문에 특별히 관심이 쏠립니다. Q1과 Q3 사이의 차이를 **사분위범위(IQR, Interquartile range)**라고 하며 `IQR()` 함수를 사용하여 계산할 수 있습니다.

```
> IQR(usedcars$price)
```

```
[1] 3909.5
```

이 값은 `14904 - 10995 = 3909`를 계산하여 `usedcars$price` 벡터에 대한 `summary()` 출력에서 수동으로 계산할 수도 있었습니다. 우리가 계산한 값과 `IQR()` 출력 사이의 작은 차이는 R이 자동으로 `summary()` 출력을 반올림한다는 사실에 기인합니다.

`quantile()` 함수는 값 집합에 대한 분위수를 식별하는 다용도 도구를 제공합니다. 기본적으로 `quantile()`은 5개 수치 요약을 반환합니다. `usedcars$price` 벡터에 함수를 적용하면 이전과 같은 요약 통계가 생성됩니다.

```
> quantile(usedcars$price)
```

```
     0%     25%     50%     75%    100%
 3800.0 10995.0 13591.5 14904.5 21992.0
```

분위수를 계산할 때 중간값이 딱 떨어지지 않는 경우 동률(Ties)인 값들의 집합을 처리하는 방법에는 여러 가지가 있습니다. `quantile()` 함수는 `type` 매개변수를 지정하여 9가지 서로 다른 동률 처리 알고리즘 중에서 선택할 수 있게 해줍니다. 프로젝트에서 분위수를 정밀하게 정의해야 한다면 `?quantile` 명령을 사용하여 함수 문서를 읽는 것이 중요합니다.

절단점을 나타내는 벡터에 대한 추가적인 `probs` 매개변수를 제공하여 1번째 및 99번째 백분위수와 같은 임의의 분위수를 얻을 수 있습니다.

```
> quantile(usedcars$price, probs = c(0.01, 0.99))
```

```
      1%      99%
 5428.69 20505.00
```

시퀀스 함수 `seq()`는 균일한 간격의 값으로 구성된 벡터를 생성합니다. 이를 통해 다음 명령에 표시된 5분위수(5개 그룹)와 같은 데이터의 다른 조각을 쉽게 얻을 수 있습니다.

```
> quantile(usedcars$price, seq(from = 0, to = 1, by = 0.20))
```

```
     0%     20%     40%     60%     80%    100%
 3800.0 10759.4 12993.8 13992.0 14999.0 21992.0
```

5개 수치 요약에 대한 이해를 바탕으로 중고차 `summary()` 출력을 다시 조사할 수 있습니다. `price`의 경우 최솟값은 \$3,800이고 최댓값은 \$21,992였습니다. 흥미롭게도 최솟값과 Q1 사이의 차이는 약 \$7,000이고 Q3와 최댓값 사이의 차이도 마찬가지입니다. 그러나 Q1에서 중앙값, 그리고 Q3까지의 차이는 대략 \$2,000입니다. 이는 하위 및 상위 25퍼센트의 값이 중심 주위에 더 조밀하게 모여 있는 것처럼 보이는 중간 50퍼센트의 값보다 더 널리 분산되어 있음을 시사합니다. 우리는 또한 `mileage`에서 유사한 경향을 봅니다. 이 장의 후반부에서 배우게 되겠지만, 이러한 산포 패턴은 매우 흔해서 데이터의 "정규(Normal)" 분포라고 불려 왔습니다.

`mileage`의 산포 또한 흥미로운 속성을 보여줍니다. 즉 Q3와 최댓값 사이의 차이가 최솟값과 Q1 사이의 차이보다 훨씬 큽니다. 다시 말해 더 큰 값이 작은 값보다 훨씬 더 분산되어 있습니다. 이러한 발견은 왜 평균값이 중앙값보다 훨씬 더 큰지 설명하는 데 도움이 됩니다. 평균은 극단적인 값에 민감하기 때문에 더 높게 당겨지는 반면 중앙값은 비교적 동일한 장소에 머무릅니다. 이는 중요한 속성이며, 데이터가 시각적으로 표시될 때 더 명백해집니다.

### 숫자형 특징 시각화하기 – 상자 수염 그림(Boxplots)

숫자형 특징을 시각화하는 것은 머신러닝 모델의 성능에 부정적인 영향을 미칠 수 있는 데이터 문제를 진단하는 데 도움이 될 수 있습니다. 5개 수치 요약을 시각화하는 일반적인 방법은 **상자 수염 그림(Boxplot)**으로, 이는 **Box-and-whisker plot**이라고도 합니다. 상자 수염 그림은 숫자형 변수의 중심과 산포를 표시하여 그 범위와 왜곡(Skew)에 대한 감을 빠르게 얻거나 다른 특징들과 비교할 수 있게 해주는 형식입니다.

중고차 가격과 주행 거리 데이터의 상자 수염 그림을 살펴보겠습니다. 숫자 벡터에 대한 상자 수염 그림을 얻기 위해 `boxplot()` 함수를 사용할 것입니다. 그림에 제목을 추가하고 수직축인 *y*축에 레이블을 지정하기 위해 `main`과 `ylab`이라는 한 쌍의 추가 매개변수도 각각 지정할 것입니다. `price`와 `mileage`에 대한 상자 수염 그림을 만드는 명령은 다음과 같습니다.

그림 2.4: 중고차 가격 및 주행 거리 데이터의 상자 수염 그림

상자 수염 그림은 가로선과 점을 사용하여 5개 수치 요약을 나타냅니다. 각 그림 중앙의 상자를 형성하는 가로선은 그림을 아래에서 위로 읽을 때 Q1, Q2(중앙값) 및 Q3를 나타냅니다. 중앙값은 `price`의 수직축에서는 \$13,592, `mileage`의 수직축에서는 36,385 마일과 일치하는 굵은 선으로 표시됩니다.

이전 다이어그램과 같이 간단한 상자 수염 그림에서 상자 너비는 임의적이며 데이터의 어떤 특성도 보여주지 않습니다. 더 정교한 분석의 경우 상자의 모양과 크기를 사용하여 여러 그룹 간의 데이터 비교를 용이하게 할 수 있습니다. 이러한 기능에 대해 자세히 알아보려면 `?boxplot` 명령을 입력하여 R `boxplot()` 문서에서 `notch` 및 `varwidth` 옵션을 살펴보는 것으로 시작하십시오.

최솟값과 최댓값은 상자 아래와 위로 뻗어 나가는 수염을 사용하여 그림으로 보여줄 수 있습니다. 그러나 널리 사용되는 관례에서는 수염이 Q1 아래로 사분위범위(IQR)의 최대 1.5배까지, Q3 위로도 IQR의 1.5배까지만 늘어날 수 있도록 허용합니다. 이 임계값을 넘어서는 값은 이상치로 간주되며 원이나 점으로 표시됩니다. 예를 들어 `price`에 대한 IQR은 3,909였고 Q1은 10,995, Q3는 14,904였습니다. 따라서 이상치는 10995 - 1.5 \* 3909 = 5131.5보다 작거나 14904 + 1.5 \* 3909 = 20767.5보다 큰 값입니다.

`price`에 대한 상자 수염 그림은 상한과 하한 양쪽 끝 모두에 두 개의 이상치를 보여줍니다. `mileage`에 대한 상자 수염 그림에서는 하한 측에 이상치가 없으므로 하단 수염이 최솟값인 4,867까지 확장됩니다. 상한 측에서는 100,000마일 기준을 넘는 이상치가 몇 개 보입니다. 이러한 이상치들은 평균값이 중앙값보다 훨씬 크다는 앞선 발견의 원인입니다.

그림 2.5: 중고차 가격 및 주행 거리 데이터의 히스토그램

히스토그램은 일련의 막대들로 구성되며, 막대의 높이는 값들을 분할하는 동일한 너비의 각 빈(Bin) 내에 떨어지는 값의 개수, 즉 **빈도(Frequency)**를 나타냅니다. 막대를 분리하는 수직선은 가로축에 레이블이 지정된 대로 빈 내에 속하는 값 범위의 시작과 끝을 나타냅니다.

이전 히스토그램들의 빈 수가 다르다는 것을 눈치채셨을 것입니다. 이는 `hist()` 함수가 해당 특징의 범위에 최적인 빈 수를 알아내려 하기 때문입니다. 이 기본 설정을 재정의하려면 `breaks` 매개변수를 사용하십시오. `breaks = 10`과 같이 정수를 제공하면 정확히 동일한 너비를 가진 10개의 빈을 생성하고 `c(5000, 10000, 15000, 20000)`과 같은 벡터를 제공하면 지정된 값에서 구분되는 빈을 만듭니다.

`price` 히스토그램에서 10개의 막대 각각은 \$2,000부터 시작하여 \$22,000에서 끝나는 \$2,000의 간격에 걸쳐 있습니다. 그림 중앙에 있는 가장 높은 막대는 \$12,000에서 \$14,000까지의 범위를 다루며 빈도는 50입니다. 우리는 데이터에 150대의 자동차가 포함되어 있다는 것을 알기 때문에 모든 자동차의 3분의 1이 \$12,000에서 \$14,000 사이의 가격이 책정되어 있다는 것을 알 수 있습니다. 절반이 넘는 약 90대의 자동차가 \$12,000에서 \$16,000 사이입니다.

`mileage` 히스토그램에는 0부터 160,000마일까지 각각 20,000마일의 빈을 나타내는 8개의 막대가 포함되어 있습니다. `price` 히스토그램과 달리 가장 높은 막대는 데이터의 중앙이 아니라 다이어그램의 왼쪽에 있습니다. 이 빈에 포함된 70대의 자동차는 주행 기록계(Odometer) 수치가 20,000~40,000마일입니다.

## 범주형 특징 탐색하기

기억하시겠지만 중고차 데이터셋에는 `model`, `color`, `transmission`이라는 세 가지 범주형 특징이 포함되어 있습니다. 게다가 `year`는 숫자형 벡터로 저장되어 있지만, 각각의 연도는 여러 자동차에 적용되는 범주로 상상할 수 있습니다. 따라서 이것을 범주형으로 취급하는 것도 고려할 수 있습니다.

숫자형 데이터와 대조적으로 범주형 데이터는 일반적으로 요약 통계가 아닌 테이블을 사용하여 검사합니다. 단일 범주형 특징을 나타내는 표를 **일원표(One-way table)**라고 합니다. `table()` 함수를 사용하여 중고차 데이터에 대한 일원표를 생성할 수 있습니다.

```
> table(usedcars$year)
```

```
2000 2001 2002 2003 2004 2005 2006 2007 2008 2009 2010 2011 2012
   3    1    1    1    3    2    6   11   14   42   49   16    1
```

```
> table(usedcars$model)
```

```
 SE SEL SES
78  23  49
```

```
> table(usedcars$color)
```

```
 Black   Blue   Gold   Gray  Green    Red Silver  White Yellow
    35     17      1     16      5     25     32     16      3
```

`table()` 출력은 명목형 변수의 범주와 각 범주에 해당하는 값들의 개수(Count)를 나열합니다. 데이터셋에 중고차가 150대 있다는 것을 알고 있으므로 49/150 = 0.327이라는 것을 고려할 때 전체 자동차의 대략 3분의 1이 2010년에 제조되었음을 판별할 수 있습니다.

R은 또한 `table()` 함수에 의해 생성된 테이블에 `prop.table()` 명령을 사용하여 테이블 비율 계산을 직접 수행할 수도 있습니다.

```
> model_table <- table(usedcars$model)
> prop.table(model_table)
```

```
       SE       SEL       SES
0.5200000 0.1533333 0.3266667
```

`prop.table()`의 결과는 출력을 변환하기 위해 다른 R 함수와 결합할 수 있습니다. 결과를 소수점 첫째 자리의 백분율로 표시하고 싶다고 가정해 보겠습니다. 다음 예제에서 볼 수 있듯이 비율에 100을 곱한 다음 `digits = 1`을 지정하면서 `round()` 함수를 사용하여 이를 수행할 수 있습니다.

```
> color_table <- table(usedcars$color)
> color_pct <- prop.table(color_table) * 100
> round(color_pct, digits = 1)
```

```
Black   Blue   Gold   Gray  Green    Red Silver  White Yellow
 23.3   11.3    0.7   10.7    3.3   16.7   21.3   10.7    2.0
```

비록 이것은 기본 `prop.table()` 출력과 동일한 정보를 포함하지만 변경 사항 덕분에 읽기가 더 쉽습니다. 결과는 검은색이 전체 광고 차량의 거의 4분의 1(23.3퍼센트)로 가장 흔한 색상임을 보여줍니다. 은색이 21.3퍼센트로 간발의 차이로 2위이고 빨간색이 16.7퍼센트로 3위입니다.

### 중심 경향성 측정 – 최빈값

통계 용어에서 특징의 **최빈값(Mode)**은 가장 자주 발생하는 값입니다. 평균 및 중앙값과 마찬가지로 최빈값은 중심 경향성의 또 다른 척도입니다. 일반적으로 범주형 데이터에 사용되는데 이는 명목형 변수에 대해서는 평균과 중앙값이 정의되지 않기 때문입니다.

예를 들어 중고차 데이터에서 `year`의 최빈값은 2010인 반면 `model`과 `color` 변수의 최빈값은 각각 `SE`와 `Black`입니다. 하나의 변수는 두 개 이상의 최빈값을 가질 수 있습니다. 최빈값이 하나인 변수는 **단봉형(Unimodal)**이고 최빈값이 두 개인 변수는 **쌍봉형(Bimodal)**입니다. 다수의 최빈값을 갖는 데이터는 보다 일반적으로 **다봉형(Multimodal)**이라고 불립니다.

`mode()` 함수를 사용할 수 있다고 의심할 수도 있지만 R은 이것을 통계적 최빈값이 아닌 변수의 유형(숫자, 리스트 등과 같은)을 구하는 데 사용합니다. 대신 통계적 최빈값을 찾으려면 가장 많은 수의 값을 가진 범주에 대한 `table()` 출력을 보면 됩니다.

최빈값 혹은 최빈값들은 중요한 가치에 대한 이해를 얻기 위해 질적인 측면에서 사용됩니다. 그렇다 하더라도 가장 흔한 값이 반드시 과반수(Majority)를 의미하는 것은 아니므로 최빈값에 너무 많은 비중을 두는 것은 위험할 수 있습니다. 예를 들어 검은색이 단일 자동차 색상 중 가장 흔하기는 하지만 전체 광고 차량의 약 4분의 1에 불과했습니다.

최빈값은 다른 범주와 관련하여 생각하는 것이 가장 좋습니다. 다른 모든 범주를 지배하는 하나의 범주가 있습니까, 아니면 여러 개가 있습니까? 이런 식으로 최빈값에 대해 생각하는 것은 무엇이 특정 값을 다른 값보다 더 일반화되게 만드는지에 대한 질문을 제기하여 테스트 가능한 가설을 생성하는 데 도움이 될 수 있습니다. 만약 검은색과 은색이 일반적인 중고차 색상이라면 더 보수적인 색상으로 판매되는 경향이 있는 럭셔리카를 이 데이터가 나타낸다고 믿을 수 있습니다. 대안적으로 이러한 색상들은 색상 옵션이 더 적은 채로 판매되는 이코노미카를 나타낼 수도 있습니다. 우리는 이 데이터를 계속 검토하면서 이러한 질문을 염두에 둘 것입니다.

최빈값을 흔한 값으로 생각하면 통계적 최빈값의 개념을 숫자형 데이터에 적용할 수 있습니다. 엄밀히 말하자면 연속 변수의 경우 어떠한 두 값도 반복될 가능성이 없기 때문에 최빈값을 가질 가능성이 낮을 것입니다. 그러나 최빈값을 히스토그램에서 가장 높은 막대로 생각한다면 `price` 및 `mileage`와 같은 변수의 최빈값에 대해 논의할 수 있습니다. 숫자형 데이터를 탐색할 때, 특히 데이터가 다봉형인지 여부를 조사하기 위해 최빈값을 고려하는 것이 도움이 될 수 있습니다.

## 특징 간의 관계 탐색하기

지금까지 우리는 단지 **단변량(Univariate)** 통계만 계산하면서 한 번에 하나의 변수씩 검사했습니다. 조사를 진행하는 동안 이전에 답할 수 없었던 몇 가지 질문들이 제기되었습니다.

- `price`와 `mileage` 데이터는 우리가 이코노미 클래스 차량만 조사하고 있음을 암시할까요, 아니면 주행 거리가 높은 럭셔리카도 있을까요?
- `model`과 `color` 사이의 관계가 우리가 조사하고 있는 자동차의 유형에 대한 통찰을 제공합니까?

이러한 유형의 질문은 두 변수 간의 관계를 고려하는 **이변량(Bivariate)** 관계를 살펴봄으로써 해결할 수 있습니다. 두 개 이상의 변수 관계는 **다변량(Multivariate)** 관계라고 합니다. 이변량의 경우부터 시작하겠습니다.

### 관계 시각화 – 산점도

**산점도(Scatterplot)**는 숫자형 특징들 사이의 이변량 관계를 시각화하는 다이어그램입니다. 하나의 특징 값을 가로축인 *x* 좌표로 제공하고 다른 특징의 값을 세로축인 *y* 좌표로 제공하여 좌표 평면 위에 점을 그리는 2차원 그림입니다. 점 배치의 패턴은 두 특징 간의 근본적인 연관성을 나타냅니다.

`price`와 `mileage` 사이의 관계에 대한 우리의 질문에 답하기 위해 산점도를 살펴볼 것입니다. 그림의 레이블을 지정하기 위해 이전에 사용했던 `main`, `xlab` 및 `ylab` 매개변수와 함께 `plot()` 함수를 사용할 것입니다.

`plot()`을 사용하려면 그림에 점을 위치시키는 데 사용되는 값이 포함된 `x` 및 `y` 벡터를 지정해야 합니다. 어느 변수가 *x* 및 *y* 좌표를 제공하든 결론은 동일하겠지만 관례상 *y* 변수는 다른 변수에 의존하는(그래서 **종속 변수(Dependent variable)**로 알려진) 변수로 가정합니다. 판매자가 자동차의 주행 기록계 판독값을 수정할 수 없기 때문에 주행 거리가 자동차 가격에 종속될 가능성은 작습니다. 대신 우리의 가설은 자동차의 가격이 주행 기록계의 주행 거리에 따라 달라진다는 것입니다. 따라서 우리는 `price`를 종속 *y* 변수로 선택할 것입니다.

산점도를 생성하는 전체 명령은 다음과 같습니다.

```
> plot(x = usedcars$mileage, y = usedcars$price,
       main = "Scatterplot of Price vs. Mileage",
       xlab = "Used Car Odometer (mi.)",
       ylab = "Used Car Price ($)")
```

그림 2.11: 중고차 가격과 주행 거리의 관계

산점도를 사용하면 중고차 가격과 주행 기록계 수치 사이의 명확한 관계를 알 수 있습니다. 도표를 읽으려면 가로축인 *x*축의 값이 증가함에 따라 세로축인 *y*축 변수의 값이 어떻게 변하는지 검사하십시오. 이 경우 주행 거리가 증가함에 따라 자동차 가격이 낮아지는 경향이 있습니다. 중고차를 팔아보거나 사본 적이 있다면 이것은 엄청난 통찰이 아닙니다.

아마도 더 흥미로운 발견은 대략 125,000마일 및 \$14,000에서의 유일한 이상치를 제외하면 가격과 주행 거리가 모두 높은 자동차가 매우 적다는 사실일 것입니다. 이와 같은 점이 더 이상 없다는 것은 데이터셋에 주행 거리가 높은 럭셔리카가 포함될 가능성이 낮다는 결론을 뒷받침하는 증거가 됩니다. 데이터에서 가장 비싼 차, 특히 \$17,500 이상의 자동차는 모두 주행 거리가 유난히 낮아 보이며 이는 우리가 새 차일 때 가격이 약 \$20,000인 단일 유형의 자동차를 보고 있을 수 있음을 암시합니다.

우리가 관찰한 자동차 가격과 주행 거리 사이의 관계는 아래로 기울어지는 선 형태로 점의 패턴을 형성하기 때문에 음의 상관관계(Negative association)라고 합니다. 양의 상관관계는 위로 기울어지는 선을 형성하는 것처럼 보일 것입니다. 평평한 선이나 겉보기에 무작위로 흩어져 있는 점은 두 변수가 전혀 연관되어 있지 않다는 증거입니다. 두 변수 간의 선형 상관관계의 강도는 **상관관계(Correlation)**로 알려진 통계에 의해 측정됩니다. 상관관계는 선형 관계를 모델링하는 방법을 다루는 *6장, 수치 데이터 예측 – 회귀 방법*에서 자세히 논의됩니다.

모든 연관성이 직선을 형성하는 것은 아님을 명심하십시오. 때로는 점이 U자 모양이나 V자 모양을 형성하는 반면 때로는 *x* 또는 *y* 변수의 값이 증가함에 따라 패턴이 더 약하거나 더 강해지는 것처럼 보입니다. 그러한 패턴은 두 변수 간의 관계가 선형이 아님을 의미하므로 상관관계는 연관성의 좋지 못한 척도가 될 것입니다.

### 관계 검토 – 양방향 교차 집계

두 명목형 변수 간의 관계를 검토하기 위해 **양방향 교차 집계(Two-way cross-tabulation)**가 사용됩니다(**교차표(Crosstab)** 또는 **분할표(Contingency table)**라고도 함). 교차 집계는 한 변수의 값이 다른 변수의 값에 따라 어떻게 변하는지 검사할 수 있다는 점에서 산점도와 같습니다. 형식은 행(Rows)이 한 변수의 레벨(Levels)이고 열(Columns)이 다른 변수의 레벨인 테이블입니다. 테이블의 각 셀에 있는 개수는 행과 열 조합에 해당하는 값의 수를 나타냅니다.

`model`과 `color` 사이에 관계가 있는지 여부에 대한 앞선 질문에 답하기 위해 교차표를 살펴볼 것입니다. R에서 2원표(Two-way tables)를 생성하는 함수는 여러 개가 있는데 이전에 일원표를 위해 사용했던 `table()`이 여기에 포함됩니다. Gregory R. Warnes의 `gmodels` 패키지에 있는 `CrossTable()` 함수가 아마도 가장 사용자 친화적일 것입니다. 단일 테이블에 행, 열 및 마진(Margin) 비율을 표시하여 우리가 직접 계산하는 수고를 덜어주기 때문입니다. 이전 장의 지침을 사용하여 아직 `gmodels` 패키지를 설치하지 않았다면 다음 명령을 사용하여 설치하십시오.

```
> install.packages("gmodels")
```

패키지가 설치된 후 패키지를 로드하기 위해 `library(gmodels)`를 입력합니다. 패키지는 한 번만 설치하면 되지만 `CrossTable()` 함수를 사용하려는 각 R 세션 중에는 `library()` 명령을 사용하여 패키지를 로드해야 합니다.

분석을 진행하기 전에 `color` 변수의 레벨 수를 줄여서 프로젝트를 단순화해 보겠습니다. 이 변수에는 9개의 레벨이 있지만 이렇게 많은 디테일이 필요하지는 않습니다. 우리가 정말로 관심 있는 것은 자동차의 색상이 보수적인지 여부입니다. 이를 위해 9가지 색상을 두 그룹으로 나눌 것입니다. 첫 번째 그룹에는 보수적인 색상인 검은색, 회색, 은색 및 흰색이 포함됩니다. 두 번째 그룹에는 파란색, 금색, 녹색, 빨간색 및 노란색이 포함됩니다. 우리는 자동차의 색상이 우리의 정의에 따라 보수적인지 여부를 나타내는 논리형 벡터를 만들 것입니다. 다음은 자동차가 4가지 보수적인 색상 중 하나이면 `TRUE`를, 그렇지 않으면 `FALSE`를 반환합니다.

```
> usedcars$conservative <-
    usedcars$color %in% c("Black", "Gray", "Silver", "White")
```

여기서 새로운 명령을 보았을 것입니다. `%in%` 연산자는 연산자 왼쪽에 있는 벡터의 각 값에 대해 해당 값이 오른쪽에 있는 벡터에서 발견되는지 여부를 나타내는 `TRUE` 또는 `FALSE`를 반환합니다. 간단히 말해서 이 줄은 "중고차 색상이 검은색, 회색, 은색 및 흰색 세트 안에 있는가?"라고 해석할 수 있습니다.

새로 생성된 변수에 대한 `table()` 출력을 살펴보면 자동차의 약 3분의 2는 보수적인 색상이고 3분의 1은 그렇지 않다는 것을 알 수 있습니다.

```
> table(usedcars$conservative)
```

```
FALSE  TRUE
   51    99
```

이제 교차 집계를 살펴보고 보수적인 색상의 자동차 비율이 모델에 따라 어떻게 다른지 확인해 보겠습니다. 자동차 모델이 색상 선택을 좌우한다고 가정하고 있으므로 보수적인 색상 표시기를 종속(`y`) 변수로 취급할 것입니다. 따라서 `CrossTable()` 명령은 다음과 같습니다.

```
> CrossTable(x = usedcars$model, y = usedcars$conservative)
```

이것은 다음 표를 생성합니다.

`CrossTable()` 출력은 숫자로 빽빽하지만 상단의 범례(`Cell Contents`로 표시됨)는 각 값을 해석하는 방법을 나타냅니다. 표의 행은 중고차의 세 가지 모델(`SE`, `SEL`, `SES`)을 나타냅니다(또한 모든 모델의 총합을 위한 추가 행이 있습니다). 열은 자동차 색상이 보수적인지 여부를 나타냅니다(또한 두 가지 색상 유형 전체를 합산하는 열이 있습니다).

각 셀의 첫 번째 값은 모델과 색상의 해당 조합을 가진 자동차 수를 나타냅니다. 비율은 각 셀의 카이제곱(Chi-square) 통계량, 행 합계, 열 합계 및 표 전체 합계에 대한 기여도를 나타냅니다.

우리가 가장 관심 있는 것은 각 모델별 보수적인 자동차의 비율입니다. 행의 비율을 보면 `SEL` 자동차의 0.696(70퍼센트) 및 `SES`의 0.653(65퍼센트)과 비교하여 `SE` 자동차의 0.654(65퍼센트)가 보수적으로 색상이 지정되어 있음을 알 수 있습니다. 이러한 차이는 비교적 작으며 이는 자동차 모델별로 선택된 색상의 유형에 상당한 차이가 없음을 시사합니다.

카이제곱 값은 두 변수 간의 독립성을 검정하는 **피어슨의 카이제곱 검정(Pearson's chi-squared test)**에서 해당 셀의 기여도를 나타냅니다. 비록 이 검정 이면에 있는 통계에 대한 완전한 논의는 매우 기술적이지만, 이 검정은 표의 셀 개수(Cell counts) 차이가 오직 우연에 의한 것일 가능성이 얼마나 되는지를 측정하므로 그룹 간의 차이가 실질적이지 않다는 가설을 확인하는 데 도움이 될 수 있습니다. 표에 있는 6개 셀에 대한 셀 기여도를 더하는 것부터 시작하여, *0.009 + 0.004 + 0.086 + 0.044 + 0.007 + 0.004 = 0.154*임을 구합니다. 이것이 카이제곱 검정 통계량입니다.

변수 사이에 연관성이 없다는 가설 하에 이 통계량이 관찰될 확률을 계산하기 위해 다음과 같이 검정 통계량을 `pchisq()` 함수에 전달합니다.

```
> pchisq(0.154, df = 2, lower.tail = FALSE)
```

```
[1] 0.9258899
```

`df` 매개변수는 표의 행 및 열 개수와 관련된 통계 검정의 구성 요소인 자유도를 나타냅니다. 다시 말하지만 그것이 무엇을 의미하는지는 무시하고, (*행 - 1*) \* (*열 - 1*)로 계산할 수 있으며 2x2 표의 경우 1, 여기 사용된 3x2 표의 경우 2가 됩니다. `lower.tail = FALSE`로 설정하면 약 0.926의 우측 꼬리 확률을 요청하게 되는데, 이는 직관적으로 우연만으로 최소 0.154 이상의 검정 통계량을 얻을 확률로 이해할 수 있습니다.

만약 카이제곱 검정 확률이 매우 낮다면—아마 10%, 5% 또는 1% 미만—표에서 관찰된 연관성이 우연히 발생했을 가능성이 낮기 때문에 두 변수가 연관되어 있다는 강력한 증거를 제공합니다. 우리의 경우 확률이 10%보다 100%에 훨씬 더 가까우므로 이 데이터셋의 자동차에 대해 `model`과 `color` 사이의 연관성을 관찰하고 있을 가능성은 작습니다.

이것을 손으로 계산하는 대신 `CrossTable()` 함수를 호출할 때 `chisq = TRUE`를 지정하는 추가 매개변수를 추가하여 카이제곱 검정 결과를 얻을 수도 있습니다. 예를 들면 다음과 같습니다.

```
> CrossTable(x = usedcars$model, y = usedcars$conservative,
               chisq = TRUE)
```

```
Pearson's Chi-squared test 
------------------------------------------------------------
Chi^2 =  0.1539564     d.f. =  2     p =  0.92591
```

반올림으로 인한 약간의 차이를 제외하면 손으로 계산한 것과 동일한 카이제곱 검정 통계량 및 확률이 산출된다는 것을 눈여겨보십시오.

여기서 수행된 카이제곱 검정은 전통적인 통계를 사용하여 수행할 수 있는 다양한 유형의 공식 가설 검정 중 하나입니다. "통계적으로 유의미하다(Statistically significant)"라는 구절을 들어본 적이 있다면 이는 카이제곱과 같은 통계 검정(또는 다른 여러 검정 중 하나)이 수행되었고 "유의미한" 수준—일반적으로 5% 미만의 확률—에 도달했음을 의미합니다. 비록 가설 검정은 이 책의 범위를 다소 벗어나지만 *6장, 수치 데이터 예측 – 회귀 방법*에서 간략하게 다시 마주치게 될 것입니다.

이 장에서는 R에서 데이터를 관리하는 기본 사항에 대해 배웠습니다. 다양한 유형의 데이터를 저장하는 데 사용되는 구조를 심층적으로 살펴보는 것으로 시작했습니다. 기초적인 R 데이터 구조는 벡터로 이는 확장되어 리스트나 데이터 프레임과 같은 보다 복잡한 데이터 유형으로 결합됩니다. 데이터 프레임은 특징(Features)과 사례(Examples)를 모두 가지는 데이터셋의 개념에 상응하는 R 데이터 구조입니다. R은 스프레드시트와 유사한 표 형식의 데이터 파일에 데이터 프레임을 읽고 쓰기 위한 기능을 제공합니다.

그런 다음 중고차 가격을 포함하는 실제 데이터셋을 탐색했습니다. 우리는 중심과 산포에 대한 일반적인 요약 통계를 사용하여 숫자형 변수를 조사했고 산점도를 통해 가격과 주행 기록계 수치 사이의 관계를 시각화했습니다. 다음으로 표를 사용하여 명목형 변수를 검토했습니다. 중고차 데이터를 검토하면서 어떤 데이터셋을 이해하는 데에도 사용할 수 있는 탐색적 프로세스를 따랐습니다. 이 기술은 이 책 전체에 걸친 다른 프로젝트에서도 필요할 것입니다.

R을 활용한 데이터 관리의 기초를 이해하는 데 어느 정도 시간을 보냈으니, 이제 머신러닝을 사용하여 실세계 문제를 해결하기 시작할 준비가 되었습니다. 다음 장에서는 최근접 이웃 방법(Nearest neighbor methods)을 사용하여 첫 번째 분류 작업을 다룰 것입니다. 단 몇 줄의 R 코드만으로 어려운 의료 진단 작업에서 기계가 인간과 유사한 성능을 낼 수 있다는 것을 발견하고 놀랄 수도 있습니다.
