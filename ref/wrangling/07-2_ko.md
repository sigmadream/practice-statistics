# 데이터 세트 로드 및 탐색 (Loading and Exploring Datasets)

모든 데이터 탐색은 데이터에서 시작됩니다. 아주 당연한 일입니다. 따라서 작업을 시작하기 전에 RStudio에 데이터 세트를 로드하는 방법을 아는 것이 중요합니다. 이 장에서는 RStudio 세션에 데이터를 로드하는 다양한 방법을 알아봅니다. R과 함께 미리 설치된 몇 가지 라이브러리에서 샘플 데이터 세트를 가져오는 것부터 시작하여, 많은 다른 프로그램 및 데이터 리더와의 호환성 덕분에 데이터 과학에서 많이 사용되는 파일 유형 중 하나인 쉼표로 구분된 값(CSV) 파일에서 데이터를 읽는 방법으로 넘어갑니다.

또한 데이터 프레임(Data Frame)과 티블(Tibble)의 기본적인 차이점에 대해 알아보고, 이어서 데이터를 획득하는 또 다른 좋은 방법인 웹 스크래핑(Web Scraping)의 기초를 배우는 섹션으로 이어집니다. 장의 뒷부분에서는 로컬 컴퓨터에 데이터를 저장하는 방법을 배우고 데이터 탐색을 위한 좋은 워크플로의 그림을 그려봅니다.

우리는 다음의 주요 주제를 다룰 것입니다.

- RStudio에 파일을 로드하는 방법
- 티블(Tibble) 대 데이터 프레임(Data Frame)

## R에 CSV 파일 로드하기 (Loading a CSV file to R)

CSV는 직사각형(행 x 열) 형태의 데이터 세트에서 널리 사용되는 파일 형식 중 하나일 것입니다. 이는 CSV 파일이 기본적으로 열이 쉼표로 최소한으로 분리된 텍스트 파일이어서 다른 많은 프로그램 및 파일 리더와 극히 호환성이 높고, 따라서 쉽게 공유할 수 있기 때문입니다.

R에서 CSV를 로드하려면 내장된 **utils** 라이브러리를 사용할 수 있습니다.

\# 파일 경로 설정 path = "C:/Users/user_name/Desktop/oranges.csv" \# 파일 로드 df \<- read.csv(path) \# 데이터 세트 보기 View(df)

세미콜론(;)으로 구분된 CSV 파일이 있다면 **read.csv2()** 를 사용할 수도 있지만, 이 역시 **read.csv()** 명령의 **sep** 매개변수를 사용하여 사용자 정의할 수 있습니다. 사용 가능한 다른 흥미로운 매개변수들은 다음과 같이 나열되어 있습니다. 전체 옵션 목록을 보려면 함수 이름 위에서 마우스 커서를 클릭한 다음 키보드의 _F1_ 키를 눌러 함수에 제공된 도움말을 탐색하세요.

- **header**: 기본값으로 **TRUE** 로 설정되어 있으며, 첫 번째 행이 헤더(열 이름)임을 나타냅니다. 그러나 헤더가 없는 데이터 세트의 경우 이를 **FALSE** 로 설정하고 **col.names** 매개변수를 사용하여 열 이름을 추가할 수 있습니다.

**sep**: 선택한 함수에 따라 기본적으로 쉼표나 세미콜론으로 설정되지만, 파이프 기호(**\|**)처럼 흔히 쓰이는 기호 등 필요한 것으로 변경할 수 있습니다.

**col.names**: 데이터 세트의 열 이름을 담은 사용자 정의 벡터(vector)를 전달할 수 있습니다.

**row.names**: 데이터 세트의 행 이름을 담은 사용자 정의 벡터를 전달할 수 있습니다.

CSV 파일은 매우 널리 사용되므로 이를 로드하는 여러 가지 함수를 찾을 수 있습니다. 다음으로 CSV 파일을 로드하는 다른 방법에 대해 알아보겠습니다.

### 가져오는 동안 데이터 사용자 정의하기 (Customizing data while importing)

데이터 세트를 로드하는 것은 데이터 랭글링 프로세스의 시작이며, 데이터를 R 세션으로 가져오는 동안 데이터를 조작하기 시작하는 데 사용할 수 있습니다. 사용자 정의에는 열의 하위 집합(subset) 또는 읽을 행의 최대 수 선택, 결측 데이터 처리, 사용자 정의 열 이름 사용 및 공백 잘라내기가 포함됩니다.

다음 연습을 완료하고 매개변수를 적절하게 보여주기 위해, 나는 **Oranges** 데이터 세트를 약간 수정하여 무작위 값과 몇 개의 결측 데이터 포인트가 있는 중복된 열 이름(circumference)을 추가했습니다. 매개변수가 문제를 해결하는 데 어떻게 사용될 수 있는지 살펴보겠습니다.

\# 원래 열과 10개의 행만 있는 파일 로드 df \<- read_csv(path, col_select = c(1, 2, 3), n_max = 10) \# 처음 3개 행 표시 df %\>% head(3) \# A tibble: 6 x 3 Tree age circumference...3 \<dbl\> \<dbl\> \<dbl\> 1 1 118 30 2 1 484 58 3 1 664 87

**col_select** 매개변수를 사용하면 로드하려는 원하는 열의 번호나 이름을 추가할 수 있습니다. 우리의 경우 이름을 사용하면 R은 중복된 이름이 있으며 어느 circumference 열을 로드해야 할지 이해할 수 없다는 오류를 발생시킵니다. 그러나 **df \<- read_csv(path, col_select =c("Tree", "age"))** 는 잘 작동할 것입니다. **n_max** 인수는 로드하려는 행의 수를 지정합니다. 정말 큰 데이터 세트로 작업하고 처음에는 데이터 세트에 익숙해지기 위해 몇 개의 행만 로드하여 적은 메모리를 사용하여 더 빠른 속도로 작업하고자 할 때 유용할 수 있습니다.

코드에서 **%\>%** 기호를 사용했다는 점에 주목하세요. 이를 파이프 연산자(pipe operator)라고 하며, 반복을 줄이기 위해 동일한 객체(여기서는 **df**)에 적용될 여러 함수를 한데 모으는 목적으로 **tidyverse** 코딩에서 흔히 사용됩니다. 파이썬에 익숙한 분들을 위해 덧붙이자면, 이는 파이썬의 점(dot) 표기법과 같은 논리를 따릅니다.

이제 결측 데이터로 넘어가 보겠습니다. 결측값이 항상 빈 셀인 것은 아닙니다. 때로는 데이터를 소유한 팀이 자신들만의 규칙을 사용할 수 있습니다. 공백과 **No Record** 항목이 결측 데이터로 있는 데이터 세트가 있다고 가정해 봅시다. 예를 들어 _그림 2.8_ 의 9번째 행을 보세요.

# 티블 대 데이터 프레임 (Tibbles versus Data Frames)

티블(tibble)은 현대적인 데이터 프레임입니다. R 언어가 진화함에 따라 과거 데이터 프레임에서 잘 작동했던 몇몇 기능들이 이제는 별로 유용하지 않게 되었습니다. 그래서 깔끔한 데이터(Tidy Data)와 **tidyverse** 의 창시자인 해들리 위컴은 데이터 세트를 다루는 자신의 방식에 더 잘 맞는 새로운 데이터 유형을 만들고 이전 기능들은 삭제하는 한편 멋진 새로운 기능들을 추가하여 이 새로운 티블이라는 데이터 유형을 만들었습니다.

공식 문서를 참고해 봅시다.

그들은 덜 수행하고(즉, 변수 이름이나 유형을 변경하지 않으며, 부분 일치를 수행하지 않음) 더 많이 불평합니다(변수가 존재하지 않을 때). 이는 여러분이 문제를 조기에 직면하도록 강제하며, 일반적으로 더 깔끔하고 표현력 있는 코드로 이끕니다. (<https://tinyurl.com/43un2f3z>)

티블과 데이터 프레임의 주요 차이점은 다음과 같습니다.

- 기본적으로 문자열을 요인(factor)으로 변경하는 등 입력 변수의 유형을 변경하지 않습니다.
- 목록(list)을 열로 가질 수 있습니다.
- 공백이 있는 이름과 같은 비표준(non-standard) 변수 이름을 가질 수 있습니다.
- 길이가 1인 벡터만 재활용(recycle)합니다.
- **head()** 함수를 사용할 때 열 유형의 축약된 설명을 출력합니다.
- 슬라이싱(slicing) 시 항상 다른 티블을 반환합니다. 데이터 프레임은 때때로 벡터를 반환합니다. 그것이 일부 라이브러리가 티블을 잘 다루지 못하는 이유입니다. **data.frame** 객체를 입력으로 요구하는 오류에 직면한다면, 단순히 **as.data.frame()** 을 사용하여 객체를 변환하세요.

Tidy Data 개념을 따르도록 개발되었기 때문에, 티블 형식은 **tidyverse** 패키지와 훨씬 더 잘 작동합니다. 데이터 프레임을 **dplyr::group_by()** 와 같은 **tidyverse** 패키지의 함수에 대한 입력으로 사용할 때, 출력 유형으로 **tbl_df** 라는 객체를 볼 수 있습니다.

# 데이터 탐색을 위한 워크플로 (A workflow for data exploration)

이제 RStudio로 데이터를 획득하고 로드하는 다양한 방법에 익숙해졌으므로 제가 데이터 탐색을 위해 정기적으로 사용하는 기본 워크플로를 살펴보겠습니다. 당연히 여기에 제시된 단계는 유연하며 데이터 세트를 이해하기 시작하기 위한 지침으로 이해해야 합니다. 이는 프로젝트의 요구 사항에 맞게 변경될 수 있고 변경되어야 합니다.

데이터 탐색을 시작할 때 최종 목표를 염두에 두는 것이 중요합니다. 당신은 어떤 문제를 해결하려고 합니까? 그런 다음 변수를 이해하려고 살펴보고, 오류와 결측 데이터를 찾으며, 분포를 이해하고, 그 과정에서 당신을 도울 훌륭한 인사이트를 추출하는 데 도움이 될 몇 가지 시각화를 만듭니다. 수행할 수 있는 단계들을 살펴보겠습니다.

1.  **로드 및 보기(Load and view)**: 모든 데이터 과학 프로젝트는 데이터로 시작합니다. 데이터 세트를 RStudio에 로드하고 처음 살펴보고, 데이터 유형이 올바르게 추론되었는지, 데이터 세트가 오류 없이 완전히 로드되었는지 확인하세요.
2.  **기술 통계(Descriptive statistics)**: 수치형 변수의 기술 통계를 표시합니다. 이는 데이터가 어떻게 분포되어 있는지 보는 데 도움이 되며, 잠재적으로 결함이 있거나 누락된 데이터에 대한 감을 줍니다.
3.  **결측값(Missing values)**: NA나 **NULL** 과 같은 결측값을 찾아 적절한 처리를 제공합니다.
4.  **데이터 분포(Data distributions)**: 데이터 세트에서 결측 데이터를 정리한 후, 변수의 분포를 살펴보고 평균과 비교하여 어떻게 나타나는지 이해합니다.
5.  **시각화(Visualizations)**: 백문이 불여일견이라는 말이 있듯이 시각화를 만들면 모델링에 좋은 변수들에 대한 느낌을 얻는 데 도움이 됩니다.

이 단계들을 자세히 살펴보겠습니다.

## 로드 및 보기 (Loading and viewing)

데이터를 탐색하고, 데이터에서 가치를 추출하고, 이를 사용하여 비즈니스 질문에 대답하는 것이 데이터 과학자로서 우리의 일입니다. 따라서 우리의 워크플로는 데이터 세트를 로드하고 표시하여 사용 가능한 변수에 익숙해지고 해결해야 할 문제와 연결하는 것으로 시작됩니다.

## 결측값 (Missing values)

결측값이란 관측치에서 특정 변수에 대해 사용할 수 없는 데이터 값을 말합니다. 쉽게 말해 데이터 세트의 어느 행을 보았을 때 한 열에 대해 값이 없는 경우입니다. 곰곰이 생각해 보면 결측 데이터조차도 그 안에 몇 가지 정보를 담고 있습니다. 때로는 캡처할 수 없었던 기록일 수도 있고, 특정 변수에 대해 데이터 포인트가 등록되지 못하게 하는 프로세스상의 오류를 나타낼 수도 있습니다.

일반적으로 결측 데이터를 처리하는 두 가지 방법이 있습니다. 첫 번째는 모두 버리는 것입니다. 널리 사용되는 경험 법칙에 따르면 전체 관측치의 5% 이하를 차지하는 경우 모든 NA를 버릴 수 있습니다. 대부분의 경우 모델링에 큰 영향을 미치지 않을 적은 양을 처리하려고 시간을 낭비하는 것은 의미가 없기 때문에 이는 매우 합리적입니다. 이 경우 이를 옹호하는 또 다른 주장은 편향(bias)과 관련이 있습니다. 결측값을 어떤 값으로 대체할지에 대한 데이터 과학자의 결정에 의해 모든 변환은 (아무리 미미하더라도) 편향될 것이기 때문입니다.

## 데이터 분포 (Data distributions)

모든 변수는 어떤 문제에 대한 데이터 포인트 모음입니다. 만약 우리가 오전 10시에 지하철에 탄 사람 수를 측정하고 오후 5시에 다시 측정한다면 거의 확실하게 두 개의 다른 수치를 얻게 될 것입니다. 그 과정을 수백 번 반복한다면 그 수치들은 계속 변할 것입니다. 그것이 바로 우리가 변동(variation)이라고 부르는 것입니다. 모든 변동은 낮은 값의 높은 집중도, 높은 값의 높은 집중도, 아니면 패턴이 정의되지 않은 무작위 숫자의 모음과 같은 일정한 패턴을 갖게 됩니다.

이를 아는 것은 변동 패턴이 무엇인지 이해하기 위해 변수의 분포를 살펴보아야 한다는 우리의 주장을 뒷받침합니다. 범주형 데이터의 경우, 반응 변수(우리가 예측하려고 하는 변수)를 살펴보면 그룹 B보다 그룹 A가 훨씬 많은 것을 발견하게 되고 우리의 모델이 B보다 A를 더 많이 분류하도록 편향될 것이라고 결론 내리는 것이 자연스럽습니다. 이와 유사하게 회귀 모델에서 낮은 값들의 집중도가 높다면 우리는 높은 값들을 예측하는 것이 더 어려울 수 있다는 것을 알게 됩니다.

데이터 분포를 확인하기 위해 좋은 그래픽 유형은 **히스토그램(histograms)**, **박스플롯(boxplots)** 및 **밀도 플롯(density plots)** 입니다. 히스토그램은 데이터가 더 집중된 위치를 알려주며 대칭 형태, 왼쪽으로 꼬리가 긴 좌편향 형태 또는 오른쪽으로 꼬리가 긴 우편향 형태를 보여줍니다. 박스플롯은 중간값, 사분위수 및 이상치와 같은 흥미로운 정보를 제공합니다. 밀도 플롯은 선형 플롯이므로 분포 형태를 더 명확하게 보는 데 도움을 줍니다.

# 기본 웹 스크래핑 (Basic Web Scraping)

웹 스크래핑은 데이터를 획득하는 또 다른 일반적인 방법입니다. 우리가 정보화 시대에 살고 있다는 것을 고려할 때, 온라인에서 사용할 수 있는 데이터 양은 엄청납니다. 현재 매일 약 2.5 퀸틸리언 바이트(2.5 다음에 0이 18개 붙는 수)가 생성되고 있습니다. 일부 전문가들은 인류가 그동안 생산한 모든 데이터의 90%가 지난 2년 사이에 생성되었다고 추산합니다(<https://cloudtweaks.com/2015/03/how-much-data-is-produced-every-day/>). 그러니 데이터가 필요하다면 주변에 차고 넘칩니다.

하지만 이 섹션을 더 진행하기 전에 이 면책 조항을 포함하고 싶습니다. 웹 스크래핑은 합법적이지만 웹사이트에서 데이터를 스크랩할 때 따라야 할 몇 가지 규칙과 윤리적 기준이 있습니다.

첫째, 개인 데이터는 다른 사람이나 회사의 소유이므로 존중하고 허가 없이 사용해서는 안 됩니다. 특히 API를 통해 제공되는 공공 데이터를 항상 찾는 것이 규칙입니다. API로 제공된다는 것은 그 데이터 세트들이 검토를 거쳐 정해진 규칙 아래에서 사용할 수 있게 되었음을 의미하기 때문입니다.

둘째, 스크랩하려는 페이지의 **robots.txt** 파일을 항상 확인하는 것이 또 다른 좋은 관행입니다. 대부분의 현대적인 웹사이트에는 이 파일이 있으며 **thewebsitename.com/robots.txt** 로 접근할 수 있습니다. 우리 예제의 경우 Wikipedia에서 데이터를 스크랩할 것이므로 [www.wikipedia.com/robots.txt](https://www.wikipedia.com/robots.txt) 를 보고 그들이 허용하는지 확인할 수 있습니다. 또한 웹상의 모든 사람을 위해 좋은 서비스를 유지하고 서버에 과부하를 주지 않기 위해 따라야 하는 요청(requests) 사항도 확인하세요.

필요한 라이브러리를 불러오며 시작합니다.

library(rvest) library(tidyverse)

## API에서 데이터 가져오기 (Getting data from an API)

앞서 조언했듯이 보통 스크래핑보다 API에서 데이터를 가져오는 것이 권장됩니다. 이는 API 사용 규칙을 이해하기 더 쉽기 때문입니다. 데이터를 가져올 수 있게 하고 사용자가 모범 사례를 따르고 있음을 증명하는 인증 코드를 사용할 수 있습니다.
우리는 필요한 모든 사람에게 공개된 재무 데이터가 있는 미국 재무부 API에서 MTS 데이터를 가져올 것입니다(<https://fiscaldata.treasury.gov/api-documentation/>).

API는 어느 정도 폴더와 파일 구조처럼 작동합니다. 데이터 세트는 **JavaScript Object Notation(JSON)** 형식으로 저장되며 URL 주소를 통해 액세스할 수 있습니다. 해당 데이터에 접근할 수 있는 키(keys)를 제공하는 것은 API 개발자들의 몫입니다. 일반적으로 우리의 비유에서 _폴더_ 에 비유할 수 있는 기본 주소(base address)와 _파일_ 과 유사하게 생각할 수 있는 엔드포인트(endpoint)가 있을 것입니다. 이 API의 기본 URL은 <https://api.fiscaldata.treasury.gov/services/api/fiscal_service> 이며 선택한 엔드포인트는 **/v1/accounting/mts/mts_table_1** 입니다. 둘을 합치면 MTS 보고서에 액세스하기 위한 URL을 얻게 됩니다. 다음은 이 주소를 복사하여 브라우저에 붙여넣을 때 찾을 수 있는 내용을 발췌한 것입니다.

{"data": \[{"record_date": "2015-03-31","parent_id": "null","classification_id": "12662418","classification_desc": "FY 2014","current_month_gross_rcpt_amt": "null","current_month_gross_outly_amt": "null","current_month_dfct_sur_amt": "null","table_nbr": "1","src_line_nbr": "1","print_order_nbr": "1","line_code_nbr": "10","data_type_cd": "S","record_type_cd": "SL","sequence_level_nbr": "1","sequence_number_cd": "1","record_fiscal_year": "2015","record_fiscal_quarter": "2","record_calendar_year": "2015","record_calendar_quarter": "1","record_calendar_month": "03","record_calendar_day": "31"},

아주 예쁘지는 않지만 파싱(parsing)하고 나면 훨씬 나아 보일 것입니다. 코드는 다음과 같습니다.

\# 라이브러 로드 library("httr") library("jsonlite") \# 원하는 URL 지정 url = "https://api.fiscaldata.treasury.gov/services/api/fiscal_service/v1/accounting/mts/mts_table_1" \# URL 콘텐츠 가져오기 treasury_api \<- GET(url)

**GET()** 함수는 웹에서 콘텐츠를 추출합니다. 이제 **treasury_api** 변수 안에 10개의 객체가 있는 리스트를 갖게 되었습니다. 우리의 다음 단계는 보고서의 내용을 추출하여 데이터 프레임으로 만드는 것입니다.

\# 결과를 텍스트로 변환 result \<- content(treasury_api,"text", encoding = "UTF-8") \# JSON 데이터 파싱 df_json \<- fromJSON(result, flatten = TRUE) \# 데이터 프레임으로 저장 df \<- as.data.frame(df_json\$data)

**result** 변수는 콘텐츠를 가져와서, 많이 사용되는 인코딩 중 하나인 **UTF-8** 악센트 인코딩을 사용하여 이전 텍스트와 매우 유사한 JSON 텍스트로 변환합니다. 이는 **content()** 함수를 통해 수행됩니다. 다음으로 JSON 데이터를 파싱하여 **df_json** 에 저장했습니다. 마지막으로 그 객체에서 보고서를 가져와 데이터 프레임으로 변환하고 이를 **df** 변수에 할당했습니다.

# 요약 (Summary)

우리는 R의 기본(native) 데이터 세트를 사용하거나 인기 있는 CSV 형식에서 데이터를 로드하여 데이터를 획득하는 방법과 로드할 행 수를 결정하는 것과 같이 데이터를 가져오는 단계에서도 데이터 세트를 사용자 정의하는 방법을 배우면서 [_2장_](B18355_02.xhtml#_idTextAnchor039)을 시작했습니다. 그런 다음 데이터 프레임과 티블 형식의 차이점에 대해 간략하게 설명했습니다. 이들은 동일한 목적을 제공하고 기본적으로 동일한 작업을 수행하지만, 티블은 몇 가지 향상된 기능을 제공하며 현대 세계에 더 적합하고 R의 tidyverse 패키지와 훨씬 더 잘 작동합니다.

다음으로, 우리는 웹 스크래핑을 사용하거나 퍼블릭 API에서 데이터 세트를 캡처하여 데이터 세트를 R 세션으로 가져오는 더 정교한 방법으로 나아갔습니다. 많은 비즈니스와 영업 사원이 Microsoft Excel을 사용하는 세상에 살고 있기 때문에 파일을 CSV로 저장하는 방법을 아는 것이 중요합니다. 이 내용 또한 이 장에서 다루었습니다.

마지막으로, 우리는 데이터 로드 및 보기, 기술 통계 계산, 결측값 및 이상치 처리, 데이터 분포 플로팅 및 시각화라는 EDA의 기본 단계를 살펴보았습니다. 우리는 실제 데이터 과학 프로젝트와 유사한 부동산 중개소를 위한 작업 프로젝트라는 맥락 안에서 이 모든 것을 수행했습니다.

데이터 시각화는 좋은 데이터 탐색에 매우 중요합니다. 따라서 다음 장에서는 R에 내장된 리소스를 사용한 데이터 시각화에 대해 자세히 알아보고, 기본 종류의 플롯을 만들 수 있을 뿐만 아니라 색상, 제목, 레이블 등을 사용자 지정하는 방법에 대해 배울 것입니다.
