# 문자열 작업 (Working with Strings)

프로그래밍 세계에서 문자열(strings)은 텍스트 정보입니다. 즉, 단일 문자, 단어, 구, 또는 더 일반적으로는 작은따옴표나 큰따옴표 사이에 오는 모든 항목이 변수에 할당되면 컴퓨터에 의해 문자열로 인식됩니다. 다음 코드와 주석을 확인하세요:

\# 변수에 할당되지 않은 경우, 텍스트는 단순한 주석입니다. "This is a text." \# 다음은 문자열입니다. my_string1 \<- "a" my_string2 \<- "Hello, World! I am learning!" my_string1 \<- "42"

인터넷에서 텍스트 형식으로 찾을 수 있는 양질의 데이터가 많기 때문에 문자열을 다루는 것은 갖춰야 할 좋은 기술입니다. **자연어 처리(Natural Language Processing, NLP)** 는 데이터 과학에서 가장 큰 분야 중 하나이며, 이 중 많은 부분이 문자열 랭글링(wrangling)에 의존합니다.

문자열로 할 수 있는 작업의 대부분은 다음과 같은 작업을 포함합니다:

- **파싱(Parsing)**: 패턴으로 구분된 텍스트의 여러 부분을 분리하고 그 일부를 추출하여 단어들을 결합합니다.
- **데이터 마이닝(Data mining)**: 텍스트를 단위(토큰화, tokenization)로 분할하고 표제어 추출(lemmatization)로 단어의 어근이나 주요 의미를 찾으며 어간 추출(stemming)로 패턴을 찾아 텍스트에 대한 좋은 인사이트를 얻습니다.

이 장에서 우리는 파싱에 초점을 맞추고 텍스트 변수 변환을 위한 최신 개념에 대해 알아볼 것입니다. 이 장을 마칠 때쯤이면 문자열의 일부를 추출하고 파싱하며 텍스트를 데이터 프레임으로 혼합할 수 있게 될 것입니다. 또한 고도로 지정된 패턴의 맞춤화 기능과 함께 텍스트 패턴 및 매우 구체적인 문자열을 찾을 수 있게 해주는 정규 표현식(*regexps*)을 다룰 것입니다.

우리는 주어진 단어의 빈도를 찾고 텍스트 데이터로부터 데이터 요약을 구성하는 데 사용할 수 있는 도구를 다룰 것입니다.

우리는 다음과 같은 주요 주제를 다룰 것입니다:

- **stringr** 소개
- 정규 표현식(regexps) 다루기
- R에서 빈도 데이터 요약 만들기
- 텍스트 마이닝
- 요인(Factors)

# stringr 소개 (Introduction to stringr)

문자열에 대해 배울 것은 많습니다. 비록 R이 통계를 염두에 두고 만들어진 언어지만 수년 동안 많이 발전해 왔고 많은 라이브러리가 등장했습니다. 이미 언급했듯이, 데이터 과학자로서 일상적인 작업에서 종종 이러한 객체를 다루어야 하기 때문에 문자열을 다루는 것은 갖춰야 할 훌륭한 기술입니다. 고객이나 소셜 미디어의 감성(sentiment) 분석, 피드백 양식의 의견 분석, 인터넷에서 스크랩한 텍스트 정보의 분석 또는 주소에서 도시 이름만 파싱하는 것 등은 데이터 랭글링 요청의 일부가 될 수 있는 수많은 작업 중 일부입니다.

이 장의 코드를 따라 하려면 다음 라이브러리들이 설치되어 있고 로드되어 있는지 확인하세요. 그중에서 Gutenberg 패키지가 빠져있을 수 있습니다. 그러므로 로드를 시도하기 전에 **install.package("gutenbergr")** 를 사용하시기를 권장합니다. 우리는 이 장의 마지막 부분에 있는 연습 문제에 이것을 사용할 것입니다:

\# 설치되어 있지 않다면 install.packages("library_name")을 사용하세요 library(tidyverse) library(stringr) library(gutenbergr)

간단하게 시작하겠습니다. 문자열을 생성하려면 작은따옴표(**'**) 또는 큰따옴표(**"**)를 사용하기만 하면 됩니다. 대부분의 프로그래밍 언어는 이를 구분하지 않습니다. R도 마찬가지이므로 여러분이 원하는 것을 자유롭게 선택하세요:

string1 \<- "I am a string." string2 \<- "Me too." string3 \<- 'quote inside "quote", use single quote for the string and double for the text.'

문자열을 출력하고 싶다면 **print()** 나 **writeLines()** 를 사용하세요. 차이점은 **writeLines** 가 따옴표나 백슬래시(**\\**) 같은 이스케이프 문자와 같은 원치 않는 문자를 가져오지 않는다는 점입니다. **string1** 에 대해 **print** 를 사용하면 큰따옴표가 표시된다는 점에 유의하세요. **writeLines** 를 사용하면 표시되지 않습니다:

\# 출력 print(string1) writeLines(string2) writeLines(string3) \> \# 출력 \> print(string1) \[1\] "I am a string" \> writeLines(string2) me too \> writeLines(string3) quote inside "quote", use single quotes for the string and double for the text.

문자열을 생성하는 방법을 알게 되었으니 **stringr** 라이브러리의 주요 함수들을 사용해 봅시다. 함수가 너무 많아 전부 다 살펴볼 수는 없지만 더 자세히 탐구하고 싶다면 *추가 읽을거리* 섹션에 공식 문서를 향하는 링크가 있습니다. 일반적으로 **stringr** 의 구문은 **str\_** 로 시작하며 뒤에 함수 이름이 옵니다.

## 패턴 감지 (Detecting patterns)

문자열 랭글링에서 패턴 감지는 흔한 작업입니다. 문구 안에 특정 단어가 포함되어 있는지, 아니면 단어 안에 주어진 문자가 포함되어 있는지 알고 싶을 수도 있습니다.

**str_detect()** 함수는 단어나 문구 내에서 패턴을 감지하는 데 도움을 줍니다:

\# 문자열 생성 text \<- "hello" \# 문자열에 "rt" 문자가 있는지 감지 str_detect(text, "rt") \[1\] FALSE \# 문자열에 "world"라는 단어가 있는지 감지 str_detect(text, "ll") \[1\] TRUE \# 구문 생성 text \<- "hello, world!" \# 문자열에 "ll" 문자가 있는지 감지 str_detect(text, "world") \[1\] TRUE

문자열이 특정 패턴으로 시작하는지 알고 싶을 때 **str_starts()** 함수를 사용할 수 있습니다. 이 함수는 구매 거래에는 **"ORDER-1234"**, 유지 관리 거래에는 **"MAINT-1234"** 와 같은 패턴을 사용하는 **"ID"** 변수가 있는 데이터 프레임을 다룰 때 유용할 수 있습니다. 그럴 때 우리는 패턴의 첫 번째 부분을 추출하기 위해 **str_starts()** 함수를 사용할 수 있습니다. 이는 어느 라인이 구매로 표시되고 어느 라인이 유지 관리 거래가 될지 알려줍니다:

\# 문자열 생성 my_id \<- "ORDER-1234" \# 시작 단어 일치 str_starts(string=my_id, pattern="ORDER") \[1\] TRUE

문자열 벡터가 있고 패턴의 인덱스 번호를 알아야 할 때 우리는 **str_which()** 를 사용할 수 있습니다. 코드는 다음과 같습니다:

\# 벡터 생성 shop_list \<- c("fruit", "vegetable", "pasta") \# "pasta" 인덱스 str_which(string=shop_list, pattern="pasta") \[1\] 3

우리는 세 번째 요소로 **"pasta"** 를 찾았습니다.

마찬가지로 **str_locate()** 함수는 패턴의 시작과 끝 위치를 보여줍니다. 다음 코드에서는 동일한 벡터를 사용합니다. 처음 두 결과는 *pasta* 패턴과 일치하지 않으므로 **NA** 이고, 세 번째 결과는 그 단어가 **1** 번째 위치에서 시작해서 **5** 번째 위치에서 끝남을 말해준다는 점에 주목하세요:

shop_list \<- c("fruit", "vegetable", "pasta") str_locate(shop_list, "pasta")      start end \[1,\]    NA  NA \[2,\]    NA  NA \[3,\]     1   5

이 개념을 굳히기 위한 좋은 연습으로 여러분의 코드에서 **pasta** 를 **more pasta** 로 변경하고 어떻게 되는지 확인해 보세요.

텍스트 내에 패턴이 몇 번 발생하는지 세려면 **str_count()** 함수를 사용합니다:

\# 텍스트 text \<- "I want want want to count the repetitions of want in this phrase. Do you want the same?" \# want의 빈도수 계산 str_count(text, "want") \[1\] 5

훌륭합니다. 우리는 *want* 패턴이 5번 반복된 것을 모두 찾았습니다. 문자열 패턴의 감지, 위치 찾기, 개수 계산은 텍스트 내에 텍스트 패턴이 존재하는지 확인하고 문구 내에서 그 위치를 찾는 함수들입니다. 이외에도 텍스트에서 텍스트 일부를 추출(파싱)해야 할 때 문자열의 부분 집합을 구하기 위한 또 다른 함수가 있습니다. 이에 대해 배워봅시다.

## 문자열의 부분 집합 추출 (Subset strings)

문자열의 부분 집합을 추출한다는 것은 어떤 목적을 위해 그 일부를 추출함을 의미합니다. 텍스트 내에서 패턴을 찾을 수 있는 위치를 알고 있다면 쉽습니다. **"ORDER-1234"** 가 포함된 ID에 대한 예제를 다시 살펴보면 첫 5글자가 우리가 필요한 패턴이라는 것을 알고 있으므로, 문서에 언급된 대로 **str_sub()** 함수를 사용하여 서브 스트링을 반환하도록 하여 단순히 **"ORDER"** 나 **"MAINT"** 라는 거래(transaction) 유형을 추출할 수 있습니다. 다음을 확인하세요:

\# 문자열 생성 my_id \<- "ORDER-1234" \# 1에서 5번째 문자 추출 str_sub(my_id, start=1, end=5) \[1\] "ORDER"

이전 코드는 요청한 대로 문자열에서 처음 5개의 문자만 반환했습니다. 하지만 **ORDER** 항목만 추출하고 **MAINT** 항목은 제외하고자 하는 트랜잭션 목록이 있다고 가정해 보겠습니다. 이때 사용할 함수는 **str_subset()** 이며 이는 주어진 패턴을 포함하는 문자열을 반환합니다. 이를 **stringr** 내에서 사용하려면 다음을 보세요:

\# 텍스트 my_ids \<- c("ORDER-1234", "ORDER-2234", "MAINT-1234", "MAINT-2234") \# orders 반환 str_subset(my_ids, "ORDER") \[1\] "ORDER-1234" "ORDER-2234"

이 결과는 일부분만이 아닌 요소 전체를 반환한다는 점에 유의하세요.

텍스트를 파싱하는 것은 힘든 작업이며, 텍스트에 잉여(extra) 공백이 포함되어 있다면 더욱 그렇습니다. 바로 이럴 때 길이를 관리하는 함수가 유용해집니다.

## 길이 관리 (Managing lengths)

**length()** 함수를 사용하여 여러분의 문자열 크기를 알아보세요. 공백과 문장 부호도 포함된다는 점에 유의하세요:

\# 텍스트 text \<- "What is the size of this string?" \# 길이 str_length(text) \[1\] 32

다음으로 문자열의 여백을 자르거나 압축하는 데 유용한 몇 가지 함수를 제시하겠습니다. **str_trim()** 이 텍스트 끝부분의 잉여 공백을 제거하지만 중간에 있는 것에는 신경 쓰지 않는 반면, **str_squish()** 는 두 가지를 모두 수행합니다:

\# 텍스트 text \<- " Text    to  be trimmed. " \# trim 여백 자르기 str_trim(text, side="both") \[1\] "Text    to  be trimmed." \# squish 압축 str_squish(text) \[1\] "Text to be trimmed."

여백을 자르는 첫 번째 함수는 텍스트 양 끝부분의 잉여 공백만 제거했음을 확인하세요. 반면 **str_squish()** 는 모든 여분의 공백을 제거했습니다.

텍스트 패턴은 정확히 똑같지 않으면 일치하지 않을 수 있으므로 양쪽의 여백을 자르거나 압축하는 것은 중요합니다. 앞으로 보게 될 것처럼 이는 대문자와 소문자에도 똑같이 적용됩니다.

## 문자열 변형 (Mutating strings)

문자열을 다룰 때 아주 흔히 쓰이는 또 다른 작업은 문자의 대소문자 변환입니다. 우리는 **대문자(UPPERCASE)**, **소문자(lowercase)**, **단어의 첫 글자만 대문자(Title Case)** 로의 빠른 변환을 수행할 수 있습니다. 함수 이름은 수행할 작업의 이름이므로 매우 직관적입니다( **str_to_upper()**, **str_to_lower()**, **str_to_title()** ):

\# 텍스트 text \<- "Hello world." \# UPPERCASE 변환 str_to_upper(text) \[1\] "HELLO WORLD." \# lowercase 변환 str_to_lower(text) \[1\] "hello world." \# Title Case 변환 str_to_title(text) \[1\] "Hello World."

단순하지만 아주 유용한 함수들입니다.

또 다른 중요한 변형 작업은 문자열 안에서 패턴을 교체하는 것입니다. **str_replace_all()** 은 매치되는 모든 패턴을 한 번에 교체하지만 **str_replace()** 는 가장 먼저 찾은 것만 교체한다는 점을 유의하세요:

\# 텍스트 text \<- "Hello world. The world is beautiful!" \# 한 패턴 교체 str_replace(text, "world", "day") \[1\] "Hello day. The world is beautiful!" \# 모든 패턴을 한꺼번에 교체 str_replace_all(text, "world", "day") \[1\] "Hello day. The day is beautiful!"

패턴을 교체하는 함수를 갖추는 것은 필수적입니다. 우리가 텍스트 안에서 특정 단어들을 얼마나 많이 반복하는지 잠시 생각해 보면, 그 단어들 중 하나를 교체하고 싶을 때 단번에 그렇게 할 수 있어야 한다는 것은 논리적으로 타당합니다.

예를 들어 단어들을 결합하여 텍스트나 패턴을 생성하거나 반대로 이를 분리하여 단어의 수를 셀 때에도 **stringr** 은 그에 맞게 갖춰져 있습니다.

## 결합과 분리 (Joining and splitting)

텍스트를 다룰 때에는 그것을 쪼개거나 쪼개진 부분들을 다시 모아 새로운 패턴을 형성하는 일이 잦습니다. 이는 다음 함수들로 수행될 수 있습니다. **str_c()** 를 이용해 두 단어를 결합해 봅시다:

\# 텍스트 s1 \<- "Hello" s2 \<- "world!" \# 사슬 잇기(concatenate) str_c(s1, s2, sep=" ") \[1\] "Hello world!"

문자열을 결합할 수 있다면 그들을 분리할 수도 있습니다. 이 예제에서는 구분 기호 패턴으로 공백을 사용했지만 대시(-), 슬래시(/), 점(.), 쉼표(,) 등 원하는 아무거나 사용할 수 있습니다. 여기에서 한 가지 덧붙이자면 R에는 연결 기능을 가진 다른 함수들도 있습니다. **c()** 와 **paste()** 둘 다 요소 수집이라는 같은 목적을 위해 쓰입니다. 하지만 **str_c()** 는 처음부터 이 목적을 위해 만들어졌고 더 나은 성능과 재활용을 위한 벡터화를 갖추고 있으며 각기 다른 길이의 벡터를 결합하는 능력까지 보유하고 있습니다:

\# 텍스트 text \<- "I am learning how to split strings" \# 분리 str_split(text, pattern=" ") \[\[1\]\] \[1\] "I"        "am"       "learning" "how"      "to"       "split"    "strings"

## 문자열 정렬 (Ordering strings)

때로는 문자열 벡터를 순서대로 정렬하는 것이 흥미로울 수 있습니다. **str_sort()** 를 사용하여 그렇게 하는 방법은 다음과 같습니다. 순서를 변경하려면 **decreasing** 매개변수를 **TRUE** 나 **FALSE** 로 설정하세요:

\# 텍스트 shop_list \<- c("bananas", "strawberries", "avocado", "pasta") \# 정렬(ordinate) str_sort(shop_list, decreasing = FALSE) \[1\] "avocado"      "bananas"      "pasta"        "strawberries"

우리는 지금까지 많은 것을 다루었습니다. 이 라이브러리는 매우 강력하여 제시된 함수들을 사용해 다양한 방법으로 텍스트를 랭글링할 수 있도록 해줍니다. 하지만 문자열 패턴이 구체적이 될수록 문자열 다루기는 훨씬 까다로워질 수 있습니다. 이럴 때 우리는 **stringr** 에 정규 표현식의 기능을 추가하여 매우 구체적인 텍스트 패턴을 찾아내게 할 수 있습니다.

# 정규 표현식 다루기 (Working with regular expressions)

정규 표현식(Regexps)은 프로그래머가 문자열을 위해 고도로 맞춤화된 파서를 만들 수 있도록 해주는 텍스트 수식(또는 코드)입니다. 고객에게 수천 건의 고객 의견이 담긴 문서가 있고 결함이 있는 제품의 일련번호(serial number)만 추출하고 싶어 한다고 가정해 봅시다. 제품 일련번호를 본 적이 있다면 그것이 일반적으로 문자(알파벳)와 숫자로 구성된 제품의 고유 식별자라는 것을 알 것입니다(예: **XYW-001AB**). 글쎄요, 정규 표현식을 사용하면 이 작업은 쉬워집니다. 문자(알파벳)와 숫자의 특정 조합에 완벽하게 들어맞는 패턴을 만들어 파싱 작업을 매우 빠르게 처리할 수 있기 때문입니다.

처음 정규 표현식(*regexp*)을 볼 때는 이상한 코드이거나 배우기 어려워 보이겠지만 실습하며 더 자주 사용하게 될수록 그런 패턴들이 자연스레 읽고 쓰기 쉬워질 것입니다. 우리는 영점부터 단계별로 정규 표현식에 대한 지식을 쌓아갈 것입니다.

## 기본 사항 배우기 (Learning the basics)

우리의 *정규 표현식* 과 일치하는 항목을 보기 위해 사용하는 **stringr** 의 함수는 첫 번째로 일치하는 항목을 반환하는 **str_view()** 와 텍스트에서 일치하는 모든 항목을 반환하는 **str_view_all()** 입니다. 정규 표현식은 텍스트 패턴을 찾기 위해 쓰이는 텍스트 코드이므로 텍스트로 텍스트를 찾다 보면 어느 정도 충돌이 있을 수 있다는 점을 기억하는 것이 중요합니다. 점(**"."**)이 그런 충돌의 좋은 예입니다. 정규 표현식에 쓰일 때 이는 어떠한 문자 하나든 상관없이 지칭하기 위해 사용됩니다.

그렇다면 점(dot) 자체를 어떻게 찾을 수 있을까요? 그럴 때 우리는 컴퓨터에게 *이봐, 내가 \\.을 사용하면, 나는 진짜 점을 찾고 있는 거야* 라고 말하기 위해 이중 백슬래시(**\\**)인 **이스케이프(escape) 문자** 를 사용할 수 있습니다. 다른 이스케이프 패턴을 보기 위해 다음 코드를 실행해 볼 수 있습니다: **?"'"**:

# R에서 빈도 데이터 요약 만들기 (Creating frequency data summaries in R)

## 토큰화 (Tokenization)

우리는 토큰(token)의 정의부터 시작해야 합니다. 토큰은 텍스트의 의미 있는 가장 작은 단위입니다. 토큰으로 단어를 발견하는 가장 일반적이지만, 프로젝트의 목적에 부합한다면 구문, 문장 또는 다른 단위가 토큰이 될 수도 있습니다. 이 개념을 설명하고 이에 대한 직관을 기르기 위해 다음 예시 문구를 생각해 보겠습니다: *He is a data scientist with many skills(그는 다재다능한 데이터 과학자이다).* 이 문장을 단어 단위로 토큰화하면 우리는 *he, is, a, data, scientist, with, many, skills* 를 얻게 될 것입니다. 따라서 한 단어가 하나의 토큰이 됩니다.

하지만 토큰화 이후, 토큰이 의미를 전달하는 텍스트의 가장 작은 단위가 되어야 함에도 불구하고, 우리는 전치사, 접속사, 일부 동사처럼 단어들을 연결하여 문구를 구성하는 데 사용되는 많은 무의미한 토큰들을 얻게 될 수 있습니다. 좋은 예시로는 *the, is, a, with*, 그리고 *many* 가 있습니다. 이러한 무의미한 단위는 텍스트 마이닝에서 **불용어(stop words)** 라고 불리며 분석 전 토큰화 단계에서 일반적으로 데이터 세트에서 제거됩니다. 그렇지 않으면 *the, is*, *a* 와 같은 단어가 텍스트에서 가장 중요한 단어임을 시사하는 결과를 얻을 위험이 있으며, 이는 사실과 전혀 다릅니다.

행(row)당 단일 관측치와 열(column)당 단일 변수를 가지면 **tidy(정돈된)** 데이터 세트로 작업하기가 더 쉽다는 것을 우리는 이미 알고 있습니다. 텍스트 마이닝에 관해 이야기할 때 **tidiness(정돈됨)** 의 개념은 *행당 하나의 토큰* 으로 정의됩니다.

토큰화를 수행해 보겠습니다. 코드는 꽤 간단합니다. 우리는 **book** 데이터 세트를 호출하고 파이프 기호 **%\>%** 를 사용하여 다음 작업인 **unnest_tokens(output= "tokens", input= text)** 함수와 연결합니다. 이 함수는 토큰을 저장할 열의 이름을 결정하는 output 인수를 받고 두 번째 인수는 우리 데이터 세트에서 온 입력 열(input column)입니다. 결과를 어떤 변수에도 할당하지 않으므로 코드는 테이블을 시각화하기 위해서만 사용됩니다:

\# 토큰화 book %\>%     unnest_tokens(output= "tokens", text)

## 어간 추출과 표제어 추출 (Stemming and lemmatization)

**어간 추출(Stemming)** 은 단어의 어간(어근)을 사용하여 분석에서 발생하는 단어 변형의 수를 줄입니다. 이런 식으로 *say* 나 *saying* 같은 단어의 변형은 그 어근인 *sai* 로 줄어듭니다 – 어간(stems)이 항상 이치에 맞지는 않지만 여전히 유용할 수 있습니다. **tidytext** 를 사용한 어간 추출 수행은 간단합니다. 다시 한 번 **clean_tokens** 개체를 사용한 다음 **mutate()** 함수를 사용하여 새 단어에 대해 **stem** 이라는 이름의 새 변수를 생성할 것입니다. 이 작업이 완료되면 **count()** 를 사용하여 빈도수를 구합니다:

\# 어간 추출 clean_tokens %\>%   mutate(stem = wordStem(tokens)) %\>%   count(stem, sort = TRUE)

반면에 **표제어 추출(Lemmatization)** 은 단어의 표제어, 즉 단어의 기본 의미를 사용합니다. 표제어는 그 단어가 사용된 문맥(context)을 고려합니다. 따라서 *say* 와 *saying* 이라는 단어는 두 변형 모두의 기본 의미인 *say* 로 단순히 바뀌게 됩니다.

이 작업을 수행하기 위해 **tm** 및 **textstem** 이라는 다른 라이브러리를 로드해야 합니다. 먼저, 텍스트를 정리하는 데 도움을 주는 사용자 정의 함수를 만들 것입니다(GitHub 리포지토리에서 코드를 볼 수 있습니다). 이 함수는 책의 텍스트를 받아서 코퍼스(corpus) 객체로 변환하고 구두점, 공백 및 불용어를 제거하여 이를 정리합니다. 참고로 코퍼스는 텍스트 마이닝 프로젝트에서 일반적으로 사용되는 텍스트 문서와 메타데이터의 모음으로 구성된 텍스트 개체 유형입니다.

다음 단계는 텍스트를 정리하기 위해 이를 적용하는 것입니다:

\# 텍스트 정리 clean_text \<- clean_corpus(book\$text)

그런 다음 표제어 추출을 수행할 수 있습니다. 다음 코드에서 **tm_map()** 함수는 **clean_text** 를 받아서 **lemmatize_strings** 함수를 추가하고 결과를 **clean_lem** 에 저장합니다. 그런 다음 이 개체를 가져와 문서별 용어 행렬(matrix of terms by documents)로 변환하는데 여기서 텍스트의 각 행은 문서로 간주되며 해당 문서에 각 단어가 몇 번 있는지 계산됩니다. 우리는 **TermDocumentMatrix** 함수를 사용하여 이 작업을 수행합니다. 다음으로 해당 개체를 정규 행렬(regular matrix)인 **TDM** 으로 변환합니다. 마지막으로 결과를 **data.frame** 개체로 변환할 준비가 될 때까지 단어 빈도수를 계산하고 정렬할 것입니다:

\# 표제어 추출 clean_lem \<- tm_map(clean_text, lemmatize_strings) TDM \<- TermDocumentMatrix(clean_lem) TDM \<- as.matrix(TDM) word_frequency \<- sort(rowSums(TDM),decreasing=TRUE) lemm_df \<- data.frame(word = names(word_frequency),freq=word_frequency)

이 작업이 완료되면 **lemm_df** 데이터 프레임을 열었을 때 알고리즘이 “ 와 ” 를 제거할 수 없었음을 알게 되며 따라서 이를 수동으로 처리할 수 있습니다:

\# " 또는 " 기호 단어 제거 lemm_df \<- lemm_df %\>% filter(!word %in% c('"', '"') )    \# 상위 데이터(head) 보기 head(lemm_df, n=10)

## TF-IDF

TF-IDF는 단어 빈도-역 문서 빈도(Term Frequency-Inverse Document Frequency)를 나타냅니다. 이 측정 기준은 텍스트 마이닝에서 단어의 중요도에 가중치를 두기 위해 정기적으로 사용됩니다. 이 지표의 근본적인 원리는 (책의 챕터(장)처럼) 코퍼스 내부 문서에서 단어가 여러 번 나타나면 전체 코퍼스 전체에 걸쳐 여러 번 나타나는 다른 단어보다 그 단어가 더 중요할 것이라는 점입니다. 개념을 설명해 보겠습니다.

여기 세 개의 문서로 된 코퍼스가 있다고 가정해 보세요. 이 경우에는 세 개의 문구입니다:

- (d1) *My dog is my beautiful dog. (나의 개는 나의 아름다운 개입니다.)*
- (d2) *My dog is an amazing animal. (나의 개는 놀라운 동물입니다.)*
- (d3) *My friend has a pet. (내 친구는 애완동물을 키웁니다.)*

**단어 빈도(Term Frequency, TF)** 는 토큰이 문서에 나타나는 횟수를 측정합니다. 문서 내의 각 단어에 대한 TF의 계산은 **\[TF\] / \[Total terms, 총 단어 수\]** 처럼 간단합니다. 따라서 d1에서 *dog* 의 TF는 **2/6 = 0.33**, d2에서는 **1/6 = 0.17**, d3에서는 **0/4 = 0** 입니다. 따라서 단어 **dog** 는 다른 어떤 문서에서보다 d1에서 더 빈번하게 등장합니다.

**역 문서 빈도(Inverse Document Frequency, IDF)** 는 용어가 얼마나 중요한지를 측정합니다. 반전된 빈도(inverted frequency)의 로그를 계산합니다. 즉, **log(\[총 문서 수\] / \[해당 단어가 있는 문서 수\])** 입니다. 이 계산은 모든 문서에서 매우 빈번하게 등장하는 단어들의 중요도를 낮추고 더 드물게 나타나는 단어들의 비중을 높일 것입니다. **dog** 의 IDF는 **log(3/2) = 0.4054** 입니다.

각 문서에 대한 단어의 최종 중요도를 계산하기 위해 우리는 단순히 두 측정값 **\[TF\] \* \[IDF\]** 를 곱하기만 하면 됩니다. d1에서 *dog* 의 TF-IDF는 **0.33 \* 0.4054 = 0.133782** 이고, d2에서는 **0.068918** 이며 d3에서는 **0** 입니다.

우리가 오직 TF만을 고려한다면 *dog* 가 **3/17** 번 등장한 것에 대비하여 *my* 라는 단어는 총 **4/17** 번 등장했으므로 이 단어가 가장 중요하게 간주될 것이라는 점에 주목하세요. 이전에 계산된 *dog* 의 점수와 비교할 때, TF-IDF를 사용하면 *my* 는 모든 문서에 등장하고 **log(3/3) = 0** 이므로 항상 0의 점수를 가집니다. 참으로 단어 *dog* 가 텍스트에 더 많은 의미를 부여합니다. 이제 RStudio에서 이 계산을 수행하는 방법을 살펴보겠습니다.

우리는 계속해서 동일한 데이터 세트를 사용할 것이므로 코딩으로 넘어가겠습니다. **clean_tokens** 개체는 모든 불용어를 정제하고 토큰화한 우리의 데이터 세트입니다. **mutate()** 함수를 사용하여 인덱스 열 **idx** 를 추가할 것입니다:

\# 인덱스가 있는 열 추가 tokens_by_chapter \<- clean_tokens %\>%     mutate(idx = 1:nrow(clean_tokens)) %\>%     select(idx, tokens)

이제 **case_when()** 과 결합된 **mutate()** 함수를 사용하여 장(chapter) 번호가 포함된 열을 추가할 것입니다. 이는 **idx** 열을 가져와서 인덱스의 번호를 기반으로 특정 관측치에 할당할 챕터를 결정합니다:

\# 챕터(장) 열 추가 tokens_by_chapter \<- tokens_by_chapter %\>%     mutate(chapter =              case_when(              idx \< 621 ~ "introduction",              between(idx, 621, 1045) ~ "ii",              between(idx, 1045, 1764) ~ "iii",              between(idx, 1764, 2566) ~ "iv",              between(idx, 2566, 3143) ~ "v",              between(idx, 3143, 3930) ~ "vi",              between(idx, 3930, 4695) ~ "vii",              between(idx, 4695, 6098) ~ "viii",              between(idx, 6098, 6825) ~ "ix",              between(idx, 6825, 7670) ~ "x",              between(idx, 7670, 8509) ~ "xi",              between(idx, 8509, 9407) ~ "xii",              between(idx, 9407, 9777) ~ "xiii",              between(idx, 9777, 10537) ~ "xiv",              between(idx, 10537, 10700) ~ "xv",              between(idx, 10700, 11171) ~ "xvi",              idx \>= 11171 ~ "epilogue"     )    ) %\>%     select(chapter, tokens)

다음 코드 스니펫은 챕터별로 토큰이 몇 번 반복되는지 세는 데 사용됩니다. 따라서 우리는 **count()** 함수를 사용하여 장별로 단어를 계산합니다:

\# 챕터별 단어 수 tokens_by_chapter \<- tokens_by_chapter %\>%   count(tokens, chapter, sort=T)

다음으로, **bind_tf_idf(term= tokens, document= chapter, n= n)** 을 사용하여 TF-IDF 계산을 추가합니다:

\# TF-IDF 계산 data_tf_idf \<- tokens_by_chapter %\>%   bind_tf_idf(tokens, chapter, n)

마지막으로 **ggplot2** 라이브러리를 사용하여 플롯을 그릴 수 있습니다. 이 라이브러리에 대해서는 3부(Part 3)에서 더 자세히 배울 것입니다. 지금은 그냥 코드를 따라가세요. **data_tf_idf** 개체부터 시작하여 장별로 그룹화하고 **slice_max()** 를 사용하여 **tf_idf** 변수 기준 가장 높은 순서대로 상위 **n=5** 항목만 가져옵니다. **with_ties = F** 인수는 챕터당 정확히 5개의 항목만 허용합니다. 그런 다음 **ungroup()** 을 사용하여 그룹화된 레벨을 제거합니다. 결과는 **plot_tf_idf** 에 저장됩니다:

\# 플로팅할 데이터 plot_tf_idf \<- data_tf_idf %\>%   group_by(chapter) %\>%   slice_max(tf_idf, n = 5, with_ties = F) %\>%   ungroup()

결과를 플로팅하기 위해 **plot_tf_idf** 와 **ggplot()** 함수를 연결하고 챕터별로 **x, y** 및 **fill(채우기)** 색상을 전달합니다. 그런 다음 **geom_col()** 그래픽 유형을 추가하고 **facet_wrap()** 을 추가하여 각 장별로 하나씩 4개의 열로 나누어 많은 플롯을 만들고 **tf_idf** 숫자를 **x** 축 라벨로 사용합니다:

\# TF-IDF 플로팅 plot_tf_idf %\>%     ggplot(aes(x=tf_idf, y=fct_reorder(tokens, tf_idf), fill = chapter)) +   geom_col(show.legend = FALSE) +   facet_wrap(~chapter, ncol = 4, scales = "free") +   labs(x = "tf-idf", y = NULL)

## N-grams

N-grams은 순차적인 N개의 단어 그룹입니다. 텍스트 마이닝 프로젝트는 바이그램(bi-grams)이나 트라이그램(tri-grams)으로 작업하는 경향이 있는데, 이들은 각각 순차적인 두 개 및 세 개 단어의 그룹입니다. 이런 작은 시퀀스(연속)는 반복될 가능성이 더 높기 때문에 선호됩니다. 4개 이상의 단어 시퀀스가 여러 번 발생할 가능성은 훨씬 적습니다. *The trip was an adventure(그 여행은 하나의 모험이었다)* 라는 문장에서 우리는 다음과 같은 바이그램(bi-grams)을 추출할 수 있습니다: *the trip, trip was, was an*, 및 *an adventure*. 당연히 N-grams을 추출하기 전에 불용어를 제거하여 텍스트를 정리하는 것이 좋습니다.

우리 데이터 세트에서 가장 많이 사용된 바이그램(bi-grams)을 살펴보겠습니다. **unnest_tokens()** 함수에는 이를 관리할 수 있는 편리한 인수가 이미 있습니다. 다음 코드에서는 우리는 원시 데이터를 사용하여 순서대로 가장 많이 사용되는 두 단어를 추출할 것입니다. 이를 위해 코드에 **token= "ngrams", n=2** 인수만 추가하겠습니다:

\# 가장 빈도가 높은 2-grams (bi-grams) book %\>%   unnest_tokens(output = ngrams,                 input = text,                 token= 'ngrams', n=2) %\>%     count(ngrams, sort=T)

# 요인 (Factors)

문자열에 대해 이야기하고 있으므로 R의 요인(factors)을 언급하는 것이 중요합니다. 이들은 해당 범주에 순서가 있는지 여부에 관계없이 범주형 변수를 생성하는 데 사용되는 개체입니다. 범주는 예를 들어 텍스트나 숫자일 수 있습니다. 우리는 **factor()** 를 사용하여 요인 변수를 생성할 수 있습니다:

\# 텍스트 변수 var \<- c('A', 'B', 'B', 'C', 'A', 'C') \# 요인 생성 factor_var \<- factor(var)

# 요약 (Summary)

이 장에서는 문자열 작업을 위한 많은 도구를 가져왔습니다. 기억을 새로 고치기 위해 말하자면 문자열(string)은 텍스트 정보입니다. 다른 데이터와 마찬가지로 텍스트는 우리가 그것을 추출할 적절한 도구가 있다면 많은 정보와 훌륭한 통찰력을 전달할 수 있습니다. 그것이 바로 우리가 지난 몇 페이지에서 정확히 수행한 작업이었습니다.

우리는 tidyverse 패키지의 일부인 **stringr** 라이브러리의 주요 함수들에 대해 배웠습니다. tidyverse의 라이브러리 사용법을 배우는 것의 이점은 쉬운 코딩과 깔끔한(tidy) 개념을 고수하여 데이터를 변환하고 모델링을 준비하는 데 도움을 준다는 것입니다. 우리는 **stringr** 함수가 작업 식별자가 뒤따르는 **str\_** 접두사로 시작한다는 것을 확인했으며 이로 인해 코딩을 배우고 기억하기가 더 쉬워졌습니다.

다음으로, 여러 다양한 분석 작업에 대해 고도로 맞춤화된 텍스트 패턴을 생성하기 위한 문자열인, 가장 많이 사용되는 정규 표현식 패턴을 다루었습니다.

마지막으로 우리는 **stringr** 함수와 정규 표현식, 그리고 일부 기본 R 함수를 결합하여 데이터 요약을 만드는 방법을 배웠을 뿐만 아니라, 여러분의 분석을 향상시킬 수 있는 아주 완벽한 분할표를 생성하기 위한 단일 함수를 포함하는 **gmodels** 라이브러리를 소개했습니다. R의 범주형 데이터에 사용되는 잘 알려진 텍스트 유형이므로 장의 마지막에서 요인(factor) 유형을 다루었습니다.
